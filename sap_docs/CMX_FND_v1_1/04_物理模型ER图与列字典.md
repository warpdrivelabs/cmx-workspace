## 0. 图例与通用约定

关系记法：`A }o--|| B` = A 多对一 B（子表 → 父表）；线上标注为外键列。

**通用列（所有表都有，各域图中不再重复画出指向 client_scope 的连线）：**

| 列 | 类型 | 含义 |
|---|---|---|
| `tenant_id` | uuid | 租户隔离键（与 mandt 共同构成范围；对应 SAP CLIENT/MANDT 语义的收敛） |
| `mandt` | varchar(3) | SAP 客户端号（CHECK：3 位数字） |

**统一 FK**：每张表的 `(tenant_id, mandt)` 外键 → `client_scope`，下文各域图省略；**另有 21 张发布绑定表**（域 C/D/E 全部 + 无）的 `release_id` 均外键 → `foundation_release`，总览图中亦省略、完整清单见 §13。

**三类数据模型的列型规范：**

| 列型 | 出现位置 | 含义 |
|---|---|---|
| `object_id` + 稳定业务编码 | `*_key` / `*_identity` 身份表 | 只表达身份的稳定 UUID；编码一经分配不得重新指向别的对象 |
| `release_id` | `*_config` 配置表 | 行属于某个不可变配置发布包；同一发布内跨表外键一致 |
| `revision_id` + `valid_from/valid_to` + `recorded_from/recorded_to` + `approved_change_id` | `*_version` 版本表 | 版本行：revision_id 为主键成分（快照/回执引用它而非业务键）；业务有效期 [from,to) 半开、to 可空=开放；系统认知期同构；时态不重叠由 EXCLUDE 约束兜底；approved_change_id 引用审批变更 |

## 2. 域 A：治理底座与运行台账（6 表）

```mermaid
erDiagram
    client_scope {
        uuid tenant_id PK "租户隔离键"
        varchar mandt PK "SAP客户端号(3位数字)"
    }
    foundation_release {
        uuid tenant_id PK "租户"
        varchar mandt PK "客户端号"
        uuid release_id PK "发布包唯一标识"
        integer version "发布版本号(>0，同scope唯一)"
        text status "状态: DRAFT-VALIDATED-APPROVED-PUBLISHED"
        text profile "能力档案标识(如FND_1_1_DEMO)"
        varchar content_hash "内容摘要(64位hex，发布必填；服务验证非签名)"
        text created_by "创建人"
        text approved_by "审批人(必须存在且不等于创建人)"
        timestamptz approved_at "审批时刻"
        timestamptz published_at "发布时刻(发布必填)"
    }
    config_head {
        uuid tenant_id PK "租户"
        varchar mandt PK "客户端号"
        uuid active_release_id PK "当前激活的发布(release_id)"
        bigint version "指针版本号(默认1，每次切换+1)"
    }
    command_receipt {
        uuid tenant_id PK "租户"
        varchar mandt PK "客户端号"
        text source_system PK "来源系统(幂等键组成)"
        text action PK "业务动作(幂等键组成)"
        text idempotency_key PK "调用方幂等键"
        varchar request_hash "请求体规范摘要(64hex，重放时比对)"
        text state "状态: STARTED-COMPLETED"
        jsonb result "完成后的结果(重放原样返回)"
        timestamptz created_at "创建时刻"
        timestamptz completed_at "完成时刻"
    }
    outbox {
        uuid tenant_id PK "租户"
        varchar mandt PK "客户端号"
        uuid event_id PK "事件唯一标识"
        text aggregate_key "聚合键(如门key-对象key)"
        bigint aggregate_version "聚合版本(同键同型同版唯一)"
        text event_type "事件类型"
        jsonb payload "事件负载(与业务同事务写入)"
        timestamptz created_at "创建时刻"
        text state "状态: PENDING-LEASED-DONE-DEAD"
        integer attempt "投递次数(>=0)"
        timestamptz available_at "下次可投时刻(退避)"
        timestamptz lease_until "投递租约到期(worker崩溃恢复用)"
    }
    context_snapshot {
        uuid tenant_id PK "租户"
        varchar mandt PK "客户端号"
        uuid context_id PK "上下文唯一标识(对外不透明)"
        uuid release_id "解析所用的发布(FK)"
        varchar request_hash "请求摘要(一致性校验，非令牌)"
        jsonb payload "完整解析结果(组织-期间-价格-版本引用)"
        timestamptz created_at "创建时刻"
        timestamptz expires_at "过期时刻(必须晚于创建)"
        text subject_id "创建主体(用户/服务)"
    }
    foundation_release |o--o| config_head : "激活指针"
    context_snapshot }o--|| foundation_release : "release_id"
```

要点：`foundation_release` 状态机由触发器保护（PUBLISHED 行禁改）；`command_receipt` 是幂等激活的唯一闸口（STARTED 与业务写入同事务）；`outbox` 租约式至少一次投递；`context_snapshot` 是服务端受控快照，**不等于过账授权**。

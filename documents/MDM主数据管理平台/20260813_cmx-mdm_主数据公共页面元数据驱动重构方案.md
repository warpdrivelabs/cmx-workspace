## 修订说明（V2 相对 V1）

经子智能体对照真实代码审查，V1 有两个**阻断级假设不成立**，本版全部修正：

- **P1**：V1 假设"默认取元数据可见列"即得干净业务列——**不成立**。`metaTableFieldsToColumns`（`packages/cmx-data-comp/src/lib/init-page-models.js:381-553`）不过滤任何列；审计/治理/scope 列**没有** `visible:false` 标记（已核实 `base_dct_meta_v1.json`：仅 `id` 标了 visible:false）。→ 改为**页面内置默认过滤 + `props.columns` 可覆盖**（用户已确认）。
- **P2**：两页是**模块级单例 state**，宿主按 pageId 只 import 一次模块 → 多菜单节点/多 tab 共用会互踩。→ 改为**按 host 隔离 state**（必做）。

其余落实项：P3 后端 idx 计数 bug、P4 openTab 去重 key、P5 搜索占位文案、P6 菜单重新部署 + index 文案通用化、P7 详情页 enum 值格式化、P8 docType 启动校验、P9 readCoord 统一等。

## 〇、目标与已确认决策

**目标**：把写死供应商的两个门面页改造成**公共页面**，每种主数据各挂一个菜单节点，差异（标题、字典、单据类型等）由**菜单节点 `props` 注入**。以后新增主数据类型只加配置与菜单节点，**零前端代码**。

| # | 决策点 | 选定方案 |
|---|---|---|
| 1 | 页面落地方式 | **原地重构**：`cr-editor.js`→`master-list.js`、`supplier-detail.js`→`master-detail.js` |
| 2 | 默认列策略 | **页面内置默认过滤 + 可覆盖**（用户确认）：内置"平台列默认隐藏"规则并尊重 `visible:false`；`props.columns` 可精确覆盖。供应商节点配 `columns` 保留含 `published_version` 的现状 |
| 3 | 详情页子表来源 | **激活映射配置自动发现**：从 `mdm_activation.line_mappings` 读子表字典 + 外键列；需给 `GET /api/mdm/activations` 补可选 `targetDict` 过滤 |
| 4 | 多实例隔离（审查新增，必做） | **按 host 隔离 state**：两页 state 从模块级单例改为挂在 host（或 host 为键的 WeakMap），支持多类型/多 tab 并存 |

## 一、关键机制核实（可行性依据，均对照代码）

1. **菜单 props → ctx.props 链路现成**：`workspace-native-pages.js:52` 读 `o.props` → 序列化进宿主属性（:61）→ `_load()` 解析（:140）→ `renderNativePage(page,{props,host})`（:150）→ 页面 `ctx.props`。零框架改动。
2. **坐标四元组（domain/application/module/dbId）**：由 DAM 经 `workspace.context` 注入（菜单节点所在域），与 `props` 无冲突；`readCoord` 两者合并读取。改 props 注入 dictCode 后坐标不受影响（审查疑点 2 已确认 ✅）。
3. **元数据列管线**：`GET /api/dct/meta?dict={code}&with_props=true` 返回 `dictMeta`（含 columns/labelField/codeField/pk/visible 等）；`metaTableFieldsToColumns` 派生 `CmxColumn[]` 但**不过滤**——过滤须页面侧做（见 §2.2/2.3）。
4. **字段集 visible 现状（已核实）**：`dictionaryAuditFields`（create_by/create_time/update_by/update_time）、`mdmGovernanceFields`（lifecycle_status/published_version/effective_date）、`dictionaryScopeFields`（scope_type/entity_id）、`dictionarySystemFields`（is_system）均**无 visible:false**；`dictionaryCommonFields` 仅 `id` 有 visible:false。故默认过滤必须由页面显式做。

## 二、改造方案

### 2.1 后端 · `GET /api/mdm/activations` 增加 `targetDict` 过滤

- `cmx-mdm-api/src/handlers/activation.rs`：`ActivationListQuery` 增 `target_dict`（`#[serde(default, alias = "targetDict")]`，与现有 `sourceDocType/crType` 同款），透传 `store::list`。
- `cmx-mdm-store-pg/src/activation_store.rs::list`：增 `target_dict: Option<&str>` 参数。

**⚠️ 必须修复的现成 bug（审查 P3）**：现有 WHERE 拼接中 `idx` 只在 `source_doc_type` 分支自增（`activation_store.rs:67-71`），`cr_type` 分支**没有** `idx += 1`（:72-75）——因它是最后一段才没炸。新增 `target_dict` 时，**每个 WHERE 分支 push 参数后必须 `idx += 1`**，否则 crType 与 targetDict 同传会共用同一 `$n`、参数个数不匹配直接报错。同时不要照抄 `:80-84` 的 `sort_order_of_none()` 占位 + 字符串 replace 怪味。

> 可选优化（审查建议）：评估复用已有 `line_tables_for_dict`（`activation_store.rs:208-246`，已按 target_dict 聚合 line_mappings 并按 (table, field) 去重），前端可少一层拼装；本次先用 `?targetDict=` 返回激活行，前端取 line_mappings。

**既有调用方影响分析（零改动）**：`targetDict` 为可选增量参数，现有调用方均不传 → 反序列化 `None` → 跳过该 WHERE 段 → SQL 与结果同现状。

| 现有调用方 | 位置 | 调用方式 | 是否需改 |
|---|---|---|---|
| MDM 健康检查 | `mdm-health.js:52` | 不带参数，仅统计条数 | ❌ |
| 激活映射配置器 | `activation-mapper.js:116` | 不带参数，拉全量 | ❌ |
| CR 表单 | `cr-form.js:321` | 不带参数拉全量，前端按 `source_doc_type+cr_type` 过滤（:322） | ❌ |
| 配置器保存/删除 | `activation-mapper.js:1008/1022` | `POST /activations`、`POST /activations/delete` | ❌ 不涉及 |

唯一新增消费方为 `master-detail.js`（`?targetDict={dictCode}`）。向后兼容，存量页面零改动。

### 2.2 前端 · `cr-editor.js` → `master-list.js`（通用主数据列表页）

**页面 id**：`portal.mdm.cr-editor` → `portal.mdm.master-list`。

**读 `ctx.props`**（菜单注入）：

| prop | 必填 | 说明 |
|---|---|---|
| `dictCode` | ✅ | 目标主数据字典码（如 `supplier`） |
| `docType` | ✅ | 该类型 CR 单据类型（= activation.source_doc_type，如 `gys`） |
| `title` | ✅ | 页面标题（如"供应商列表"） |
| `entityName` | ⭕ | 实体名（按钮文案"新增供应商"），缺省取 title |
| `icon` | ⭕ | 图标 |
| `columns` | ⭕ | 列子集/顺序（字段名数组）；缺省走默认过滤 |
| `searchPlaceholder` | ⭕ | 搜索占位文案；缺省按 labelField/codeField caption 拼 |

**关键实现要点**：
1. **按 host 隔离 state（P2，必做）**：`state/coord/currentHost/rootEl` 从模块级单例改为挂 host（`host.__state`）或以 host 为键的 WeakMap；`content(ctx)` 内一切读写走各自 host 的 state，`refresh` 只刷自己的 host；顺手删除只写不读的死变量 `listGrid`（`cr-editor.js:172`）。
2. **列模型（P1）**：`loadDictMeta(dictCode)` 用 `?with_props=true` → `metaTableFieldsToColumns` 得全量列 → **默认过滤**：剔除平台列集合 `{id, sort_no, create_by, create_time, update_by, update_time, lifecycle_status, published_version, effective_date, effective_from, effective_to, disabled_reason, disabled_time, scope_type, entity_id, is_system, level_no, full_path, is_leaf, parent_id, parent_code}` 且尊重 `visible===false`；若 `props.columns` 有值则**以其为最终显示清单**（按其筛选并排序，显式覆盖默认，供应商借此保留 `published_version`）→ 追加 `_action` 操作列（查看详情/变更）。
3. **启动校验 docType（P8）**：用 `GET /api/mdm/activations?targetDict={dictCode}` 校验存在 `source_doc_type===docType` 的激活；缺失则给可读报错（配置脱节快速暴露）。
4. **搜索占位（P5）**：默认按 `labelField`/`codeField` 的 caption 拼（如"名称/编码"），或 `props.searchPlaceholder`。**不要沿用**现状"名称/编码/信用代码"（后端 `q` 只搜 code+labelField，credit_code 本就不在范围）。
5. **openTab 去重 key（P4）**：key 派生加入 `context.recordId`（现状 `cr-editor.js:91` 用 supplierId，改 recordId 后会落 `Date.now()` 致重复 tab）。
6. **readCoord 统一（P9）**：采用 `cr-form.js:104-115` 版本（module 回退 'mdm'、dbId 兼读 wctx）。
7. 新增 → 开 `cr-form` `{mode:'create', docType, crType:'create', ...coord}`（单例）；变更 → `{mode:'update', docType, crType:'update', targetId, targetName, ...coord}`；查看详情 → 开 `portal.mdm.master-detail` `{dictCode, recordId, title, columns, ...coord}`（`columns` 为列表页已解析的显示列，透传给详情页保持一致）。

### 2.3 前端 · `supplier-detail.js` → `master-detail.js`（通用主数据详情页）

**页面 id**：`portal.mdm.supplier-detail` → `portal.mdm.master-detail`。

**读参**（`workspace.context` 优先、`ctx.props` 兜底）：`dictCode`、`recordId`、`title`、`icon`、`columns`（由列表页透传，缺省走默认过滤）。

**关键实现要点**：
1. **按 host 隔离 state（P2）**：同 §2.2。
2. **头字段（P1）**：`GET /api/dct/meta?dict={dictCode}&with_props=true` → 优先用 context 透传的 `columns`，缺省按 §2.2 同款默认过滤 → 渲染 `cmx-desc-list`，label 用列 caption。
3. **值格式化（P7）**：desc-list 渲染时做 **enum 映射**（列 `enumValues` 把裸值 "1"→"启用"）；refDict 回显可后置（见 §七）。
4. **头记录**：`POST /api/dct/data/search?dict={dictCode}` + `filters:{ id: recordId }`。
5. **子表自动发现**：`GET /api/mdm/activations?targetDict={dictCode}` → 取 `line_mappings[]`（多条激活优先 cr_type=create，否则首条）→ 每个 lineMapping：子表字典 `targetDict`、外键列 `parentIdField`；子表列 `GET /api/dct/meta?dict={targetDict}&with_props=true` 经默认过滤后**无条件剔除 `parentIdField`**（不依赖元数据 visible 纪律，防止新类型忘标 visible:false 致外键漏出）；子表用**页面级表格渲染**（同现状 supplier-detail 的 `<table>`），渲染时对 enum 列做值→label 映射；子表数据 `POST /api/dct/data/search?dict={targetDict}` + `filters:{ [parentIdField]: recordId }`；卡片标题取子字典 `dict_name`；子表默认 pageSize=100、超量提示。
6. **优雅降级**：无激活配置/无子表（扁平主数据）时只渲染头字段，不报错。

## 三、菜单 props 契约（新增主数据类型照此填）

```jsonc
{
  "id": "mdm-<type>-list", "caption": "<中文名>列表", "type": "workspace-node",
  "workspace": { "content": { "caption": "<中文名>列表",
    "views": [{
      "type": "native_pages", "native_page": "portal.mdm.master-list",  // ← 公共页，恒定
      "view": "content",
      "props": {
        "dictCode": "<字典码>",              // 必填
        "docType": "<CR单据类型>",            // 必填（= activation.source_doc_type）
        "title": "<中文名>列表",              // 必填
        "entityName": "<中文名>",            // 可选
        "icon": "<icon>",                    // 可选
        "columns": ["code","name"],          // 可选，列子集/顺序（缺省走默认过滤）
        "searchPlaceholder": "名称/编码"      // 可选
      }
    }]
  } }
}
```
详情页无需菜单节点（由列表页"查看详情"经 openNode 打开，context 携带 `dictCode/recordId`）。

## 五、验收标准

1. 供应商菜单进列表页：标题"供应商列表"，列为 `props.columns` 精选列（含 published_version），分页/搜索正常。
2. "新增/变更"正确开 cr-form（docType=gys）；"查看详情"开 master-detail 显示供应商头字段 + 银行账户子表（子表自动从激活映射发现，外键列不显示，status 等 enum 正确回显）。
3. `GET /api/mdm/activations?targetDict=supplier` 能过滤。
4. **回归**：不带 `targetDict` 调用，返回与改前一致；健康检查/配置器/CR 表单三处行为不变。
5. **多实例（P2 关键）**：同时打开两个不同类型 master-list + 两个 master-detail，**互不串数据**。
6. **详情 F5 刷新（对齐框架现行行为）**：动态页 F5 按产品行为回首页、无报错/白屏（框架「动态页刷新不留页」，`portal-router.js:573-581`）。F5 留页属框架能力缺口，如需支持另立项（见 §七）。
7. 全库 grep 无残留 `portal.mdm.cr-editor` / `portal.mdm.supplier-detail`；`cargo check` 通过；前端改动 lint 通过。
8. 模拟新类型：临时把某菜单节点 props 换成另一字典码，列表/详情正确切换（零代码复用）。

> **验收口径说明（元数据驱动的可接受差异，非 bug）**：供应商详情头字段将由现状 code/name/short_name/tax_no/credit_code/published_version 变为默认过滤集（新增 status/phone、去掉 published_version）；列表列序/caption/宽度取自元数据，默认排序回退后端规则（现状是 create_time desc）。如需逐像素复现现状，用 `props.columns` 精确配置。

## 七、本次不做（留作后续）

- 详情页 refDict 列回显（裸 id → 字典名）。
- 列表默认按 `lifecycle_status=published` 过滤（现状未过滤，保持行为一致；如需另立任务）。

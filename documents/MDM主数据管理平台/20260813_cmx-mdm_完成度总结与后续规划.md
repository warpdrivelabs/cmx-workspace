## 一、核心架构回顾（V3.1 设计方案铁律）

| # | 铁律 | 落地状态 |
|---|---|---|
| 1 | **reference 纯净**：主数据 `cm_*` 只存 published，草稿一律走 CR 单据 `cv_*` | ✅ `LifecycleStatus` 仅 4 值（published/frozen/archived/merged），无 draft |
| 2 | **激活器是 `cm_*` 唯一写入闸口**（dct_accessor 强制 published） | ✅ `dct_accessor` 写入强制 `lifecycle_status='published'`，update 走 CAS；M7 后激活由流程回写触发，闸口不变 |
| 3 | **单事务原子**：激活/合并全流程一个 DB 事务，失败整体回滚 | ✅ `activate`(七步) / `merge`(十步) 均 RAII guard 单事务；webhook 触发的激活失败回置 approving 可重试 |
| 4 | **并发控制**：CR 互斥 + 乐观锁（published_version）+ 合并行锁 | ✅ CAS 版本号 + `FOR UPDATE` + lifecycle 双保险；M7 增补 `try_set_cr_status` 条件 UPDATE 抢占（webhook/懒同步/手动三方并发单赢家） |
| 5 | **配置驱动**：通用激活器读映射配置，新增主数据只加配置 | ✅ `mdm_activation` + UI 映射配置器 + 公共页 props 注入（列表/详情也配置化） |
| 6 | **合并走激活器统一入口**（不绕开闸口，事件不漏） | ✅ `merge` 分支经 dct_accessor，发 md_event_log |
| 7 | **驳回复活 = 原单编辑重提**（rejected → edit → submit → approving） | ✅ submit 接受 rejected；M7 重提自动发新流程实例（旧实例事件被「当前实例规则」拦截） |
| 8 | **cm_* 写端点对 MDM 域降级只读** | ⚠️ **未做**——`/api/dct/*` 写端点未对 MDM 域做只读降级（见技术债 D-06） |

**M7 新增两条设计铁律**（20260817 V4 方案确立，均已落地）：
- **回写统一入口**：CR 状态落位只经 `sync_flow_result`（webhook/懒同步/review 主动同步三方共用），业务动作层不直写状态；
- **信封判据**：回环调 flow 成功 = HTTP 2xx **且** 信封 `code==0`（flow 业务错误返回 200+code=1，只看 HTTP 状态码会产生 approving 孤儿单）。

## 十、风险提示

1. **M7 部署依赖**：BPMN 须先 `deploy-mdm-flow.sh` 发布 + `mdm_approver` 角色有成员（候选 start 时物化，事后补角色对运行中实例无效——迁移已预分配 admin 消除陷阱，生产须按人员分离原则分配）。`[mdm.flow].webhook_secret` 须与 flow-server `FLOW_WEBHOOK_SIGNING_KEY` 一致，空密钥 = callback 拒收。
2. **匹配量级假设**：M3 假设 published ≤1 万/字典可全量装载；超限路线（blocking 下推 SQL 已部分实现 load_suspects，但模糊簇键缺失可能在大库下召回不足）。
3. **D-06 铁律缺口**：cm_* 写端点未降级只读，生产环境若有人直写 cm_* 会破坏 reference 纯净。建议尽快补路由层拦截。
4. **cmx-agg 误判**：若 M6 含组织/财务域，层次汇总是隐藏关键路径（平台零代码，需新造，曾被误当复用）。
5. **多库边界**：M7 回写链在多业务库部署下有 D-09 限制（callback 定位默认库）；单库/同库多 schema 不受影响。

## 〇、范围与关键决策

**M3 做**：
- 匹配算法：分块（多簇键+优先级+护栏）→ 字段级比较 → 双阈值裁决（≥95 AutoMerge / 80–94 Review / <80 NoMatch）
- 字段级存活（survivorship）：逐字段取值策略（master 优先 / 最全 / 最新）
- `md_merge_record` / `md_xref` 读写
- **合并经激活器 merge 分支**（V3.1 统一闸口）：`md_merge_record` 即合并请求载体（**不建 cv_* CR**，审查重要-1 统一表述；规划文档 M3 提纲的"内部 merge CR"语义由 md_merge_record 承载，不回写 cv_*）
- merge 分支：victim `lifecycle_status='merged'`（+version+1 破 CAS）、明细 re-parent、存活值写回 master、`md_xref` inactive、`survivorship_log`、`md_event_log` merged（payload 带追溯）
- unmerge 还原（status='unmerged'，防重复 undo）
- 端点：find-duplicates / merge-requests(GET/POST) / merge-requests/undo
- 前端：查重候选 UI

**M3 不做**：管家工作台四区（留 M4）、分发消费（M5）、模糊匹配 ML。

### 关键决策（审查修订）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 合并载体 | **md_merge_record 即合并请求，不建 CR** | 审查重要-1：统一表述；追溯靠事件 payload（match_group_id/master_id/victim_ids） |
| D2 | merge 审批 | 不走审批（管家确认即生效） | 内部操作，直接调闸口 |
| D3 | 匹配起点 | 精确 + 编辑距离（name） | 准确性优先 |
| D4 | 存活策略 | 逐字段配置；默认 master 优先 + 空值补全 | M4 加人工裁决 |
| D5 | 并发安全 | 单事务 + master `FOR UPDATE` + victim lifecycle CAS + **set_lifecycle 同时 version+1** | 审查重要-4/5：防交叉 merge、防 merged 行被 update CR 写入 |
| D6 | unmerge | 反向亦经 dct_accessor；md_merge_record.status='unmerged' | 审查建议-7：防重复 undo |
| D7 | 表名解析 | **handler 入参 dictCode → 经 DCT meta 解析 head_table/line_tables 传入 merge** | 审查重要-6：model/store 不发明映射 |

## 二、M3-0 · 闸口扩展（dct_accessor.rs 追加）

```rust
/// 改 lifecycle_status（merge→merged / unmerge→published）。
/// **双保险**（审查重要-5）：① CAS expected→next 防双 merge；② SET 同时
/// published_version+1，使并发的 update-CR 写入者版本失配回滚。
/// 不 SET update_time 之外的时间戳列不存在问题（cm_* 有 update_time）。返回行数（0=冲突）。
pub async fn set_lifecycle(
    mm, db_id, txn_id, table, record_id, expected: &str, next: &str,
) -> Result<u64, Error> {
    validate_ident(table)?;
    let sql = format!(
        "UPDATE {table} SET lifecycle_status = $1, published_version = published_version + 1, \
         update_time = now() WHERE id = $2 AND lifecycle_status = $3");
    ...
}

/// 明细 re-parent：detail 表 parent_field=from 的行改指 to。返回行数。
pub async fn reparent_lines(mm, db_id, txn_id, detail_table, parent_field, from_id, to_id) -> Result<u64, Error>;

/// 锁行（审查重要-4）：merge 事务内先 SELECT id ... FOR UPDATE 占 master 行锁，串行化交叉 merge。
pub async fn lock_record(mm, db_id, txn_id, table, record_id) -> Result<bool /*exists*/, Error> {
    validate_ident(table)?;
    let sql = format!("SELECT id FROM {table} WHERE id = $1 FOR UPDATE");
    ...
}

// validate_ident 提升为 pub(crate)（审查建议-6，match_store 复用，不复制第二份）
```

> **M1 补强（重要-5 顺手项）**：`build_update_sql` 的 WHERE 追加 `AND lifecycle_status = 'published'`，merged 行拒绝任何 CAS 写入。

### 验收
- set_lifecycle published→merged n=1 且 version+1；重复 n=0。
- 交叉 merge：两事务 FOR UPDATE 串行，后到者 victim CAS 失败。
- merged 行调 update_header → n=0（lifecycle 条件）。

## 三、M3-1 · 匹配算法（model/match_algo.rs，纯逻辑可单测）

```rust
pub struct MatchRecord { pub id: i64, pub fields: Map<String, Value> }
pub enum FieldKind { Exact, EditDistance }
pub struct MatchFieldSpec { pub field: String, pub weight: u32, pub kind: FieldKind }
pub enum Decision { AutoMerge, Review, NoMatch }
pub struct MatchCandidate { pub record_id: i64, pub score: u8, pub decision: Decision }

/// 分块。cluster_keys 按优先级序（如 [credit_code, tax_no, name]）；
/// 护栏：簇键 NULL/空 → 该记录不进共享块（独立块，防 NULL 巨簇）；
/// 块上限 500：超出 **tracing::warn + 截断**（审查建议-3，M3 记日志，M4 降级次簇键）。
pub fn blocking(records: &[MatchRecord], cluster_keys: &[&str]) -> Vec<Vec<&MatchRecord>>;

/// 比较（审查重要-3 设防）：
/// - 中间量 u32：score = Σ(field_score×weight) / Σweight（field_score 0-100）
/// - Σweight == 0 → 返回 0（NoMatch）
/// - EditDistance：两侧均空 → 视为相等满分；max_len==0 显式分支（不除零）
/// - Exact：相等满分，不等 0；两侧均空 → 0 分（空值不构成匹配证据）
pub fn compare(target: &MatchRecord, other: &MatchRecord, specs: &[MatchFieldSpec]) -> u8;

pub fn decide(score: u8) -> Decision  // ≥95 AutoMerge / ≥80 Review / 否则 NoMatch

/// 查重：target vs all（先 blocking 再块内 compare），排除自身与 lifecycle≠published。
pub fn find_candidates(target, all, specs, cluster_keys) -> Vec<MatchCandidate>;
```

默认 specs（supplier）：`credit_code Exact w40 / tax_no Exact w30 / name EditDistance w30`；
cluster_keys：`["credit_code", "tax_no", "name"]`。

### 验收（单测级，审查建议-4 修正前置）
- 同 credit_code → 同块；credit_code 空 → 独立块；块>500 截断+warn。
- 全等 → 100 → AutoMerge。
- **name 簇键块场景**（credit_code/tax_no 均空）：name 差一字 → 80–94 → Review。
- credit_code+tax_no 相等、name 差一字 → ≈97 → AutoMerge（公式验证）。
- Σweight=0 → 0；双空 name → 不除零。

## 四、M3-2 · 字段级存活（model/survivorship.rs）

```rust
pub enum SurvivorRule { MasterFirst, Fullest, Latest }
pub struct SurvivorLogEntry { pub field: String, pub from: String /*master|victim*/, pub value: Value }
/// 逐字段存活。MasterFirst/Fullest：master 非空用 master 否则 victim（都非空 master）；
/// Latest：按 fields.update_time 新者。返回 (存活行, log)。
pub fn survive(master: &MatchRecord, victim: &MatchRecord,
    survive_fields: &[String], rules: &std::collections::HashMap<String, SurvivorRule>)
    -> (Map<String, Value>, Vec<SurvivorLogEntry>);
```

### 验收
- master 空 victim 非空 → victim + log from=victim；都非空 → master。

## 六、M3-4 · 激活器 merge / unmerge（activation_service.rs 追加）

```rust
/// 合并（单事务，审查修订）：
/// ① lock_record(master, FOR UPDATE) ② 读 master/victims（须 published）
/// ③ survive 逐字段 ④ victim: set_lifecycle(published→merged, CAS+version+1)，n=0 即冲突报错
/// ⑤ reparent_lines(各 line_tables) ⑥ update_header(master, 存活值+version+1, CAS)
/// ⑦ deactivate_xref(victim) ⑧ write_audit(action=merge, source_cr_id=None)
/// ⑨ write_event(merged, payload={match_group_id, master_id, victim_ids, survivorship_log 摘要})（审查重要-1/建议-9 追溯）
/// ⑩ update_match_group(status=reviewed/auto_merged, survivorship_log, master_id)
///    —— 手工合并先 insert_match_group 承载（审查建议-8），保证⑩有对象、undo 有入口。
pub async fn merge(
    mm, db_id, dict_code: &str, head_table: &str,
    master_id: i64, victim_ids: &[i64],
    survive_fields: &[String], rules: &HashMap<String, SurvivorRule>,
    line_tables: &[(String, String)], operated_by: i64, match_group_id: i64,
) -> Result<i64>;

/// unmerge：victim merged→published（CAS）、re-parent 回 victim、activate_xref、
/// update_match_group(status='unmerged')；双 unmerge 第二笔 CAS n=0 报错（审查建议-7）。
/// master 存活值不回退（仅留痕），避免数据抖动。
pub async fn unmerge(mm, db_id, dict_code, head_table, master_id, victim_id,
    line_tables, operated_by, match_group_id) -> Result<()>;
```

### 验收
- merge：victim=merged+version+1、明细指 master、master 存活值 version+1、event payload 含 match_group_id、xref inactive、group status reviewed。
- 双 merge 第二笔 n=0 报错；交叉 merge FOR UPDATE 串行后失败。
- merged 行被 update CR 激活 → n=0 回滚（lifecycle 条件）。
- unmerge 还原 + 双 unmerge 报错。

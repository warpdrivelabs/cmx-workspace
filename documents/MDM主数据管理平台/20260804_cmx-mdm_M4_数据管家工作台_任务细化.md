## 〇、范围与关键决策

**M4 做**：
- 匹配评审队列（四区：待审 pending / 已自动合并 auto_merged / 已评审 reviewed / 已驳回 rejected + unmerged）
- 合并请求详情 + **红线 diff**（master vs victim 字段级新旧对比）
- 存活字段**人工裁决**（逐字段选真值 → 调 merge 带 survivorship 规则/显式值）
- 审批留痕（md_audit，复用 write_audit）

**M4 不做**：分发（M5）、多域（M6）、flow（M7）。

### 关键决策（审查修订）

| # | 决策 | 选择 | 理由 |
|---|---|---|---|
| D1 | 详情数据 | `GET /mdm/merge-requests/detail?mergeId=` 返回 master+victim（显式列清单 load_columns）；返回前 parse group 的 JSONB | 审查 B1/B2 |
| D2 | 人工裁决翻译表 | 选 master→规则 MasterFirst；**选 victim→overrides[field]=victim 值；手填→overrides[field]=手填值** | 审查 A1：现有规则无法显式取 victim |
| D3 | overrides 约束 | 键必须 ⊆ survive_fields，未知键报错；override 在 survive 后覆盖并改写 log from=override | 审查 A2/A3 |
| D4 | 四区 | pending / reviewed / rejected / unmerged（**删 auto_merged 死 tab**） | 审查 C4 |
| D5 | group 消费 | MergeBody 增 `mergeId`（管家路径必填）→ 复用 group 不新插；find-duplicates 置 master_id=target.id | 审查 C1/C2 |
| D6 | 状态互斥 | reject CAS `pending→rejected`；merge ⑩ CAS `pending→reviewed`（0 行=已被驳回/处理，报错） | 审查 C3 |
| D7 | reject 留痕 | 小事务内 update_match_group(rejected)+write_audit(action=reject)+reason | 审查 C5/D1 |
| D8 | 前端注册 | index.json + mdm-menu.json 双注册 `portal.mdm.steward` | 审查 E1 |

## 二、M4-0 · merge 支持 overrides

`activation_service::merge` 增参 `overrides: &Map<String,Value>`：
- survive 后，对 overrides 有的字段直接用 override 值覆盖存活行（并在 survivorship_log 记 from="override"）。
- 其余不变。

### 验收
- 带 overrides 的 merge → master 该字段=override 值，log from=override。

## 三、M4-1 · 详情端点

```rust
/// GET /mdm/merge-requests/detail?mergeId=
/// 读 group → master_id + member_ids(victims) → load_by_ids 全字段 → 返回
/// { group, master: {...}, victims: [{...}] }
pub async fn mdm_merge_request_detail(...);
```
路由：`.route("/mdm/merge-requests/detail", get(...))`。

### 验收
- 返回 master+victim 全字段供 diff。

## 四、M4-2 · merge body 增 overrides

`MergeBody` 增 `#[serde(default)] overrides: Option<Map<String,Value>>`，透传 store::merge。

## 五、M4-3 · 前端 steward.js

- 四区 tab（pending/auto_merged/reviewed/rejected/unmerged）→ GET merge-requests?status=
- 行「评审」→ GET detail → 红线 diff 表（字段 | master | victim | 裁决选择）
- 逐字段 radio（master/victim/手填）→ 生成 survivorship+overrides → POST merge-requests（master=group.master_id, victims, survivorship, overrides）
- 「驳回」→ update group status=rejected（需端点？复用 undo 不可；增 `POST /mdm/merge-requests/reject` body{mergeId}）
- Neo 主题

> 需补端点 `POST /mdm/merge-requests/reject`（update_match_group status=rejected）。

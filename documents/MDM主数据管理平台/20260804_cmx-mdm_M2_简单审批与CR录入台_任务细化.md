# M2 · 简单审批流转 + CR 录入台 · 任务级细化

> **文档定位**:[分阶段规划](./20260804_cmx-mdm_开发计划分阶段规划.md) M2 的任务级细化。MVP 收尾——CR 录入→提交→**简单按钮审批通过→激活器单事务落字典**→cm_* published。不接 cmx-flow。
> **依据**:cmx-container 代码库(M0+M1 已落地)+ V3.1 设计方案 + 第一轮审查修订。
> **日期**:2026-08-04　**状态**:**✅ 已实现（2026-08-13 代码核查确认，100%）** ｜ 详见 [完成度报告](./20260813_cmx-mdm_完成度总结与后续规划.md)

## 〇、范围与关键决策

**M2 做**:
- CR 状态机强校验:`draft→approving→approved→activated` / `→rejected` / `rejected→(clone)→draft` / `draft→aborted(作废)`
- 简单审批端点(不经 cmx-flow):**create**(新建 draft)/ submit / approve / reject / clone-revise / abort
- **approve 原子性(方案 A)**:approve 端点**直接对 approving 的 CR 调激活器**;激活器单事务内完成 `approving→activated`(改 M1 activation_service 接受 approving 起步)。失败自动回滚到 approving,不留脏状态。
- CR 列表/详情端点
- 前端:CR 录入工作台 + 待办台 + 菜单(Neo 主题)

**M2 不做**:cmx-flow 多级审批(留 M7)、审批留痕独立审计行(留 M7)、匹配、分发、cmx-code。

### 关键决策(审查修订)

| 决策 | 选择 | 理由 |
|---|---|---|
| **approve 原子性(阻塞-1)** | **方案 A:激活器接 approving 直激** | approve 端点删掉 set_status(approved),直接对 approving 调 activate;激活器单事务内 approving→activated。失败回滚到 approving,可重试。避免 set approved + activate 两步非原子。 |
| **CR create 端点(阻塞-3)** | **补 /mdm/change-requests/create** | MDM 自洽,doc_status 由后端强制 draft,不依赖 DOC save 协议。 |
| **set_cr_status 合并(重要-1)** | **复用 M1 的 set_cr_status,改签名 txn_id: Option** | 不新增 set_status,统一一个函数。 |
| **状态机元数据(阻塞-4)** | **补 clone-revise transition + draft→aborted** | 元数据与实现一致;前端按 doc_status 硬编码按钮。 |

## 二、M2-0 · 激活器接受 approving 起步(方案 A)

### 文件
`crates/libs/cmx-mdm/cmx-mdm-store-pg/src/activation_service.rs`(改)

### 改动
激活器的状态校验放宽:接受 `approved` / `activating` / **`approving`**(新增)。这样 approve 端点可直接对 approving 的 CR 调激活器,无需先 set approved。

```rust
// activation_service.rs:75 改为(加 approving):
if status != "approved" && status != "activating" && status != "approving" {
    return Err(api_err(&format!(
        "CR {cr_id} 状态「{status}」不可激活(须 approved/approving)"
    )));
}
```

激活器第 7 步的 `set_cr_status(activated)` 不变——无论从 approved 还是 approving 起步,最终都置 activated(单事务内,PG UPDATE 直接改 doc_status)。

### 影响
- M1 已验证的 activate 端点(/mdm/change-requests/activate)仍可用(接受 approved,兼容旧行为)。
- M2 的 approve 端点对 approving 的 CR 直接调 activate,无需 set approved,原子性由激活器单事务保证。
- **无需改 M1 的其它逻辑**(create/update 分支、明细处理、审计、事件不变)。

### 验收
- 对 approved CR 调 activate 仍成功(兼容);对 approving CR 调 activate 成功(新增);对 draft/rejected CR 调 activate 被拒。

## 三、M2-1 · CR 服务

### 文件
`crates/libs/cmx-mdm/cmx-mdm-store-pg/src/cr_service.rs`(新建)

### 目标
封装 CR 的:状态校验、列表、详情、克隆(驳回复活)、新建、作废。

### 状态机(对齐 M0 voucherStatusFlow + 补 clone-revise/abort)
```
draft ──submit──→ approving ──approve(激活器)──→ activated(归档)

```

```rust
/// 新建 draft CR(录入台用)。head/lines 由前端提供。
/// 返回新 CR id。doc_status 强制 'draft'。
pub async fn create_cr(
    mm: &DatabaseManager, db_id: &str, head: &Value, lines: &[Value], operated_by: i64,
) -> Result<i64, cmx_api_types::Error> {
    let cr_id = cmx_utils::next_pk_id();
    // 头:从 head JSON 取字段,补 id/line_no/doc_no/doc_status/审计列
    let h = head.as_object().ok_or_else(|| api_err("CR head 非对象"))?;
    let now = "now()";
    let sql = r#"INSERT INTO cv_mdm_apply
        (id, upper_id, line_no, doc_no, doc_type_id, doc_type, target_dict_code, target_record_id,
         source_cr_id, cr_type, effective_date, name, tax_no, credit_code, short_name, ext_attrs,
         field_deltas, doc_status, business_status, entity_id, doc_date,
         create_by, create_time, update_by, update_time, delete_flag, attach_count, remark)
      VALUES ($1, NULL, 1, $2, 1, $3, $4, $5, NULL, $6, NULL, $7, $8, $9, $10, NULL, NULL,
         'draft', 'normal', 1, CURRENT_DATE, $11, now(), $11, now(), 0, 0, NULL)"#;
    mm.execute_sql_with_datavalues(db_id, None, sql, dv![
            DataValue::Int(cr_id),
            DataValue::String(format!("CR-{cr_id}")),       // doc_no
            DataValue::String(h.get("doc_type").and_then(|v| v.as_str()).unwrap_or("mdm_supplier_apply").into()),
            DataValue::String(h.get("target_dict_code").and_then(|v| v.as_str()).unwrap_or("supplier").into()),
            // target_record_id(可空,新建时 NULL)
            h.get("target_record_id").and_then(|v| v.as_i64()).map(DataValue::Int).unwrap_or(DataValue::Null),
            DataValue::String(h.get("cr_type").and_then(|v| v.as_str()).unwrap_or("create").into()),
            DataValue::String(h.get("name").and_then(|v| v.as_str()).unwrap_or("").into()),
            DataValue::String(h.get("tax_no").and_then(|v| v.as_str()).unwrap_or("").into()),
            DataValue::String(h.get("credit_code").and_then(|v| v.as_str()).unwrap_or("").into()),
            DataValue::String(h.get("short_name").and_then(|v| v.as_str()).unwrap_or("").into()),
            DataValue::Int(operated_by),
        ]).await
        .map_err(|e| api_err_db(&format!("新建 CR 头失败: {e}")))?;
    // 行:逐行铸号插入(upper_id=cr_id)
    for (i, line) in lines.iter().enumerate() {
        let line_id = cmx_utils::next_pk_id();
        let lo = line.as_object().ok_or_else(|| api_err("CR line 非对象"))?;
        let sql_l = r#"INSERT INTO cv_mdm_apply_line
            (id, upper_id, line_no, line_type, line_action, line_payload,
             create_by, create_time, update_by, update_time, delete_flag)
          VALUES ($1, $2, $3, $4, $5, $6, $7, now(), $7, now(), 0)"#;
        let payload = lo.get("line_payload").map(|v| v.to_string()).unwrap_or_else(|| "{}".into());
        mm.execute_sql_with_datavalues(db_id, None, sql_l, dv![
                DataValue::Int(line_id),
                DataValue::Int(cr_id),
                DataValue::Int((i as i64) + 1),  // line_no 从 1 起
                DataValue::String(lo.get("line_type").and_then(|v| v.as_str()).unwrap_or("bank_account").into()),
                DataValue::String(lo.get("line_action").and_then(|v| v.as_str()).unwrap_or("insert").into()),
                DataValue::Json(payload),
                DataValue::Int(operated_by),
            ]).await
            .map_err(|e| api_err_db(&format!("新建 CR 行失败: {e}")))?;
    }
    Ok(cr_id)
}

/// 克隆 CR(驳回复活):基于 rejected CR 复制新 draft。
/// 行逐行铸号(避免 id 冲突)。返回新 CR id。
pub async fn clone_revise(
    mm: &DatabaseManager, db_id: &str, src_cr_id: i64, operated_by: i64,
) -> Result<i64, cmx_api_types::Error> {
    // 校验旧 CR 须 rejected
    check_status(mm, db_id, None, src_cr_id, "rejected").await?;
    let new_id = cmx_utils::next_pk_id();
    // 头:INSERT...SELECT 复制(头只一条,$1=new_id 正确),覆盖关键列
    // ★ 28 列严格对齐:SELECT 每一项对应 INSERT 同位列(含 doc_type_id,不能漏)
    let sql = r#"INSERT INTO cv_mdm_apply
        (id, upper_id, line_no, doc_no, doc_type_id, doc_type, target_dict_code, target_record_id,
         source_cr_id, cr_type, effective_date, name, tax_no, credit_code, short_name, ext_attrs,
         field_deltas, doc_status, business_status, entity_id, doc_date, attach_count, remark,
         create_by, create_time, update_by, update_time, delete_flag)
      SELECT $1, upper_id, line_no, $2, doc_type_id, doc_type, target_dict_code, target_record_id,
         $3, cr_type, effective_date, name, tax_no, credit_code, short_name, ext_attrs,
         field_deltas, 'draft', business_status, entity_id, CURRENT_DATE,
         COALESCE(attach_count, 0), remark,
         $4, now(), $4, now(), delete_flag
      FROM cv_mdm_apply WHERE id = $5"#;
    mm.execute_sql_with_datavalues(db_id, None, sql, dv![
            DataValue::Int(new_id),
            DataValue::String(format!("CR-CLONE-{new_id}")),  // doc_no
            DataValue::Int(src_cr_id),                          // source_cr_id 指向旧
            DataValue::Int(operated_by),
            DataValue::Int(src_cr_id),
        ]).await
        .map_err(|e| api_err_db(&format!("克隆 CR 头失败: {e}")))?;
    // 行:读旧行 → 逐行铸号插入(upper_id=new_id)
    let old_lines = crate::doc_accessor::load_cr_lines(mm, db_id, None, src_cr_id).await?;
    for (i, line) in old_lines.iter().enumerate() {
        let line_id = cmx_utils::next_pk_id();
        let lo = line.as_object().ok_or_else(|| api_err("旧 CR line 非对象"))?;
        let sql_l = r#"INSERT INTO cv_mdm_apply_line
            (id, upper_id, line_no, line_type, line_action, line_payload,
             create_by, create_time, update_by, update_time, delete_flag)
          VALUES ($1, $2, $3, $4, $5, $6, $7, now(), $7, now(), 0)"#;
        let payload = lo.get("line_payload").map(|v| v.to_string()).unwrap_or_else(|| "{}".into());
        mm.execute_sql_with_datavalues(db_id, None, sql_l, dv![
                DataValue::Int(line_id),
                DataValue::Int(new_id),
                DataValue::Int((i as i64) + 1),
                DataValue::String(lo.get("line_type").and_then(|v| v.as_str()).unwrap_or("").into()),
                DataValue::String(lo.get("line_action").and_then(|v| v.as_str()).unwrap_or("insert").into()),
                DataValue::Json(payload),
                DataValue::Int(operated_by),
            ]).await
            .map_err(|e| api_err_db(&format!("克隆 CR 行失败: {e}")))?;
    }
    Ok(new_id)
}

/// 作废 draft CR(录入台建错时用)。draft → aborted。
pub async fn abort_cr(
    mm: &DatabaseManager, db_id: &str, cr_id: i64,
) -> Result<u64, cmx_api_types::Error> {
    check_status(mm, db_id, None, cr_id, "draft").await?;
    set_cr_status(mm, db_id, None, cr_id, "aborted").await
}
```

### 注意
- **复用 set_cr_status**(重要-1):不新增 set_status。M1 的 `set_cr_status` 需把签名从 `txn_id: &str` 改成 `txn_id: Option<&str>`(向后兼容,激活器传 Some,CR 服务传 None)。**改 md_accessor.rs**。
- **clone_revise 头复制**(重要-3):INSERT 列含全 28 列(含 attach_count/remark),用 COALESCE 兜底 NOT NULL。
- **list_cr**:实现时补动态 WHERE + row.to_json_value(初版骨架)。

### approve handler(方案 A,原子)
```rust
/// 审批通过:approving → 激活器单事务 → activated。
/// 不再先 set approved——直接对 approving 的 CR 调激活器(激活器接受 approving 起步)。
/// 激活器内部单事务完成 cm_* 写入 + CR 状态 activated,失败回滚到 approving。
pub async fn mdm_cr_approve(
    State(_s): State<CmxAppState>,
    CmxSvrContext(svr_ctx): CmxSvrContext,
    headers: HeaderMap,
    Json(body): Json<CrIdBody>,
) -> Result<Json<ApiResp<Value>>> {
    let mm = get_default_pg_db_manager();
    let db_id = resolve_db_id(db_id_from_headers(&headers).as_deref()).await;
    // 校验当前 approving
    store::check_status(mm, &db_id, None, body.cr_id, "approving").await?;
    // 直接调激活器(单事务原子:approving→activated;失败回滚到 approving)
    let operated_by = svr_ctx.auth_context.as_ref()
        .and_then(|a| a.user_id.parse::<i64>().ok()).unwrap_or(0);
    let codegen = RandomCodeGenerator;
    let record_id = store::activate(mm, &db_id, body.cr_id, operated_by, &codegen).await?;
    Ok(Json(ApiResp::ok(json!({ "crId": body.cr_id, "status": "activated", "recordId": record_id }))))
}
```

其它 handler(submit/reject/clone-revise/abort/create)骨架见初版,关键:
- submit:`check_status(draft)` → `set_cr_status(approving)`
- reject:`check_status(approving)` → `set_cr_status(rejected)`(cm_* 全程不动)
- clone-revise:`store::clone_revise` → 返回新 draft id
- abort:`store::abort_cr`
- create:`store::create_cr`(body 头+行)

### 事务原子性(N2,create_cr/clone_revise 用事务 guard)
create_cr / clone_revise 的头+行多语句**必须用事务包裹**(对齐 activation_service.rs:30-56 模式):
```rust
let txn_ctx = mm.get_transaction_context();
let guard = txn_ctx.begin_with_guard(db_id).await.map_err(|e| api_err(&format!("开事务失败: {e}")))?;
let txn_id = guard.txn_id().to_string();
// 头 + 行 INSERT 都传 Some(&txn_id)
... execute_sql_with_datavalues(db_id, Some(&txn_id), ...) ...
guard.commit().await.map_err(...)?;  // 失败 guard drop 回滚
```
注:check_status 在事务外读(只读校验),INSERT 在事务内。

## 八、验收用例(M2 验收门)

| # | 验收项 | 通过标准 |
|---|---|---|
| B1 | 新建 | POST create(头+2行) → draft CR 建成,id 返回 |
| B2 | 提交 | POST submit → doc_status=approving |
| B3 | 审批通过 | POST approve → doc_status=activated + cm_* 落 published(激活器单事务,失败回滚到 approving) |
| B4 | 驳回 | POST reject → doc_status=rejected,cm_* 零变化 |
| B5 | 驳回复活 | POST clone-revise → 新 draft CR,source_cr_id 指向旧,行逐行铸号(无 id 冲突) |
| B6 | 作废 | POST abort → draft→aborted |
| B7 | 状态机校验 | 对 activated CR 调 submit → 被拒;对 draft 调 approve → 被拒 |
| B8 | approve 原子性 | 构造会失败的 approve(如删映射) → CR 保持 approving(回滚,不留脏 approved) |
| B9 | 列表/详情 | GET change-requests?docStatus= 返回正确;GET detail 返回头+行 |
| B10 | CR 录入台 | 前端录入头+行、保存 draft、提交 |
| B11 | 待办台 | 前端三区显示 CR,操作按钮调端点生效 |

# 页面索引文件格式与加载机制说明

> 日期：2026-08-25 · 性质：核查结论存档 · 范围：`cmx-container/assets/*/web/ui-native/index.json`、`assets/*/web/ui-html/index.json` 及 `index/<domain>.pages.json` 分片
>
> 关联文档：`20260825_cmx-container_model与portal资产页面重复收敛方案.md`（model ↔ portal 页面重复收敛，本文第六节有衔接说明）

## 一、结论

三个索引文件**格式都正确、代码完全支持**。字段看起来不一样是设计如此——native 与 html 是**两套不同的索引体系**（native 扁平 v1 / html 域分片 v2），不是格式错误。

唯一解析方是 `cmx-container/crates/libs/cmx-form/src/serve/loader.rs`。

## 二、两套索引体系总览

| 体系 | 索引文件 | 结构 | 适用 |
| --- | --- | --- | --- |
| native 页 | `<native_dir>/index.json` | v1 扁平：`{version, pages[]}` 单文件 | native 页 id 无域命名空间约束（如 `portal.datasource.cluster` 自由 id），扁平列表即可 |
| html 页 | `<html_dir>/index.json` + `index/<domain>.pages.json` | v2 域分片：manifest 声明域清单，每域一个分片 | html 页 id 严格 = `domain.app.module.page`，行内冗余域字段供列表过滤；按域分片避免单文件膨胀 |

html 还保留 v1 扁平兼容（`n.json`，`pages/html.rs` 三级回退：relPath → `n` 取 basename → `<id>.html`）。

## 三、逐文件格式与代码对应

### 3.1 `web/ui-native/index.json`（v1 扁平）

```json
{
  "version": 1,
  "pages": [
    {
      "id": "portal.model.datasource.cluster",
      "name": "集群数据源浏览",
      "details": "…",
      "sourceType": "js",
      "relPath": "portal/datasource/cluster-datasource.js"
    }
  ]
}
```

- 解析代码：`loader.rs::read_index` → `IndexFile{pages}` / `IndexEntry`
- 读取字段：`id`（必填）、`name` / `details` / `sourceType`（可选，null 容错）、`relPath`（必填）
- **`version: 1` 代码不读**，纯标记
- `sourceType` 缺失时按 relPath 扩展名兜底（js/mjs → js；html/htm → html）

### 3.2 `web/ui-html/index.json`（v2 manifest）

```json
{
  "version": 2,
  "domains": ["cr", "fi"]
}
```

- 解析代码：`loader.rs::read_html_rows` → `HtmlManifest{domains}`
- 只读 `domains[]`；每个域去 `index/<domain>.pages.json` 读分片
- **`version: 2` 代码同样不读**

### 3.3 `index/cr.pages.json`、`fi.pages.json`（v2 分片）

```json
{
  "pages": [
    {
      "id": "portal.model.gl.voucher",
      "name": "财务会计凭证",
      "details": "…",
      "domain": "fi",
      "app": "cmxfico",
      "module": "gl",
      "page": "voucher",
      "relPath": "fi/cmxfico/gl/voucher.html",
      "latestHtmlFile": "voucher.html"
    }
  ]
}
```

- 解析代码：`HtmlShard{pages}` / `HtmlRow`
- 读取字段：`id`（必填）、`name` / `details` / `domain` / `app` / `module` / `doc`（可选，null 容错）、`relPath`（必填）
- **`page`、`latestHtmlFile` 是额外字段**：serde 默认忽略未知字段，全代码库无消费方，纯冗余（`page` 是 id 末段重复；`latestHtmlFile` 历史遗留，注意 html.rs 的 v1 回退用的是 `n` 字段不是它）
- 行内 `domain/app/module` 的用途：列表接口过滤（`GET /api/html-pages?domain=fi&app=cmxfico&module=gl`）

## 四、relPath 解析与安全规则

- **相对基准 = 索引文件所在目录**：native 行相对 `native_dir`（如 `web/ui-native`），html 行相对 `html_dir`（manifest 所在目录，即 `web/ui-html`），**不相对分片所在的 `index/` 子目录**
- `safe_join` 安全校验：拒绝空段与 `..` 越界（防路径穿越）
- 实测两侧均自洽：model 侧 `relPath: "fi/cmxfico/gl/voucher.html"` → `web/ui-html/fi/cmxfico/gl/voucher.html`（文件在）；native 同理

## 五、容错设计（loader.rs 的降级哲学）

| 异常 | 行为 |
| --- | --- |
| 索引文件缺失 | 空集，不告警（未部署页面属常态） |
| native 索引 / html manifest 解析失败 | 空集 + warn（绝不 500 整个服务） |
| 单个域分片解析失败 | 跳过该域 + warn |
| 字段显式 `null`（如 `doc: null`） | `null_str` 反序列化为空串（serde `default` 只覆盖缺失字段不覆盖显式 null，专门处理过） |
| `sourceType` 缺失 | relPath 扩展名兜底推导 |

## 六、消费链路与资产目录格局

- **引擎侧服务**（cmx-rpt-server 实证，cmx-model 同构）：`main.rs` 挂 `cmx_form::serve::frontend_pages_routes` + `PageServeConfig::from_assets()`，目录经 `[assets]` 段 `ui_native_dir` / `ui_html_dir` 配置（默认 `web/ui-native` / `web/ui-html`，可 env `ASSETS__UI_NATIVE_DIR` 覆盖）。例：`cmx-report/report-server.toml` 指向工作区 `../cmx-container/assets/report/web/ui-native`
- **门户不走这套**：cmx-portalservice 的页面走 `[assets] root` 指向的 jsonstore 数据体系（`portal-server-dev.toml`：`root = "../cmx-container/assets/portal/data"`）
- **`cmx-container/assets/` 六个属主目录**：`flow` / `mdm` / `model` / `portal` / `report` / `rules`，经 `scripts/publish-assets.sh` 单向流出到各服务仓（如 `assets/report/web` ↔ `cmx-report/web` 逐字节一致——这是发布机制的设计产物，**不是重复问题**）
- 真正的重复在 **model ↔ portal**（工作区真源层 91 对页面双份），已由收敛方案文档记录，待确认后处理

3关键差距详述（按痛感排序）

① 会话压缩——长会话的生存线（P0）

参照产品靠"接近上限自动压缩"保证长任务不中断。我们没有压缩，长会话必然撞上下文墙，且撞前用户毫无感知。建议落点：Session::model_context 投影层插入摘要步骤（把旧工具输出与早期对话折叠成摘要），配一条手动 /compact；改动集中在 core 的投影层，不 touching 工具层。

② 上下文用量可见（P0）

用量统计与压缩是同一根因：openai.rs 不解析返回里的 usage 字段。建议落点：模型缝收口处捕获 usage，写入会话元数据；UI 显示"已用 / 剩余"，为压缩阈值提供依据。一次改动同时清掉"用量/费用统计"这一条。

③ 图片输入（P0）

截图给模型看是多模态助手的入门项。建议落点：model.rs 的 User 消息从纯文本改为 content parts（text / image_url），openai.rs 按 Provider 能力序列化；UI 侧粘贴/选择图片存数据根 attachments/。渲染端补 <img> 白名单（现全转义是防注入的正确保守，需开受控口子）。

④ AGENTS.md 项目规则（P0）

项目级"长期指令"的标准载体，参照产品全部支持分层加载。我们连注释里都写明了这是 M0 简化项——等于欠账自认。建议落点：workspace.rs context_for 里按 全局→项目根→子目录 顺序读取并拼接，成本极低、收益立竿见影。

⑤ 附件上传（P1）

现方案（@引用 + 模型自读）对工作空间内文本文件够用；缺的是工作空间外的文件与二进制（表格、PDF、图片）的拖拽/粘贴入口。建议落点：composer 增加上传通道，落数据根 attachments/，消息带引用。

⑥ 会话管理三件套 + 检查点（P1）

搜索/改名/置顶是纯 UI 层补齐（SessionMeta 加字段、protocol.rs 加命令）；检查点则建议从 apply_patch/fs_write 前置快照做起（快照存数据根，配 /undo），先保文件编辑可回退。

⑦ 技能升级为 SKILL.md 体系（P1）

现在"技能"只是工具别名，与九概念文档第 7 章的目标形态（文件夹 + 元数据渐进披露 + 可带脚本）差距大。建议落点：新增 skills 目录扫描器（名字+一句话常驻上下文，正文按需注入），/名字 触发改走技能解析而非提示词约定；这一步同时把"参数化命令"（占位符模板）带上。

⑧ 扩展体系补全（P2）

MCP 增加 HTTP/SSE 传输（client.rs 传输层抽象）；插件/连接器市场后置（先把本地装包体验做稳）；钩子按九概念文档第 9 章的留口方案——权限守卫已按钩子思想实现，开放"工具调用前/后"两个事件位即可平滑演进；定时任务做时间触发一支。

⑨ 体验补零（P2）

渲染端加语法高亮（引入 hljs 或自研子集，注意 CSP）；整会话导出 Markdown；跨会话记忆按九概念文档第 4 章条目式设计实施（event 日志地基已留）。

4优先级建议

  • P0＝长会话生存线 + 输入短板：会话压缩 → 上下文用量 → 图片输入 → AGENTS.md。这四项决定"能不能长时间真用"，且改动都集中在模型缝与上下文组装层，互相呼应（用量是压缩的依据）。
  • P1＝日常手感：附件上传、会话搜索/改名/置顶、检查点回滚、技能 SKILL.md 升级。
  • P2＝生态与治理：MCP 多传输、市场、钩子、定时任务、记忆、渲染增强、导出分享、Windows 沙箱 OS 级。

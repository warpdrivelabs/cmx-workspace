# 多维度数据与 Excel 报表格式结合方案

## 1. 背景与问题

复杂报表通常面临两个独立世界的对接：

- **数据侧**：基于维度（Dimension）、指标（Metric）、属性（Attribute）、度量（Measure）组织的多维数据，天然是 N 维结构
- **格式侧**：固定的 Excel 模板，是二维的、带有样式/合并单元格/固定表头的刚性结构

核心挑战是：**如何在不破坏 Excel 格式的前提下，将多维数据"折叠"到二维表格中，并保持可维护性**。

---

## 2. 核心概念定义

| 概念 | 说明 | 示例 |
|------|------|------|
| **维度 Dimension** | 数据的观察角度，通常是离散枚举值 | 时间、地区、产品线、渠道 |
| **维度层级 Hierarchy** | 维度内的上下钻取结构 | 年 → 季 → 月 → 日 |
| **维度成员 Member** | 维度的具体取值 | 华东、华南、华北 |
| **属性 Attribute** | 维度成员的附加描述信息（不参与聚合） | 地区编码、销售经理姓名 |
| **度量 Measure** | 事实表中的原始可加数值 | 销售额、订单数、成本 |
| **指标 Metric** | 基于度量派生的计算值，可有复杂逻辑 | 毛利率 = (销售额 - 成本) / 销售额 |
| **切片 Slice** | 对某维度指定固定值，降低维度数 | 固定时间 = 2025年Q1 |
| **行轴 / 列轴** | 多维数据投影到二维时，哪些维度展开为行，哪些展开为列 | 行：地区×产品；列：时间 |

## 5. 报表映射规则设计（Report DSL）

### 5.1 报表定义文件结构（YAML）

```yaml
report:
  id: sales_monthly_report
  name: 月度销售汇总报表
  template: templates/sales_monthly.xlsx   # Excel 模板路径

  # ── 数据源定义 ───────────────────────────────────────────
  datasource:
    type: sql                              # sql / api / cube
    query: |
      SELECT d.year, d.quarter, d.month,
             r.zone, r.region,
             p.category, p.product_name,
             SUM(f.sales_amt) AS sales_amt,
             SUM(f.cost_amt)  AS cost_amt
      FROM fact_sales f
      JOIN dim_date d ON ...
      JOIN dim_region r ON ...
      JOIN dim_product p ON ...
      WHERE d.year = :year AND d.quarter = :quarter
      GROUP BY GROUPING SETS (
        (d.year, d.quarter, r.zone, r.region, p.category, p.product_name),
        (d.year, d.quarter, r.zone, r.region),   -- 小计
        (d.year, d.quarter)                       -- 合计
      )

  # ── 参数（过滤/切片）──────────────────────────────────────
  parameters:
    - name: year
      type: int
      default: 2025
    - name: quarter
      type: string
      default: Q1

  # ── 指标计算（派生）──────────────────────────────────────
  metrics:
    - name: gross_margin
      label: 毛利率
      formula: "(sales_amt - cost_amt) / sales_amt"
      format: "0.00%"
    - name: gross_profit
      label: 毛利额
      formula: "sales_amt - cost_amt"
      format: "#,##0"

  # ── 轴定义（决定数据如何展开）────────────────────────────
  axes:
    rows:
      - dimension: zone          # 大区（一级）
        attribute: zone_name
        level: 1
      - dimension: region        # 地区（二级）
        attribute: region_name
        level: 2
      - dimension: product       # 品类（三级）
        attribute: product_name
        level: 3
    columns:
      - dimension: time
        levels: [month]          # 只展开到月维度

  # ── 区域绑定（核心：告诉引擎数据写到模板哪里）────────────
  zones:
    - id: header_info
      type: static               # 静态区域，写固定值
      bindings:
        - cell: B2
          value: "{{year}}年{{quarter}}销售汇总"
        - cell: F2
          value: "制表日期：{{today}}"

    - id: col_headers
      type: dimension_header     # 列维度头
      anchor: C4                 # 从 C4 开始向右展开
      dimension: time
      expand: horizontal
      template_col_width: 1      # 每个成员占 1 列
      bindings:
        - offset: [0, 0]
          value: "{{member.label}}"

    - id: row_data
      type: data_grid            # 数据主区域（核心区域）
      anchor: A6                 # 数据从 A6 开始
      row_dimension_col_offset:
        zone:    0               # 大区名在 A 列（offset 0）
        region:  1               # 地区名在 B 列（offset 1）
        product: 2               # 产品名在 C 列（offset 2）
      expand: vertical           # 沿行方向扩展
      metrics_col_offset:        # 指标列偏移（相对于列维度展开后的位置）
        sales_amt:    0
        gross_profit: 1
        gross_margin: 2

    - id: subtotal_rows
      type: subtotal             # 小计行
      trigger_dimension: region  # 当 region 切换时插入小计
      row_label_col: B
      row_label: "{{region}}小计"
      style: subtotal_style      # 引用样式定义

    - id: grand_total
      type: grand_total          # 合计行
      anchor_from_bottom: 2      # 模板最后第 2 行
      row_label_col: A
      row_label: "合计"

  # ── 样式规则 ─────────────────────────────────────────────
  styles:
    subtotal_style:
      font_bold: true
      fill_color: "#E8F4FD"
    negative_value:
      condition: "value < 0"
      font_color: "#FF0000"
```

### 5.2 Excel 模板中的锚点标记规范

在 Excel 模板中使用特殊命名约定标记可变区域：

```
单元格命名规则：
  {{zone_id}}          → 区域起始锚点
  {{zone_id:END}}      → 区域结束占位（引擎会在此之后插入行/列）
  {{param.year}}       → 参数占位符
  <<ROW_TEMPLATE>>     → 该行是数据行模板，引擎按此行格式复制 N 行
  <<SUBTOTAL_ROW>>     → 小计行模板
```

模板示意（Excel 截面）：

```
行  │ A         │ B         │ C         │ D(锚)   │ E       │ F       │
────┼───────────┼───────────┼───────────┼─────────┼─────────┼─────────┤
2   │           │ {{header_info:title}}  │         │         │{{header_info:date}}
4   │ 大区      │ 地区      │ 品类      │{{col_headers→展开列头→}}
5   │           │           │           │ 销售额  │ 毛利额  │ 毛利率  │ ... (每月重复)
────┼───────────┼───────────┼───────────┼─────────┼─────────┼─────────┤
6   │{{row_data→引擎在此行开始写数据，按<<ROW_TEMPLATE>>行格式复制}}
... │ <<ROW_TEMPLATE>>（该行有格式/公式，引擎复制此行格式）
N   │{{row_data:END}}
N+1 │           │           │ 合计      │ {{grand_total→}}
```

## 6. 引擎工作流程

```
输入：报表定义(YAML) + Excel模板 + 查询参数
  │
  ▼
Step 1  查询执行
        └─ 执行 datasource.query，获取原始数据集
           结果：List[Row]
  │
  ▼
Step 2  Hypercube 构建
        └─ 将 List[Row] 按维度组合 key 索引
           合并多级小计数据（GROUPING SETS 结果分层）
  │
  ▼
Step 3  维度成员枚举
        └─ 从数据中提取各维度的有序成员列表
           按 hierarchy 排序（可配置排序规则）
           行轴成员集合 × 列轴成员集合 = 交叉点坐标映射
  │
  ▼
Step 4  派生指标计算
        └─ 对每个 DataPoint 执行 metrics.formula
           结果写回 hypercube
  │
  ▼
Step 5  模板解析
        └─ 读取 Excel 模板
           识别所有锚点、命名区域、ROW_TEMPLATE 行
           计算需要插入/删除的行列数量
  │
  ▼
Step 6  布局计算（Layout Engine）
        ├─ 列方向：列维度成员数 × 每成员指标数 = 总列数，确定每列 Excel 坐标
        ├─ 行方向：按行轴维度成员顺序计算每个数据行的 Excel 行号
        │          含小计行 = 在每个 level-2 组末尾插入小计行
        └─ 输出：CellAddress Map { (dim_coords, metric) → (row, col) }
  │
  ▼
Step 7  写入 Excel（使用 openpyxl / ExcelJS / Apache POI）
        ├─ 静态区域：直接写值
        ├─ 列头区域：按列坐标映射写维度成员标签
        ├─ 数据区域：按 CellAddress Map 从 hypercube 取值写入
        ├─ 小计/合计：写预计算或 Excel SUM 公式
        └─ 样式：按 styles 规则应用（复制模板行样式 + 条件样式）
  │
  ▼
输出：填充完毕的 .xlsx 文件
```

## 7. 关键设计决策

### 7.1 行列动态扩展策略

**问题**：维度成员数量运行时才知道，Excel 是固定行列结构。

**方案**：
- 列方向扩展：在锚点列之后插入列（`ws.insert_cols()`），然后按模板列格式复制样式
- 行方向扩展：在模板 ROW_TEMPLATE 行之后插入行，复制该行的行高、样式、条件格式
- 合并单元格：维度分组时合并同一组的行头单元格（大区名跨多行合并）

```python
# 行扩展伪代码
def expand_rows(ws, anchor_row, template_row, data_rows):
    needed = len(data_rows) - 1
    if needed > 0:
        ws.insert_rows(anchor_row + 1, amount=needed)
    for i, row_data in enumerate(data_rows):
        target_row = anchor_row + i
        copy_row_style(ws, source=template_row, target=target_row)
        fill_row_values(ws, target_row, row_data)
```

### 7.2 多级行头的合并单元格处理

```
大区    │ 地区   │ 品类   │ 1月销售额 │ 2月销售额 │
───────────────────────────────────────────────
东区    │ 华东   │ 产品A  │  100,000  │  120,000  │
(合并)  │ (合并) │ 产品B  │   80,000  │   90,000  │
        │        │ 小计   │  180,000  │  210,000  │
        │ 华北   │ 产品A  │   60,000  │   70,000  │
        │ (合并) │ 小计   │   60,000  │   70,000  │
        │ 东区合计        │  240,000  │  280,000  │
```

合并规则：同一父维度成员下的子行，父维度列单元格合并。
引擎在写完所有行后，回扫维度列，对连续相同值的单元格执行 `merge_cells()`。

### 7.3 小计/合计的两种实现方式

| 方式 | 优点 | 缺点 | 适用场景 |
|------|------|------|----------|
| **预计算值**（从 GROUPING SETS 取） | 精确、支持复杂指标 | 需要数据库支持 | 毛利率等非线性指标 |
| **Excel SUM 公式**（`=SUM(D6:D10)`） | Excel 可二次编辑 | 复杂指标无法用公式表达 | 简单求和/求平均 |

推荐混合策略：度量用 Excel 公式，派生指标用预计算值。

### 7.4 指标的列组织方式

对于列维度 × 指标的组合，有两种列排列方式：

**方案 A：按时间分组（指标内聚）**
```
│←─── 1月 ─────→│←─── 2月 ─────→│
│ 销售额 毛利额  │ 销售额 毛利额  │
```

**方案 B：按指标分组（时间内聚）**
```
│←────── 销售额 ──────→│←────── 毛利额 ──────→│
│ 1月    2月    3月    │ 1月    2月    3月    │
```

在 DSL 中通过 `column_group_by: time|metric` 控制。

## 8. 数据结构代码示例

### 8.1 维度定义（Python dataclass）

```python
@dataclass
class DimensionMember:
    key: str
    label: str
    level: int
    parent_key: Optional[str]
    attrs: Dict[str, Any]     # 属性字典

@dataclass
class Dimension:
    name: str
    members: List[DimensionMember]
    hierarchy: List[str]       # 层级名称列表，从粗到细

@dataclass
class Metric:
    name: str
    label: str
    formula: Optional[str]     # None 表示直接来自度量
    format_code: str           # Excel 数字格式
    aggregation: str           # sum / avg / last / custom
```

### 8.2 Hypercube 查询接口

```python
class Hypercube:
    def __init__(self, data: List[Dict], dims: List[str], measures: List[str]):
        self._index: Dict[Tuple, Dict] = {}
        for row in data:
            key = tuple(row[d] for d in dims)
            self._index[key] = {m: row[m] for m in measures}

    def get(self, **dim_filters) -> Optional[Dict]:
        """精确坐标查询"""
        key = tuple(dim_filters[d] for d in self._dims)
        return self._index.get(key)

    def slice(self, **fixed_dims) -> "Hypercube":
        """切片：固定某些维度，返回降维的子集"""
        ...

    def project(self, keep_dims: List[str], agg: str = "sum") -> "Hypercube":
        """投影：聚合掉某些维度"""
        ...

    def get_members(self, dim: str) -> List[str]:
        """获取某维度所有成员（已排序）"""
        ...
```

### 8.3 报表区域绑定执行器

```python
class ZoneRenderer:
    def render_data_grid(self, ws, zone_def, hypercube, layout):
        for row_coords in layout.row_members:      # 行维度坐标组合
            excel_row = layout.get_row(row_coords)

            # 写行头（维度名称）
            for dim, col_offset in zone_def.row_dimension_col_offset.items():
                col = zone_def.anchor_col + col_offset
                ws.cell(excel_row, col).value = row_coords[dim]

            # 写数据单元格
            for col_coords in layout.col_members:  # 列维度坐标组合
                excel_col = layout.get_col(col_coords)

                for metric, metric_offset in zone_def.metrics_col_offset.items():
                    cell = ws.cell(excel_row, excel_col + metric_offset)
                    value = hypercube.get(**row_coords, **col_coords)
                    cell.value = value.get(metric) if value else None
                    apply_style(cell, metric, value)
```

## 9. 多维数据与格式结合的最佳实践

### 9.1 模板设计规范

1. **区域隔离**：不同语义的区域（标题、参数信息、表头、数据体、合计）物理隔离，用命名区域或锚点标记
2. **模板行完备**：ROW_TEMPLATE 行必须包含完整的格式、条件格式、数据验证，因为引擎复制此行
3. **避免绝对引用公式**：模板中的 Excel 公式用相对引用，行插入后自动调整
4. **冻结行列在模板中预设**：引擎填充后保留冻结窗格设置

### 9.2 维度设计规范

1. **维度成员 key 与 label 分离**：key 用于程序逻辑，label 用于展示，支持多语言
2. **层级排序显式定义**：不依赖数据库返回顺序，在维度定义中指定 sort_key
3. **空成员处理**：某些维度组合无数据时，决策是显示空行还是跳过（在 DSL 中配置 `show_empty_members: false`）

### 9.3 性能优化

1. **GROUPING SETS 一次查询**：利用 SQL GROUPING SETS 同时获取明细、小计、合计，避免多次查询
2. **维度成员缓存**：维度表变化频率低，可缓存成员列表，避免每次报表生成都查询
3. **流式写入**：数据量大时用 `openpyxl` 的 write-only 模式流式写入，减少内存占用

## 10. 技术选型建议

| 层次 | 技术选项 | 推荐理由 |
|------|----------|----------|
| 报表 DSL 解析 | YAML + Pydantic | 类型安全，易于验证 |
| Excel 操作（Python） | openpyxl | 功能全面，支持样式/公式/合并单元格 |
| Excel 操作（Java） | Apache POI | 企业级，SXSSF 支持大数据流式写入 |
| Excel 操作（Node.js） | ExcelJS | API 友好，支持流式 |
| 多维查询 | 数据库 GROUPING SETS | 充分利用数据库聚合能力 |
| 维度元数据管理 | 独立维度服务或 JSON/YAML 文件 | 与报表定义解耦，复用 |

## 11. 完整示例：月度销售报表生成流程

```
1. 加载报表定义
   └─ 解析 sales_monthly_report.yaml
   └─ 实例化 Dimension(time), Dimension(region), Dimension(product)
   └─ 编译 Metric(gross_margin).formula

2. 执行数据查询
   └─ 替换参数 year=2025, quarter=Q1
   └─ 执行 SQL，含 GROUPING SETS (明细 + 地区小计 + 合计)
   └─ 结果：850 行原始数据

3. 构建 Hypercube
   └─ 明细层：Dict[(month, region, product)] → {sales, cost}
   └─ 小计层：Dict[(month, region)] → {sales, cost}
   └─ 合计层：Dict[(month,)] → {sales, cost}

4. 计算派生指标
   └─ 对所有层计算 gross_margin, gross_profit

5. 解析 Excel 模板
   └─ 识别锚点：header_info@B2, col_headers@C4, row_data@A6
   └─ ROW_TEMPLATE 在第 6 行

6. 布局计算
   └─ 列轴：time.members = [1月, 2月, 3月]，每月 3 个指标 = 9 列
   └─ 行轴展开：
      东区 → 华东 → [产品A, 产品B, 产品C, 华东小计]
           → 华北 → [产品A, 产品B, 华北小计]
           → 东区合计
      西区 → ... → 西区合计
      合计行
   └─ 总行数：42 行，插入 41 行（模板已有 1 行）

7. 写入 Excel
   └─ 写标题、制表日期
   └─ 写月份列头（1月~3月，每月占3列）
   └─ 逐行写入数据，小计行用不同背景色
   └─ 合并大区、地区的行头单元格
   └─ 合计行写 SUM 公式 + 预计算毛利率

8. 输出
   └─ 保存为 sales_2025_Q1_report.xlsx
   └─ 文件大小：约 280KB，打开正常，格式与模板一致
```

## 12. 扩展：支持多 Sheet 报表

对于需要多个 Sheet 的复杂报表（如总表 + 各地区分表），在 DSL 顶层添加 `sheets` 列表：

```yaml
report:
  sheets:
    - id: summary
      template_sheet: 汇总
      # 与上述结构相同，但 axes.rows 只到 region 级别

    - id: detail_{region}    # 动态 sheet 名
      template_sheet: 明细模板
      foreach:
        dimension: region
        members: all         # 为每个地区成员生成一个 sheet
      # 该 sheet 内固定 region 维度，展开 product 维度
      slice:
        region: "{{foreach.member}}"
```

引擎识别 `foreach` 标记，循环为每个维度成员复制模板 sheet 并填充对应切片数据。

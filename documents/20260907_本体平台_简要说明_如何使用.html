CMX 本体平台（cmx-ontology :8097）

简要说明 2/4如何使用

三种入口（工作台页面 / 建模控制台 / REST API），一套统一前缀 /api/onto/v1，从建模、发布、写数到查数、执行动作的全动线。

一、三种使用入口

入口地址适合
门户工作台（推荐）门户菜单 → 数据平台 → 本体：设计工作台 portal.onto.designer、对象浏览器 portal.onto.explorer、对象工作台 portal.onto.workshop日常建模、浏览图谱、办理动作（四区界面 + 可视化图编辑）
建模控制台直开 http://127.0.0.1:8097/快速统计、建类型、发布版本的免登录单页
REST API / OSDKhttp://127.0.0.1:8097/api/onto/v1（门户内走 /api/onto/v1 同源）程序化集成、脚本、生成 TS 客户端

另有 Swagger 交互文档 /api/onto/v1/docs、OpenAPI 契约 /api/onto/v1/openapi.json、SSE 事件流 /api/onto/v1/events（发布/动作等事件推送）。

二、地址与鉴权

场景怎么调
浏览器/前端页面走门户同源 /api/onto/...，门户反代自动注入服务身份（X-API-Key + 委托用户令牌），前端零配置
脚本/直连调试直连 http://127.0.0.1:8097/api/onto/v1，请求头 X-API-Key: cmx_sk_dev_A1b2C3d4E5f6G7h8I9j0K1l2M3n4O5p6（开发环境密钥）
JWT 模式Authorization: Bearer <token>（生产推荐，主体以令牌为准）

所有响应统一信封 { code, msg, data }，code=0 成功。

三、常用端点速查

域端点作用
建模POST /object-types、/link-types、/action-types、/functions…六类元素 upsert（apiName 即主键）
POST /object-types/validate只校验不落库
POST /publish ／ GET /versions发布不可变版本 / 查版本列表
数据POST /objects/{type} ／ /objects/{type}/batch写对象（单条/批量事务）
POST /objects/{type}/{pk}/modify乐观锁修改（带 expectedUpdatedAt）
POST /object-sets/load ／ /aggregate对象集代数查询 / 聚合
动作POST /action-types/{api}/execute ／ /dry-run执行 / 预演动作（事务+审计+副作用）
GET /action-logs ／ /action-outbox审计 / 副作用投递状态
函数POST /functions/{api}/evaluateFEEL 函数求值（输入可绑对象/对象集）
集成/import/doc、/import/dct、/funnel/*、/osdk/typescriptDOC/DCT 导入、源同步、TS SDK 生成

四、标准使用动线

① 建模 → 设计工作台画对象/关系（或 API 建类型）
② 发布 → POST /publish 固化版本（SSE 广播 published 事件）
③ 灌数据 → 写对象 + 建关系边（或 funnel 从源表同步）
④ 查数据 → 对象浏览器 / 对象集代数（Filter + Search-Around 钻取）
⑤ 定义动作 → 参数 + FEEL 校验 + 编辑 + 副作用（可从模板创建）
⑥ 办理动作 → 对象工作台选中对象执行动作 → 事务写回 + 起审批流/算报表

六、OSDK：生成强类型 TS 客户端

浏览器打开 GET /osdk/typescript 直接拿到按当前本体生成的 TypeScript SDK：每个对象类型一个 interface，附 objects.<T>.all()/.filter()、actions.<A>(params)、functions.<F>(args) 等客户端方法，前后端字段契约自动对齐。

前端页面改样式/逻辑：改 cmx-container/assets/onto/web/ui-native/onto/ 下的 designer.js / explorer.js / workshop.js 后须重启 onto-server（服务从磁盘读页面，非热更）。

# 原生页面多实例模块隔离方案（cr-form 跨 tab 串数据根治）

> 日期：2026-08-27 · 模块：portal（CMXPortalManager + native pages）· 状态：待评审

## 一、背景与根因

2026-08-27 上午上线「供应商列表→新增 每次新开并列 tab」（master-list 去 single 单例）后，同浏览器可并存多个 cr-form 实例，实测复现跨 tab 串数据：

- 开 tab B 时 `content(ctx)` 重置共享 `state`（`savedCrId=null`、`keyVals={}`…），tab A 正在编辑的数据被清；
- tab A 的按钮 handler 闭包操作的 `rootEl`/`currentHost` 已被 tab B 的 render/bind 覆盖，A 的保存/刷新作用到 B 的 DOM；
- 实测页面卡死在中间态（DOM 中出现两个 `.pg` 根容器、操作按钮消失）。

**根因链**：

```
portal 平台层 workspace-native-pages.js 的 _moduleCache：Map<pageId, Promise<module>>
  → 同 code（如 portal.mdm.cr-form）的所有 CE 实例共用【一份模块实例】
    → cr-form 的模块级可变变量（state/rootEl/...）成为事实上的全局单例
      → 多实例并存必然串扰
```

cr-form 模块级可变状态盘点（引用规模）：

| 变量 | 引用量 | 说明 |
| --- | --- | --- |
| `state`（对象） | 203 处 `state.` | 核心业务状态（mode/step/savedCrId/…） |
| `rootEl` | 10 处 | 当前渲染根 |
| `headForms` / `lineGrids` / `keyForm` | 5/7/5 处 | 表单卡片、明细 grid、查重表单实例 |
| `activeLineIdx` / `lineSeq` / `initToken` / `currentHost` | 少量 | 明细激活行、行序号、init 令牌、宿主指针 |

（master-list 早已按 `_hostState = new WeakMap()` per-host 范式隔离，故列表页多开无恙。）

## 二、候选方案

### 方案 A：cr-form 页面级 per-host 化（master-list 范式）

把上表全部模块变量收进 `WeakMap<hostEl, pageState>`，函数入口（`content`/`bind` 内所有 handler/`refresh`/异步回调恢复点）按 host 取 state，203+ 处引用机械改写。

- 优点：爆炸半径只限 cr-form；与 master-list 范式一致；native page 改动无需 build portal。
- 缺点：1400 行核心单据页全量触碰，回归面 = cr-form 全业务链（查重/草稿/提交/审批/撤回/作废/明细编辑）；**其他同病页面不解决**（多开场景今后会越来越多，steward、dispatch-monitor 等同代码多实例同样危险）。
- 工作量：约 236 处编辑 + 全链路回归，一次大提交。

### 方案 B：模块变量「当前实例」指针 + 事件入口切换（否决）

保持 `state.` 引用，事件入口先 `useHost(root.host)` 切换模块指针。**否决理由**：async 链跨 `await` 后模块指针可能已被另一 tab 的事件切走，串扰依旧——除非入口快照局部变量，那等价于方案 A 的改法。

### 方案 C（推荐）：平台层模块实例隔离——每 CE 独立 import

改 `workspace-native-pages.js` 的 `importNativePageModule`：模块缓存不再按 `pageId` 全局共享一份，**每个 CE 实例独立 `Blob + import()`**（源码仍走 page-cache/HTTP 缓存，只多一次解析执行，cr-form 84KB 约 <10ms/实例，可忽略）。

```js
// 现状：_moduleCache.set(pageId, ...) —— 同 pageId 全局一份模块实例
// 改为：每实例独立 import（伪代码）
async function importNativePageModule (pageId, source) {
  const blob = new Blob([source], { type: 'text/javascript' })
  const url = URL.createObjectURL(blob)
  try { return wrapPageDef(await import(/* @vite-ignore */ url)) }
  finally { URL.revokeObjectURL(url) }
}
```

cr-form **零改动**即获得完整实例隔离；`state/rootEl/headForms/…` 全部天然 per-instance。

- 优点：根因在平台（缓存按 pageId 共享实例），在平台修；**一次修复所有 native page** 的同类隐患；cr-form 业务代码不动，回归面是「加载路径」而非「业务逻辑」；与页面级 per-host 范式（master-list）不冲突、双保险。
- 缺点：影响全部 native page（需按清单回归）；**需 build portal**（改 CMXPortalManager 源码）。
- 工作量：平台 ~30 行改动 + build + 回归清单。

## 三、方案 C 实施细节

### 3.1 改动点（唯一文件：`../../cmx-portal-manager`）

1. `importNativePageModule`：去掉 `_moduleCache` 按 pageId 的共享缓存，每调用独立 Blob+import；`_moduleCache` Map 与 `bustCache` 路径（`_moduleCache.delete(pid)`）保留为兼容空操作或直接删除（每实例 import 后源码更新天然生效，bust 语义自动满足）。
2. `pageModule()`/`renderNativePage` 调用链不变（仍返回 `{defaultView, views}` 包装）。
3. HTML 片段路径（`sourceType==='html'`）不受影响。

### 3.2 风险与对策

| 风险 | 对策 |
| --- | --- |
| 个别页面在 document/window 上挂全局监听，多实例=多份监听泄漏 | 回归清单覆盖已知页面（flow design-workbench 曾有 keyboard 泄漏前科）；规范本就要求 disconnected 清理，发现一个修一个 |
| 页面依赖模块级单例做跨实例通信（未发现先例，master-list 注释明确"页面间无法共享代码"） | 回归时观察；如有，改走 globalThis 或 workspace.context |
| dialog-workspace（对话框内嵌 native page）同 loader | 回归一例（如帮助中心 node: 链接或待办审批打开） |
| Blob URL 生命周期 | 沿用现有 `finally { URL.revokeObjectURL(url) }`（import 后 revoke 安全） |

### 3.3 回归清单

1. **核心验收**：开两个「新增供应商」tab——A 填名称过查重 → 开 B → 回 A 继续填写并保存草稿 → A/B 单据号、数据互不串扰；B 独立提交成功。
2. 单 tab：保存草稿 / 保存并提交 / 防抖锁 + busy 进度条（2026-08-27 已修项回归）。
3. cr-todo 打开草稿编辑再保存；待办中心审批打开（flowApprove 路径）。
4. 任选 2 个常用 native page（如 dct data-editor、flow todo-center）开双实例验证。
5. 页面「刷新」（bustCache）路径仍能取到最新源码。

### 3.4 实施步骤

1. 改 `workspace-native-pages.js`（~30 行）。
2. `npm run build:portal`（build 时机由用户掌握）。
3. 按 3.3 回归。
4. 与已完成的 cr-form 防抖修复（未提交）一并提交。

## 四、结论

**推荐方案 C**：根因在平台加载器，一次修复所有原生页面；cr-form 零改动、回归面可控。方案 A 作为「不愿动平台层」时的备选（仅修 cr-form，其他页面隐患保留）。

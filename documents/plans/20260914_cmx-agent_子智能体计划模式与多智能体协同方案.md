## 4. 对标调研结论（opencode / codex）

### 4.1 子智能体

- **opencode**：`task` 工具（`description / prompt / subagent_type / task_id / background`）；子代理 = 独立子会话（parentID 挂链），跑完取**最后一条 text** 包 `<task_result>` 回灌父代理；工具限制 =「注册期过滤工具清单 + 运行期权限规则」双保险，**deny 优先**；子代理默认再禁 `task`/`todowrite` 防递归；内置 build / plan / general / explore，自定义 = markdown frontmatter 或配置文件；深度上限默认 1。
- **codex**：`spawn_agent`（message / task_name / agent_type / model / fork_turns）；子代理独立线程真并发，上限 `agent_max_threads`（默认 6）+ 深度上限；跨代理消息 `send_message / followup_task / wait_agent / list_agents` + 统一消息信封。

### 4.2 计划模式

- **opencode**：plan = 内置 agent（edit 全 deny），`plan_exit` 工具弹问询，批准后向同一会话注入合成 user 消息切回 build。
- **codex**：plan = 会话级 `ModeKind::Plan` 枚举；**模型不能自行进出 Plan 模式，只有用户能切**；Plan 模式下 `update_plan` 直接报错防混淆；`request_user_input` 仅 Plan 模式可用。
- **采纳**：codex 的骨架（模式枚举 + 用户独占切换 + 硬闸）+ opencode 的退出体验（问询批准后同回合继续），批准交互用我们自己的 ask_user 答题卡。

### 4.3 协同

- 并行：opencode 靠模型一条消息发多个 `task`；codex 真线程 + 槽位计数。cmx-agent 内核已是 `join_all` 真并行，**P1 并行基本免费**。
- 后台唤醒：opencode `background=true` 立即返回"勿轮询"，完成后**合成消息注入父会话**自动唤醒——照搬。
- 跨代理消息：codex 独有，成本高，列远期（对齐 cmx-agent 路线图 M4）。

## 6. 阶段一：子智能体类型化

### 6.1 AgentSpec 与注册表

```rust
// cmx-agent-core/src/agents.rs（新，纯数据类型，tools/app 共用）
pub struct AgentSpec {
    pub name: String,          // 唯一 snake_case；内置与自定义共用命名空间
    pub title: String,         // UI 显示名
    pub description: String,   // 给模型的选型描述（进 task 工具 description 枚举）
    pub tools: ToolSelection,  // All | Allow(..) | Deny(..)
    pub model: Option<String>, // provider id（非显示名）；None = 继承默认
    pub system_prompt: String, // 空 = 用默认子代理提示词
    pub enabled: bool,
    pub builtin: bool,
}
#[serde(tag = "mode", rename_all = "snake_case")]
pub enum ToolSelection { All, Allow { names: Vec<String> }, Deny { names: Vec<String> } }
```

- 存储：`<data_dir>/agents.json`（与 mcp.json / im.json 同级同风格，`data_dir` 统一解析已有）。**全局一份**——子智能体是"能力编制"不是个人数据；`model` 引用在**派生时按当前登录人**解析（§6.5）。文件示例：

```json
{
  "custom": [
    { "name": "code_reviewer", "title": "代码评审员", "description": "只读审查代码变更",
      "tools": { "mode": "allow", "names": ["fs_read", "grep", "glob", "repo_map", "lsp"] },
      "model": "builtin-mlamp", "system_prompt": "你是严格的代码评审员。", "enabled": true }
  ],
  "builtin_overrides": { "explore": { "model": null, "enabled": true } }
}
```

- 内置两条编译进代码，agents.json 只存自定义 + 内置覆盖项（仅 `model`/`enabled` 两键）；自定义可删，内置不可删。
- **文件损坏容错**：解析失败 → warn 日志 + 只用内置两条（对齐 `read_meta` 降级先例），不炸启动。
- **语义定义（红队 N7 定稿公式）**：记父回合可见集为 `visible`——`All → visible`（含后装的插件/MCP 动态工具）；`Allow{names} → visible ∩ names`（冻结清单，后装插件不在名单即不可用，须改 agents.json）；`Deny{names} → visible \ names`。文档与 UI 提示说明 Allow 的冻结性。
- **热生效机制（替代草案的 register_dyn 重注册）**：`TaskTool` 持共享 `Arc<RwLock<Vec<AgentSpec>>>`，而 `ToolRegistry::specs()` 每回合现调 `t.spec()`（`tool.rs:215-226`）——**`TaskTool::spec()` 内部动态拼 enum + description**，agents.json 变更改共享注册表即天然生效，零额外同步路径。

### 6.3 task 工具升级（`crates/cmx-agent-tools/src/task.rs` 重写）

入参 schema（`subagent_type` enum 由 `spec()` 从共享注册表动态注入）：

### 6.4 工具过滤与守卫继承（fail-closed）

- **派生时现建子 Agent**（不搞 Agent 池）：结构全是 Arc 字段成本可忽略，且规避 Web 壳 per-user 模型配置的池失效问题。
- **有效工具集按 §6.1 公式对 `visible` 求值，未知名忽略**；**子代理一律再收走三个控制面工具：`task`、`ask_user`、`exit_plan`**（类型显式 Allow 也不生效，v1 硬规则）——`task` 防递归炸弹（对齐 opencode）；`ask_user`/`exit_plan` 因子会话无实时事件通道，放行会无限挂死父回合（红队 N4）。**双重保险**：ToolRegistry 层收走（本方案）+ 内核 `SUBAGENT_TURN` 门控自动 dismissed（**现网已有先例** `agent.rs:556-572`）；交互控制面留父层，§9 子会话 BusSink 落地后再解禁。
- 守卫与审批**不打折**：子 Agent 共享父 GuardPipeline（sandbox/approval 照常生效）与父 `InteractiveApprover`；工具白名单是**额外收紧，不是放宽**。
- 审批透传核实结论（蓝队）：`InteractiveApprover::decide` 按 call_id 校验，前端回投带父 session_id 不影响命中，现网行为已如此，无需改。

### 6.5 模型覆盖解析

- core 定义回调缝（tools 不得依赖 cmx-agent-model/app）：

```rust

pub trait ModelResolver: Send + Sync {
    fn resolve(&self, provider: Option<&str>) -> Result<Arc<dyn ModelSeam>, String>;

```

- app 实现：`provider = None` → 父 `ModelSlot` 当前 seam（切模型自动跟随）；`Some(id)` → 在 `providers_lock` 下走 `load_providers()`（**必须走该函数**：内含 per-user 目录回落与同网关 key 继承；现拆为 `app.rs:611-614` 组合 `:592-607` 与 `:619-629` 两 helper），按 **provider id**（`p-<nanos>` / `builtin-mlamp`）查 `NamedProvider` → `OpenAiCompatModel::new(cfg)`。
- 失败语义：显式报错不静默降级——`task: 子智能体类型 '<type>' 的模型 provider '<id>' 不存在或未配置（当前登录：<user>）`。

## 7. 阶段二：计划模式

### 7.1 表示、切换与回合内真源（红蓝第一轮修订核心）

**回合内唯一真源 = task-local 活开关**（对齐 `TURN_POLICY_OVERRIDE` 先例，`agent.rs:65-69`）：

```rust
// cmx-agent-core/src/agent.rs
tokio::task_local! { pub static TURN_PLAN_MODE: Arc<AtomicBool>; }
```

- `run_turn_observed_as_cancellable_with_policy` 加一参 `plan: Option<Arc<AtomicBool>>`，Some 时 scope 整个回合 future——**task-local 随 future 树下传，task 子回合自动继承且不可绕过**（§7.5）。
- app 侧 `turn_plan_flags: Mutex<HashMap<session_id, Arc<AtomicBool>>>`：回合开始插入（值 = `meta.plan_mode`），回合收尾摘除并**对账回写**（flag 与 meta 不一致时以 flag 为准持久化 + Note 事件——覆盖 exit_plan 批准后 meta 落盘）。
- `SessionMeta` 加 `#[serde(default)] plan_mode: bool`（旧 meta.json 兼容）；**必须**同步改 `send_inner_locked` 的 meta 重建（`app.rs:1384-1400`）从 `prev` 回填该字段——否则每回合结束被抹成 false（红队 P2-4 / 蓝队 A14 双重命中）。
- `SetPlanMode { session_id, enabled }` **仅用户可调**（UI chip）：**先取该会话 `session_locks` permit**（与回合生命周期串行，红队 N1——否则落在「回合收尾摘 flag 之后、对账回写之前」的窗口会被旧 flag 覆盖），再**校验会话存在**（红队 N6：`put_meta` 直接建目录，不校验会造幽灵会话），然后写 meta + 翻转 map 中活 flag（有进行中回合立即生效，无则下回合生效）。模型侧无任何切换工具（codex 原则）。
- `im-assistant` 会话拒绝 SetPlanMode（IM 共享会话 + 无人值守 FULL_ACCESS，不进只读规划态的模糊地带）；模式变更落 Note 事件（审计 + UI 系统行）。
- **chip 状态来源**：无独立会话详情命令，直接读 `ListSessions`——`SessionMeta` 本就 Serialize，加字段后自动出现在回包，零后端改动；切换后重拉。

### 7.2 PlanModeGuard：默认拒绝 + 显式白名单（第一轮从黑名单改判）

红队 P0-1/P0-2 + 蓝队 A26 联合结论：**hints 黑名单不可行**——MCP 工具 hints 全默认（拦不住）、git/run_tests/computer_use/browser_do 无 writes/exec 标注、连接器 6 个写侧工具显式 `writes:false`（翻 `writes:true` 会改变 ReadOnly 沙箱现网行为）。改判：

```rust
// cmx-agent-core/src/guard.rs
const PLAN_READ_TOOLS: &[&str] = &[
    // 本地只读
    "fs_read", "grep", "glob", "repo_map", "lsp", "data_describe", "doc_read",
    // 联网只读（调研需要）
    "web_fetch", "web_search", "browser_read",
    // 控制面
    "update_plan", "ask_user", "exit_plan", "task",
    // 只读连接器与插件面
    "enterprise_context", "flow_list_definitions", "onto_list_object_types",
    "report_list_reports", "plugin_list", "plugin_marketplace",
    // 演示工具（纯计算）
    "echo", "clock", "add",
];
```

- 规则：`TURN_PLAN_MODE` 开启时，**工具名不在 `PLAN_READ_TOOLS` 一律拒绝**，拒绝文案引导：`计划模式：工具 '<name>' 被拒（只读档）。完成调研后调用 exit_plan 提交计划请求用户批准`。
- **user_interactive 工具同样先过守卫管道再进内核特判**（执行序：路由 → pre 守卫 → 审批闸 → 内核特判，`agent.rs:475 → 486-496 → 515 → 556`）——`ask_user`/`exit_plan` 入白名单是**必要条件而非冗余**：漏列会在计划模式里连提问与退出批准一并拦死。
- 由此**零 hints 改动**：MCP（`mcp_*`）、git（含读子命令——守卫是工具粒度，git 单工具带 subcommand 参数无法区分读写，整体拒绝，git log 类需求让用户临时切出计划模式）、run_tests、shell、连接器写侧、`fs_write/fs_edit/apply_patch/chart/xlsx_write/pptx_write/browser_screenshot`（截图落盘）、插件 http/command/wasm、`danger_rm`（high_risk）**全部天然拦住**；新工具默认拒绝，符合仓规 fail-closed。
- `task` 放行的安全性 = §7.5 继承：子回合 scoped 在同一 `TURN_PLAN_MODE` 下，子代理同样只读——explore 类型 + 计划模式是天然搭档（调研分工）。
- 装配序：builder 守卫链 `auth → sandbox → high_risk → approval` 中插在 sandbox 之后；**danger 档不豁免**（守卫不读 sandbox/approval 旋钮，计划模式是用户意图，比旋钮硬；`TurnPolicyOverride::FULL_ACCESS` 只覆盖两旋钮，互不相干）。
- **注册面保留名（红队 N3，白名单借道封堵）**：白名单按工具名匹配，而 `register_dyn` 现无重名检查（`tool.rs:196-200`）、插件工具名 = 清单 name 原样注册——恶意插件取名 `fs_read`/`task` 可整体顶掉内置同名工具借道白名单。修复：**`register_dyn` 对已存在名一律拒绝**（core 一处小改），插件安装路径把错误上抛为安装失败；MCP 有 `mcp_` 前缀天然隔离。

### 7.3 提示词（`app.rs` 系统提示词拼装处）

plan_mode 回合追加固定章节：只调研不改任何状态；先充分调研再收敛；最终产出结构化计划（目标 / 步骤 / 涉及文件 / 风险 / 验证方式）；完成后调用 `exit_plan` 提交计划请求批准；**不得宣称已修改任何文件**。

### 7.4 exit_plan：ask_user 联动的退出批准（按实装形态修订）

**实现形态对齐 ask_user 实装**：内核托管 `user_interactive` 工具（非普通 `Tool::invoke`）——core 内与 `question.rs` 同模式（并列新文件 `crates/cmx-agent-core/src/exit_plan.rs`），`agent.rs` 托管路径处理，`invoke` 照 ask_user 先例兜底不可达。

- 入参：`{ "plan": "完整计划文本（markdown）" }`。
- GuardHints 对齐 ask_user：`requires_approval: Never` + `idempotent: true`（`question.rs:431-436` 同款）——确保计划模式下不被审批闸二次拦截。
- 执行：托管路径走 QuestionService 问固定一问——header「计划审批」，question「计划已就绪，是否批准并开始实现？」，options：`批准并开始实现 (Recommended)` / `继续调整计划`；**超时沿用服务默认 30 分钟**，超时 = 「继续调整」（实装超时语义，§5）。
- **门控（现成机制，零新增）**：子回合（`SUBAGENT_TURN`）与非交互回合（无人值守/无头）直接 dismissed——同 ask_user 现网门控（`agent.rs:556-572`）。由此：① 红队 N4 的挂死面在内核层关闭；② **N2 场景从根上消失**——exit_plan 只可能发生在顶层回合（必在 `turn_plan_flags` 注册表内），批准持久化回归 §7.1 **回合收尾对账**即可，原 `PlanModeSink` 回调**省略**。
- **批准判定**：按实装编码（label 在前、`user_note: ` 追加在后，`session.js:303-318`），仅当该问答案 `v[0] == "批准并开始实现 (Recommended)"` **且不含 user_note 项**才算批准；选批准又附言 → 按「继续调整」处理附言带回（红队 P2-3 + N8）。
- 批准后三件事：① `TURN_PLAN_MODE.try_with(|f| f.store(false))`——托管路径与守卫同在回合任务树内，try_with 必命中，**同回合下一批工具调用立即放行写**；② 计划文本落盘 `<allowed_roots[0]>/.cmx/plans/<ts>.md`（失败不阻塞，计划仍在会话内）；③ tool result 回灌「计划已批准，计划存于 <路径>，现在开始按计划实现」——opencode 语义：批准 = 授权写。meta 落盘由回合收尾对账完成（flag=false → meta=false + Note）。
- 「继续调整」：tool result 回灌用户附言，保持计划模式继续规划；忽略/超时/门控降级（dismissed 带 `note`，实装格式 `agent.rs:719-724`）→ 同「继续调整」；**模式外调用 exit_plan → 报错「当前不在计划模式」**。
- 用户独占性不破坏：批准动作是**用户点击**，应用层只代为持久化；模型无法伪造（answers 只能来自 QuestionService 真实答复，会话绑定校验现成 `question.rs:256-269`）。

### 7.5 与子智能体 / IM / 后台的交叉规则

- **子代理继承**：前台子回合 scoped 在父回合 future 树内，`TURN_PLAN_MODE` 自动下传——堵住"父在计划模式、让 general-purpose 子代理写文件"的绕过路径；且该继承**不可绕过**（子会话 id 是 `subtask-*`，按 session_id 建索引的方案会漏掉它们——蓝队明确否决该替代实现）。
- **后台派生必须显式 re-scope**（本方案修订新增的自查点）：tokio task-local **不跨 `tokio::spawn` 传播**，后台子回合在 scope 外 `try_with` 会落空成"非计划模式"。§8 的后台 spawn 闭包必须显式捕获父回合 flag Arc 并重新 scope（连同 `TURN_SUBJECT`/`SUBAGENT_DEPTH` 一并）。
- IM 无人值守 `TurnPolicyOverride::FULL_ACCESS` 不影响本守卫；IM 会话本就进不了计划模式（§7.1）。

## 8. 阶段三：后台子智能体与完成唤醒

- task 入参 `background: bool`（默认 false，§6.3 schema 已含）。true 时：并发/深度检查后 `tokio::spawn`，**spawn 闭包内显式 re-scope 全部 task-local**（§7.5），立即返回 `{"task_id": "<sub_id>", "background": true, "note": "已在后台启动，完成后自动通知，勿轮询"}`。
- **完成注入**：`SubagentHandle` 加 `injector: OnceLock<Arc<dyn Fn(String, String) -> BoxFuture<'static, ()> + Send + Sync>>`；app 层经 `AgentApp::into_shared(self) -> Arc<AgentApp>`（内部 Arc::new + 存 Weak 进闭包）装配，回调体 `upgrade 后 a.send(&parent_id, &text)`——`AgentApp::send` 自动获得 `session_locks` 按会话排队（父忙则排队，IM 桥同走此族函数佐证）。`into_shared` 触点：Web 壳一处（`main.rs:53`）、Tauri 壳三处（`main.rs:794/806/818`）（红队 N5 勘正）。**injector 未装配（CLI/e2e 无头）→ `background=true` 直接报错拒绝**（fail-closed，不静默丢结果）。回灌文本：`<task_result id="…" state="completed|failed">…</task_result>`。
- **注入消息的 UI 形态**（红队 P2-2）：render.js 识别 `<task_result` 前缀的 UserMessage，渲染为可折叠系统卡（不出现"用户说"气泡）；重放恢复同规则。
- **取消收尾**（红队 P1-3）：子回合改用 **cancellable 入口**（`run_turn_observed_as_cancellable…`），子 `TurnCancel` 登记进 `SubagentHandle.cancels: Mutex<HashMap<parent_id, Vec<(sub_id, TurnCancel)>>>`；`AgentApp::cancel_session_turn` / `delete_session` 追加调 `handle.cancel_for_parent(session_id)`（handle 已提升为 AgentApp 字段；实现对每个 sub_id **复用 `cancel_session_turn(sub_id)`**——连带清掉 approver/questions 在 `subtask-*` 会话名下的挂起项，审批可挂在子会话名下是实测路径）。现状核实：对 `subtask-*` 调 `cancel_session_turn` 恒为 no-op（active_turns 只在 send_inner 注册）——本设计修复之。后台任务**不进** active_turns（避免被当父回合误取消）；`delete_session` 连带清理 `turn_plan_flags` / `cancels` 残项（红队 N6 内存泄漏点）。panic → `JoinError` 分支注入 `state="failed"` + 摘要。
- **并发上限**：`SubagentHandle.active_children: Mutex<HashMap<parent_session_id, Arc<AtomicUsize>>>`（key = `ctx.session_id`——**ask_user 实装未含 ToolCtx.session_id，由本方案阶段一补上**，§11.1）；上限 4，前台（join_all）与后台合计；`fetch_add` 超限即 `fetch_sub` + 报错「子智能体并发已达上限 4」；**RAII guard 释放**（成功/失败/panic 全路径）。
- **结果截断**：前台与后台回灌统一 20k 字符截断 +「（已截断）」注记（父上下文无压缩机制，防多条结果撑爆）。
- 已知限制（明示不做）：进程重启后台任务丢失（与回合同生命周期）；不做跨会话结果订阅。

### 13.5 实施勘误与遗留

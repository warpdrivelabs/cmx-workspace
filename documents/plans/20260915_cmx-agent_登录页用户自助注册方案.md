# cmx-agent 登录页用户自助注册方案

> 2026-09-15 · 状态：待评审 · 涉及仓：`backend/cmx-container`（门户 auth/iam）、`backend/cmx-portalservice`（配置）、`backend/cmx-agent`（双壳 + UI）
> 本文档只做方案，不改代码；实施须等用户明确指令。

---

## 1. 背景与目标

TrueMate（cmx-agent）目前只能用门户已存在的账号登录，账号由管理员在门户逐个创建。目标：**登录页提供自助注册**，注册即得门户账号并直接进入主界面。

- 账号真源不变：仍落门户 `cmx_user`，门户与 agent 双端通用；
- 双壳一次生效：Tauri 桌面壳与 Web 壳共用单份 UI 真源（`crates/cmx-agent-web/ui/`），改一处两边生效；
- 遵循全局规约：新增接口 `POST` + JSON body，无可变路径段、无 PUT/PATCH/DELETE。

## 2. 决策记录（用户拍板 2026-09-15）

| 决策点 | 结论 |
| --- | --- |
| 注册开放策略 | **完全放开**（不做邀请码、不做审核）；**不新增开关配置**，匿名可达性复用现有部署级 `[auth] whitelist` 控制（同日二次拍板：后端不感知权限开关，路由常挂）；agent 侧配置控制**是否展示注册按钮** |
| 新用户默认权限 | **注册不绑任何角色**（同日三次拍板：`default_role_code` 配置也去掉，门户侧零新增配置）；无角色可登录有现存先例，业务接口授权由管理员事后在门户分配 |
| 注册成功后 | **直接自动登录**（注册接口直接签发 token 对，注册即登录） |

## 3. 现状与关键事实（探查结论，含证据）

### 3.1 agent 侧（backend/cmx-agent）

- **UI 真源**：`crates/cmx-agent-web/ui/`；登录视图在 `ui/index.html:580-643`（`#login-view`/`#login-form`），登录逻辑 `ui/js/login.js`，样式 `ui/css/login.css`。`sync-ui.sh` 整目录同步到 Tauri 壳 `src-tauri/ui/`（生成物禁手改）。
- **登录链路**：`login.js:109-118` —— Tauri 壳 `invoke('login')`（`src-tauri/src/main.rs:546-573`），Web 壳同源 `POST /api` body `{cmd:'login',...}`（`cmx-agent-web/src/main.rs:251-257`），两路同汇 `dispatch_json` 前门。
- **真调门户处**：`AgentApp::login`（`cmx-agent-app/src/app.rs:443-460`）→ `AuthProvider::login`（`cmx-agent-connectors/src/auth.rs:88-120`）：`POST {base}/api/auth/login`，body 带 `device_type:"desktop"` / `device_id`；解析 `access_token / refresh_token / access_expires_at / refresh_expires_at / must_change_password`。
- **门户基址构建期烧录**：Tauri `src-tauri/build.rs:5-16` 读仓库根 `.env` 的 `CMX_AGENT_PORTAL_BASE` 注入 `CMX_AGENT_PORTAL_DEFAULT`，`main.rs:41-43` `portal_base()` 运行期不可改；Web 壳用 `AuthConfig::default()`（`cmx-agent-web/src/main.rs:102`）。
- **免登录白名单**：前门协议仅 `Login | CurrentUser` 免登录（`cmx-agent-app/src/protocol.rs:296-301`），其余未登录一律拒——新增注册命令必须进此白名单。
- **会话持久化**：`auth.json` 落 `<数据根>/auth.json`（`app.rs:113-154`，双壳共享）；启动回放 `try_restore_session`（`app.rs:466-524`）+ refresh 轮换。
- **密码策略镜像**：`app.rs:597-609` 已镜像门户复杂度策略做本地快速失败（注释明确"门户仍为最终裁决"），注册可直接复用。
- **无任何现成注册代码**（全仓 grep 无 register/signup/邀请码命中）。

### 3.2 门户侧（backend/cmx-container）

- **auth 模块**：`/api/auth/*` 路由挂载在 `cmx-apis/cmx-iam-api/src/handlers/auth/mod.rs:39-55`（login/refresh/logout/me/...），handler 同目录 `handler.rs:27-92`。
- **免鉴权机制**：`mw_auth` 按白名单放行，白名单 = `BUILTIN_WHITELIST`（`cmx-auth/src/config.rs:47-66`，含 `/api/auth/login`）+ TOML `[auth] whitelist` 合并。**新增免鉴权路由 = 加白名单条目，无需动 layer 顺序**。
- **配置门控先例**：`agent_updates_edge_routes`（`cmx-platform-app/src/router.rs:75-89`）——配置关闭则路由不挂载，注释明说不门控会把端点挂上全部引擎。注册开关照此办理。
- **建号逻辑可复用**：`UserServiceImpl::create_user`（`cmx-iam/src/user/service/crud.rs:22-92`）：唯一性检查（`archived=0`，重名 → `IamError::UsernameExists`）+ `auth.hash_password`（Argon2）+ 最小长度校验；`cmx_user` DDL 见 `docs/sql/v2/platform/init_ddl.sql:1434-1458`（`username`、`nickname`、`email`、`status`、`must_change_password` 等；`uk_cmx_user_username`、`uk_cmx_user_email` 两个部分唯一索引）。
- **密码策略**：完整复杂度（长度≥8 + 大小写 + 数字 + 特殊字符）在 `cmx-auth/src/password/policy.rs:11-86`，目前只在**改密路径**强制（`AuthError::PasswordPolicyViolated → 400`）。**注册路径应强制同款策略**（用户自设密码，与管理员代填初始密码场景不同）。
- **无角色可登录是现存先例**：登录流程取角色为空 Vec 照常签发 token（`cmx-auth/src/auth_service_impl/login.rs:94-117`）。
- **token 签发**：login 成功后 `issue_token_pair`，响应 `LoginResponse{access_token, refresh_token, token_type, access_expires_at, refresh_expires_at, must_change_password}`（`handlers/auth/response.rs:11-26`）。
- **限流**：登录已有 `Error::RateLimitExceeded → HTTP 429`（`handler.rs:66-77`），注册复用同机制。
- **错误响应惯例**：`ApiResp{code,msg,data}` camelCase，成功 code=0；业务错 HTTP 200 + body code（`cmx-api-types/src/api_response.rs`、`error.rs:162-172`）。
- **现状配置**：`portal-server-dev.toml [auth]`（:213-231）无任何 register 项；模板 `cmx-container/config/config_template.toml`（`[auth.argon2]` :435-444 等）。
- **迁移规范**：`docs/sql/v2/platform/migrations/`，命名 `yyyyMMdd_NNN_描述.up.sql` 配 `.down.sql`（样例 `20260909_002_智能体自动更新建表.up.sql`）。**本方案无迁移**（§8）。

## 4. 总体设计

```
┌─ agent 登录页（双壳共用 UI 真源）────────────────────────────┐
│ [注册账号] 链接 → 注册表单（用户名/密码/确认密码/昵称选填）        │
│ 展示与否 ← ui_config{register_enabled} ← agent 侧配置(默认true) │
└──────┬───────────────────────────────────────────────────┘
       │ Tauri: invoke('register')      Web壳: POST /api {cmd:'register'}
       ▼
dispatch_json 前门（免登录白名单 + Register）  ← protocol.rs 白名单扩 Register|CurrentUser|Login|UiConfig
       ▼
AgentApp::register ── 本地快速校验(镜像策略,可复用 app.rs:597-609)
       ▼
AuthProvider::register → POST {portal_base}/api/auth/register
       ▼
门户：路由常挂(后端不感知任何开关) → 匿名可达性由部署 [auth] whitelist 决定 → IP 限流
   → 校验(用户名格式/唯一、密码复杂度、email 查重)
   → Argon2 哈希 → INSERT cmx_user(status=1, must_change_password=0, 无角色)
   → issue_token_pair → 返回 LoginResponse 同构
       ▼
AgentApp 写 auth.json → 返回 LoggedInUser::public_json → 前端进主界面（与登录成功完全同路径）
```

**两层控制**：

| 层 | 机制 | 默认 | 作用 |
| --- | --- | --- | --- |
| 门户（匿名可达性） | 现有部署级 toml `[auth] whitelist` 加 `/api/auth/register` 条目 | 不在白名单（匿名 401） | 部署方手动放行匿名注册；**零新增配置**，后端路由常挂、不感知权限 |
| agent（按钮展示） | `CMX_AGENT_REGISTER_ENABLED` | `true` | 控制登录页是否显示注册入口；Tauri 构建期烧入、Web 壳运行期 env |

> 已接受的口径：未加入 whitelist 时，匿名请求被 `mw_auth` 拦为 401，但**已登录 token 仍可调 register 建号**——这是"后端不感知权限开关"的必然结果，2026-09-15 拍板接受，后端不做额外拦截。

## 5. 门户侧设计（backend/cmx-container + cmx-portalservice）

### 5.1 配置项

**门户侧零新增配置**（同日三次拍板）：不加注册开关，也不加默认角色配置，不动 `AuthConfig`。匿名可达性完全交给现有部署级 `[auth] whitelist`（`BUILTIN_WHITELIST` + toml 合并机制，`cmx-auth/src/config.rs:28-40`），无需为此改任何白名单代码。部署方放行时在既有 `[auth]` 段加一条即可：

```toml
[auth]
whitelist = ["/api/auth/register"]
```

- `/api/auth/register` **不进** `BUILTIN_WHITELIST`（`cmx-auth/src/config.rs:47-66`）——进了就是全部署恒匿名可达，部署侧无法收口。
- 注册**不自动绑定角色**：新用户无角色（凭"无角色可登录"现存先例直接可用），业务接口由管理员事后在门户分配。
- 无新增配置项，**无需走 `config-sync`**。

### 5.2 API 契约

`POST /api/auth/register`（免鉴权，白名单放行）

请求 `RegisterRequest`：

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `username` | 是 | `^[A-Za-z0-9_@.\-]{2,100}$`（对齐 DDL VARCHAR(100)） |
| `password` | 是 | 完整复杂度策略（`password/policy.rs`，与改密一致） |
| `nickname` | 否 | 缺省取 `username` |
| `email` | 否 | 填了先查重（`uk_cmx_user_email`） |
| `device_type` / `device_id` | 否 | 同登录，进 token 签发语境 |

响应：**`LoginResponse` 同构**（token 对 + `must_change_password=0`）+ 用户摘要（id/username/nickname）。前端拿到即可直接进入已登录态。

错误（沿用门户惯例）：

| 场景 | 返回 |
| --- | --- |
| 未加入部署 whitelist | 匿名请求被 `mw_auth` 拦 → 401（已登录 token 仍可调，已接受口径见 §4/§7） |
| 用户名非法 / 已存在 | HTTP 200 + body 业务错（`用户名已存在` 与管理员建号口径一致；并发窗口由唯一索引兜底，捕获冲突转同文案） |
| 密码不符合复杂度 | 400（`PasswordPolicyViolated` 同款） |
| 触发限流 | 429（复用登录限流，按 IP） |

### 5.3 服务端流程

1. 路由常挂：`AuthModule` 无条件注册 `register` 路由，后端代码不感知任何开关（权限拦截完全交给部署 whitelist）；
2. 免鉴权：**不改** `BUILTIN_WHITELIST`；部署方放行 = toml `[auth] whitelist` 加 `/api/auth/register`（现有合并机制，零代码）；
3. 限流：复用登录 `RateLimitExceeded` 机制，按 IP 计；
4. 校验：用户名格式 + 查重（`archived=0`）+ 密码策略 + email 查重；
5. 落库：Argon2 哈希 → 插 `cmx_user`（`status=1`、`must_change_password=0`、`create_by="self-register"`、`create_name="自助注册"`，便于审计区分）；复用 `UserForCreate`/`create_user` 既有校验与哈希；**不绑任何角色**（零配置拍板）；
6. 签发：复用登录的 `issue_token_pair`，返回 `LoginResponse` 同构。

### 5.4 代码落点

| 内容 | 位置 |
| --- | --- |
| 校验/建号/签发服务 | `cmx-auth` auth service（与 `login.rs` 调 iam 查询同构的方式复用 `cmx-iam` 能力；不改 `create_user` 对外行为） |
| handler / request / response | `cmx-iam-api/src/handlers/auth/`（`mod.rs` 加路由，常挂、无门控） |

### 5.5 下游验证（全局规约 §六.4）

cmx-container 共用 crate（cmx-auth / cmx-iam-api）改动后：至少 `cd backend/cmx-portalservice && cargo check` + `cd backend/cmx-flowengine && cargo check` 双仓过。

## 7. 安全与集群合规

- **公网暴露**：注册端点随登录端点公网可达（agent 基址 `https://cmx.pansoft.com`）。已接受"完全放开"决策，防线 = 部署 whitelist（不放行则匿名 401）+ IP 限流 + agent 按钮开关。**已接受口径：未加入 whitelist 时已登录用户仍可调 register 建号**（后端不感知权限开关的必然结果）。后续如需收紧，邀请码/验证码为增量项（本次不做）。
- **防枚举**：重名返回显式"用户名已存在"（与管理员建号口径一致，企业内可接受）。
- **口令安全**：全程 HTTPS；Argon2 落库（与登录同参数）；注册路径强制完整复杂度策略（严于管理员建号，因用户自设密码）。
- **token 不进浏览器**（Web 壳）：与 login 同构，`LoggedInUser` token 字段 `#[serde(skip)]`，注册响应同样只回 `public_json`；注册命令经前门信封，不扩大 Web /api 鉴权面。
- **审计**：`create_by="self-register"` 区分自助账号；`last_login_ip` 既有机制照常生效。
- **无状态合规（§五）**：注册为纯 DB 写，无本地业务状态；限流沿用登录现机制（若其为实现于进程内存，与登录现状一致，不在本次范围放大）。
- **fail-closed**：agent 侧注册失败一律转信封错误；`ui_config` 查询失败时按"不展示注册入口"降级。

## 8. SQL 说明

**无迁移**。`cmx_user` / `cmx_user_role` 现有结构完全够用（status、must_change_password、唯一索引均已就位），不动 `init_ddl` / `migrations`。

## 10. 风险与回滚

| 风险 | 处置 |
| --- | --- |
| 公网刷号 | 限流兜底；从部署 whitelist 移除条目即收口（匿名 401）；agent 侧 `CMX_AGENT_REGISTER_ENABLED=false` 收入口 |
| agent 按钮常显但部署未放行 whitelist | 服务端 401，前端统一报"注册未开放"类文案，不影响登录主流程 |
| 回滚 | 无迁移、无破坏性变更：whitelist 移除条目即回滚；代码回退无数据残留风险（自助账号可在门户正常管理/停用） |

## 12. 实施记录（2026-09-15 已落地，未提交）

三批全部实施并通过验证。与 §5/§6 设计的**实现落点偏差**（审查后择优，行为契约不变）：

1. **注册逻辑落点**：放 `cmx-iam-api` handler 层组合（`iam().user_service.create_user` 建号 + `auth_service().authenticate(Credentials::Password)` 取 token），**未动 cmx-auth 内部与 cmx-traits**——原方案"服务逻辑放 cmx-auth"不可行：`UserAuthQuery` 是只读查询缝、`auth_service()` 返回 trait 对象（固有方法不可达）。密码复杂度校验经公开导出的 `cmx_auth::password::PasswordPolicy` 复用（与改密路径同款代码）。
2. **token 签发**：注册成功后直接 `authenticate(密码凭据)` ——复用整条登录链路（会话创建/审计/metrics/refresh 轮换完全同构），注册响应与 `LoginResponse` 同构 + 用户摘要（`RegisterResponse`）。
3. **限流**：未新增——审查发现 handler 层拿不到客户端 IP（`SVRContext` 只有 headers），登录的"限流"实为按用户名的账号锁定（缓存计数），无 IP 基建可复用；新增 IP 限流属新基建，违背"零新增"基调。收口手段 = 部署 whitelist 总闸 + 密码策略 + 唯一性约束，公网刷号残留风险已在 §10 记录。
4. **Tauri 壳零新 command**：前端注册/查询 `ui_config` 走通用 `call()` 双桥（Tauri `invoke('agent')` / Web `POST /api`），比原方案"加 register 命令"更符合"壳零业务逻辑"。
5. **来源标识**：`UserForInsert` 无 `create_by` 入参，行级标识用 `description="自助注册"`（管理员可改），操作留痕走 audit 日志（原方案写 create_by=self-register 不可行）。
6. **按钮显隐链路**：`CMX_AGENT_REGISTER_ENABLED`——Tauri 经 build.rs 构建期烧录（`.env` 可设 false/0/off/no，缺省展示）、Web 壳运行期 env；经免登录命令 `ui_config` 下发前端（缺省查询失败保持展示，注册成败最终由门户裁决）。

**验证结论**：cmx-iam-api 注册单测 4 绿；下游 `cmx-portalservice` / `cmx-flowengine` cargo check 双绿；cmx-agent 全量 428 测试 0 失败、`cargo clippy --all-targets` 零告警；Web 壳与 Tauri 壳（独立 workspace）cargo check 均绿；UI 真源经 `sync-ui.sh` 同步 Tauri 侧。集成验收（建号成功/重名/邮箱撞唯一/whitelist 401）需真机门户，按 §9 端到端路径手测。

**真机反馈修复（同日第二轮）**：
1. **重名注册文案**：用户实测重名时前端显示"业务错误: 用户名已存在: xxx"（错误链 `IamError::UsernameExists` → `TraitError::Business` Display 加"业务错误:"前缀 → 信封透传）。修复 = 注册前置用户名查重直接给"用户名已存在，请直接登录或换一个用户名" + create 兜底按文案归一（并发窗口撞服务层查重时同样剥前缀）。
2. **登出未回登录页观感**：`logoutConfirm` 本身会切登录视图，但注册成功进主界面后表单仍停在"注册模式"，登出回来看到的是注册表单而非登录页。修复 = `showLoginView` 复位到登录表单并清空两表单输入与错误提示（换号清场）；同时把启动路由 `routeByHash()` 从文件中段挪到末尾——它先于注册表单常量初始化执行时，复位逻辑会踩 TDZ。

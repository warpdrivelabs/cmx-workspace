## 一、背景与决策

本体工作室页面 `backend/cmx-container/assets/onto/web/ui-native/onto/studio.js` 此前为 4439 行单文件，维护困难；同时存在顶部按钮区拥挤、右栏窄栏（344px）塞 9 列属性编辑表、大量点击后页面上下跳动等体验问题。经与用户确认，按以下决策实施：

| 决策点 | 结论 |
| --- | --- |
| 拆分方式 | 原地拆分：studio.js 改写为薄壳装载器，内容搬入 `onto/studio/*.js` 8 个子模块；菜单/宿主契约零改动 |
| 拆分粒度 | 8 模块（state/controls/css/panels/inspector/canvas/runtime/main） |
| 实施节奏 | 两阶段：阶段 A 纯拆分（零行为变化，回归通过后用户 commit 锚点）→ 阶段 B UI 优化 |
| 顶部按钮区 | 画布 7 工具下沉为画布右上角悬浮工具组；顶栏只留全局件 |
| 右侧编辑区 | 属性表卡片化（保留 table DOM 语义）+ 表单双列网格 + 分区折叠 + 浏览态结构化 |

### 对抗审查结论（已全部采纳）

子智能体对照代码逐行审查发现并修正：映射表两处整段遗漏（L211-294 直写层、L1889-2586 动作/函数编辑器约 780 行）、runPanelHtml 错归 canvas、跳动修复③「paintSelection 同选中短路」会废掉 17/19 个调用点的数据刷新（守卫上移至 selectElement 入口）、跳动修复⑥逐行就地增删会令兄弟行下标路径失配（改为沿用 refreshPropTable 的 tbody 级局部重建先例）、blobImport 自举矛盾（壳自带）、卡片化选择器契约不全（保留 table DOM 语义）、ovlCss 样式必须随 dlg 迁移、存量 bug deleteScene `${pendNote}` 未定义（studio.js:4225，点击即 ReferenceError）、index.json 免重启生效（服务端每次读盘）。

## 二、阶段 A：纯拆分（已实施）

### 2.1 拆分机制

- **薄壳** `onto/studio.js`（~95 行）：configure 宿主注入契约、blobImport（fetch→解 ApiResp 信封→Blob import）、装载链（state 先行 → controls/css/panels/inspector/canvas/runtime 六模块并行 → main 收尾 → 统一执行 NS.__init 绑定）、mount/default 导出。
- **晚绑定公约**：每模块顶层 `const NS = globalThis.__ontoStudio` + 底部 `Object.assign(NS, {本模块导出})`；跨模块引用 = 模块顶部 `let` 别名列表，由壳在全部模块求值完后执行 `NS.__init` 回调统一绑定 `X = NS.X`。**函数体逐字搬运零改动**，规避逐调用点改写的机械风险。
- **生成方式**：脚本化拆分（声明提取 → 分区铺贴断言 → 别名自动计算 → 落盘），4439 行每行恰好归属一处（55 段严丝合缝），204 个顶层声明零跨模块重名；死代码 projectDefToNode（L316-330）删除。
- **登记**：index.json 新增 8 条（portal.onto.studio.{state,controls,css,panels,inspector,canvas,runtime,main}），不进菜单；服务端每次读盘，免重启生效（实测 ：8097 直连与 :8080 代理均即时返回）。

5. **【已修复 20260913】校验条串对象**：用户实测报告「主键 contractNo 不在属性列表中」提示的是上一个对象的。根因 = `validatePropDraft()` 主键优先读当前 DOM 表单，而 `objectInspector` 编辑态渲染期校验发生在 innerHTML 替换之前，读到的是上一个对象的表单值。修复 = `validatePropDraft(explicitPk)` 增加显式主键参数，渲染期（objectInspector）传当前 def 主键，交互期（键入/保存）仍读实时 DOM 行为不变。已浏览器复验五步全过。
6. **【已调整 20260913】页签「对象目录」改名「元素目录」**：用户提议，采纳——该目录实为 对象/关系/接口/共享属性/动作/函数 六类元素可切换目录，不止对象；且与本页既有用词一致（delElement、“不删除任何全局元素定义”、elementLibrary）。改动 panels.js tabsHtml + index.json studio 条目描述文案。
7. **【已修复 20260913】动作 Inspector 脏 logic 项崩溃**：用户控制台报 `TypeError: Cannot read properties of null (reading 'op')`（logicBlockHtml L622，选中动作即崩，右栏整个挂掉）。根因 = `S.selDef.logic` 数组混入 null 项，`logic.map(r => logicBlockHtml(r,…))` 读 `r.op` 即崩。当前库里 7 个动作详情逐个扫描均干净——null 系会话早期脏数据态（如切库期间）单查进内存的残留。修复两层：① `normalizeDefArrays(d)` 在 actionInspector / fnInspector 渲染入口对 parameters/logic/validations/sideEffects/inputs **就地剔除 null/非对象项**（自愈：之后任意保存经 collect 重建落库，脏项自动清除，索引与 collectAction 同源不失配）；② `logicBlockHtml` 对 null/非对象兜底渲染「⚠ 脏数据项」块。浏览器验证：动作/函数各注入 null+非对象后重渲零报错、脏项即被剔除、编辑态逻辑块正常渲染。

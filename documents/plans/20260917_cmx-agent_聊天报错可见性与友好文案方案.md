# cmx-agent 聊天报错可见性与友好文案方案

> 2026-09-17 · 状态：**A + B + C 已实施 + E2E 自测全过（同日）**（用户 /goal 授权 + "不要独立排期，全做"；D 项维持不做）
> 实施补充：`error_friendly.rs` 七类 classify 为关键词启发式（HTTP {code} 标注优先），openai.rs 全部错误构造点经 `err()` 收口；C 期 `tc-err-inline`/`cg-err` 落 .tc-trig 内折叠态可见；收尾行采用方案内选项二「⚠ 回合失败 · 原因见上方红字（点此展开过程）」。
> 用户原话痛点：「agent 的报错如果不展开会看不到内容，小白用户不太理解原因」

---

## 1. 痛点复现路径（用户视角）

用户发一条消息，模型调用失败（比如 Key 填错了），界面上看到的是：

```
已工作 3 秒
— 回合异常结束 —
```

**就这么多。** 错误原因「⚠ 处理出错：model error: invalid api key」其实产生了，但被折叠 CSS 藏掉，只有点「已工作」行展开回合才能看到；看到了还是英文原文，小白仍然不知道该干什么。

工具失败的展示更绕：工具行只有 ✕ 图标，详情要点开卡片（第一次点击）；只读工具（读文件、grep 等）失败折进引用组，要点开组、再点条目（两次点击）。

## 2. 根因（代码层三层）

| # | 根因 | 位置 |
| --- | --- | --- |
| 1 | 回合结束默认整体折叠，折叠规则只豁免收尾行，**错误 note 被一起藏掉** | `ui/css/chat.css:366-367`：`.turn.folded .meta:not(.turn-note), … {display:none}`；错误 note 渲染在 `ui/js/render.js:1191-1200`，收尾行「— 回合异常结束 —」在 `render.js:1169` |
| 2 | 工具失败详情在 `hidden` 的卡体里；只读工具还在引用组里再折一层 | `render.js:103`（建卡即 hidden）、`render.js:518-525`（错误详情）、`render.js:226,448-476`（引用组两层） |
| 3 | 错误文案零翻译透传：上游英文原文（"invalid api key"）、reqwest 英文报错直达用户；系统里已有友好映射先例（登录 `friendly_auth_error`，`app.rs:2262-2276`），但聊天回合没有对应层 | 产出点：`crates/cmx-agent-model/src/openai.rs:117-124,379,384,388,451,454-460`；错误 note 产生：`crates/cmx-agent-app/src/app.rs:1643-1670` |

补充事实：错误在事件协议里没有专用 kind，只以四种形态存在——回合内 `Note("⚠ 处理出错：…")`、`ToolResult(ok=false)`、壳层 `stream_error`、RPC 错误信封。IM（飞书）桥复用同一份错误文案回发（`cmx-agent-im/src/lib.rs:362,367`）。**两壳（Tauri/Web）渲染同一份 UI 真源**，改一处两端同时生效。

## 3. 方案设计

### A. 错误行豁免折叠（核心修复，前端小改）

1. **识别**：`render.js` note 渲染处（`:1191-1200`），`text` 以「⚠ 处理出错」开头的 note 追加类 `note-err`。前缀是后端 `app.rs:1651-1654` 写死的约定，前后端各留常量/注释互指；历史会话回放走同一渲染路径，**老数据自动生效**，无需迁移。
2. **豁免**：`chat.css` 增加 `.turn.folded .meta.note-err { display:block }`——回合折叠后错误行仍然可见。这是整个方案里最小的一刀，直接解决"不展开看不到内容"。
3. **样式**：错误行强化为红字，正文 `line-clamp` 限 2 行省略，`title` 悬停看全文；点击错误行 = 展开/收起整个回合（复用 `work-dur` 行的 folded 切换逻辑，`render.js:926`），想看全过程一键展开。
4. **收尾行语义升级**：「— 回合异常结束 —」本身无信息量，改为「⚠ 回合失败 · 原因见上方红字（点此展开过程）」或直接在该行内联错误首句摘要（二选一，实施时定，倾向后者：折叠态一行看到原因，红字行承担全文）。

> 效果：折叠态固定可见 = 「已工作 N 秒」+ 一行红色错误原因 + 收尾行。不吵（单行），但原因看得见。

### B. 友好文案后端一次成型（小白层）

**在 `cmx-agent-model`（openai.rs 各错误构造处）就把话说人话**，而不是前端映射——理由：IM 桥复用同一文本，后端成型三端（Web 壳/Tauri 壳/飞书）同时受益；且 HTTP 状态码等分类信息 Rust 端现成，前端反而要解析字符串。

新增映射函数（暂名 `friendly_model_error`，与登录侧 `friendly_auth_error` 对称），产出格式：**「友好话术（说用户该干什么）＋ 技术原文折叠保留（给支持人员）」**：

| 触发 | 友好话术示例 |
| --- | --- |
| HTTP 401 / 403 | 「API Key 无效或没有权限。请到 设置 → 模型 检查 API Key，或点"测试连接"验证」（原文：HTTP 401 invalid api key） |
| HTTP 404 | 「接口地址或模型名不对（404）。请检查 Base URL（一般以 /v1 结尾）和模型 ID 拼写」 |
| HTTP 429 | 「请求太频繁或额度不足（429），请稍后再试，或检查账户余额」 |
| HTTP 5xx | 「模型服务暂时不可用（服务端错误 {code}），请稍后再试」 |
| 连接失败（connect/dns/refused） | 「连不上模型服务。请检查网络 / VPN，以及 Base URL 是否填对」 |
| 超时 | 「模型 {n} 秒内没有响应。可在 设置 → 模型 → 高级 里调大超时时间后重试」 |
| 断流重试 3 次耗尽 | 「模型响应中断，已自动重试 3 次仍失败，请稍后再试」 |
| 其他 | 原样透传（不丢信息兜底） |

- 技术原文附在友好话术后的括号/次行，UI 上由 A 项的样式控制（折叠态截断、展开看全文），IM 侧自然带原文方便排障。
- 映射表与模型配置方案的「测试连接」错误分类**共用**（`auth/network/timeout/model_not_found/rate_limit/server/unknown` 七类，`model_not_found` 对应 404），一处实现两处消费。

### C. 工具失败行内联摘要（第二批，可选）

1. 工具卡失败（✕）时，把 `output.error` 的**首行摘要（约 80 字，省略号截断）**提到卡头内状态行旁常显（注意：摘要放 `.tc-trig` 内，不进被 `hidden` 的 `.tc-body`），点击卡仍展开看全文。
2. 引用组内失败条目：条目行直接带首行摘要（现状只有 ✗ 图标），组头「N 失败」徽标保留。
3. 此项改动面稍大（涉及工具卡结构与引用组渲染），可独立于 A/B 单独排期；A/B 落地后它只影响工具级失败的可读性，不影响回合级错误的可见性。

### D. 明确不做

- 顶部常驻红条 / toast 轰炸：回合内已有常显错误行，再加全局横幅对小白是二次惊吓；现有 toast（1.6 秒）继续只用于命令级失败。
- 为错误新增独立事件 kind（`EventKind::Error`）：协议改动 + 回放兼容成本高，A 项前缀识别已覆盖且天然兼容历史数据。

## 5. 验收清单

1. 填错 Key 发消息：**不展开回合**即可见红字「API Key 无效或没有权限…」，悬停/点开看原文。
2. 断网发消息：红字「连不上模型服务…」。
3. 打开**历史会话**（存量「⚠ 处理出错」数据）：错误行同样豁免折叠显示。
4. 工具失败：回合折叠态可见失败行数；（C 期后）✕ 行旁可见首行原因。
5. 飞书 IM 触发同样错误：回复文本为友好话术 + 原文。
6. 正常回合、中断（⎋ 已中断）、步数上限收尾形态不受影响。
7. 双主题（UI5 变量派生 / Neo 皮肤）下错误红字与折叠豁免均正常；Web 壳与桌面壳表现一致。

## 6. 风险与注意

- 「⚠ 处理出错」前缀成为前后端间的隐式契约：两端常量化并注释互指，避免一方改文案另一方失明。
- 友好话术里引用的入口路径（"设置 → 模型"）须与设置中心实际分区名一致；若模型配置方案 P1 落地改了分区结构，话术同步更新。
- `line-clamp` 2 行在极长单行无空格原文（如 URL 长串）下可能溢出不省略，样式需 `word-break: break-all` 配合。
- IM 桥文案变长需确认飞书卡片渲染不被超长原文撑爆——映射函数里对技术原文做 200 字截断。

# cmx-iam 批量账号创建与默认密码强制改密方案

> 状态：**已实施并验收通过**（2026-09-09）。批量账号已创建（0001–9999，挂 `user` 角色）。
> 范围：仅后端。前端只需消费登录 / 刷新 / `/me` 响应中的 `must_change_password` 标识，**后端不做接口拦截**（提醒依赖前端弹框）。
> 验收证据见文末「十一、实施记录与验收」。

## 一、背景与目标

为公司同事批量创建工号账号（`0001`–`9999`），初始密码统一 `pansoft`。要求：

1. 使用初始密码登录成功时，**登录响应携带"须改密"标识**，供前端提醒用户修改密码；
2. 用户修改密码成功后，**旧 token 全部失效**，用户被引导重新登录；
3. 批量建号以脚本交付，不改既有用户管理接口。

## 三、总体设计

核心一招：给账号加 `must_change_password` 标志列，作为**账号属性**（而非逐次比对默认密码）：

- 批量建号 / 管理员重置为初始密码时置 `1`；
- 登录 / 刷新 / `/me` 响应透出该标志；
- 用户改密成功后清除为 `0`（复用既有 `revoke_all_tokens` 完成下线）。

采用账号属性而非"登录时再比对一次 pansoft"的理由：Argon2 校验单次约数百毫秒，逐次比对给每次登录加一次全量哈希开销；且账号属性能覆盖"管理员重置密码"场景，语义清晰。

### 3.1 登录数据流（标识透出路径）

```
cmx_user.must_change_password
  → UserAuthData.must_change_password        (get_user_by_username, login.rs:47)
  → TokenPair.must_change_password           (authenticate 返回值)
  → LoginResponse.must_change_password       (auth_login handler)
```

`/api/auth/refresh` 与 `GET /api/auth/me` 两处已有用户查询，同字段透出，保证前端在会话恢复场景也能拿到标识。

### 3.2 改密时序（本方案验收主链路）

```
1. POST /api/auth/login {"username":"0001","password":"pansoft"}
   → 200 {code:0, data:{access_token, ..., must_change_password:true}}
2. 前端提示"请修改初始密码"
3. POST /api/auth/change-password {"old_password":"pansoft","new_password":"Xx@12345"}
   → 校验旧密码 → 策略 → 历史 → Argon2 → 持久化新哈希 + 清 must_change_password=0
   → revoke_all_tokens：当前 access 立即入黑名单、refresh 全撤销、会话销毁、广播
4. 该用户任何后续请求 → 401 TokenRevoked
5. 前端引导重新登录；must_change_password=false，恢复正常
```

## 六、接口契约

### 6.1 登录 `POST /api/auth/login`

```json
{
  "code": 0,
  "msg": "成功",
  "data": {
    "access_token": "...",
    "refresh_token": "...",
    "token_type": "Bearer",
    "access_expires_at": 1757400000,
    "refresh_expires_at": 1758000000,
    "must_change_password": true
  }
}
```

- 初始密码未改的批量账号：`"must_change_password": true`；
- 正常用户 / 管理员：`false`；
- 登录失败：`code=401/403`（无 data，无标识）。

### 6.2 修改密码 `POST /api/auth/change-password`（需登录态）

请求 `{"old_password":"pansoft","new_password":"Xx@12345"}`：

- `200 {code:0}`：成功。**此刻起旧 token 已全部失效**，后续任意请求返回 `401`（`TokenRevoked`），前端据此跳转登录页；
- `401`：旧密码错误；
- `400`：新密码不符合策略（≥8 位且含大小写 / 数字 / 特殊字符）或与近 5 次历史重复。

注意：`pansoft` 仅 7 位、纯小写，**不满足策略**——这是刻意的：初始密码只经批量脚本直写库，永不通过改密接口回流；用户改密时必须设置合规强密码。`pansoft` 亦无法作为"新密码"再次设置（新旧相同校验 + 历史查重双拦）。

### 6.3 刷新与用户信息

- `POST /api/auth/refresh`：响应结构同登录，`must_change_password` 取 DB 实时值；
- `GET /api/auth/me`：`UserInfoResponse` 同样追加 `must_change_password`。

## 七、批量创建脚本

**位置**：`scripts/batch_create_users.py`（工作区根 `scripts/`，跨子项目运维脚本惯例）。

**关键设计**：

- **直写 platform 库**，不走 `/api/iam/users/create`：绕过"新密码须满足策略"的管理端约束（初始密码本就不合规），且免去 9999 次 Argon2 哈希（约数百 ms/次）；
- **单哈希复用**：内嵌一条已验证的 `pansoft` Argon2id PHC 串（`m=65536,t=3,p=4`，与生产 `Argon2Config` 默认一致；校验按 PHC 内嵌参数走，全部账号共用无额外泄露——密码本就相同）；
- **幂等**：`INSERT ... SELECT ... WHERE NOT EXISTS (username 存在且 archived=0)`，重跑只补缺号，不动存量；
- **id 沿用雪花数字串**（与存量用户一致），单进程内 ms + 12bit 序列自增，无自碰撞；
- **默认值**：`nickname=工号`、`status=1`、`archived=0`、`description='批量创建，初始密码须修改'`、`create_by='batch-script'`；
- **可选举角色**：`--role-code user`（现库已有该通用角色），查 `cmx_role` 得 role_id 后补 `cmx_user_role`，同样幂等；
- **前置检查**：自动探测 `must_change_password` 列，缺失时默认报错并给出 ALTER 语句，`--add-column` 可代为执行（幂等）；
- **数据库解析**：与 `sync_menu_db.py` 同源——`backend/cmx-portalservice/.env` → `CONFIG_FILE` → toml `[[databases]]` 的 `default=true` 项；可用 `--db-url` 或环境变量 `CMX_USER_DB_URL` 覆盖；不硬编码地址。

**用法**：

```bash
# 全量 0001-9999，默认密码 pansoft，缺列自动补，并挂通用 user 角色
python3 scripts/batch_create_users.py --add-column --role-code user

# 试跑（只打印 SQL 概要，不落库）
python3 scripts/batch_create_users.py --dry-run

# 指定号段 / 显式连接串
python3 scripts/batch_create_users.py --start 1 --end 500 --db-url postgres://user:pw@host:5432/cmxlocal
```

## 八、安全考量

1. **锁定策略照常生效**：`auth:{username}:login_fail` 5 次锁 900s，对批量账号一视同仁，可缓解 pansoft 被外部爆破；
2. **改密下线是集群安全的**：`revoke_all_tokens` 走 Redis 黑名单 + Pub/Sub 广播，多实例本地缓存同步失效，无状态约束满足；
3. **本期不做（明确 YAGNI）**：未改密用户的接口白名单强制（中间件拦到只许访问 change-password）——需求仅为"返回标识提醒"，属建议性改密；如后续要强制，可在 `mw_auth` 校验 `must_change_password` 时放行白名单实现，预留自然；
4. **dev 配置注意**：`portal-server.toml` 把 access TTL 覆盖为 1800000s（约 500 小时），改密下线不依赖 TTL（黑名单即时生效），但联调时勿以"等过期"验证下线。

## 一、总体设计决策（D 编号）

### D1 · Redis 是「多副本模式开关」，不是硬依赖（可选启用）

- `[redis]` 未配置 → 单副本模式：全部现状行为；已配置 → 多副本模式。
- 判断点：读侧 `GlobalCacheManager::try_get()`；订阅侧 `is_initialized()` 守卫。
- 配置了但初始化失败 → **有界启动重试**（每 5s × 12 次 ≈ 1 分钟，穷尽退出——不静默降级）；重试间隔/次数可配（`redis.init_retry_secs`/`redis.init_max_retries`，默认 5/12）以便测试加速。
- 多副本部署必须配 `[redis]`；单副本可配可不配。

### D2 · R4.1 与 R4.2 解耦：pin 版本是正确性，失效广播只是收敛速度

（同 v2）R4.1 后发布新版本不影响在跑实例；失效缺失后果 = 新发起短暂 404/旧版发起，轮询 TTL 自愈。正确性兜底永远交给轮询指纹对账。

### D3 · R4.1 注册表版本化：`deploy` 旧签名保留 + `deploy_versioned(def, promote_active)`，启动装载「active + 在跑 pin」

- 存储改 `HashMap<String(key), DefEntry>`，`DefEntry { active: Option<ProcessDefinition>, pinned: HashMap<i32, ProcessDefinition> }`。
- **API 定稿**（二轮 M-5 修复——engine 不碰 DB，不能自己判断"v 是否 active"）：
  - `deploy(def)`（version=None）：写 active 槽 + **清空该 key 的 pinned**（裸装载恢复双槽一致不变量——裸 deploy 仅测试用，现有测试从不建 pinned，零影响）；
  - `deploy_versioned(def, promote_active: bool)`：def.version=Some(v) 写 pinned[v]；`promote_active=true` 时同步覆盖 active 槽（装载侧判定：build_for 装载的 active 版本、hot_load_version 装载的主表现 active 版本传 true；**启动装载扩展的纯 pin 历史版本传 false**）。
- 取定义三入口：`get_definition(key)`（active，同步，签名不变）；`get_definition_versioned(key, Option<i32>).await`（Some(v) → pinned → miss 走 DefinitionLoader → 仍 miss 报 DefinitionNotFound 含 key@version；None → active fallback）；`def_for_instance` helper——**16 处调用点统一迁移**。
- **启动装载扩展**：`build_for` 直查（flow-app 层 SQL，跨域只读查询先例 = 同文件 incident 扫描 L803——**不放 def crate**，二轮 M-3 修复）`SELECT DISTINCT definition_key, definition_version FROM cmx_flow_instance WHERE state='ACTIVE' AND definition_version IS NOT NULL`，pin 历史版本编译装载（pinned 槽 + rt.definitions 双入，与 active 相同者跳过，失败 warn 不阻断）。
- **UI 投影版本感知**：
  - `get_my_tasks`/`page_resp` 查找键：优先 `(key, Some(v))` 精确匹配 → miss 退 `version==None` 条目（裸装载）→ 再退该 key 的 active 条目（**确定性规则**，二轮 S-1 修复；rt.definitions 是 Vec，find 按序——规则写死不依赖序）。任务行查询（biz_link.rs paged_todos/list_instances_paged/list_cc_paged/list_done_paged 四条 SQL + TodoRow/RawTodo）JOIN 实例表补 `i.definition_version`。
  - `FORM_KEY_REFERENCED` 扫描集合 = rt.definitions 全量（active + 在跑 pin）。
  - **终态投影降级声明**：已办/CC/历史列表的行属终态实例，其 pin 版本不在装载集合（装载只查 state='ACTIVE'）→ 投影退 active（**文档显式声明接受**——终态表单查看用 active 近似，避免装载集合无限膨胀）。
- **`rt.definitions` 消费点过滤**（二轮 M-6 修复，F7c 全集）：`get_definitions` / `get_todo_filters` / `list_design_definitions` / `list_startable_definitions` 四处按 `version == 该 key 主表 active_version`（等价：promote 时同步维护一份 `active_keys` 视图或按 version 匹配 active 槽）过滤——同 key 只出 active 一条；投影/引用检查两处用全集不过滤。
- **rt.definitions 刷新精确定位**（二轮 M-5b 修复）：`hot_load_version` 的 Vec 刷新从"首个 key 命中槽替换"升级为 **(key, version) 精确定位替换，miss 才 push**——防 activate(v1) 时把 [active v2, pinned v1] 刷成 [v1, v1] 丢 v2。
- A9 迁移：写新 key + 目标版本（active），经 `update_instance_cas` 落库（F18）。

### D4 · 装载协议：装载必带版本号 + promote 判定在装载侧

`load_published`（service 层编译时回填 `def.version = Some(v)`，签名不变）与 `hot_load_version`（get_version → compile → 回填）装载时带版本；`deploy_versioned(def, promote_active)` 按装载侧判定传参（D3）。装载只经两条路径（build_for / hot_load_version）。**守护断言形式**（二轮 B4 修复）：装载后 `get_definition(key)` 与 `get_definition_versioned(key, Some(active_version))` 返回同版本产物（引擎单测 + app 装载测试双落位）。

### D5 · R4.2 失效协议：单频道 + 租户维度 + 跳过自身 + 「成功才提交指纹」轮询兜底

- 频道 `cmx:flow:cache:invalidate`，载荷 `{ tenant, kind, action, key, version?, ts, src }`——tenant 必带（F19）；src 跳过自身。
- 接收方：`flow_for_tenant(tenant)` 定位 rt → definition 走 `hot_load_version(key, 主表现 active_version)`（按 DB 现值装载，免疫乱序/过期）；decision upsert → register；delete → `remove_decision(key)`（修 F15）。
- **兜底轮询**：`spawn_def_reload_poller` 遍历 RUNTIMES 逐租户，`flow.def_cache_ttl_secs`——**语义定稿**（二轮 A3 修复）：未启用 Redis 且未显式配置 = 0（关，单副本零变化）；**显式配置优先于默认**（允许无 Redis 纯轮询模式——六.7 场景 A 第二段与 T2 免 Redis 测试的前提）；启用 Redis 未显式配置 = 30。
- **指纹聚合**（二轮 S-2 修复，防 activate 交换抵消）：`(md5(string_agg(key || ':' || coalesce(active_version::text,'N') ORDER BY key)), COUNT 版本表, MAX(版本表 published_at), 决策表 COUNT, MAX(决策表 updated_at))` 五元组——主表 (key, active_version) 全量聚合哈希（任何 activate/publish 变更必变），不含主表 updated_at（草稿噪音免疫，限定同一 key 连续 save_draft 不触发）；NULL 全 COALESCE。单条 SQL 跨三源（def 主表/版本表/decision 同库）scalar 子查询可行。
- **指纹消费时机**：仅 reload 全部成功后提交 last-seen；失败保留旧指纹 → 下轮重试自愈。
- 前置修复 F8：`mark_published` 补 `updated_at = now()`。
- 发布闸补 `Engine::check_topology`（pub 化零影响面，已验证）——堵 handler 入口；**注**：直调 def_svc.publish/store 仍可造"可编译但拓扑违规"版本（T2 失败注入路径，故意保留——测试用它造 reload 失败）。
- Start 订阅不随热装载刷新 = 既有现状（F20），声明不修。

### D6 · R4.3 票据：JWT + 域分隔派生密钥 + **三配置形态全覆盖**（二轮 M-2 修复）

- **域分隔**：派生密钥 `HS256(secret + ":sse-ticket")`——票据塞 Bearer 必败、用户 JWT 塞 ticket 必败。
- **密钥来源**：flow-app 经 ConfigManager 自读 `auth.jwt_secret` / `auth.jwt_alg`（engine-kit 不暴露 secret，F10）。
- **三态定稿**：
  1. `auth.mode = "off"`：`issue_ticket` 返回**占位票据**（如 `"off"` 常量）——off 模式 SSE 路径不走 consume（resolve_ctx Off 分支），占位票据仅维持「前端统一一条路径」既有契约；文档注明 off 模式无票据校验。
  2. `jwt + HS256` 但 `jwt_secret` 缺失：签发端点 500 带配置指引（fail-fast）。
  3. `jwt_alg ≠ HS256`（RS256）：同上 500 带指引（RS256 部署无对称 secret 可用）。
- 核销（`consume_ticket` 同步签名不变）：派生密钥 decode + exp 校验 → TenantCtx。**不做单次消费**（consume 是同步 fn 指针挂不进 async；GETDEL 原语缺失；威胁模型：泄露面 = URL query，重放收益 = 60s 只读事件流，低危——60s exp 是底线，单次消费是锦上添花）。重放窗口 60s 文档声明。
- **配套更新** `docs/full-test/fe/sse_jwt_ticket.cjs` 断言③：同票 60s 内二次连 → **200**（重放窗口行为锁定）+ exp 过期后 → 401（二轮 M-1 修复）；域分隔两条 401 断言（票据塞 Bearer / 用户 JWT 塞 ticket）平移至此脚本（手搓 JWT 能力现成，F25）。

### D7 · R4.3 事件转发：全局单频道 + src 跳过自身 + inject 防回环

（同 v2）publish 双写（载荷 `{src, event}`）；桥 src 跳过自身 → inject（只进本地 bus）。**src 去重的保护对象 = 发布方本地订阅者**（不跳过则发布方双收；远端副本天然单收）——T3 进程内测试与六.7 场景 C 的断言都放在**发布方端**（二轮 A4 修复）。乱序窗口文档声明（FlowEvent 无全局序）。

### D8 · R4.4 协同：Redis 分支实现 + 序列化形态拆分 + src 去重

（同 v2）seq → Redis INCR（根治跨副本 seq 重复；传输丢失仍 at-most-once——措辞校准）；presence → StoredPresence 形态（含 last_seen 可序列化）HASH + EXPIRE 60s + 读侧过滤/惰性清理；广播收敛 `emit(event)`（Redis publish `{src, event}` / 本地 BUS）+ psubscribe 桥 src 去重 + inject。切换语义声明（部署事件、建议无会话期）。

### D9 · R4.5 incident 抢占：条件 UPDATE CAS + 分级释放

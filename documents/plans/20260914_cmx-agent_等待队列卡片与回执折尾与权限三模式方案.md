## 2. 改造一：等待队列卡片化（图一）

**纯前端改动，数据结构升级 + 卡片 UI + 拖拽排序。**

### 2.1 数据结构

`t._queue`：`string[]` → `[{qid, text}]`（qid 为会话内自增短 id）。数组仍是唯一真源，DOM 全量重渲（队列深度个位数，无性能顾虑）。

### 2.2 DOM 与渲染（原型场景 1）

- `ui/index.html` `tpl-session` 模板：`.interact` 与 `.chatfoot` 之间加 `<div class="queued" hidden></div>`（每 tab 独立；首页无队列概念不加）。
- `session.js` 新增 `renderQueue(t)`：按数组序生成卡片；空则容器 `hidden`；容器顶部一行「⏳ 等待队列 · N 条」小字 + 操作提示。
- 卡片结构（样式全部 `var(--*)`，见 `chat.css` 新增 `.queued`/`.qcard` 段）：
  ```html
  <div class="qcard" draggable="true" data-qid="…">
    <span class="qgrip">⋮⋮⋮</span>
    <span class="qtext">消息预览（单行截断，title=全文）</span>
    <button class="qa qa-now"  title="提到队首，当前回合结束后立即发送">↑ 立即</button>
    <button class="qa qa-edit" title="取出编辑">✎</button>
    <button class="qa qa-del"  title="删除">✕</button>
  </div>
  ```
  视觉：`--surface` 底 + `--border` 描边圆角卡，拖拽悬停位 `--gold` 描边提示；与子任务卡同属一套令牌语言。

### 2.3 交互

- **入队**：`doSendTab` 忙时分支改为 push `{qid,text}` + `renderQueue(t)`（替代原 queueNote 文字行；queueNote 保留用于中断等提示）。
- **出队**：三处 drain 改 `next.text`；发出一张即从数组移除并重渲（卡片随发送消失）。
- **拖拽排序**：HTML5 DnD（`dragstart` 记 qid、`dragover` preventDefault + 插入位高亮、`drop` 后按 DOM 序重排数组再重渲）。触屏无拖拽属可接受降级（桌面壳为主），卡片上的 ✎/✕/↑ 不受影响。
- **↑ 立即**：`t._busy` → 移到队首 + toast「将在当前回合结束后立即发送」；空闲 → 直接 `doSendTab` 发出。
- **✎ 编辑**：从数组移除该卡 → 文本回填 `.inp2` 并 focus（多行文本原样回填）。
- **✕ 删除**：从数组移除 + 重渲。
- **中断行为变更（决策 D1）**：不再清空队列——删掉 `t._queue=[]` 与「队列已清空」提示，改为 note「🛑 已中断，等待队列已保留」；中断后 finally **不自动 drain**（用户刚叫停，紧接着自动发下一条很突兀），卡片保留待用户手动「↑ 立即」或再次发送时接续。自然完成的回合仍按序自动 drain（现行语义不变）。

### 2.4 样式

`ui/css/chat.css` 新增 `.queued` / `.qcard` / `.qgrip` / `.qa-*` / 拖拽占位态（`.qcard.drag-over`）。**全部走 `var(--*)` 既有令牌，零硬编码色值**（对齐 UI 主题通路约束）。

## 3. 改造二：子任务回执折尾（图二）

**核心思路：注入器分流——父会话空闲走现行独立回执回合（图三，不动）；父会话在途则挂「待注入」队列，由内核回合循环在收口点吸收，同回合续一轮模型调用把回执折进当前回复。**

### 3.1 内核层（cmx-agent-core/src/agent.rs）

- `run_turn_inner`（及 `run_turn_observed_as_cancellable_with_policy` 透传链）增参：
  ```rust
  /// 回合收口点轮询的「延迟注入」缝：返回 Some(text) 则作为 UserMessage 注入本回合并续跑。
  deferred: Option<&dyn Fn() -> Option<String>>,
  ```
- 收口点改造：
  ```rust
  if !resp.wants_tools() {
      if let Some(text) = deferred.and_then(|f| f()) {
          session.log.append(EventKind::UserMessage { text });
          continue;   // 同回合续一轮：模型把回执折进本回合回复
      }
      break StopReason::Completed;
  }
  ```
- 约束说明：注入迭代同样计入 `steps`、受循环顶部 `max_steps` 上限约束（无独立上限开关；触顶后剩余回执走 §3.2 兜底，不丢）；注入文本**必须落日志**（模型可见 → 必落日志的既有不变量）。

### 3.2 应用层（cmx-agent-app/src/app.rs）

- 新字段：`pending_receipts: std::sync::Mutex<HashMap<String /*session_id*/, Vec<String>>>`。
- **注入器分流**（`into_shared`，改 app.rs:316 回调）：
  ```rust
  let busy = app.active_turns.lock().expect("active turns").contains_key(parent_id);
  if busy {
      app.pending_receipts.lock().expect("receipts").entry(parent_id.to_string()).or_default().push(text);
  } else {
      app.send(parent_id, &text).await …   // 现行图三路径，原样保留
  }
  ```
- **回合内吸收**：`send_inner_locked` 构造 poll 闭包（`pending_receipts` 弹队首）作为 `deferred` 传入内核四处调用 match 臂（闭包借 `&self`，随回合生命周期）。
- **折尾注入文本**：原始 `<task_result …>…</task_result>` + 内联一行指令（措辞方向：「请在本回合回复的末尾顺带向用户转述上述后台子任务结果，不要另起话题」）。系统提示词回合中不可变，故指令随消息走（独立回执回合的 `TASK_RESULT_PROMPT_SECTION` 维持原样）。
- **收尾兜底 drain（防丢 + 关 race 窗口）**：`run_turn` 返回、错误收尾落库之后、**仍持会话锁**期间，循环弹出该会话剩余 `pending_receipts`，逐条以独立回执回合续跑（复用现有回执回合逻辑：system 追加转述章节 → `run_turn`）。覆盖四类场景：
  1. 回执在「收口点检查之后、TurnEnded 之前」的 race 窗口到达；
  2. 回合以 `Stopped` / `Error` / `MaxSteps` 终止（收口点未执行或未吸收完）——回执照达，降级为图三形态；
  3. 注入器在「检查 active_turns 之后、回合真正结束之前」误判在途；
  4. 兜底回合自身执行中又来新回执（循环直至清空）。
- 实现形态：把 `send_inner_locked` 中「执行一个回合 + 错误收尾」的主体抽成小助手（如 `run_one_turn(...)`），首条输入与兜底回执共用，避免复制四臂 match。

### 3.3 前端（ui/js/render.js）——与可视化方案的「回执合一」对齐

`task_result` 渲染分支（render.js:847-871）改为**三态**（原型场景 2 / 3 已演示前两态）：

1. **折尾在途回合（图二）**：回执到达时存在开放回合（`log._turn` 且 `!log._closed`）→ **先走回执合一**：`log._subCards[id]` 命中后台卡则原地收口（✓ + final 文本并入卡内），**不建任何新卡**；模型续写文本按现行规则流进同回合末尾。
2. **独立回执回合（图三，父空闲）**：无开放回合 → 回执合一同样先行（后台卡在场则收口合一）；后台卡不在场（刷新后/纯回放/未实施可视化方案）→ 维持现状 `.notify` 通知卡（可折叠原文卡）+ 转述回合。
3. **兜底一致性**：合一分支依赖可视化方案 S1 建立的 `log._subCards` 登记；本方案先行实施时该 Map 恒空，自然全走 notify 卡路径——两方案无实施顺序耦合，后实施的一方自动升级为合一。

折叠豁免（新增 CSS 规则）：`.turn.folded` 的收纳不得藏掉仍在跑的后台卡——
```css
.turn.folded .subcard:not(.run){display:none}   /* 已收口的子任务卡随回合折叠 */
.turn.folded .subcard.run{display:block}         /* 后台执行中卡豁免，保持可见 */
```

本地流（`/api/stream` 回调）与远端观众（`/api/subscribe` SSE、Tauri `session_event`）走同一 `renderEvent` 路径，态判定一致，无双壳分叉。

### 3.4 IM 链路

折尾后 `TurnOutcome.final_text` 已含转述 → ImBridge 一条消息送达（原来是两条：回合回复 + 独立回执回合），体验更优，无需改动。

## 4. 改造三：权限下拉迁输入框 + 三模式（图四需求）

**「变更前确认 / 计划模式 / 完全访问」三选一下拉，替换首页 `.selectors` 的 🛡 下拉与会话内的「📋 计划」chip，落到 home 与会话两个输入框 crow。**

### 4.1 三模式与后端状态映射

| 选项 | value | set_policy（全局两旋钮） | set_plan_mode（会话级） |
| --- | --- | --- | --- |
| 🛡 变更前确认 | `confirm` | `workspace-write / on-request` | `false`（若在计划模式则退出） |
| 📋 计划模式 | `plan` | `workspace-write / on-request`（只读由计划守卫强制，比旧「只读」档更强：白名单默认拒 + exit_plan 批准门） | `true`（当前会话） |
| ⚡ 完全访问 | `full` | `danger-full-access / never` | `false`（互斥，隐式退出计划模式） |

- 旧「只读 · 按需审批」档**删除**（决策 D3）：计划模式是其强化替代（只读 + 产出计划 + 批准后才可写）。
- 决策 D2：full 与 plan 互斥——切 full 隐式关计划模式；切 plan 把两旋钮带回安全档（守卫层兜底，双保险）。

### 4.2 DOM（ui/index.html）

- **首页**：`.selectors` 里 🛡 `<select id="perm">` 整块移除（该行只剩工作空间钮）；home composer 的 `.crow`（/ 按钮与 spacer 之间）加：
  ```html
  <div class="selbtn"><select data-role="perm" title="默认权限：变更前确认 · 计划模式 · 完全访问">
    <option value="confirm">🛡 变更前确认</option>
    <option value="plan">📋 计划模式</option>
    <option value="full">⚡ 完全访问</option>
  </select></div>
  ```
- **会话模板**：`tpl-session` 的 `.crow` 删 `plan-chip` 按钮，同位置放同款 `<select data-role="perm">`。
- 标签用 `data-role`（会话 tab 多实例，不能用重复 id；bridge 的 `sel.id !== 'perm'` 判定同步改为 `[data-role=perm]`）。

### 4.3 前端逻辑

- `bridge.js`：`change` 委托改匹配 `[data-role="perm"]`；切档 = `set_policy`（全局）+ 会话 tab 时补 `set_plan_mode`；持久化键沿用 `cmx-perm` 但值域换新（**迁移**：旧值 `workspace-write/on-request`、`read-only/on-request` → `confirm`；`danger-full-access/never` → `full`）。
- `session.js`：
  - 克隆 `tpl-session` 后对其中 select 调 `cmxInitDropdown(sel)`（§1.3 关键坑：template 内 select 不会被首扫初始化）；
  - 状态同步：原 plan-chip 同步点（session.js:580-584）改为同步下拉显示 = `meta.plan_mode ? plan : 全局 policy 映射档`；`exit_plan` 批准后回合收尾回写 meta，下拉随之回落 confirm；
  - im-* 会话：plan 选项 `disabled`（后端本就拒绝，UI 提前灰掉）；
  - `togglePlanMode` chip 逻辑并入新的 `setPermMode(t, mode)`（set_policy + set_plan_mode 组合调用，toast 文案沿用）；
  - **首页选择带到新会话**：`startFromHome` 建会话后若当前档为 `plan` → 先 `set_plan_mode(newSid, true)` 再发首条。
- 跨 tab 一致性：policy 全局 → 切档后广播（自派 `cmx-perm-changed` 自定义事件）同步所有实例的 label；plan 态各会话独立显示。

### 4.4 后端

零改动（`set_policy` / `set_plan_mode` 命令与语义均现成）。

## 5. 明确不做（边界）

- 队列**跨刷新持久化**：`t._queue` 仍为内存态（与现状一致），刷新丢队列可接受。
- 触屏拖拽排序（pointer events 方案）：桌面壳为主，触屏降级用卡片按钮。
- 折尾回合的中途改写 system 提示词：回合中 system 不可变，指令随注入消息走。
- 图三独立回执路径的重设计：已达标，只做折尾分流后的回归验证。
- 队列卡的「上下移动按钮」：拖拽 + 立即已覆盖，不加冗余按钮。

   - core：折尾同回合——fake model 第一次返回纯文本（无工具调用），deferred 首次 poll 返回回执随后 None → 断言单回合（一次 TurnStarted/TurnEnded）、两条 UserMessage（原始 + 注入）、两条 ModelMessage、`steps==2`、reason==Completed；deferred 恒 None → 行为与现状逐字节一致（回归）。
   - app：`pending_receipts` 收尾 drain 干净（回合后 map 无残留）；注入器路由（在途 push / 空闲 send）。
2. **静态**：`cargo clippy` 根 workspace + `src-tauri` 双处零告警；`cargo test` 全绿；前端 `node --check` 全部 JS。
3. **真机 E2E（:8123，已授权实例）**：
   - 队列：忙碌时连发三条 → 三张卡；拖拽换序；「立即」插队；「编辑」回填；「删除」；中断后卡片保留、不自动发。
   - 折尾：派后台慢任务（`background=true`）→ 立刻发第二条消息 → 第二条回复末尾同回合出现转述、后台卡原地收口（图二）；空闲时派后台任务 → 独立 `.notify` 回执回合（图三回归）；后台卡运行中折叠上一回合 → 卡保持可见（R7）。

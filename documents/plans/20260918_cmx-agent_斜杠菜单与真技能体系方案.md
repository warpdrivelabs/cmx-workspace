## 1. 现状定论：`/` 菜单是「工具别名」，不是技能

已核实的代码事实：

1. `cmx-agent-app/src/app.rs:2178` `list_skills()` = `self.agent.tools().specs()` 原样改名——返回的是**已注册工具清单**（`shell`、`fs_read`、`fs_write`、`fs_edit`、`apply_patch`、`grep`、`glob`、`git`、`run_tests`、`repo_map`、`task`、`plan`、`chart` 等，含 `echo`/`add`/`clock` 演示工具）。注释自述：「技能 = 当前已注册工具」。
2. 选中条目后（`cmx-agent-web/ui/js/workspace.js` `selectPopoverItem`）只是往输入框插入 `/工具名 ` 文本，当普通消息发送。
3. 靠系统提示词一句话兜底（`app.rs` 两处系统提示词构造：`session_system_prompt` :2169 / `current_system_prompt` :2396）：「用户输入以 / 开头时，斜杠后是技能名，请优先调用同名工具」——模型看到 `/shell xxx` 就去调同名工具。
4. 全仓无 `SKILL.md`、无技能目录、无按需加载——**没有技能文件体系**。

结论：现状 `/` 菜单是「工具快捷输入」，无知识/流程内容、无渐进披露、无用户可扩展性。

## 2. 方案设计

### 2.1 真技能体系（数据 + 加载）

- **目录**：`<数据根>/skills/<目录名>/SKILL.md`；frontmatter 仅两键（`---` 围栏 + `key: value` 手写解析，不引新依赖）：
  ```markdown
  ---
  name: meeting-notes
  description: 把会议录音转写或速记整理成结构化纪要
  ---
  （正文 = Markdown 指令，技能被调用时注入）
  ```
  `name` 缺省取目录名；规范 `[a-z0-9_-]+`，不合规目录跳过并在列表接口标记（不静默吞）。
- **加载**：不做文件监听；`ListSlash` 调用时惰性重扫（本地目录，量小成本可忽略）。目录不存在时自动创建并放一份 `README.txt` 说明格式。
- **模型感知（深审补，同批必做）**：workspace context 注入技能清单一行一条（`- name：description`，opencode `system.ts:106-120` 的 `<available_skills>` 简化版）——**没有这一步，模型自己不知道技能存在**，只有用户敲 `/name` 才能触发。清单随 `ListSlash` 同源生成，空目录时不注入。opencode 的完整三层是「系统提示词清单 + `skill` 工具按需加载正文（带 permission 门，且 prune 豁免其输出）+ `/命令` 注入」；本方案一期 = 清单 + 斜杠注入两件，`skill` 工具（模型自主加载、过审批守卫）留二期。
- **调用语义（一期）**：`/name 参数` 命中技能 → 后端构造注入消息进正常回合（append-only 不破坏）：
  ```
  [用户调用技能 meeting-notes，请严格按其指引执行]
  <skill-instruction name="meeting-notes">
  （SKILL.md 正文）

  技能基准目录：<数据根>/skills/meeting-notes/，正文中出现的相对路径（scripts/、references/ 等）均相对该目录。
  </skill-instruction>

  用户指令：参数原文
  ```
  基准目录尾注为 opencode 同款（`command/index.ts:143-148`）——技能目录制天然支持携带脚本/参考资料。以 `UserMessage` 落日志（Model-visible means logged 保持）。渐进披露（正文按需分层）不在一期（部分由二期 `skill` 工具承担）。
- **种子**：首次创建目录时放一个示例技能 `meeting-notes`（会议纪要整理），保证「看得到、点得动」；用户可删。

### 2.2 Send 斜杠分发器（app 层，唯一分发点）

`app.send()` 入口统一处理 `/` 前缀，**优先级：内置命令 > 技能 > 子智能体 > 原样发送**：

| 分发 | 行为 |
| --- | --- |
| `/compact [关注]` | 调用压缩方案 §4.2 的同一压缩例程（`reason=Manual`），返回结果文案；`Compacted` 事件经既有 SSE 上屏。`AppRequest::Compact` 协议动作保留（壳直调用），两者共用内部函数 |
| `/plan [任务]` | 映射既有 `SetPlanMode { session_id, enabled: true }`；带任务文字时注入计划模式指令后正常跑回合 |
| `/技能名 参数` | §2.1 注入语义 |
| `/子智能体名 参数` | **一期软委派**：注入消息指示主对话「用 task 工具、`subagent_type=<名>` 委派以下事项：参数」（task 工具与注册表现成，不动 spawn 路径）；后端直派留二期 |
| 未匹配 `/xxx` | 原样发送（现状行为，不报错） |

- **同步删除** workspace context 里那句「用户输入以 / 开头时，斜杠后是技能名，请优先调用同名工具」——工具就是工具，`/` 归技能与命令。**二轮核实：该句在 app.rs 出现两处**（`session_system_prompt` :2169 会话同源版 + `current_system_prompt` :2396 全局当前空间版，两函数逐字同段），**两处都要删**；技能清单注入也进这两处（`execute_turn_locked` 每回合重建 session.system，清单自动随目录新鲜，无陈旧问题）。
- IM 遥控同路径受益：飞书/QQ/微信发 `/compact`、`/技能名` 走同一 `send` 分发，无需 ImBridge 单独实现（二轮核实：`cmx-agent-im/lib.rs:360-365` 经 `send_as_with_policy`/`send_with_policy` 进 `send_inner`，分发器挂 `send_inner` 即全覆盖）。
- **分发器挂点（二轮定细节）**：`send_inner` **持会话锁之后、落任何事件之前**——① 与活动回合串行（压缩/注入不与在途回合竞写日志）；② `/compact` 消费掉输入**不落 `UserMessage`**（执行压缩例程 + 返回回执文案；`TurnStarted`/`UserMessage` 本就由 core `run_turn` 追加，不走 run_turn 就不落）；③ 技能注入与软委派才把改写后的消息交给正常回合路径。

### 2.3 协议动作 `ListSlash`（新）

```
AppRequest::ListSlash → {
  commands:  [{ name, description }],   // 内置：compact / plan
  skills:    [{ name, description, invalid: Option<String> }],  // 数据根 skills/ 扫描
  subagents: [{ name, title, description }]  // AgentRegistry::list() 过滤 enabled
}
```

- **`list_skills` 保持原样不动**：agents.js 的子智能体编辑器拿它做**工具白/黑名单选项**（语义=工具契约），改名会破坏既有功能。
- 前端菜单每次 `/` 触发拉一次 `ListSlash`（本地 IPC，低成本），替换现在的 `SKILL_CACHE` 常驻缓存。

### 2.4 UI `/` 菜单三分（workspace.js）

- `queryTrigger` 的 `/` 分支改调 `ListSlash`；三类合并进 `POP.items`，每项带 `group` 字段（`command`/`skill`/`subagent`）。
- `renderPopover` 按 group 分组渲染：**组头小标题**（「命令」「技能」「子智能体」，ZCode 同款灰色小字）+ 条目行（`/name` 加粗 + 描述灰字）；搜索过滤跨三组照旧。
- `selectPopoverItem` 统一插入 `/name `（三类同构，后端分发）。
- 输入框旁「调用技能」工具图标（现状=插入 `/`）保留，语义不变。

## 4. 验收清单（用户自测口径：看哪里、点什么）

1. **菜单三分**：输入框敲 `/` → 弹层分「命令 / 技能 / 子智能体」三组；`/compact`、`/plan` 在命令组；`meeting-notes` 在技能组；内置专家在子智能体组；输入文字跨组过滤。
2. **真技能**：`/meeting-notes 把这段速记整理一下：xxx` → 回合按技能正文执行（产出结构化纪要）；往 `skills/` 手工加一个新 SKILL.md → 再敲 `/` 能看到新条目。
3. **模型感知**（深审补）：不敲 `/`，直接对模型说「帮我整理会议纪要」→ 模型回答中能列出可用技能（来自 workspace context 清单）；再问「有哪些技能」→ 回答与 `skills/` 目录一致。
4. **/plan**：`/plan` → 计划模式开启（现状计划模式 UI 反馈不变）；`/plan 帮我规划 X` → 直接进计划模式跑。
5. **子智能体软委派**：`/某专家 做某事` → 时间线出现 task 工具调用、subagent_type=该专家。
6. **工具不再冒充**：`/` 菜单里看不到 `shell`/`fs_read` 等工具名；`/shell` 原样发送不报错。
7. **IM**：飞书发 `/compact` → 收到压缩简讯、会话出现压缩卡。
8. **旧功能不回归**：设置 → 子智能体编辑器的工具白/黑名单选项照常（list_skills 未动）。

## 5. 风险与注意

1. **frontmatter 手写解析容错**：缺 frontmatter/字段 → `name` 回落目录名、`description` 空；非法 name 的目录在 ListSlash 里带 `invalid` 提示而非静默消失。opencode 要求 frontmatter `name` 必填且做目录名一致性校验（`NameMismatchError`）、重名告警（duplicate skill name）——我们宽松回落 + `invalid` 标记，另补**重名告警**（同名技能后扫到的标记冲突提示，不覆盖先到者）。
2. **命名冲突优先级**已定（命令>技能>子智能体>原样），技能建目录时若与命令重名，ListSlash 返回时标记冲突提示。
3. **tagged enum 老坑**：`ListSlash` 变体字段显式声明；响应 JSON 结构前端要做空态兜底（目录为空/无子智能体）。
4. **注入体积**：超大 SKILL.md 正文整篇注入会占上下文——一期接受（与压缩方案互为兜底：压得住），文档里提示单技能建议 <2k 字。
5. **IM 注入消息的回显**：技能注入消息含正文，IM 侧会把整条 UserMessage 回显飞书——ImBridge 回显裁剪只回参数部分（实施时注意）。
6. 删除旧引导句后，旧的「`/shell` 直呼工具」用户习惯失效——属预期行为（工具走模型自主选择），验收 6 覆盖。
7. **清单注入的同步**（深审补）：workspace context 的技能清单与 `skills/` 目录若各自扫描会短暂不一致——清单注入与 `ListSlash` 共用同一次惰性扫描（`send` 时重扫，本地目录成本同量级），从根上消除不一致。
8. **二期候选记录**（不实施，防遗忘）：① `skill` 工具（模型自主加载正文，过审批守卫，输出 prune 豁免——opencode 同款三件套）；② 工作空间级技能目录（`.agents/skills/`，opencode 兼容 Claude 格式的发现范围）；③ 自定义命令模板（opencode `$1/$ARGUMENTS/` 内联 shell` 的模板体系）；④ `skills.urls` 远程技能拉取。

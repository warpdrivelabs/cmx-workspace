## 六、R4 · 完整多副本专项（008 + 006，引入 Redis）

**目标**：消除单写者假设全部三障碍 + 实例 pin 定义版本；执行面/推送面/协同面全量多副本。

**基建前置（R4.0）**：flow 引入 Redis——`cmx-service-base` 已有 `redis` feature（拉 cmx-buffer，portal 已启用先例），flow 侧开启并在 toml 增 Redis 连接段（**走 config-sync 技能同步模板与手册**）。Redis 成为 flow 运行时新依赖：部署拓扑、健康检查、文档同步声明。

### R4.1 实例 pin 定义版本（006 残余，纯 DB 无 Redis，可先行）

**基建已有**：`cmx_flow_definition_version` 不可变版本快照表（每次 publish 追加，uq(def_key, version)）+ 主表 `active_version` 指针。

1. DDL 迁移：`cmx_flow_instance` / `cmx_flow_hi_instance` 加 `definition_version INTEGER`。
2. start 时冻结 active_version 入实例行；存量实例一次性回填（`UPDATE ... SET definition_version = d.active_version FROM cmx_flow_definition d WHERE ... IS NULL`）。
3. 引擎侧：`definitions` 从 `key → 产物` 改 `(key, version) → 产物` + `key → latest 指针`；实例推进按 pin 版本取产物。
4. **行为变更**：发布新版本不再影响在跑实例（须写测试断言 + 文档声明）；删版本端点补在跑实例引用检查（同 006 已销账的 FORM_KEY_REFERENCED 模式）。

### R4.2 定义/决策跨节点失效（008①）

1. 写侧：`hot_load_version` / `register_decision` 落库后 `PUBLISH flow:def:invalidate {key, version, ts}`。
2. 读侧：各节点订阅，收消息按 key 重编译热装载；启动全量装载不变。
3. **兜底必做**（Redis pubsub 是 fire-and-forget）：周期指纹轮询（主表 `updated_at`/`active_version`，TTL 30~60s）防丢消息，与事件路由缓存 TTL 同款思路。

### R4.3 SSE 跨副本（008②）

1. **票据 JWT 化**：sse.rs 进程内 `TICKETS HashMap` → 签名短时 JWT（ticket id / exp / scope），无状态、任意副本可验；吊销以短 exp 兜底。
2. **事件跨副本转发**：EVENT_BUS 发布侧同时 `PUBLISH flow:sse`，各副本订阅注入本地 broadcast——SSE 客户端收全量事件，不再受所连副本限制。
3. 头部「单实例假设」注释同步移除。

### R4.4 协同编辑外置（008③）

1. presence：Redis hash + TTL 心跳续期（`flow:collab:presence:{defKey}`）。
2. op seq：`INCR flow:collab:seq:{defKey}`——per-(tenant, defKey) 全局单调，跨副本唯一，根治 LWW 丢 op。
3. op 广播走 Redis pubsub，按全局 seq 应用。

### R4.5 次要项（同期顺手）

- `spawn_incident_retry` 补 SKIP LOCKED 抢占（复用 acquire_due_jobs 模式）；
- metrics「每副本独立口径」写入部署文档；事件测试投递限流多副本放大——文档化接受或配额外置（低优）。

### R4 验收（双副本集成测试）

| 场景 | 断言 |
| --- | --- |
| A 副本发布新定义 → B 副本 start 新 key | 成功（失效广播生效）；杀 Redis 后 ≤ 轮询 TTL 内仍生效（兜底） |
| 在跑实例 + 发布新版本 | 实例仍按 pin 版本推进至终态 |
| A 副本签 SSE 票据 → B 副本连接 | 票据核销通过，事件流完整 |
| 双副本协同编辑同一 defKey | seq 全局单调无重复，op 无丢失 |
| 双副本并发推进同一实例 | CAS 冲突 409（既有能力回归） |

**风险**：Redis 成新单点依赖（部署侧须按工作区集群原则配哨兵/高可用）；pubsub 丢消息依赖轮询兜底；R4.1 行为变更（在跑实例不再跟随新版本）需业务侧知晓。

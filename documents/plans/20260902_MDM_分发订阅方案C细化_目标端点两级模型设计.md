## 一、目标与范围

把"目标系统级配置（通道/凭证/投递策略）"从订阅行拆出，收敛为**目标端点（md_target_endpoint）一份**；订阅瘦身为"端点 × 字典"的轻记录（事件类型/行级过滤/字段映射）。达成：

1. 一个目标系统接 N 种主数据，凭证只配一次，密钥轮换单点修改；
2. 新建订阅**单条弹框**（新建/编辑两态复用；初版规划的"多选字典批量向导"已在实现期取消，§5.2）；
3. 启停分两档：端点级（级联停其下全部订阅，**含存量积压**）与订阅级；
4. 投递实例（md_dispatch_log）、补发、分发监控、rest_pull 游标**结构不动**；
5. 通道可插拔：webhook / rest_pull 本期实现；**kafka / rocketmq 预留**（feature 骨架与 §八 设计已备，暂不启用）。

不在范围：kafka/rocketmq 实施（预留，§八）、md_event_log 结构、分发监控页改造。

## 二、数据模型

### 2.1 新表 `md_target_endpoint`

```sql
CREATE TABLE IF NOT EXISTS md_target_endpoint (
    id             BIGINT       NOT NULL,
    target_sys     VARCHAR(64)  NOT NULL,
    channel        VARCHAR(16)  NOT NULL,          -- webhook / rest_pull / kafka / ...
    name           VARCHAR(128),
    description    VARCHAR(512),
    channel_config JSONB        NOT NULL DEFAULT '{}',
    retry_max      INT          NOT NULL DEFAULT 8,
    timeout_ms     INT          NOT NULL DEFAULT 10000,
    batch_size     INT          NOT NULL DEFAULT 50,
    active         BOOLEAN      NOT NULL DEFAULT TRUE,
    created_by     VARCHAR(64),
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    PRIMARY KEY (id)
);
-- v2：不建唯一索引（审查 A3）——同系统同通道允许多端点（ERP 多区域各自 webhook / 多 topic 各自 kafka 端点）
CREATE INDEX IF NOT EXISTS idx_md_target_endpoint ON md_target_endpoint (target_sys, channel);
```

- **不设 uk 的理由**（v2 修订）：现状模型 `(target_sys, dict_code, channel)` 本就允许同系统不同字典配不同 URL；端点表若 uk(target_sys, channel) 反而是能力倒退，且迁移回填时同组 URL/秘钥分歧无法收敛。同 (target_sys, channel) 重复创建由**应用层提示**（保存时查询同组端点，存在则要求确认/建议复用），不阻断。
- `channel_config` 沿用既有结构：webhook `{url,secret,timeout_ms}` / rest_pull `{consumerId}` / kafka `{brokers,topic,partition_key,...}`（§八）；secret 列表回传掩码 `***`、保存未变更沿用的既有约定平移。

### 2.2 `md_subscription` 瘦身（两阶段）

**阶段一（迁移 `20260902_001_target_endpoint.up.sql`）**——加列回填，旧列**双写**保留：

```sql
-- 0) 前置分歧检测（fail-fast，审查 A3）：同 (target_sys, channel) 组内 url/secret 不一致则中止
--    有结果 = 存在分歧，人工裁决后再执行回填（v2：不再静默 min()）
SELECT target_sys, channel,
       count(DISTINCT channel_config->>'url')    AS url_variants,
       count(DISTINCT channel_config->>'secret') AS secret_variants,
       array_agg(DISTINCT channel_config->>'url') AS urls
FROM md_subscription WHERE channel = 'webhook'
GROUP BY target_sys, channel
HAVING count(DISTINCT channel_config->>'url') > 1 OR count(DISTINCT channel_config->>'secret') > 1;
-- ↑ 部署脚本检查：结果非空 → 迁移报错退出，输出本行供人工拆端点。

ALTER TABLE md_subscription ADD COLUMN IF NOT EXISTS endpoint_id BIGINT;

-- 1) 回填端点（幂等：ON CONFLICT 主键不冲突；bool_or 语义见下）
INSERT INTO md_target_endpoint (id, target_sys, channel, channel_config, retry_max, timeout_ms, batch_size, active, created_at, updated_at)
SELECT 9000000000 + row_number() OVER (ORDER BY target_sys, channel),
       target_sys, channel,
       -- 分歧已被步骤 0 拦截，组内取任一（min 仅在值全相同时有意义）
       jsonb_build_object('url', min(channel_config->>'url'), 'secret', min(channel_config->>'secret')),
       min(retry_max), min(timeout_ms), min(batch_size),
       bool_or(active),          -- v2 修订（A4）：组内任一订阅启用 → 端点启用；
                                 -- bool_and 会静默掐死组内其它启用订阅的扇出
       now(), now()
FROM md_subscription
WHERE NOT EXISTS (SELECT 1 FROM md_target_endpoint t
                  WHERE t.target_sys = md_subscription.target_sys AND t.channel = md_subscription.channel)
                  -- v2.2（P1）：组级幂等闸（原表级闸在回填中途失败后重跑会跳过全部回填，致订阅 endpoint_id 恒 NULL）；
                  -- 组级闸天然断点续跑：已回填组跳过、未回填组补插
GROUP BY target_sys, channel;

-- 2) 订阅挂端点（幂等：仅补 NULL）
UPDATE md_subscription s SET endpoint_id = t.id
FROM md_target_endpoint t
WHERE t.target_sys = s.target_sys AND t.channel = s.channel AND s.endpoint_id IS NULL;

ALTER TABLE md_subscription ALTER COLUMN endpoint_id SET NOT NULL;
DROP INDEX IF EXISTS uk_md_subscription;
CREATE UNIQUE INDEX IF NOT EXISTS uk_md_subscription ON md_subscription (endpoint_id, dict_code);
```

- 回填端点 id 用 `9000000000+序号` 非 snowflake 保留段（10 位 < snowflake 14 位，无碰撞），仅作 FK；新建端点走应用层 snowflake。
- **多库维度（v2 补，审查 A5）**：`md_subscription` 在**业务库**（`docs/sql/v2/biz`，现状 fico-db）。迁移须在**每个**启用 MDM 治理的业务库执行（沿既有 biz migrations 部署链）；端点 API 与订阅 API 同样逐 `db_id` 隔离（handler 既有 `resolve_db_id_from_headers` 范式不变）。

**阶段一双写（v2 补，审查 B2）**：端点保存/启停时，同事务把 channel/retry_max/timeout_ms/batch_size/channel_config 冗余回写其下订阅旧列（一条 `UPDATE md_subscription s SET ... FROM md_target_endpoint t WHERE ...`）。目的：阶段一回滚到旧代码时旧列数据不陈旧（密钥轮换不丢失），回滚干净。

**阶段二（全链路验证后另起迁移）**：drop 订阅旧列 + 停双写。

### 2.3 读写口径

- 订阅行有效 = `s.active AND t.active`（扇出 JOIN 与 claim 投递路径双重保证，见 §4.1）；
- 删除端点：仅"端点停用 且 其下订阅全部停用/为空"可删；连带删其下停用订阅，投递流水保留审计。

## 六·五、集群部署核验（v2.2 新增）

架构事实：dispatcher 在**每个** mdm 节点启动（`distribution/mod.rs`，`cfg.enabled` 控制），多节点 = 多进程并发扇出 + 并发投递。逐机制核验结论——**方案集群合规：全部改动落在 DB 事务与无状态查询，不新增任何进程内状态/缓存/广播需求**：

| 机制 | 核验结论 |
|---|---|
| 扇出 fanout_tick | **天然单飞**：`mdm_wm` 水位行事务内锁定，同一时刻仅一个节点推进扇出；INSERT `ON CONFLICT (subscription_id, event_id) DO NOTHING`（uk_md_dispatch_sub_event）幂等兜底。节点崩溃重启从水位重跑不丢不重。方案仅 JOIN 加端点表，水位机制零改动 |
| 投递 claim_dispatches | `FOR UPDATE SKIP LOCKED` 多节点不抢同行；candidates 的 `NOT EXISTS`（同订阅更早 event_seq 未决不抢）保证跨节点按序。新增活性门 EXISTS 为普通读子查询，不改锁语义；每候选行多两次主键点查（md_subscription→md_target_endpoint），量级=deliver_batch 可接受。fanout 持水位锁期间多一次 JOIN，批 500 内锁窗口可控 |
| 配置即时性 | 订阅/端点**每 tick 直查 DB、无缓存**（现状设计）→ 端点级联停用与密钥轮换在**全部节点准即时生效**（下一 tick / 下一批投递），无需缓存广播 |
| 双写 / batch / upsert | 均单事务 DB 操作；不新增 OnceCell/LazyLock 业务缓存（ChannelRegistry 为基础设施注册表，既有豁免） |
| 端点统计聚合 | 复用既有 `idx_md_dispatch_sub (subscription_id, ...)` 前缀索引，无需新索引 |

## 八、Kafka 通道订阅支持（v2.1：**预留设计，暂不实施**）

> 消息队列通道仅作为扩展示例预留：代码 feature 骨架与本章设计保留备将来启用；本期不实现、不引入 rdkafka、工作量不计入。将来启用时按本章直接落地。

### 8.1 现状 grounding（已核实）

代码已预埋完整骨架，**本节是"激活"而非从零设计**：

- `channels/kafka.rs`：`channel_type="kafka"`，`validate_config` 已验 `brokers/topic`；`deliver` 返回"未实现"占位（不产生错误投递）；
- `channels/mod.rs` + `Cargo.toml`：`channel-kafka` feature 已声明（当前空依赖表）；
- `distribution/mod.rs:141`：feature 开启后自动注册进 `ChannelRegistry`；`registry.types()` 即 `/mdm/subscriptions/channels` 数据源——**前端通道下拉无需改代码自动出现 kafka**；
- `md_subscription.channel VARCHAR(16)` 与端点表同宽，"kafka" 放得下。

### 8.2 配置契约（channel_config）

```json
{
  "brokers": "kafka1:9092,kafka2:9092",        // 逗号分隔字符串（对齐骨架 validate 的 as_str）
  "topic": "cmx-mdm-master-data",
  "partition_key": "record_id",                 // record_id | dict_code | record_code，默认 record_id
  "security_protocol": "SASL_PLAINTEXT",        // 可选
  "sasl": { "mechanism": "PLAIN", "username": "", "password": "" }   // 可选；secret 同掩码策略
}
```

**端点模型契合**：一个 kafka 端点 = brokers + topic 一份配置；其下 N 个订阅的事件进同一 topic，消费者按信封 `dictCode` 路由（与 webhook 单 URL 收多字典同构）。需要按字典分 topic 的场景 = 建多个 kafka 端点（端点表已无 uk 限制，§2.1 v2）。`partition_key` 端点级统一——同 key 同分区有序，跨 key 不保证全序（at-least-once + 消费端按 `eventId` 幂等，信封契约 §既有）。

### 8.3 实现要点（channels/kafka.rs 补全）

| trait 方法 | 实现 |
|---|---|
| `validate_config` | 扩展现有：brokers/topic 非空 + `partition_key` 枚举校验 + sasl 结构校验 |
| `deliver` | rdkafka producer（`acks=all`，启动惰性建、连接级复用属基础设施单例，集群合规）；**单事件单消息**（对齐 trait"逐条返回"约束）：key=partition_key 解析值（record_id/dict_code/record_code），value=EventEnvelope JSON，headers 带 `event_id/seq/dict_code`；每条 future timeout 映射 `DeliveryResult`：broker ack=ok；超时/断连=retryable；配置类错误=不可重试 |
| `health_check` | metadata fetch + topic 存在校验 |

### 8.4 依赖与构建风险

- 引入 `rdkafka`（需 librdkafka；`cmake-build` feature 静态编译）。**Windows 开发链风险**：本机需 cmake/nasm 工具链；缓解：feature 保持可选（不开不编译），CI/部署在 Linux 构建；本机联调用 Docker 起 kafka。
- feature 默认关闭 → 发布时构建参数开启（`--features channel-kafka`），注册表自动暴露通道，DB/前端零感知。

### 8.5 测试补充

- validate：缺 brokers/topic、非法 partition_key 拒绝；
- deliver：Docker kafka 联调——ack 成功/超时重试/配置错误不重试三分支；同 record_id 事件同分区有序验证；消费端按 eventId 幂等去重演示；
- health：broker 不可达/topic 不存在两种失败文案；
- 端点级：kafka 端点下多字典订阅 → 同 topic 按 dictCode 可路由；分 topic 场景建两个端点互不串。

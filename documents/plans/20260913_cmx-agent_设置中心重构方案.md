## 1. 一句话结论

**左下角只留一个 TrueMate logo，点 logo 直接打开「设置中心」大面板**——账户、模型、IM 遥控、外观、通用、关于全部收进去。现在活动栏底部的「头像 + logo」两个按钮、点出来的两个小弹菜单、以及散落的 Modal，全部取消或归位。

类比：现在是"抽屉里塞抽屉"（点 logo 弹小菜单、小菜单里再弹 Modal）；改完是"一间屋子一扇门"（一个 logo 进门，屋里六间房）。

## 3. 调研：ZCode 和 TraeWork 是怎么做的

### 3.1 ZCode 桌面端（本机 `D:\ZCode` 实测其前端代码，非道听途说）

- 全部设置**只有一个入口**，打开后是**左侧分组导航 + 右侧详情面板**，官方文案："从左侧切换主要设置项，右侧查看详细配置"。
- 左侧导航分三组，实测其源码中的导航数组：

| 分组 | 导航项 |
| --- | --- |
| 基础设置 | 通用、外观、**模型服务**、浏览器、电脑操控 |
| Agent 能力 | 记忆、子代理、插件、MCP、技能、命令、自动化(β)、钩子 |
| 数据与统计 | 索引、用量 |

- **模型服务是一级分区**；内置模型目录（provider + baseURL + 双协议 + 模型清单）随安装包以 JSON 发布，UI 里再叠加自定义条目。
- 会**记住上次停留的分区**（localStorage），下次打开直接落在原地。
- 语言、代理、更新、数据目录、主题、字号……全部收在这一处，主界面不再放任何设置类按钮。

### 3.2 TraeWork（= TRAE SOLO CN，本机 `D:\TraeWork CN`；结构以官方文档为准）

- 右上角齿轮 → **设置中心**，9 个分类：**账号** / 通用 / 智能体 / MCP / 对话流 / CUE / **模型** / 上下文 / 规则。
- **账号就是一级分区**：头像昵称、"管理账号"、隐私模式、退出登录——"把用户收进设置中心"的直接先例。
- 模型分区管自定义模型的增删改。

### 3.3 两家的共同点 → 我们直接抄的结论

1. **唯一入口**，主界面零散设置按钮清零；
2. **左导航 + 右详情**的两栏布局；
3. **账户进设置中心**（Trae 已验证此模式）；
4. **模型是一级分区**（ZCode 已验证）；
5. **记住上次分区**。

### 4.3 交互细则（点哪里 → 发生什么）

1. 点左下角 logo → 打开设置中心，落在上次停留的分区（localStorage，key `cmx-settings-section`）；首次打开落在「账户」。
2. 左导航点击 → 右侧整片切换；分区名 + 一句说明在右栏顶部。
3. 模型分区：左列表选 provider → 右详情；「新增 Provider」加一条；自定义条目可删，内置预设删除按钮禁用；保存/删除后刷新列表——**逻辑全部沿用 `mcfg*` 函数，只挪 DOM 容器**。
4. IM 遥控分区：左列通道（勾选=启用）+ 右侧所选通道凭证表单；QQ/微信「扫码登录」二维码逻辑原样调现有 `scfg*` 流程——**逻辑全部沿用，只挪 DOM 容器**。Web 壳（无 Tauri）进 IM 分区显示"仅桌面版可配置"提示。
5. 外观分区：点主题卡立即生效并持久化（等价原 `toggleTheme`，复用 `applyTheme(t)`）。
6. 退出登录：仍走现有 `logoutConfirm` 确认弹框。
7. Esc / ✕ / 点遮罩 → 关闭；`_pwdForced`（强制改密态）时设置中心**不响应打开**（改密弹框优先，维持现有不变量）。

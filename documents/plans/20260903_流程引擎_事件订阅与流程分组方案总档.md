v2.4 被推翻的核心原因（决策记录）：
1. 实例级 `subscriber_id` 绑定把路由关系散进实例表，衍生悬空绑定/幽灵处置/滚动发布假成功等新问题，防御机制（单条 SQL 守卫、幽灵计数、绑定订阅主键点查、滚动行为矩阵、route_source 审计列）复杂度超过价值。

3. 「订阅者 + rules JSONB 内嵌多规则」以更低复杂度覆盖全部诉求（三维 AND、跨规则 OR、数组序命中）。

## 一、目标与非目标

**目标**
- G1 企业级订阅匹配：订阅者 + 多规则（事件类型 × 流程分组 × definitionKey glob 三维 AND、跨规则 OR、数组序 = 命中序）。
- G2 流程分组：一级扁平、可排序、可启停（enabled 仅影响定义页展示位，**永不参与运行时匹配**）。
- G3 定义管理独立页面：左分组右列表、搜索分页、详情视图（元数据 + 版本表 + 工作台入口）。
- G4 投递可观测：KPI 统计 + 流水 + 死信处置 + 补发，独立成页。
- G5 通道可扩展：DeliveryChannel trait + 注册表 + MQ feature 骨架不动，本期只走 webhook。
- G6 复杂度惩罚：每一处新增结构过「三问纪律」（§九）。

**非目标（显式排除）**
- 不做 tag 标签路由、多级分组树、正则匹配（globset 也不引入，自实现双指针）。
- 不做跨实例事件聚合/转换管道（接收方自理）、订阅者级灰度/审批流、订阅版本化。
- 不做 MQ 实装（仅保持 trait 形态，kafka/rabbitmq feature 骨架返回「通道未启用」）。
- wire 契约不变：三头（`x-cmx-flow-signature/event/delivery`）+ HMAC-SHA256 + HTTP 2xx 判定；payload **additive** 增 `systemId?/groupId?/groupName?`（接收端 mdm 泛型解析容忍新字段，已核实）。

## 二、决策拍板项（定稿口径）

1. **不兼容旧设计**：不合理的表与代码直接删（旧 webhook 两表、三级路由列、subscribe/unsubscribe 端点、env 种子导入、legacy 内存链路）。
2. **流程定义归属流程分组**（非 tag、非树）：一级扁平分组表，创建定义时挂分组；DAM 三段列（domain/application/module）冻结，分组是唯一新增归属维度。
3. **定义管理独立成页**：左分组面板 + 右列表；分组维护内嵌定义页左侧面板上方弹框（增删改/启停/上移下移），不设独立菜单。
4. **订阅模型两级**：先注册订阅者（名称/回调方式/回调地址等），再在其下配多条订阅规则；逻辑两级、物理单行（rules JSONB 内嵌）。
5. **拆除三级路由，纯订阅规则匹配**；通道抽象保持不动以便后续接 MQ。
6. **前端三页对标 mdm 范式**（subscription-manager / dispatch-monitor）：流程定义管理、事件订阅管理、投递记录（含统计）。
7. **匹配语法仅 glob 通配（`*`）**，不引入正则/复杂表达式。
8. **迁移落盘**：不新建版本，直接改写已提交的旧 004 迁移并改号为 `20260902_005_流程引擎事件订阅分组与实例治理`（up/down 同步 git mv）；旧表当日建、未投产，sql-guide「up 禁 DROP TABLE」红线经用户明示豁免，幂等清理段收口已执行过旧版的环境。
9. **webhook 目标双模式**（2026-09-03 拍板）：生产新增订阅不允许改 toml——`channel_config` 的 `service_key` 与 `target_url` **二选一**（详见 §五.2）；互斥/全空/非 http(s) 由 `validate_config` 拒绝；不做配置开关与 URL 白名单。

## 三、数据模型（全 biz 库，已落地）

### 3.1 `cmx_flow_def_group`（流程分组）

```sql
CREATE TABLE cmx_flow_def_group (
    id         BIGINT       NOT NULL,            -- Pk52 雪花（52 位 JS Number 安全）
    name       VARCHAR(64)  NOT NULL,            -- 全局唯一（uk）
    sort_no    INT          NOT NULL DEFAULT 0,  -- 展示序（上移下移改此列，纯展示不参与匹配）
    enabled    BOOLEAN      NOT NULL DEFAULT TRUE,  -- 仅定义页展示位：停用组折叠置灰
    remark     VARCHAR(512),
    created_at TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ  NOT NULL DEFAULT now(),  -- DB 时钟；进 EventRouteCache 指纹
    PRIMARY KEY (id)
);
CREATE UNIQUE INDEX uq_cmx_flow_def_group_name ON cmx_flow_def_group (name);
```

### 3.2 `cmx_flow_definition` 加列

```sql
ALTER TABLE cmx_flow_definition ADD COLUMN group_id BIGINT;   -- NULL = 未分组
CREATE INDEX idx_cmx_flow_definition_group ON cmx_flow_definition (group_id);
```
- NULL = 未分组（匹配语义 =「不在任何组」，只有 groupIds 为空的规则可命中其事件）。
- 同步五处：迁移、init_ddl、`cmx-flow-def` DDL（幂等补列）、`PgDefinitionStore` upsert/get/list SQL、`DefinitionRecord.group_id`。group_id 仅 INSERT 生效（冲突更新不触碰——分组改挂走 set-group，不随草稿保存变化）。

### 3.3 `cmx_flow_event_subscriber`（订阅者，rules 内嵌单行）

```sql
CREATE TABLE cmx_flow_event_subscriber (
    id             BIGINT       NOT NULL,        -- Pk52 雪花
    name           VARCHAR(128) NOT NULL,        -- uk(tenant_id, name)
    description    VARCHAR(512),
    channel        VARCHAR(16)  NOT NULL DEFAULT 'webhook',
    channel_config JSONB        NOT NULL DEFAULT '{}',
    rules          JSONB        NOT NULL DEFAULT '[]',
    retry_max      INT          NOT NULL DEFAULT 10,   -- 含首发，默认 = 重试 9 次
    active         BOOLEAN      NOT NULL DEFAULT TRUE,
    tenant_id      VARCHAR(64)  NOT NULL DEFAULT 'default',
    created_by     VARCHAR(64),
    created_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),
    updated_at     TIMESTAMPTZ  NOT NULL DEFAULT now(),  -- 缓存指纹对账列
    PRIMARY KEY (id)
);
```
- **rules JSONB 内嵌**（红队裁定）：save 单行 upsert 天然原子（无跨表一致性窗口）、数组序即命中序（无需 sort 列）、匹配侧一次读全。
- rules 元素结构：
```json
{ "name": "规则名≤64（同订阅者内唯一，落投递行 matched_rule）",
  "enabled": true,
  "eventTypes": [],      // 空 = 全部 6 种；非空 = 事件类型须 ∈
  "groupIds": [],        // JSON number 数组；空 = 不限分组；非空 = 定义所属组 ∈
  "keyPatterns": [] }    // glob（仅 *）；空 = 不限；≤128 字符/条
```
- 全空且 enabled 的规则 = 匹配全部（网关形态）。
- 删除守卫：仅 `active = FALSE` 且名下无 `PENDING/IN_FLIGHT/DEAD` 投递行可删（单条 SQL，防僵尸死信）。
- set-active 硬约束：UPDATE 必带 `updated_at = now()`（缓存指纹对账依赖）。

### 3.4 `cmx_flow_event_delivery`（投递，继承租约/保序/死信机制）

```sql
CREATE TABLE cmx_flow_event_delivery (
    id                    BIGINT        NOT NULL,   -- Pk52
    seq                   BIGSERIAL     NOT NULL,   -- 保序键（DB 提交序，雪花不做保序）
    subscriber_id         BIGINT        NOT NULL,
    subscriber_name       VARCHAR(128)  NOT NULL,   -- 快照（删除/改名后流水仍可辨识）
    channel               VARCHAR(16)   NOT NULL,   -- 快照
    event_id              VARCHAR(64)   NOT NULL,
    delivery_id           VARCHAR(160)  NOT NULL,   -- wire 幂等参考键 {instanceId}-{taskId?}-{occurredAt}
    source                VARCHAR(8)    NOT NULL DEFAULT 'emit',  -- emit/test/rebuild
    event_type            VARCHAR(32)   NOT NULL,
    definition_key        VARCHAR(128),
    business_key          VARCHAR(128),
    instance_id           VARCHAR(64)   NOT NULL,
    payload               JSONB         NOT NULL,
    state                 VARCHAR(16)   NOT NULL DEFAULT 'PENDING',  -- PENDING/IN_FLIGHT/DONE/DEAD/SKIPPED
    attempts              INT           NOT NULL DEFAULT 0,
    next_attempt_at       TIMESTAMPTZ,
    locked_by             VARCHAR(64),
    lock_expires_at       TIMESTAMPTZ,
    last_error            TEXT,
    last_http_status      INT,
    last_response_snippet VARCHAR(512),
    matched_rule          VARCHAR(64),              -- 命中规则名快照（emit 时定版；test/rebuild 行 NULL）
    created_at            TIMESTAMPTZ   NOT NULL DEFAULT now(),
    delivered_at          TIMESTAMPTZ,
    PRIMARY KEY (id)
);
```
- 索引：`uk(seq)`、`uk(subscriber_id, event_id)`、`(state, next_attempt_at)`（worker 扫描）、`(subscriber_id, seq)`（保序）、`(delivery_id)`、`(created_at)`（stats 时间窗）。
- 相对旧投递表：`subscription_*` → `subscriber_*`；**删 route_source**（三级路由拆除）；+`matched_rule`（列宽与规则名校验上限同为 VARCHAR(64)，save 校验拦超长——防炸批）。
- `uk(subscriber_id, event_id)` 幂等语义**仅约束 rebuild/test**（确定性 event_id 重复点击去重）；emit 行 event_id 每行 uuid，不提供业务幂等（文档口径，防误读）。
- 保序粒度 = 订阅者级（同订阅者按 seq 串行）；终态（DONE/DEAD/SKIPPED）均不阻塞后续，阻塞仅来自未终态行。

### 3.5 可观测计数

`EMIT_NO_MATCH`（事件零订阅命中）、`EMIT_NULL_DEFKEY`（事件缺 definitionKey，keyPatterns 非空规则不可命中）、`OUTBOX_INSERT_ERRORS` 三个全局原子计数，随 `/event-deliveries/stats` 一并返回（独立 mon 端点已砍）。

## 四、匹配引擎（`event_outbox.rs`，已落地）

### 4.1 算法

```
match_rules(subscriber, event, def_group_id):
  for rule in subscriber.rules:            # 数组序
    if !rule.enabled: continue
    if rule.eventTypes 非空 && event_type ∉ rule.eventTypes: continue
    if rule.groupIds 非空 && (def_group_id == null || def_group_id ∉ rule.groupIds): continue
    if rule.keyPatterns 非空 && (def_key == null || !any(glob_match(p, key))): continue
    return rule.name                        # 首个命中即返回（数组序 = 命中序）
  return None
```
- null definitionKey 仅被「三维全空/相应维为空」的规则命中——无法证明命中的维度一律不命中（防泄露默认放行）。

### 4.2 glob 实现（`glob_match`，仅 `*`，迭代双指针 O(n·m) 无回溯）

- 不支持 `?`/`[]`/`**`/转义——要扩先换 globset（硬承诺，不做增量扩展）。
- 按字符（非字节）推进，切片走 char 边界防 UTF-8 panic（key 可含中文）。
- 单测穷举：空串/单 `*`/多 `*`/无星/全星/中缀/边界（`event_outbox.rs` `mod tests`）。

### 4.3 EventRouteCache（单一缓存，`event_store.rs`）

- 内容：`active_subscribers`（含 rules）、`def_key → group_id` map、`group_id → name` map。
- 指纹 = 三表 `(COUNT, MAX(updated_at))` 并集（subscriber 仅 active 行）。
- TTL 5s 版本对账：命中即返、过期先对账、变了全量重载；写操作失效本副本，跨副本 ≤5s 收敛。

### 4.4 emit 链路

- `publish_events(rt, events)`：SSE 广播 + `emit_to_outbox(events)`。
- `emit_to_outbox`：查缓存 → 逐事件解析 def→group → 逐订阅者跑 4.1 → 命中即产投递行（matched_rule 定版）；payload 注入 `systemId?/groupId?/groupName?`（additive，systemId 由 handler 侧从实例快照带上）。
- rebuild / rules-preview 复用**同一 matcher 函数**（禁第二份过滤逻辑——旧 rebuild 手写第二份过滤是对抗审查教训）。

### 5.1 webhook 目标双模式（`cmx-flow-adapters/channel_webhook.rs`）

- **生产新增订阅不允许改 toml**——`channel_config` 四字段：`service_key` | `target_url` 二选一 + `callback_path`（仅目录模式生效）+ `secret`。
- 有服务键 = **目录路由**：`RpcRequest` 经 `[service_rpc.services]` 定位（内部微服务形态，走 service_rpc 基座）。
- 无服务键只有完整 URL = **直连**：reqwest 直发（含路径），`callback_path` 不生效，全程不经 service_rpc——外部系统订阅页自助接入。
- 互斥/全空/非 http(s) 由 `validate_config` 拒绝；deliver 按 config 分派 `deliver_via_directory` / `deliver_direct`，签名对实际发送字节（Raw body）。

## 九、相对旧设计的优化（本次重构收益）

1. **路由模型简化**：三级路由 → 纯规则匹配。拆除实例级 `subscriber_id` 绑定及其全部防御负担（悬空绑定守卫、幽灵计数、绑定订阅主键点查、滚动发布行为矩阵、route_source 审计列、绑定/旁听/屏蔽三态匹配）——匹配回归单一函数，行为可静态推演。
2. **订阅模型升级**：单层 definition_keys 精确集 → 订阅者 + 多规则两级；**rules JSONB 内嵌单行**使 save 天然原子（无跨表一致性窗口）、数组序即命中序（免排序列）、匹配一次读全。
3. **匹配维度扩展**：新增分组维度（groupIds）与 glob 通配（keyPatterns），支持网关形态（全空规则 = 匹配全部），接入方自助粒度从「逐 definitionKey 勾选」升级为「模式表达」。
4. **可审计性**：投递行落 `matched_rule` 命中规则快照（emit 时定版），回答「这条投递为什么发生」。
5. **可观测性收敛**：独立 mon 端点删除，三个 emit 侧计数（零命中/缺 defKey/落行失败）并入 `/event-deliveries/stats`。
6. **单一 matcher**：emit / rebuild / rules-preview 共用同一匹配函数，杜绝旧 rebuild 手写第二份过滤的漂移风险。
7. **通道目标双模式**：`service_key`（目录路由）| `target_url`（直连）二选一——外部系统订阅页自助接入，生产免改 toml、免经 service_rpc。
8. **legacy 链路清账**：`FLOW_WEBHOOK_MODE` 双轨、内存 mpsc 队列、env 种子导入整体删除，outbox 为唯一投递链路（订阅表为唯一真源）。
9. **缓存指纹扩维**：EventRouteCache 指纹由订阅单表扩为三表并集（订阅者/分组/定义），分组改名/启停 ≤5s 对账收敛。
10. **迁移收口**：旧 004 原地改写改号 005（避免死迁移文件），幂等清理段保证已执行旧版的环境重放无副作用。

## 十、继承不变的部分（自 v2.3 延续）

- **outbox 租约投递**：`SKIP LOCKED` 抢占 + 120s 租约 + 逐行续租 + 持有者守卫（`locked_by` 不匹配即中止本批）；同订阅者按 seq 保序（终态不阻塞）；退避 1s 起指数封顶 5min × retry_max（含首发，默认 10）；HTTP 408/429/5xx/超时可重试、其余 4xx 直达 DEAD；投递语义 **at-least-once**（接收方按 delivery_id 或业务键幂等）。
- **wire 契约**：三契约头 + HMAC-SHA256（每订阅独立 secret，mask/keep）+ HTTP 2xx 成功判定；delivery_id 含 taskId（修同刻多任务碰撞）；payload additive 增量不破坏既有接收端。
- **事件契约修复**（随 v2.3 落地，保留）：6 事件全量携带 definitionKey、TaskCreated 只对新建任务 emit。
- **通道抽象**：`DeliveryChannel` trait + 注册表；kafka/rabbitmq feature 骨架（`channel-kafka`/`channel-rabbitmq`，M4+ 实装，连接凭据走 toml、订阅只存路由目标）。
- **测试体系**：`event_store_pg.rs` 等 PG 门控集成测试（outbox 全链/死信 retry/保序守卫/缓存指纹）+ http_guard_test 角色闸回归。

## 十一、复杂度惩罚（硬承诺）

1. 三问纪律：①能少一个表/端点/概念吗？②抽象现在有几个实现（>1 才配存在）？③用户看得见这个复杂度吗？
2. 砍单清单（已裁 15 项）：规则独立建表、规则级启停端点、tag 体系、分组树、正则、Trie/倒排索引（订阅量级 <100 线性扫够）、事件转换管道、订阅审批流、订阅版本化、灰度发布、跨租户路由、matched_rule 宽列、rebuild 第二份过滤、preview 全量扫描、mon 独立端点。
3. 硬承诺：glob 要扩先换 globset 不做增量扩展；rebuild/preview/emit 共用 matcher；分组 enabled 永不参与运行时。

# cmx-agent 子智能体执行过程可视化方案

> 2026-09-15 · 模块 `backend/cmx-agent` · 状态：**待指令**（说「改」即按 §七 顺序实施）
> 背景：子智能体（task 工具）前台/后台执行期间，用户在会话界面完全看不到它在做什么——前台只有一张静态工具卡转圈，后台只有完成后的回执卡。本方案给出实时、回放、恢复三个层次的可见性设计。

---

## 一、问题与根因（现状诊断，含代码证据）

子智能体执行链路的四个断点：

1. **子会话从不挂事件总线**。`BusSink` 只在父会话回合入口 `app.rs` `send_inner`（`crates/cmx-agent-app/src/app.rs:1435`）挂载；子会话在 `crates/cmx-agent-tools/src/task.rs` 里 `Session::new(sub_id)`（前台 :449 / 后台 :543）后**从未 `add_sink`**——子回合的全部事件（思考、工具调用、工具结果）只累积在内存 `sub.log`，不进 `SessionEventBus`。U16 总线 → Web SSE `/api/subscribe` / Tauri `session_event` 的实时通路对子会话是断的。
2. **子会话事件只在收尾整批落审计 JSONL**（`builder.rs:336-346` 注入 `log_sink`；`task.rs:498` / `:566` 收尾调用），落 `sessions/subtask-*/log.jsonl`，仅审计可查，UI 无任何入口。
3. **父视图只有两张静态卡，都无过程**：
   - 前台：`tool_invoked(task)` 建普通工具卡（`render.js:124 ensureToolCard`，阶段一已加 subagent_type / 后台徽标 `render.js:136-144`），`tool_result` 回填 `{final, steps, …}`，中间步骤不可见；
   - 后台：工具卡立即返回 `task_id`，完成后 `<task_result>` 渲染为 `.notify` 回执卡（`render.js:849-873`），运行期间界面无任何表示。
4. **子会话审批卡父 UI 不可见**（已知坑）：子回合的 `approval_requested` 事件落在子会话 log（不广播）；`InteractiveApprover` 按子 sid 挂起（`approval.rs` `pending_in_session` 精确匹配），而前端 `list_pending_approvals` 按当前打开的**父** sid 轮询（`app.rs:431-434`）→ 查不到，子任务静默卡死等待审批。

**好消息（零改动即可用的地基）**：

- `get_events` 对 `subtask-` 会话**没有读取门**（`app.rs:1587-1593` 直读 store；`store.rs:254-257` 只在 `list()` 过滤前缀）→ 子日志回放通道现成；
- U16 总线信封 `{session_id, event}` 结构简单，加字段是纯加法；
- 前端 `onSessionEvent`（`session.js:157`）按 `session_id` 分流，天然是插入「子事件→父视图」分支的位置；
- `renderApprovalCard(zone, ev, sid)` 的 approve 调用本来就带 `session_id` 参数（`session.js:292`）→ 传子 sid 即可复用整张审批卡。

## 二、目标与非目标

**目标（三个可见性层次 + 一笔清偿）**

| 层次 | 场景 | 效果 |
| --- | --- | --- |
| 实时 | 前台 / 后台子任务运行中 | 父会话视图内「子任务卡」实时滚动过程行（思考摘要、工具行、文字） |
| 回放 | 事后重开父会话 | 子任务卡 / 回执卡提供「查看完整过程」，懒加载子日志渲染只读时间线 |
| 恢复 | 页面刷新 / 重开期间后台任务仍在跑 | 重新打开父会话时重建「后台执行中」卡，实时事件续流 |
| 清偿 | 子会话审批 | 审批卡渲染进父视图交互槽，可直接批准/拒绝 |

**非目标**：子会话开独立 tab 或进侧栏列表（保持「嵌套在父回合」的语义，`store.list` 前缀过滤不动）；子会话 token 级打字机（完整事件粒度与 ZCode 子任务展示对齐，足够）；IM 壳推送子任务过程（总线是进程内的，IM 桥不经总线，维持现状）。

## 三、总体设计

```
子回合事件                          父会话视图
──────────                         ──────────────────────
Session(subtask-*)                 ▸ 用户气泡
  │ log.add_sink(SubEventSink)       ┌──────────────────────┐
  │   每条 append →                  │ 🛰 子任务 · explore · 调研路由  ● 执行中 0:42
  │   EventEnvelope{                 │ │ 💭 先找路由定义文件…
  │     session_id: subtask-…,       │ │ ⚙ grep "route" src/ ✓ 0.3s
  │     parent: 父sid,        ────►  │ │ ⚙ fs_read router.ts ✓ 0.1s
  │     event }                      │ │ …
  │                                 │ └ [展开过程 ▾]
  └ 收尾: log_sink 整批落审计 JSONL   │   （完成后自动折叠为卡头一行）
                                    └──────────────────────
```

三条设计原则：

1. **过程嵌在父回合里，不开新会话**。子任务的真实结构就是「父回合内嵌套一个隔离会话」，UI 用嵌套时间线如实表达（§六）。
2. **子事件只走总线，粒度 = 完整事件**。不打字机、不新增通道；复用 U16 广播 + 既有丢帧兜底（Web Lagged 提示重拉 / Tauri resync）。
3. **回放一律懒加载**。子日志已在盘上，`get_events(sub_id)` 现成；父历史渲染时不预取，点开「查看过程」才拉。

## 四、后端改造

### B1 总线信封加 `parent` 字段（`crates/cmx-agent-app/src/bus.rs`）

```rust
pub struct EventEnvelope {
    pub session_id: String,
    /// 子智能体会话事件 → 所属父会话 id；父会话事件为 None（兼容旧信封）。
    #[serde(default)]
    pub parent: Option<String>,
    pub event: SessionEvent,
}
```

`BusSink` 增加 parent 参数（`BusSink::new` 保持 None 语义，新增 `BusSink::new_sub(sub_id, parent, tx)`）。`#[serde(default)]` 保证旧落盘/旧前端反序列化兼容。

### B2 子会话挂实时事件 sink（`crates/cmx-agent-tools/src/task.rs` + `builder.rs` 装配）

**分层注意**：`cmx-agent-tools` 不能反向依赖 `cmx-agent-app`（bus 所在）。仿照 `log_sink` 的装配模式，`SubagentHandle` 增加一个解耦回调：

```rust
/// 子会话实时事件回调：(sub_id, parent_id, event)。app 装配层注入（内部包总线 publish）。
pub type SubagentEventSink = Arc<dyn Fn(&str, &str, &cmx_agent_core::SessionEvent) + Send + Sync>;
```

- `SubagentHandle` 加 `event_sink: OnceLock<SubagentEventSink>` + `attach_event_sink`；
- `builder.rs`（`into_shared` 附近，紧挨 `attach_log_sink` 的 :341）装配：闭包里 `event_bus.publish(EventEnvelope{ session_id: sub, parent: Some(parent), event })`；
- `task.rs` 前台 `run_foreground`（:449 `Session::new` 之后）与后台 `run_background_child`（:543 之后）各 `sub.log.add_sink(...)` 一个薄壳 `EventSink`，转发进 `event_sink`。

前台子回合运行在父 future 树内、后台在独立 spawn 内——两种路径事件都会流经 `sub.log.append`，一个 sink 点全覆盖。

### B3 前台 `tool_result` 补 `task_id`（`task.rs:505-510`）

前台成功分支的 `ToolResult::ok(json!({...}))` 增加 `"task_id": sub_id`。这是回放时父历史 `tool_result(task)` 卡片能懒加载子日志的锚点（后台路径已有 `task_id`、`<task_result>` 已带 `id`，无需动）。

### B4 父会话活动子任务查询（恢复层，S3）

`SubagentHandle.cancels`（`task.rs:84`）已按 parent 登记活动子任务，但只有 `(sub_id, TurnCancel)`，缺展示信息。改造：

- 登记结构升级为 `HashMap<String /*parent*/, Vec<ActiveSubTask>>`，`ActiveSubTask { sub_id, description, subagent_type, background, started_at }`（`invoke` 处一并登记，`remove_cancel` 同步摘除）；
- 暴露只读快照 `active_for_parent(parent) -> Vec<ActiveSubTask>`；
- `AgentApp` 暴露 `list_active_subtasks(parent_id)`，Web `/api/…` 与 Tauri command 各加一个只读端点（新接口走既有 query/body 约定）。

### B5 子会话审批可见（清偿层，S3）

- **实时**：子回合 `approval_requested` 事件经 B2 总线到达前端（信封带 parent）→ 前端在父视图交互槽画卡（approve 的 `session_id` 用信封的 `session_id` 即子 sid，后端 `decide` 按 `call_id` 命中、`pending_info` 校验一致，**零后端改动**）。
- **恢复**：`list_pending_approvals` 不动（`pending_in_session` 无法从子 sid 反查父——subtask id 不含 parent）。改为前端对 B4 的活动子任务清单逐个 `list_pending_approvals(sub_id)` 补画。审批只在运行中挂起，恰好被活动清单覆盖。

### 明确不动的地方

`store.list()` 的 subtask 前缀过滤、`app.rs:1203` 的建会话保留前缀守卫、`log_sink` 审计落库、`cancel_for_parent_with_ids` 级联清理——全部维持。

## 五、前端改造（UI 真源 `crates/cmx-agent-web/ui/`，改完 `bash sync-ui.sh` 同步桌面壳）

### F1 `onSessionEvent` 加 parent 分流（`session.js:157`）

```js
function onSessionEvent(env){
  if(!env || !env.session_id || !env.event) return;
  if(env.parent){ handleSubagentEvent(env); return; }   // ← 新增，必须在 openSessionLive 之前
  ...现状...
}
```

**必须在 `openSessionLive` 之前短路**：否则子信封会被当成「未知新会话」开一个 subtask tab。

`handleSubagentEvent(env)`：

1. 定位父 tab：`findTab("s:"+env.parent)`，没有则丢弃（父会话没开着，回放走懒加载，不缓存）；
2. 定位卡片：`log._subCards`（Map<sub_id, card>）命中 → 渲染；未命中 → 尝试配对（见下）；配不上 → `log._subPending[sub_id]` 暂存，卡片建立后 flush；
3. **前台运行卡的配对键 = 子 prompt 全文**：子会话首条 `user_message.text` 就是 `task` 的 `input.prompt`（`task.rs` 用 prompt 起 turn），与运行中 task 卡的 `card._input.prompt` 精确相等即配对；同 prompt 并发双发的极端场景回退「运行中卡队列顺序」。`tool_result(task)` 带 `task_id` 落定时回写 `_subCards[task_id]=card`，此后直配；
4. **子事件不写 `log._seqs`**（那是父会话的去重集合，子 seq 空间独立，混入会误吞父事件）；
5. `turn_ended(reason)` → 卡片状态机收口。

### F2 task 工具卡特化（`render.js` `ensureToolCard` / `completeToolCard`）

- `ensureToolCard`：`task` 卡头部改为「子任务」形态（§六），`tool_invoked` 时即建**过程区** `.tc-body`（空）；
- `completeToolCard` 对 `task` 特化：
  - 前台：卡落定（✓/✕ + 耗时 + `final` 摘要正文），结果体**不 dump JSON**（现状 `toolBodyHtml` 会展示 `{final, steps…}` 原文，改为渲染 `final` 文本 +「查看完整过程」按钮，用 `output.task_id` 懒加载）；
  - 后台：`output.background===true` 时不落定，改状态「后台执行中」，登记 `log._subCards[task_id]=card`，后续子事件实时续；
- `<task_result>` 回执渲染分支（`render.js:849`）：先查 `log._subCards[id2]`——命中则**收口那张后台卡**（状态/正文并入，不再建独立 notify 卡）；未命中（刷新后 / 纯回放）维持现状 notify 卡 + 补「查看完整过程」按钮。两态兼容，重放与实时同形。

### F3 过程行渲染 `renderSubLine(card, ev)`（新函数，`render.js`）

子事件 → 过程区的映射（v3 定稿：**卡内直接复用主会话渲染组件**，实施 = 把 `renderEvent` 管线跑在子任务卡的内容器（mini-log）上，不另造样式）：

| 子事件 | 渲染（与会话同款） |
| --- | --- |
| `user_message`（= 派下去的 prompt） | **「📋 下发提示词」行**（思考卡同款可折叠行：无边框、默认展开、点标题收起），全文，固定为卡体第一块 |
| `reasoning` | **思考卡 `.reasoning`**：流式 shimmer「思考」→ 收口自动折叠成「思考 · 持续了 N 秒」，点头部重开；正文全文、超长内部滚动 |
| `tool_invoked` / `tool_result` | **工具卡 `.tool.tcard`**：转圈 → ✓/✕，中文工具名（检索/读取/终端…），结果点开看 `.tterm`，耗时 >2s 才显示 `.tc-dur` |
| 连续只读工具（fs_read/glob/grep…） | **折叠入上下文引用组 `.ctxgroup`「已引用 N 处」**，条目点开看完整结果（真源 `foldIntoCtxGroup` 同款） |
| `model_message.text` | **`.bubble.bare` 过渡文字气泡**（主会话同款，全文不截断） |
| `approval_requested` / `resolved` | `⏸ 等待确认` / `✕ 已拒绝`（轨迹行；卡本体走交互槽，F1/B5） |
| `turn_started` / `turn_ended` | 忽略（turn_ended 触发卡收口） |

实现要点：mini-log 是「log 样」对象（持有 `_tools` Map、`_rcard`、`_ctx` 等状态槽），`ensureToolCard` / `completeToolCard` / `ensureReasoningCard` / `foldIntoCtxGroup` 等真源函数只需把宿主从主 log 换成 mini-log 即可复用——子过程与主会话样式**结构性同源**，永不跑偏。运行中默认展开、尾部保留最近 6 项 +「⋯ 前面 N 步」展开全量；完成后自动折叠为卡头一行。

### F4 恢复（S3，`session.js` `openSession` 流程）

父会话打开后异步调 `list_active_subtasks(sid)`，为每个后台活动任务重建「后台执行中」卡（`_subCards[sub_id]` 登记，实时事件续流），并逐个 `list_pending_approvals(sub_id)` 补画审批卡。

## 六、UI 设计（子任务卡规格）

沿用现有 opencode/ZCode 对齐的工具卡语言（`.tool.tcard` + `.tc-trig` 头 + `.tc-body` 体 + `.iline` 行），**不新造组件体系**。本方案的签名元素是**嵌套时间线脊线**：过程区左侧一条 2px 竖脊（`var(--gold)` 派生、40% 透明度），过程行缩进挂脊上——「孩子会话嵌在父回合里」的结构真相直接编码进视觉，与折叠组（「已工作」收纳 `.iline`）形成同一套嵌套语法。

```
运行中（前台）                          完成后（自动折叠）
┌───────────────────────────────┐    ┌───────────────────────────────┐
│ 🛰 子任务 · explore · 调研路由   │    │ ✓ 子任务 · explore · 调研路由   │
│   ● 执行中 0:42        [收起 ▴] │    │   已完成 · 1 分 12 秒  [展开 ▾] │
│ │ 📋 下发提示词（可折叠行·全文）   │    └───────────────────────────────┘
│ │ │ 💭 思考（完整块·全文）         │    展开后体 = 提示词 + 全量思考块 +
│ │ │ ⚙ grep "route" src/  ✓ 0.3s  │         工具时间线 + 「final 结果正文」
│ │ │ ⚙ fs_read router.ts ✓ 0.1s   │
│ │ …                             │
└───────────────────────────────┘
```

- **状态机**：`执行中`（呼吸点 + 实时计时）→ `已完成` / `失败` / `已中断`（级联取消时）；后台另有一态 `后台执行中`，由 `<task_result>` 收口。
- **文案**（用户侧词汇，不暴露实现名）：卡头「子任务 · <类型> · <description>」（description 缺省取 prompt 前 20 字）；按钮「展开过程 / 收起」；空过程体显示「（无中间步骤，直接返回）」；回执合一后不重复出现「后台子任务完成」notify 卡。
- **色值**：全部 `var(--*)` 派生（呼吸点复用现有 `run` 态动画 token；脊线/弱化行用现有 `--line`/`--muted` 系），双主题通路不破例。
- **降噪**：父回合 `turn_ended` 折叠组只收父级 `.iline`；子任务卡作为 `.tcard` 留在组外，收口后自带一行高度，多子任务并发时纵向堆叠不超过卡头高度和。

## 九、风险与坑

1. **`env.parent` 分支必须先于 `openSessionLive`**（F1）——漏了会把每个子任务当成新会话开 tab。前后端同仓同版发布（Web 壳 UI 内嵌同二进制、桌面壳整包），不存在「新后端 + 旧前端」长期组合。
2. **子事件不进父 `log._seqs`**——两个 seq 空间独立，混用会让历史 prepend 去重误吞父事件（P3-4 修复的同类坑）。
3. **前台配对竞态**：子事件可能先于 `tool_invoked(task)` 卡建立到达（同回合多工具交错）——`_subPending` 暂存 + 卡片建立后 flush 兜底。
4. **广播量**：每父会话并发上限 4，事件粒度为完整事件（非 delta），`BUS_CAPACITY=1024` 足够；丢帧走既有 Lagged 兜底（Web 跳帧提示重拉 / Tauri resync），回放懒加载是最终兜底。
5. **安全面无新增**：子日志读取复用 `get_events` 既有鉴权（Web 登录门）；子会话不进列表、不可建（保留前缀守卫不动）；`list_active_subtasks` 是只读端点，走新接口 query 约定。
6. **折叠组交互**：子任务过程行全部在卡内 `.tc-body`，不落在父 log 根上，不会撑爆「已工作」折叠组的 CSS 收纳。
7. **`<task_result>` 双态渲染**：合一分支只处理「卡片在」的实时态；回放/刷新态走原 notify 卡路径——两条路径都要过 e2e，防止只测一边。

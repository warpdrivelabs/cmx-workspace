# 本体工作室新界面场景化方案（cmx-ontology）

> 日期：2026-09-10 · 模块：cmx-ontology（后端）+ assets/onto（前端 native page）
> 定位：**新建一个独立 native page「本体工作室」**承载本体目录、场景视图、版本发布、元数据导入与全局搜索；**现有三页（设计工作台/对象浏览器/对象360）与其菜单项零改动**。
> 方案来源：多轮评审定稿（场景=透镜、草稿/发布双轨、版本快照、DCT/DOC 导入），并吸收《20260909_本体设计器大图规模架构优化方案》（下称"大图方案"）的 A 阶段 API 结论与 B 阶段机制。
> 本文档为方案；实施按 §八 分期另行排期。

## 一、背景与目标

### 1.1 总原则：新界面、零侵入

1. **不动旧页面与旧组件**：`designer.js` / `explorer.js` / `workshop.js` / `page-kit.js` 及现有 `cmx-ontology-graph` 组件源码/vendor 一律不改；新画布能力（角标/引用卡/虚拟化）以**新建组件 `<cmx-ontology-canvas>`** 承载（§5.3），纯增量、旧设计器零回归。
2. **不动旧菜单项**：`onto-menu.json` 中现有三个 workspace-node 原样保留；仅**追加**新节点（P1 为「本体工作室」单节点；P2 授权上线后按 §4.5 追加「场景视图」业务入口节点并给工作室节点挂 permissionId）。
3. **后端只增不改**：全部能力通过**新增**端点/表/字段实现；既有端点语义、路径、行为零变化（旧设计器继续使用旧端点）。
4. 旧设计器何时下线由后续单独决策，本方案不涉及。

### 1.2 现状痛点（证据）

| # | 痛点 | 证据 |
|---|---|---|
| 1 | 左栏过载：搜索 + 对象 DAM 树 + 关系/接口/共享属性/动作/函数 5 个平铺列表 + 全部新建入口 + 帮助，全挤 240px 左栏 | `designer.js` explorerHtml()（约 :380） |

### 1.3 目标

1. **找得到**：上千对象类型/关系/函数/动作规模下，3 秒内通过搜索/目录/树定位任意元素（⌘K 命令面板 + 服务端过滤表格 + DAM 树三通路）。
2. **看得清**：日常以"场景视图"（5~30 个类型的小图）为工作单元；底座全量只作治理视角（域盒折叠 + 引用卡），不要求一屏看全。
3. **分得开（按角色分受众）**：**场景视图 = 最终业务用户的消费形态**（看自己业务域的小图）；**底座全量（目录/域盒图/版本发布/导入/元素库）= 管理员与维护人员的治理形态**——两类受众的边界是**角色**而非模式开关；浏览（只读）与编辑分离、发布（版本诞生）与编辑（草稿）分离叠加其上；业务用户永远看不到半成品定义，也看不到全量底座（§4.5）。
4. **接得上**：DCT/DOC 元数据→本体的反向导入接线（T5），映射规则以代码为真源，补跨单据关系解析。
5. **不破坏**：旧页面、旧菜单、旧端点零改动；新页面完整体验在门户（UI5 + 全量 datacomp），独立 :8097 提供只读降级。

**非目标（本期不做）**：多人实时协同编辑；按域多草稿；冻结视图（读历史版本对外发布）；旧设计器功能对齐。（全量虚拟化画布原列二期池，经用户裁决**提为正式交付且独立排期**——P4 一期、插于 P3 之后，设计见 §5.3.2。）

## 二、架构总纲（评审定稿浓缩）

### 2.1 场景是过滤器/透镜，不是容器

- **全局底座（om_*）**：对象/关系/接口/共享属性/动作/函数定义**全部唯一**，永不复制。
- **场景视图（om_view，新表）**：只存**成员引用**（对象类型 + 接口的 apiName 清单）+ 画布布局。进入场景看到的是"与场景成员相关的全局元素"——**看到 ≠ 属于**。
- 视图从 DAM 三级自动播种，零人工起步；业务再精修出真正的场景视图。om_view 带 `source: auto|manual`：**auto 视图成员读时按 DAM 现算**（不物化，类型改域自动跟随、零漂移），manual 视图才物化 members。
- **auto 视图生命周期（钉死，防 P1 直写期歧义）**：①**播种 = 读时惰性派生**——GET /views 按 manifest 当前出现的 DAM 域集合现算虚拟条目（不落行）；用户拖动布局时按需 upsert 落行（meta+layout+source=auto，**永不落 members**）；域消失（无任何类型归属）→ 虚拟条目自然消失，无幽灵视图。②**未分组伪域不播种 auto 视图**（会一锅炖收编全部无 DAM 类型，撞软上限且无治理意义）。③auto 视图操作集 = 打开 / 布局编辑 / **「转为手动场景」**；不提供直接删除、重命名、成员编辑——重命名与精修成员先转 manual（UI 弹层提示"转为手动后成员不再随域自动跟随"，确认后物化 members、source 切 manual），删除同理（转 manual 后再删）。
- 解决"重复 vs 臃肿"：同一对象多场景出现 = 多条引用非复制；语义确不同的"同名"概念 = 两个类型 implements 同一接口（建模问题，靠校验兜住）。借鉴 Playground 的"场景化小图"体验，**不采用**它"每图独立本体"的存储。

### 2.2 七类元素归属定稿

| 元素 | 定义位置 | 场景能做什么 |
| --- | --- | --- |
| 对象类型 | 全局 | 引入/移出（引用）、新建（落全局+自动入本场景） |
| 关系 | 全局 | 拉线建（落全局）、按两端在场派生显示、角标补引 |
| 接口 + 共享属性 | 全局 | 引用/新建、画布虚线挂接 |
| 动作 | 全局 | 新建（落全局）；元素库按场景过滤浏览；v2 可精选展示 |
| 函数 | 全局 | 同动作 |

场景权利 = 成员管理、独立布局、派生显示、（v2）展示裁剪——**只策展、不定义**。

### 2.3 边显示规则（定稿）

- 两端对象都在场景成员里 → 画边。
- **仅一端在场 → 默认不画边**；对象卡挂角标"+N"（N 条关系连向场景外），点开列出外部对端，可点击补引。防"孤岛错觉"、保留跨域耦合治理信号，视觉零负担。
- 引入对象弹层两档：「仅此对象」/「连同直接关联（一跳邻域）」。
- 场景里拉线建关系：操作入口在场景，落点仍是全局 `POST /link-types`（P2 后落草稿），语义与现状一致。

### 2.4 草稿/发布双轨（P2 落地）

```
设计者                          消费方
  │
  ▼
om_draft 草稿工作区 ──发布──▶ om_*（已发布真源，表结构零改动）──▶ 场景视图/浏览器/360/实例/API/AI
（单工作区 JSONB+乐观锁）        ▲
  编辑=写草稿                    │
  发布=校验→diff预览→确认        om_version 快照（每次发布自动留痕，rev 去重）
```

- **om_* 保持"已发布真源"**：所有既有消费方读取路径零改动，永不看见草稿。
- 编辑流：新页面画布操作照旧，保存=整体写草稿（P1 过渡期走现有元素级 API，P2 切草稿流）。
- 发布流：校验（命名/铁律/引用检查）→ diff 预览（草稿 vs 已发布）→ 确认 → 原子应用 om_* + 打 om_version 快照 + SSE 广播。**发布 = 版本诞生点**，版本列表即发布历史。**应用含删除**：草稿携带显式 deletions 清单，发布时对清单元素复用元素级删除的既有级联逻辑（接口实现/共享属性解挂），保证 diff 预览与实际一致。
- **基线防覆盖**：om_draft 记 `base_rev`（fork/最近同步时 live 的**内容指纹**——注意比对的是当前 live 快照指纹而非版本表最新 rev，两者在"发布过但 live 被旧设计器直改"时不相等），发布时服务端比对，不一致返回 409 要求先 rebase。**rebase 语义（钉死，防 409 退化为仪式）**：服务端以当前 live 为基线重算"草稿 vs 新 live"的元素级 diff，双方都改过的元素进**冲突清单**逐条裁决，最低限度 rebase 后强制重看 diff 预览并高亮 live 侧变更；草稿行级乐观锁 409（他人改草稿）与 base_rev 409（live 被改）是两个错误源，客户端提示可区分。
- **双轨纪律边界（诚实化）**：双轨仅约束**新页面**的写路径；旧设计器直写 om_* 即时生效且不经评审门，其写路径收口列为旧设计器下线决策的**前置项**（另行立项，不在本方案内）。
- 回滚闭环：restore 版本 = 写进**草稿**（回滚也过校验+发布门，无绕过评审的后门）。①deletions 语义：restore 由服务端计算 `deletions = live 七类元素 − 快照七类元素`（回滚不是并集，live 多出的元素进删除清单），确认弹层展示增/删双向清单；②views 回写：om_draft 增 **views 段**，视图回滚同过发布门；③快照中的 auto 视图只存 meta+layout+source（不物化 members），manual 视图存 members。草稿存在未发布差异时 restore 强制确认弹层。
- **视图写轨对齐（R1 裁决）**：P2 起场景成员与视图元数据（名称/描述）编辑与七类元素**同模式走草稿 views 段**，live om_view 仅由 publish 应用写入（`POST /views` 标注 P2 语义切换：P1 直写 om_view → P2 切草稿段，切换时向导提示；**画布 layout 除外，见下条豁免**）；发布对话框的视图 diff 基线 = **当前 live om_view vs 草稿 views 段**。消除"restore→直接改场景→发布回吞自己/B 的编辑"主线。
- **草稿生命周期（钉死，防 P1→P2 交接丢数据）**：首次 GET /draft 时**惰性 fork**——七类元素 = 当前 live 全量、views 段 = **当前 live om_view 全量拷贝**、base_rev = 当时 live 快照指纹；发布成功后草稿**原子重置为已发布内容**并推进 base_rev。P1 期用 POST /views 直写建立的存量视图留在 live，P2 首次 fork 自然带入草稿——不存在"首次发布 diff 显示删除全部场景"的假变更。
- **views 的删除表达**：场景是小集合，普通发布时 views 段走"**草稿 views 全量 vs live om_view 全量**"整体 diff（live 有、草稿无 = 删除该视图），不引入 per-view deletions 清单；restore 的减法语义（deletions = live − 快照）仅针对七类元素。
- **layout 豁免双轨**：`POST /views/layout`（LWW 直写）**不随 P2 切草稿**，始终直写 live om_view.layout 列——画布布局是纯视觉状态；发布应用 views 段时**保留 live 侧 layout**（草稿 layout 仅作新建视图缺省值），消除"发布回吞他人刚拖的布局"。
- **restore 到无 views 段的历史版本**（P2 上线前的旧版本）：views 段**保留当前 live 场景不动**（旧版本无场景数据 ≠ 删除现有场景），确认弹层明示"该版本无场景数据，场景保持现状"。
- 导入向导写草稿，人审后发布。
- **SSE 受众含消费端**：发布广播不只维护工作台订阅——消费角色打开着的场景页签同样经 `GET /events` 感知刷新（业务用户看到的是已发布真源，发布即其内容更新时刻）。

### 2.5 版本语义

- 快照式整体存储：om_version 一条记录 = 发布时刻的全量 JSONB。**口径定义**：`snapshot` 含七类元素（既有行为）+ `snapshot.views`（场景定义，**可空**——历史旧版本无此段，回看时显式标注"该版本无场景数据"）；**rev 指纹覆盖七类元素 + views 语义字段（名称/描述/成员清单），排除 layout 与审计字段**——纯布局拖动不涨版本，但**视图成员变更必须涨版本并留快照**（否则"只改场景→发布"因 rev 未变被去重分支跳过 INSERT，views 变更失去留痕、事后回滚将回吞已确认的场景变更）。**auto 视图口径**：其永不物化 members，参与指纹的仅名称/描述/source——成员随 DAM 现算不入指纹（DAM 变更已由七类元素侧计入，双重计入反而致冗余版本）。读历史 = 一条查询直接渲染，无跨表拼装。
- xxh64 内容指纹（rev）去重：无实质变更不生成新版本（**仅新端点 `POST /releases/publish`；旧 `POST /publish` 原语义保留、空发布仍涨版本，属旧设计器既有债务**）。**（新增实现项——现状 `store.rs` publish 算完 rev 无条件 INSERT 无比对，P2 补"取最新一条 rev 比对、相同即返回当前版本元数据不插入"分支）**；导入前自动留痕的 summary 用固定文案"导入前自动留痕"、published_by 记操作人，防与人工发布混淆；发布对话框在 rev 未变时明示"无实质变更，本次不产生新版本"。
- 视图跟随**已发布**定义，不钉版（防止"图与实例数据行为撕裂"）；自本方案实施起的新快照含 views 段（历史版本含当时场景划分，回滚视图随滚；旧版本缺段显式处理）。冻结视图列二期。

### 2.6 Palantir 对照与规模论证（要点）

| Palantir Foundry | 本方案 |
| --- | --- |
| Ontology（每租户唯一） | 全局底座 om_* |
| Ontology Manager | 本体工作室·底座目录 |
| Workshop 模块（只绑定不定义） | 场景视图 om_view |
| OSDK（按所选类型生成投影） | `GET /graph?view=X` 成员级装载 |

规模论证：底座是**定义真源**不是**渲染对象**。2000 类型的 manifest 薄清单仅百 KB 级；装载量永远与"正在做的事"（场景成员）成正比、与底座总量无关；日常没有人需要看全图——场景小图 + 域盒折叠 + ⌘K 搜索优先；维护角色的全量浏览诉求由**虚拟化画布**（视口剔除+LOD，§5.3.2）兜底，"看全"从架构负担变为受控能力。真正要拆的只有合规/物理隔离/多租户级别，不是企业内多业务线。

## 三、DCT/DOC 元数据导入设计（代码即真源）

### 3.1 现状与接线方向

- 后端已实现：`POST /import/doc`、`POST /import/dct`（`import_handlers.rs`）+ 纯逻辑映射 `map_doc` / `map_dct`（`cmx-onto-model/src/import.rs:153/233`），**无任何调用方**（全景文档 T5）。
- 接线二选一（全景文档）：push（模型中心 deploy 回调）/ **pull（设计器"从模型中心导入"向导）**。本方案选 **pull**：单向依赖、人审在前、不动模型中心。

### 3.2 映射规则（按 `import.rs` 实况）

**DOC（主从实体图）→ 对象类型 + 嵌套层块（每根实体产一个对象类型）**：

| 规则 | 说明 |
|---|---|
| 根实体 = 对象类型 | 根 = 无入边实体（不作为任何 relation.to）；全成环取首实体兜底 |
| 子实体 = 嵌套层块属性 | 递归折叠：1:N → `array`、1:1 → `struct`；`constraints = {level:true, entity, displayName, children:[...]}`，层中层递归 |
| **不产 LinkType** | 单据内部层次 = 嵌套属性，非对象间关系（"单据层次用嵌套属性"铁律的代码体现） |
| 主键/标题推断 | 指定优先；缺省取首个标量属性 / 同理 |
| 回填 | DAM 三级 + `doc_type`（单据 apiName/displayName）+ `cmx_origin{source:"doc", docApiName, docDisplayName}`；status=Active |

**DCT（字典）→ 参照对象类型 + 种子对象**：

| 规则 | 说明 |
|---|---|
| 参照类型 | `codeProperty`(默认 code) 主键 + `nameProperty`(默认 name) 标题，两属性 |
| 种子对象 | `items:[{code,name}]` 批量种为对象实例（ensure_object_table + put_objects） |
| 回填 | DAM + `cmx_origin{source:"dct", dctApiName}`；doc_type 留空 |

### 3.3 缺口补全：跨单据关系解析（后端增量）

当前 `map_doc` 的 `relations` 仅用于识别**单据内部**父子层级；**跨单据**的对象关系（订单→客户这类外键/引用 → LinkType）尚无解析实现。导入链路后端增强：

1. 引用属性识别：实体属性标注/推断为对另一实体（或 DCT 参照类型）的外键 → 生成 LinkType（cardinality 默认 N:1，role 按"对端实体名小驼峰"命名，可在向导中改）。
2. **"物理外键 ≠ 本体关系，精挑选"**：向导预览阶段逐条勾选要建的关系，默认只勾"语义明确"的引用（名称含对端实体语义/标注为引用的），其余折叠为"候选"。
3. 解析结果与手建关系一样进**草稿**，走发布门。**对端限定**：仅根实体、他单据根实体、DCT 参照类型可作为关系对端——被折叠为层块的子实体不是对象类型，外键指向层块实体不生成 LinkType（该引用已由层块属性表达）。

### 3.4 导入向导流程（新页面功能）

```
入口（底座目录工具栏「从元数据导入」）
 → ① 选源：拉模型中心 DOC/DCT 清单（经门户反代 /api/model 通路；独立态降级为粘贴归一化 JSON）
 → ② 预览映射：将建对象/层块/关系/种子项树状预览 + DAM 归属 + cmx_origin（可调整 DAM/命名/勾选关系）
 → ③ 写入：apiName 已存在者**强制逐条 diff 确认**；应用前**自动打一次发布快照留痕**（防盲写覆盖不可回滚，复用现成 publish）；**向导 P3 上线即写草稿**（双轨 P2 已就绪）；P3 前仅 API 直调场景为 live 直写（§九-10 已知风险）
 → ④ 评审发布：走发布流（校验+diff）
 → ⑤ 一键生成场景视图：成员 = 本次导入对象 + 其直接关联对端，边自动派生显示
```

### 4.5 受众与权限分层（场景=消费、底座=治理）

## 五、千级规模的查找/搜索/使用设计（重点）

### 5.1 装载分层（吸收大图方案 A 阶段结论）

| 层 | 策略 | 支撑端点（新增） |
|---|---|---|
| 清单层 | manifest **恒全量**（薄清单，千级百 KB，大图方案 D1 裁决：影响面计算必须全量真实） | `GET /manifest` 富化（A3：linkTypes 附两端 DAM、interfaces 附实现者清单与 extends 链） |
| 目录层 | 对象目录表格**服务端**过滤+分页（不在前端拉全量详情）；元素库 / ⌘K = **现有清单端点会话缓存 + 前端过滤**（动作/函数/共享属性薄清单千级 KB 级，配虚拟滚动；省三族 q 扩展端点） | `GET /object-types` 扩展 `q/dam/page/size` Query（A2，零破坏，**仅对象目录表格使用**） |
| 详情层 | 按需批量 | `POST /object-types/batch` **已存在（D15：纯数组响应、静默跳过缺失项、ids≤500，旧设计器在用——不改形态）**，新页面按纯数组消费、缺项由客户端比对清单发现；**新增仅 `POST /shared-properties/batch`**（A1，ids≤500，`{items,errors}`） |
| 画布层 | 场景成员级装载（8~30 类型） | `GET /graph?view=X`（服务端组装成员全量定义+共享属性，一条请求） |

### 5.2 搜索三通路（处处可达）

1. **⌘K 命令面板**（全局）：`cmx-floating-dialog` + **前端过滤**，**数据源按角色分流**——维护角色：面板打开时拉一次 manifest（D1 已裁决恒全量、千级仅百 KB）+ 动作/函数清单（现有清单端点）缓存于会话（stale-while-revalidate），本地过滤零请求零防抖；**消费角色：不拉 manifest**，基于已装载的场景成员（GET /graph 已在内存）过滤——既守住"限场景内"承诺（全量底座清单不下发到消费端内存），也不与 P5 读收口（manifest 限维护角色）冲突。五路命中（对象/关系/接口/动作/函数）分类展示（各取前 8 条 + 计数）。命中路由：对象/接口→切上下文并选中定位；关系→**切底座并定位该边（当前场景已含任一端则留在场景内高亮）**；动作/函数→打开元素库定位行。
2. **目录表格**：列过滤 + DAM 树过滤 + 关键字（apiName/displayName contains），全部服务端；`cmx-revo-grid` 虚拟滚动扛千行，`cmx-pager` 分页。
3. **画布内**：选中卡→聚焦模式（一跳邻域，含实现虚线，吸收大图方案 C 阶段，只读）；角标"+N"补引即"以关系找对象"。

### 5.3 画布组件策略与渲染有界化（新建组件，用户裁决 20260910）

#### 5.3.2 全量虚拟化画布（正式交付，独立一期 P4——插于 P3 之后；原列二期池，经用户裁决提级并独立排期）

- **验收**：1000 类型全量视图打开 <3s；平移/缩放帧间隔 p95 <24ms、>50ms 长任务 = 0；视口外节点零渲染（自动化断言）；LOD 三级切换无闪烁抖动。

## 六、功能详细设计

### 6.1 底座目录（content·目录视图，底座上下文；维护角色专属——消费角色不渲染本页签，§4.5）

- 表格列：显示名 / apiName / DAM（域·应用·模块）/ 状态（Experimental/Active/Deprecated tag）/ **被 N 个场景引用**（孤儿标灰提示；**数据源 = GET /views 清单前端计数**，视图为小集合无需后端聚合）/ 来源（`cmx_origin`：doc/dct 图标，hover 显示源 apiName）/ 更新人 / 更新时间（时区转换）。
- 行操作（浏览态）：查看详情、加入场景…；编辑态：编辑、废弃（引用检查后）、从场景移除。**孤儿口径：仅按 manual 场景计数**（auto 视图人人都有，若计入则孤儿恒 0、指标失效）。
- 工具栏：新建对象类型（带归属域预填）/ 从元数据导入 / 导出清单。

### 6.2 场景视图管理（content·场景管理视图）

- 卡片网格：名称/描述/DAM/成员数/更新人/时间；操作：打开（切上下文）、编辑成员、重命名、删除（POST remove，二次确认）。**auto 视图（域默认视图）操作集受限**：打开 / 布局编辑（编辑态拖动落行、浏览态只进本地，§6.3 分轨）/ 「转为手动场景」（弹层确认后物化 members、source 切 manual）；重命名/编辑成员/删除须先转 manual（§2.1 生命周期）。**按角色**：消费角色看到的场景卡片仅"打开"一个动作（纯消费，§4.5）；上述全部写操作仅维护角色可见。
- 新建场景：空白起步 / **从 DAM 域播种**（选域→**拷贝该域当前对象清单生成 manual 快照视图**，与 auto 视图的"读时跟随"语义明确区分——快照后成员不随 DAM 变化）/ 从导入生成。
- 成员编辑：引入弹层（搜索 + 「仅此对象 / 连同直接关联」两档）；移出（影响提示：仅解除引用不删定义）。

### 6.3 场景画布（content·画布视图）

- 成员小图：全卡渲染成员对象 + 两端在场边；角标"+N"补引；拉线建关系（落草稿/落库随模式）；双击节点聚焦（一跳邻域压暗其余，Esc 退出）。**按角色**：消费角色=纯浏览——readonly 画布、角标仅作"还有 N 条关系"的提示（无补引动作）、无拉线/无写入口（§4.5），个人布局拖动只进本地。
- 切换上下文状态机（平移大图方案 §6.2.1）：冲刷挂起落库 → 未保存变更提示 → 清撤销栈 → 切换；编辑态下有未落库错误时阻止切换。
- 布局分轨：**编辑态**拖动布局写 om_view（服务端存，换设备不丢；last-write-wins、不占版本号）；**浏览态**拖动只进本地 localStorage——readonly 下组件本就允许拖动重排，不产生服务端写入口，也避免浏览者之间/与编辑者乐观锁互踩 409。**本地键设计**：`layout:<场景id>:<用户名>`（防共用终端多用户互踩），值携带服务端 layout 的 updated_at 作软失效标记（服务端被维护者调整后本地旧布局提示"布局已更新，重置/保留"二选一，并提供"重置布局"按钮）。

### 6.4 版本与发布中心（工具条入口 → 弹层/页签；维护角色专属，§4.5）

- 版本列表（revo-grid）：版本号/摘要/发布人/时间/rev 指纹；「当前草稿有未发布变更」徽标。
- 快照回看：任选版本 → 新画布页签只读渲染（含当时场景划分；auto 视图的"当时成员"由快照内七类元素的 DAM 数据现算，实现时注明此推导）。
- 对比：任选两版 / 草稿 vs **当前 live**（与 §2.4 base_rev 同基线，消除 live 被旧设计器直改后"最新版≠live"的口径歧义）→ diff 清单（新增/修改/删除的对象·属性·关系·接口·动作·函数·视图，按元素分组着色）。
- 发布对话框：校验结果（可点击定位到元素）+ diff 预览 + 摘要必填 → 发布。**头部标注草稿最近编辑人与时间**（"草稿含非本会话变更，确认后一并发布"——单工作区整体发布单元，防绑发无感知）；**rev 未变时明示"无实质变更，本次不产生新版本"**（§2.5 去重）。
- 回滚：restore 至草稿 → 走发布门。

### 6.5 Inspector（页内右栏）

- 只读：`cmx-desc-list` 分组（基本信息/属性清单/关系两端/实现接口/**动作与函数清单**（参数签名只读——消费角色"使用"场景含理解对象能做什么；运行入口仍在对象浏览器/360）/来源 cmx_origin/引用场景列表）。
- 编辑（编辑态）：`cmx-ui5-form` + CmxColumnModel；对象属性表格沿用设计器既有交互模式（主键/必填/索引/语义类型/层块子属性）。
- 动作/函数详情：参数表（引用反查列表降 v2——对象与动作间无结构化引用字段，见 §5.4）。

### 6.6 命令面板（⌘K / 工具栏按钮）

- 通配入口：搜元素、搜场景、搜版本、执行动作（切上下文/新建对象/打开导入）。第一版先做"搜元素+搜场景"。**范围按角色收敛**（§4.5）：消费角色=场景内元素与场景清单；维护角色=全库元素/场景/版本/命令。

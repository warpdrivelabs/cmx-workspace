# 数据字典：分类 / 分组 / 分级 设计方案

> 目标：为数据字典提供统一的「搜索 + 枚举过滤」能力，支撑三种正交的组织维度——**分类(Classify)**、**分组(Group)**、**分级(Hierarchy)**。
> 本文档只产出元数据 / 字典 / 分类 / 分组的**定义与使用方式**，不涉及具体实现代码。

---

## 1. 三个维度的语义辨析

三者相互正交，可叠加使用，互不冲突：

| 维度 | 本质 | 基数关系 | 取值来源 | 是否分级 | 典型用途 |
|------|------|----------|----------|----------|----------|
| **分级 Hierarchy** | 字典自身的 `id / parent_id` 树 | 一条数据有且仅有一条父路径 | 字典自身 | 是(自分级) | 上下钻取、按子树过滤 |
| **分类 Classify** | 数据的某个/某些属性 | **单选**：每个分类属性下，数据只能属于一个分类值 | 另一个「分类字典」(通常自分级) | 是(分类字典自分级) | 互斥归属、按类目筛选 |
| **分组 Group** | 标签化集合 | **多选**：一条数据可同时属于多个分组 | 另一个「分组字典」 | 是(分组字典可分级) | 跨类目聚合、自定义集合、权限集 |

**一句话区分**：
- 分级 = 我的「血缘」（我从哪来）
- 分类 = 我的「身份」（我是什么，单选、互斥）
- 分组 = 我的「标签」（我被归到哪些集合，多选）

---

## 2. 元数据总览（Meta Schema）

沿用项目现有 `voucher_meta.json` 的 `fieldName / fieldComment / dataType ...` 字段元数据风格，扩展出字典体系所需的几类元数据对象。

### 2.1 字典定义元数据 `dictMeta`

描述「一本字典」本身（一个枚举集合 / 主数据集合）。

```json
{
  "dictMeta": {
    "dictCode": "cost_center",
    "dictName": "成本中心",
    "dictKind": "BUSINESS",
    "selfHierarchy": true,
    "remark": "业务主数据字典，自分级"
  },
  "fields": [
    { "fieldName": "id",        "fieldComment": "字典项主键",   "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
    { "fieldName": "parent_id", "fieldComment": "上级字典项ID", "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
    { "fieldName": "dict_code", "fieldComment": "所属字典编码", "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
    { "fieldName": "item_code", "fieldComment": "字典项编码",   "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
    { "fieldName": "item_name", "fieldComment": "字典项名称",   "dataType": "VARCHAR", "fieldLength": 128, "nullable": false },
    { "fieldName": "full_path", "fieldComment": "物化路径(/分隔)","dataType": "VARCHAR","fieldLength": 512,"nullable": false },
    { "fieldName": "level_no",  "fieldComment": "层级深度(1~N)", "dataType": "TINYINT", "fieldLength": 2,   "nullable": false },
    { "fieldName": "sort_no",   "fieldComment": "同级排序号",   "dataType": "INT",     "fieldLength": 6,   "nullable": false },
    { "fieldName": "status",    "fieldComment": "启用状态",     "dataType": "TINYINT", "fieldLength": 1,   "nullable": false }
  ]
}
```

字段 `dictKind` 三态，决定这本字典扮演的角色：

| dictKind | 含义 | 举例 |
|----------|------|------|
| `BUSINESS`  | 被组织的业务字典（主角） | 成本中心、科目、物料 |
| `CLASSIFY`  | 作为分类维度的分类字典 | 科目类别、物料大类 |
| `GROUP`     | 作为分组维度的分组字典 | 报表分组、专项标签 |

> 注：同一本字典可同时是某场景的 BUSINESS、又作为另一场景的 CLASSIFY——`dictKind` 只描述「主用途」，真正的角色由下面的「分类定义 / 分组定义」关联关系决定。

### 2.2 分类定义元数据 `classifyMeta`

把「业务字典的某个属性」绑定到「一本分类字典」，并声明单选/互斥规则。

```json
{
  "classifyMeta": {
    "classifyCode": "subject_category",
    "classifyName": "科目类别",
    "targetDict": "ac_subject",          // 被分类的业务字典
    "classifyDict": "subject_cat_dict",  // 提供分类取值的分类字典(自分级)
    "bindField": "category_id",          // 业务字典上承载分类的属性字段
    "multiAttr": false,                  // 单选：同一分类下只能归一个值
    "leafOnly": true,                    // 是否只允许挂到分类字典的叶子节点
    "inheritUp": true,                   // 查询时是否按分类字典子树向上归并(选中父类=命中其所有子类)
    "remark": "每个科目只能属于一个科目类别"
  }
}
```

要点：
- **`multiAttr=false` 是分类的核心约束**——保证「数据的某个分类属性只能属于此分类中的一种」。
- 一个业务字典可有**多个 classifyMeta**（多个分类属性，如「科目类别」「核算维度」「现金流量类别」各是一条 classifyMeta），彼此独立单选。
- 分类字典自分级，所以 `bindField` 存的是分类字典的**叶子/某节点 id**，过滤时按分类字典 `full_path` 做子树匹配即可实现「选父类命中全部子类」。

### 2.3 分组定义元数据 `groupMeta`

把「业务字典」与「一本分组字典」建立**多对多**关系。

```json
{
  "groupMeta": {
    "groupSchemeCode": "report_group",
    "groupSchemeName": "报表分组方案",
    "targetDict": "ac_subject",       // 被分组的业务字典
    "groupDict": "report_group_dict", // 提供分组取值的分组字典(可分级)
    "multiValue": true,               // 多选：一条数据可属于多个分组
    "relationTable": "dict_group_rel",// 多对多关联表
    "inheritDown": true,              // 归入子分组时是否自动隶属父分组
    "remark": "科目可同时进入多个报表分组"
  }
}
```

`relationTable`（多对多关联）字段元数据：

```json
{
  "relMeta": {
    "tableName": "dict_group_rel",
    "fields": [
      { "fieldName": "id",            "fieldComment": "关联主键",     "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
      { "fieldName": "scheme_code",   "fieldComment": "分组方案编码", "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
      { "fieldName": "target_item_id","fieldComment": "业务字典项ID", "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
      { "fieldName": "group_item_id", "fieldComment": "分组字典项ID", "dataType": "VARCHAR", "fieldLength": 64,  "nullable": false },
      { "fieldName": "sort_no",       "fieldComment": "组内排序",     "dataType": "INT",     "fieldLength": 6,   "nullable": true }
    ]
  }
}
```

## 3. 三维度的数据落地方式

```
                      ┌────────────────── 业务字典 ac_subject ──────────────────┐
                      │ id  parent_id(分级)  category_id(分类)  ... 其它属性     │
                      └───┬───────────────┬────────────────────┬───────────────┘
       分级(自身树) ──────┘               │                    │
                                          │ bindField 单值      │ 多对多关联表
                       ┌──────────────────▼─────┐     ┌─────────▼──────────┐
                       │ 分类字典 subject_cat    │     │ 分组字典 report_grp │
                       │ (自分级, 单选互斥)       │     │ (可分级, 多选)      │
                       └─────────────────────────┘     └────────────────────┘
```

- **分级**：靠业务字典自身的 `parent_id` + 物化 `full_path`，无需额外表。
- **分类**：靠业务字典上的外键属性字段（如 `category_id`）指向分类字典，**1 个字段=1 个值**，天然单选。
- **分组**：靠独立的 `dict_group_rel` 关联表，一条业务数据可有多行关联，天然多选。

## 4. 搜索与枚举过滤的使用方式

统一查询请求结构（DSL，示意）：

```json
{
  "dictCode": "ac_subject",
  "keyword": "差旅",                    // ① 全文/编码/名称模糊搜索
  "hierarchy": {                        // ② 按分级过滤
    "underId": "1001",
    "includeSelf": false,
    "recursive": true
  },
  "classify": [                         // ③ 按分类过滤(每项单选, 项间 AND)
    { "classifyCode": "subject_category", "valueId": "C-COST", "withSubtree": true },
    { "classifyCode": "cashflow_type",    "valueId": "CF-03" }
  ],
  "group": {                            // ④ 按分组过滤(多值, 可选 AND/OR)
    "schemeCode": "report_group",
    "valueIds": ["G-PNL", "G-TAX"],
    "match": "ANY",                     // ANY=属于任一组 / ALL=同时属于全部组
    "withSubtree": true
  },
  "status": 1,
  "page": { "no": 1, "size": 50 }
}
```

四种过滤的求值规则：

| 过滤项 | 匹配逻辑 | 子树处理 |
|--------|----------|----------|
| `keyword` | `item_code / item_name / full_path` 模糊匹配 | — |
| `hierarchy.underId` | `full_path LIKE '<父path>/%'` | `recursive=true` 走物化路径前缀匹配 |
| `classify[i]` | `target.bindField ∈ {选中分类节点及其子树}` | `withSubtree` → 用分类字典 `full_path` 展开子树 id 集合 |
| `group` | 经 `dict_group_rel` 关联 | `ANY`=IN 命中即可；`ALL`=对每个 group_id 都需存在关联行 |

**整体 = `keyword AND hierarchy AND (classify1 AND classify2 ...) AND group`**，各分类项之间 AND（不同属性叠加收窄），分组内部按 `match` 决定 ANY/ALL。

## 5. 枚举过滤面板的元数据驱动

前端「过滤面板」完全由元数据生成，无需为每本字典写死 UI：

```json
{
  "filterPanel": {
    "dictCode": "ac_subject",
    "facets": [
      { "type": "HIERARCHY", "label": "按层级",   "source": "self",            "widget": "TREE" },
      { "type": "CLASSIFY",  "label": "科目类别", "source": "subject_category","widget": "TREE_SINGLE" },
      { "type": "CLASSIFY",  "label": "现金流量", "source": "cashflow_type",   "widget": "SELECT_SINGLE" },
      { "type": "GROUP",     "label": "报表分组", "source": "report_group",    "widget": "TREE_MULTI" },
      { "type": "KEYWORD",   "label": "搜索",     "source": null,              "widget": "SEARCH_BOX" }
    ]
  }
}
```

- `CLASSIFY` → 单选控件（`TREE_SINGLE` / `SELECT_SINGLE`），对应 `multiAttr=false`。
- `GROUP` → 多选控件（`TREE_MULTI` / `CHECKBOX`），对应 `multiValue=true`。
- `HIERARCHY` → 字典自身树，单选某节点后按子树收窄。
- 每个 facet 自带「计数(facet count)」可选项：聚合各分类/分组下命中条数，用于显示徽标。

## 6. 关键设计约束小结

1. **分类单选互斥**由 `classifyMeta.multiAttr=false` + 业务字典单值外键字段双重保证。
2. **分组多选**由独立关联表 `dict_group_rel` 承载，不污染业务字典宽表。
3. **分级**统一用 `parent_id` + 物化 `full_path`，分级/分类字典/分组字典三者都复用同一套自分级结构，过滤一律走「路径前缀」实现子树展开。
4. **可叠加**：分级、分类(多属性)、分组(多方案) 任意组合，最终以 AND 收窄结果集。
5. **元数据驱动**：新增一本字典或一个分类/分组维度，只需新增 `dictMeta / classifyMeta / groupMeta` 配置，搜索与过滤面板自动生效，无需改代码。

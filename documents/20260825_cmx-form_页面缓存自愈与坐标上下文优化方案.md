# 页面缓存自愈与设计器坐标上下文优化方案（C6 / C7）

> 状态：已实现（C6/C7 全部落地，2026-08-25 验收通过）· 日期：2026-08-25 · 作者：ox-alpha 会话整理
> 涉及仓库：`cmx-container`（后端 Rust）、`cmx-html-designer`（设计器）、`cmx-portal-manager`（门户）
> 前置知识见 §1 背景；两个问题相互独立，可并行开发， **建议 C7 先上**（后端一处改动全局生效）。

## 1. 背景：资产模型与坐标注入链（必读）

### 1.1 两条正交轴（已定论，勿混淆）

| 轴 | 载体 | 用途 |
|---|---|---|
| **资产归属** | 页面 id 前缀（`portal.model.*` → model 服务、`portal.rpt.*` → report…） | 门户按 id 路由读/写（读扇出 batch、写反代 F3-save）；判定函数 `owner_service_of` |
| **业务取数坐标** | html 分片**行字段** `domain / app / module / doc`（如 `fi / cmxfico / gl / null`） | 运行时数据源定位，经 enrich 注入 `host.$coord` |

### 1.2 坐标注入链（前端）

```
batch 响应行(id,domain,app,module,doc,rev,html)
  → workspace-html-pages.js putPages() 写 IndexedDB page-cache（键=id，值={rev,source,domain,app,module,doc}）
  → 差异同步命中时（本地 rev === 服务端 rev）跳过 body，坐标从 IndexedDB 旧记录「原样恢复」   ← C7 问题放大器
  → enrich 注入 host.$coord
  → init-page-models.js _buildLoadDef() 展开 ...host.$coord + ...source + doc:moduleCode
```

关键文件：
- 后端 rev 计算：`cmx-container/crates/libs/cmx-form/src/pages/html.rs`、`pages/native.rs`、`serve/loader.rs`
- 前端缓存：`../cmx-portal-manager`（IndexedDB）、`lib/workspace-html-pages.js`（batch/diff 同步）

## 2. C7：行字段纳入 rev → 缓存自愈

### 2.1 问题

**现象**：服务端修改某页分片行的 `domain/app/module/doc/name/details/relPath`（不动 html 内容）后，已打开过该页的浏览器**永远拿旧坐标**，直到用户手动清站点数据。历史上真实发生过：id 统一改名轮次中批量修正了 81 行坐标，受影响浏览器全部残留污染坐标。

**根因**：rev（前端缓存校验锚点，xxhash64→16hex）**只哈希源码内容**：

| 位置 | 读路径 | 现状代码 |
|---|---|---|
| `crates/libs/cmx-form/src/pages/html.rs:289` | 门户本地 html 全量读 `read_full_from_row` | `let rev = content_rev(html.as_bytes());` |
| `crates/libs/cmx-form/src/serve/loader.rs:214` | 引擎侧 html 全量读 `load_html_full`（model/flow/rule/mdm 走此路径） | 同上 |
| `crates/libs/cmx-form/src/pages/native.rs:190` | 门户本地 native 全量读 | `content_rev(source.as_bytes())` |
| `crates/libs/cmx-form/src/serve/loader.rs:111` | 引擎侧 native 全量读 `load_native_full` | 同上 |

配合前端 `workspace-html-pages.js`（约 185-200 行）：diff 命中时注释明确写「差异同步命中缓存时需原样恢复，供 enrich 注入 host.$coord」——即坐标不参与失效判定。

### 2.2 改造方案

把行字段的 canonical 串拼进哈希输入，4 处统一替换：

```rust
/// canonical 串：固定字段顺序，`\u{1F}` 分隔，缺失字段一律空串。
/// html 版参与字段：domain|app|module|doc|name|details|relPath
/// native 版参与字段：name|details|sourceType|relPath
fn content_rev_with_meta(fields: [&str; N], source: &str) -> String {
    let mut buf = String::new();
    for f in fields { buf.push_str(f); buf.push('\u{1F}'); }
    buf.push_str(source);
    content_rev(buf.as_bytes())
}
```

- `read_full_from_row`（html.rs）：`content_rev_with_meta([domain, app, module, doc, name, details, rel_path], &html)`
  - 字段全部取自行 row，注意 `doc` 可能为 `null` → 归一为空串
- `load_html_full`（loader.rs）：同上，字段来自 `HtmlRow` 结构体字段
- `load_native_full` / native.rs 对应处：`[name, details, source_type, rel_path]` + source

**约束**：
- 不要把 html/source 拼进 canonical 函数又单独传 source，避免重复哈希
- rev 输出格式不变（16hex），前端零改动
- 新增 helper 放在 `crate::cache`（content_rev 所在模块）并补单测

### 2.3 影响面

- **部署后一次性全量重拉**：所有客户端 rev 失配 → 重拉 body → 写回新坐标。这正是期望行为（顺带治愈存量污染缓存），无需迁移脚本。
- ETag 语义更严格：行元数据变更现在会正确失效。
- 无协议变更：`{pages, revs, errors}` 信封、clientRevs 机制均不动。

### 2.4 验收标准

1. **单测**（加在 `cmx-form`）：
   - 同一 html、不同 `domain/app/module` → rev 必不同
   - 字段与内容完全一致 → rev 稳定（幂等）
   - `doc=null` 与 `doc=""` 的 canonical 等价（归一验证）
2. **E2E**（本地起 portal 8080 + 任一引擎）：
   - `POST /api/html-pages` 只改 `name`（html 原样提交）→ 下一次带旧 rev 的 `clientRevs` batch 请求必须返回该页 body（判定为已变更）
   - 改回原值 → 再次请求返回 `errors`/未变更（幂等回归）
3. `cargo test -p cmx-form` 全绿（现存 17 例不回归）；`cargo check -p cmx-portal-server -p cmx-flow-server -p cmx-rule-server -p cmx-model-server` 通过（loader.rs 被多仓引用）。

## 3. C6：设计器坐标从上下文取，不从 id 猜

> 既定原则：**页面尽可能从上下文取 DAM，而不是解析页面 id**。运行时代码此前已全量排查无「从自身 id 解析坐标」残留（init-page-models 已用 `$coord`）；本节只解决**设计器写入侧**的三个缺口。

### 3.1 缺口①：设计器加载已有页时丢弃坐标

**现状**：`../cmx-html-designer` `_openPageByIdFromUrl()`（约 213-228 行）把 `getHtmlPage(id)` 响应存进 `_exportPageMeta`，但只保留 `id/name/details/latestHtmlFile/timestamp` —— 响应里明明有 `domain/app/module/doc`（后端 `read_full_from_row` 返回全量行）却被扔掉。保存载荷因此不带坐标，只能依赖引擎「既有行回退」兜底。

**改造**：
1. `_exportPageMeta` 增加 `domain/app/module/doc` 四个字段（加载时透传保存）
2. 保存载荷组装处（`src/components/designer-app/designer-server-export.js`，搜 `domain:` 的 POST body 构造，约 119-135 行附近）按以下**优先级**合并：
   ```
   三下拉显式值(selDomain/selApp/selModule 有值) > _exportPageMeta 坐标 > 不传（留空走引擎回退）
   ```
3. `getHtmlPage` 的 JSDoc 返回类型注释（`src/api/html-pages-api.js:42-44`）补上这四个字段

### 3.2 缺口②：门户打开设计器不带业务上下文（根治点）

**现状**：门户入口 `../cmx-portal-manager`：

```js
const url = new URL(`/html/?id=${encodeURIComponent(pageId)}`, window.location.origin).toString()
```

新建页场景没有 pageId，设计器三下拉全空；用户在高级模式手敲 `portal.model.gl.xxx` 就触发了「id 推导出 portal/model 坐标」的污染路径。

**改造**：
1. **门户侧**：构造 URL 时追加当前 workspace/explorer 树节点的 DAM 上下文：
   ```js
   const url = new URL(`/html/?${params}`, origin)
   // params: id(可选) + domain + app + module（取当前选中节点所属业务域，无则为空串不传）
   ```
   注意排查是否还有其他打开设计器的入口（目前检索仅此一处 `/html/?`），如有同步补参。
2. **设计器侧**：`designer-app.js` `_readPageIdFromUrl()`（约 200 行）旁新增 `_readDamFromUrl()`，读 `domain/app/module` query 参数；在导出条初始化时预填 `selDomain/selApp/selModule`（复用现有 fillSelect 流程；高级模式同样预填但不锁定，用户仍可改）。
3. 新建页默认继承「用户当前所在业务位置」——从根上消除裸建场景。

### 3.3 缺口③：高级模式新建页护栏

**现状**：`designer-server-export.js` 的 `composeIdFromParts()` 在高级模式直接跳过（chkAdvanced.checked 时 return），id 由用户手工输入；保存时不校验坐标完整性 → 引擎 `save.rs` 三级回退落到最末级「id 推导」，产出 `domain=portal/app=model` 的污染行。

**改造**（保存前置校验，放在 save payload 组装后、fetch 前）：

```
阻断条件（同时满足才拦）：
  a. id 命中属主前缀表（见下）且非编辑已有页（无法确认既有行时一律按新建处理）
  b. 三下拉与 _exportPageMeta 坐标均为空

行为：阻断提交，toast 提示「请先选择业务域(DAM)坐标或切换普通模式」，焦点移到 Domain 下拉。
```

**属主前缀表**（与后端两处路由表对齐，若后端后续扩表需同步）：
- `portal.model.`（model）、`portal.flow.`（flow）、`portal.rule.`（rule）、`portal.rpt.`（report）、`portal.consol.`（report）、`portal.mdm.`（mdm）
- 后端权威定义：`cmx-common-api/src/handlers/portal/pages.rs::owner_service_of` + `cmx-rpt-api/src/proxy.rs::is_report_owned_page`

**不做**：不给普通模式加任何新交互（三下拉本来就有）；不强制老页面编辑补坐标（缺口①已保证带回）。

### 3.4 引擎侧

`save.rs` 三级回退（显式入参 > 既有行 > id 推导）已就绪，**本方案不改任何后端保存逻辑**。C7 上线后即使出现个别推导行，修复行字段也会自愈传播。

### 3.5 验收标准

1. 编辑已有页：URL 打开 `?id=portal.model.gl.voucher` → 导出条三下拉自动带出 fi/cmxfico/gl（缺口①生效）；保存后引擎分片行坐标不变
2. 从门户树节点（如 总账/gl）打开设计器新建页：三下拉预填当前 DAM；拼出的普通模式 id 前缀正确（缺口②）
3. 高级模式裸敲 `portal.model.gl.foo` 且无坐标 → 保存被阻断并有提示（缺口③）
4. `npm test -w cmx-html-designer`（~108 例）与 `npm run lint` 不回归；`npm run build -w cmx-html-designer` 通过
5. 手动联调走一遍：新建→保存→`GET /api/html-pages/batch` 验证行坐标为业务坐标而非 portal/model

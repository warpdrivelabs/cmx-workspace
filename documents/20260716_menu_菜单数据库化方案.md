# 菜单数据库化方案

> 日期：2026-07-16
> 范围：cmx-container（后端）+ CMXPortalManager（前端）
> 状态：设计已与用户确认，待转入实施计划

---

## 一、背景与目标

当前门户菜单以 JSON 文件形式存放在 `cmx-container/data/menu-pages/**/*.json`，后端 `GET /api/menu-pages?menu=<menuRef>` 只读加载，前端 CMXPortalManager 侧栏消费。菜单无法在界面上增删改，只能手编 JSON。

后端已有完整的菜单数据库实体 `cmx_menu`（表 + `/api/menu/*` CRUD + 树形 service），但与 menu-pages 文件是两套并行体系，未打通。

**目标**：

1. 菜单数据**仅存数据库**（`cmx_menu` 表），不再读写文件。
2. CMXPortalManager 新增树形 CRUD 管理页（参考 cmx-portal `sysmenu/index.vue`）。
3. 复用已有"编辑菜单节点"弹框，使其编辑结果落库到 `cmx_menu`。
4. 提供 SQL 迁移，将现有 menu-pages 文件数据导入 `cmx_menu`。

---

## 二、现状分析

### 2.1 两套菜单体系

| 维度 | A. `cmx_menu` 数据库实体 | B. `menu-pages` 文件文档 |
|------|------------------------|------------------------|
| 存储 | PostgreSQL 表 `cmx_menu` | `data/menu-pages/**/*.json` |
| 接口 | `/api/menu/*`（create/get/update/delete/list/page/tree，完备） | `/api/menu-pages`（仅 GET 只读） |
| 粒度 | 树形节点行 + `definition` JSONB 透传字段 | 整文档（`{version, items:[...]}`），节点含 `workspace`/`dialogspace` 富布局 |
| 前端消费 | cmx-portal `sysmenu` 管理页 | CMXPortalManager 侧栏（`loadMenuPagesMenu` 只读） |

### 2.2 关键事实

- **一模块一菜单文件**：`data/menu-pages/<domain>/<app>/<module>/<filename>.json`，模块下仅一份。故 `domain_code/application_code/module_code` 三级即可定位一份菜单，无需额外文档标识列。
- **menuRef 寻址**：点分 `fi.cmxfico.gl.explorer-menu`，前 3 段 = domain/app/module，第 4 段 = 文件名（仅寻址用，不入库）。
- **现有文件**：`fi/cmxfico/gl/explorer-menu.json`（gl 模块）、`fi/cmxfico/report/report-menu.json`（report 模块）。report-menu 是 explorer-menu 的精简副本。
- **重复 code**：两文件共享 7 个顶层组及其子树：`grp-ignite-demo`、`grp-meta-def`、`grp-pages`、`portal-dam-registry`、`grp-components`、`grp-services`、`grp-data`。code 全局冲突。
- **已有编辑弹框**：`../cmx-portal-manager`，由侧栏右键"编辑菜单节点"触发（`portal-side-nav-menu.js:402-471` → `portal-app.js:553-562`）。编辑节点的 `workspace` 富布局（9 区域 + 多视图 + html/native 页面）+ 元信息（id/name/icon/details）。当前 `_save()` 调 `POST /api/workspace-nodes`（独立文件存储）， **不回写菜单节点**。
- **`/api/workspace-nodes`**：cmx-container 已实现（`portal/handler.rs:196-237` + `cmx-portal/src/meta/workspace_nodes.rs`），文件存储，独立于菜单，**本次不在范围**。

## 三、已确认决策

| 项 | 决策 |
|---|---|
| 存储模型 | 节点级映射到 `cmx_menu`（每节点一行，富数据入 `definition` JSONB） |
| 存储 | 仅数据库，不读写文件；现有文件保留备份不删 |
| 文档定位 | 不加 `menu_ref` 列，按 `domain_code/application_code/module_code` 三级定位 |
| code 唯一性 | 保持全局唯一（不动 `uk_cmx_menu_code` 索引）；迁移 SQL 处理重复 |
| 重复处理 | report-menu 与 explorer-menu 冲突的 code 追加 `_rpt` 后缀 |
| 接口 | `/api/menu/*` 全复用，不改；`/api/menu-pages` 改 DB 回源 |
| 编辑弹框 | 右键菜单节点入口的保存改走 `/api/menu/update`，写回 `cmx_menu.definition` |
| 重建文档 | `/api/menu-pages` 返回的节点嵌入 `_cmxId`（cmx_menu 主键），供弹框定位更新 |
| 迁移 | 脚本读取菜单文件生成 INSERT SQL（透明可核对） |

## 四、数据模型与字段映射

### 4.1 表结构

`cmx_menu` 表不动（不加列、不改索引）。复用现有字段：

- 归属：`domain_code` / `application_code` / `module_code`（从 menuRef 前 3 段解析）
- 树形：`parent_id` / `code_path` / `id_path` / `depth` / `leaf`（由 `MenuService` 计算）
- 元信息：`code` / `name` / `icon` / `fun_code` / `sort_order` / `visible` / `open_type` / `status`
- 富数据：`definition`（JSONB）

### 4.2 字段映射（menu-page 节点 ↔ cmx_menu 行）

| ExplorerMenuNode 字段 | cmx_menu 列 | 说明 |
|---|---|---|
| `id` | `code` | 节点 id → 业务 code（全局唯一） |
| `caption` | `name` | 显示文案；字符串直接入 `name`，i18n 对象取默认值入 `name`、原对象入 `definition.caption` |
| `icon` | `icon` | |
| `permissionId` | `fun_code` | 权限关联 |
| `children` | `parent_id` 树 | `sort_order` 取数组下标 |
| `workspace` | `definition.workspace` | JSONB 富布局 |
| `dialogspace` | `definition.dialogspace` | JSONB |
| `expanded` / `type` / `name`(内部名) | `definition.*` | 透传 |
| `selected` / `dirty` | 丢弃 | 运行时态 |
| — | `path` / `component` / `open_type` / `visible` / `status` | 默认值（visible=1, status=1, open_type=0，其余 null） |

`definition` 结构约定（可逆，用于 `/api/menu-pages` 重建）：

```json
{
  "caption": "<原 caption 原值，字符串或 i18n 对象>",
  "workspace": { ... },
  "dialogspace": { ... },
  "expanded": true,
  "type": "workspace-node",
  "name": "<内部 name>"
}
```

## 五、后端接口（全复用）

`/api/menu/create`、`/get`、`/update`、`/delete`、`/list`、`/page`、`/tree` **原样复用**，无需改造：

- `tree` 已支持按 `domain_code/application_code/module_code` 过滤，CRUD 页直接用。
- `create` 时由调用方传 `domain_code/application_code/module_code`（CRUD 页从选中的模块上下文带入）。
- `update` 接收 `{id, data}`，`id` 为 cmx_menu 主键；弹框用嵌入的 `_cmxId` 调用。

`/api/workspace-nodes` 不动（范围外，保持文件存储）。

## 六、`/api/menu-pages` DB 回源改造

### 6.1 改造点

`cmx-portal/src/meta/menu_pages.rs` 的 `get_menu_page_json` 重构读取分支：

- `dam:` 前缀 → 保留现有 DAM 派生逻辑（从 DAM 注册表 + manifest 合成，不依赖文件）。
- 点分 menuRef → **改为查 `cmx_menu`**：
  1. 解析 menuRef 前 3 段为 `domain/application/module`（第 4 段及以后忽略）。
  2. `SELECT * FROM cmx_menu WHERE domain_code=$1 AND application_code=$2 AND module_code=$3 AND archived=0 ORDER BY sort_order`。
  3. 按 `parent_id`/`sort_order` 组树。
  4. 用 `definition` 还原 `workspace/dialogspace/caption/expanded/type`，输出 `{version:1, source:"db", items:[...]}`，结构与原文件一致。
  5. **每个节点嵌入 `_cmxId`**（cmx_menu 主键 `id`），供编辑弹框调用 `/api/menu/update` 定位。侧栏显示 id 仍用 `code`，前端零改动。
- 文件直读分支（`parse_menu_ref` → `read_json`）删除。

### 6.2 联动改造

- `cmx-portal/src/launcher/mod.rs`：当前直接读 menu-pages 文件（`menu_ref_to_path` + `read_json`）。改为调用上述 DB 回源函数；`MENU_REFS` 硬编码枚举保留（或改为 `SELECT DISTINCT domain_code,application_code,module_code`）。
- `cmx-biz/src/dam_asset_service.rs`：`menu-pages` DAM 树根保留（目录管理用），但不再作为菜单数据源。

### 6.3 兼容性

- CMXPortalManager 侧栏 `loadMenuPagesMenu` → `/api/menu-pages`，URL/参数/响应结构不变，数据源透明切换到 DB。
- 短 menuRef（<3 段，无 domain/app/module）：当前 cmx-container 数据无此情况，DB 回源不支持，返回 not_found。

## 七、已有编辑弹框落库改造

### 7.1 改造目标

`portal-workspace-node-dialog.js` 的 `openWithNode(node)`（右键菜单节点入口）改为**菜单节点模式**：保存时写回 `cmx_menu`，而非 `/api/workspace-nodes`。

### 7.2 改动点

- `openWithNode(node)`：设模式标记 `this._mode = 'menu-node'`，记录 `this._cmxId = node._cmxId`。
- `_save()`：当 `_mode === 'menu-node'` 时，改为调 `POST /api/menu/update`，body：
  ```json
  {
    "id": "<node._cmxId>",
    "data": {
      "name": "<name>",
      "icon": "<icon>",
      "definition": {
        "caption": "<caption>",
        "workspace": { ... },
        "dialogspace": { ... },
        "details": "<details>",
        "expanded": true,
        "type": "workspace-node"
      }
    }
  }
  ```
  把 workspace 写回该 cmx_menu 行的 `definition`。
- `open(id)`（`workspace-node-editor` 类型入口）保持原 `/api/workspace-nodes` 路径不变（范围外）。
- 弹框内编辑能力（区域/视图/html-native 页面选择/JSON 源码 Tab）全部保留，仅改保存目标。
- 新增 API 封装 `src/api/menu-api.js`（基于 `api-client.js`）：`updateMenu({id, data})` 等。

## 八、新增 CRUD 管理页（CMXPortalManager）

参考 cmx-portal `packages/sys-core/src/sysmenu/index.vue` 的交互，用 UI5 WebComponents + Lit 实现。

### 8.1 新增 API 封装

`src/api/menu-api.js`（基于 `api-client.js`）封装 `/api/menu/*`：`getTree({domain_code,application_code,module_code})`、`create`、`update`、`delete`、`get({id})`、`page`。

### 8.2 管理页布局

新工作区节点，注册到活动栏/setting-menu 增「菜单管理」入口：

- **左**：domain→app→module 级联选择器 + `ui5-tree`（按选中模块调 `/api/menu/tree` 加载树，懒加载子节点）。
- **右**：节点表单（`ui5-form` / dialog）：`code`、`name`(caption)、`icon`、`fun_code`、`sort_order`、`visible`、`open_type`、`parent`（只读展示）。**不含 workspace**。
- **操作**：新增子节点、编辑、删除（非叶子禁删，复用后端校验）、拖拽排序（调 `update` 改 `sort_order`/`parent_id`）。
- **右键节点**：可调起 §7 的 workspace 编辑弹框。

### 8.3 技术栈说明

cmx-portal 是 Vue，CMXPortalManager 是 UI5/Lit。**交互参考、技术栈按 CMXPortalManager 既有模式实现**，不直接移植代码。

## 九、迁移 SQL

用一次性生成脚本读取菜单 JSON 文件，展平树并计算树形字段，输出透明可核对的 INSERT 语句。产出：

- 生成脚本：`cmx-container/scripts/gen_menu_migration.mjs`（Node，JSON 处理直观；读取 `data/menu-pages/**/*.json`）
- 迁移文件：`docs/sql/migrations/<日期>_001_menu_pages_to_cmx_menu.up.sql`（INSERT 语句）+ `.down.sql`（DELETE）
- `init_ddl.sql` 本次表结构无变更，无需改

### 9.1 生成脚本逻辑

1. **读取**：`data/menu-pages/fi/cmxfico/gl/explorer-menu.json`（gl 模块）、`data/menu-pages/fi/cmxfico/report/report-menu.json`（report 模块）。
2. **递归展平**：遍历 `items` -> `children`，逐节点产出字段：
   - `code` = 节点 `id`
   - `parent_code` = 父节点 code（顶层为 null）
   - `sort_order` = 数组下标
   - `name` = `caption`（字符串直接用；i18n 对象取默认值），原 `caption` 入 `definition.caption`
   - `icon` / `fun_code`（= `permissionId`）
   - `definition`（JSONB）= `{caption, workspace, dialogspace, expanded, type, name(内部名)}`
   - `domain_code/application_code/module_code` = menuRef 前 3 段
3. **树形字段计算**（脚本内完成）：
   - `depth`：根=1，子=父+1
   - `code_path`：`/` + 祖先 code 用 `/` 拼接
   - `id_path`：同 code_path 但用确定式 id
   - `leaf`：无子节点=1，否则=0
   - `parent_id` = 父节点确定式 id
4. **确定式 id**：`<domain>.<app>.<module>/<code>`（迁移期确定式，便于算 id_path；运行时新建节点仍用雪花 id，互不冲突，因 id 为 VARCHAR）。
5. **重复 code 处理**：先处理 explorer-menu（code 原样）；再处理 report-menu，与已生成 code 冲突的追加 `_rpt` 后缀，子节点 `parent_code`/`parent_id` 跟随父节点重命名同步。
6. **输出 INSERT**：每个节点一条 `INSERT INTO cmx_menu (...) VALUES (...)`，附 `ON CONFLICT (code) DO NOTHING` 保证幂等可重跑。
7. **down.sql**：`DELETE FROM cmx_menu WHERE domain_code='fi' AND application_code='cmxfico' AND module_code IN ('gl','report')`。

### 9.2 INSERT 语句示例

```sql
INSERT INTO cmx_menu
  (id, code, name, icon, fun_code, sort_order, definition,
   domain_code, application_code, module_code, parent_id, parent_code,
   depth, leaf, code_path, id_path, visible, status, open_type, archived,
   create_time, update_time)
VALUES
  ('fi.cmxfico.gl/gl', 'gl', '基础数据管理', 'tree', NULL, 1,
   '{"caption":"基础数据管理","expanded":true}'::jsonb,
   'fi', 'cmxfico', 'gl', NULL, NULL,
   1, 0, '/gl', '/fi.cmxfico.gl/gl', 1, 1, 0, 0,
   now(), now())
ON CONFLICT (code) DO NOTHING;
```

> 完整 INSERT 集由脚本生成，逐条可核对；脚本本身作为可重跑工具保留在 `scripts/`。

## 十二、风险与回滚

| 风险 | 应对 |
|---|---|
| `/api/menu-pages` 重建文档与原文件结构不一致，侧栏/launcher 异常 | 迁移后对比 DB 重建输出与原文件 diff；保留文件备份可即时回滚读取分支 |
| 重复 code 重命名后影响节点引用（tab id 等） | report-menu 节点 id 加 `_rpt` 后缀，影响仅限 report 模块菜单；迁移前核对引用 |
| 编辑弹框保存目标切换破坏现有 workspace-node 流程 | 仅改 `openWithNode` 路径；`open(id)` 路径不变，独立测试 |
| 迁移 INSERT 树形字段算错（path/depth/leaf） | 生成脚本输出后核对若干节点 path/depth；`ON CONFLICT DO NOTHING` 可重跑；down.sql 可清理重导 |

**回滚**：down.sql 清理迁移数据；`/api/menu-pages` 读取分支保留文件回退开关（或 git revert 读取改造）。

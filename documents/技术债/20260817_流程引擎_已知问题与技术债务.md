## 附：多副本部署结论（008 汇总，2026-09-03 按事件订阅重构后代码刷新）

**执行内核已多副本安全**：

- **定时器抢占**：`acquire_due_jobs` `FOR UPDATE SKIP LOCKED` + `claimed_by`/`lease_expires_at` 60s 租约（到期可重抢）+ worker id `timer-{pid}`；触发保存遇 CAS 冲突（他副本已推进）即放弃本批。
- **实例并发写**：`cmx_flow_instance.version` 乐观锁 CAS（`WHERE id AND version`，0 行命中整体回滚），冲突 409 `CONCURRENCY_CONFLICT` 不自动重试。
- **事件订阅投递**（20260903 重构后）：`cmx_flow_event_delivery` outbox 租约抢占（SKIP LOCKED + `locked_by`/`lock_expires_at` + DB 时钟）+ 持有者守卫（finish/renew 均校验 `locked_by`）+ 逐行续租 + 同订阅 seq 保序（小 seq 未终态行阻塞 + 组内排序串行）——at-least-once，多副本正确；路由缓存 TTL 5s + 三表指纹对账，跨副本 ≤5s 收敛。
- **异步 Job 抢占**：`acquire_async_jobs` 同款 SKIP LOCKED。
- **retention 清理**：按状态/时间条件幂等删除 + LIMIT 批处理，多副本并发仅重复空扫描，天然可重入。
- 数据源懒注册、配置/连接快照各副本独立等价，无碍。

**仍有障碍（横向扩展前须补）——✅ 已随 R4 全批次消除（2026-09-03）**：

1. ~~定义/决策表热装载只进本进程~~ → R4.2 pubsub 失效广播 + 指纹轮询兜底（双副本 E2E 场景 A 实证：即时生效 + 无 Redis 纯轮询 ≤6s 收敛）；

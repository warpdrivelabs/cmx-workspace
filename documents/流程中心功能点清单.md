# 流程中心功能点清单与使用场景

> 版本：V1.0　　
> 适用系统：流程中心（符合 BPMN 2.0 规范）

---

## 0. 文档说明

### 0.1 编写目的

本文档按"功能点"为粒度，列出流程中心的全部功能，并为每个功能点给出四项内容：**功能描述、详细使用、使用场景、开发要点**。可以按功能点编号逐一开发，每个功能点都是一个可独立交付的开发单元。

### 0.2 阅读约定

- 功能点按模块分组编号：A 流程设计、B 流程审批运行时、C 流程运维、D 流程监控、E 系统集成与配置。如 `A3` 表示流程设计模块第 3 个功能点。
- 每个功能点的四项内容含义：
  - **功能描述**：这个功能解决什么问题，做什么事。
  - **详细使用**：用户怎么操作、怎么配置、关键参数含义、入口路径。
  - **使用场景**：什么业务情况下会用到，典型用例。
  - **开发要点**：开发时必须实现的关键规则、边界条件、异常处理、与其他功能点的联动关系、校验规则。
- 文中出现的"主流程""子流程""节点""边""实例""任务""待办""会签"等术语，含义见 0.3。

### 0.3 术语

| 术语 | 含义 |
|---|---|
| 流程定义 | 在设计器中绘制并保存的流程图，对应一个可被发起的流程模板 |
| 流程实例 | 一张单据发起后产生的运行实例，全局唯一 |
| 任务（待办） | 流程实例流转到某节点后生成、等待审批人处理的事项 |
| 节点 | 流程图中的任务节点，编号 `S_x`，系统自动生成不可编辑 |
| 边 | 节点间的连接，编号 `R_x`，可挂分支条件 |
| 制单人 | 单据的发起人、创建人 |
| 主流程 | 一张单据对应的完整审批主干流程 |
| 子流程 | 挂在主流程"子流程边"上、按组织机构差异化的分支流程 |
| 或签 | 节点多人中任意一人审批即通过 |
| 串行会签 | 多人按顺序依次审批，全部通过才通过 |
| 并行会签 | 多人同时收到待办，全部通过才通过 |
| 票签 | 并行会签 + 权重投票，累计通过权重大于阈值即通过 |
| 加签 | 事前加签：A 加签 B，B 审完回 A；事后加签：A 加签 B，B 审完节点即过 |
| 转签 | A 将任务转给 B，B 审完进入下一节点 |
| 排他边 | 当其他出边条件都不满足时的兜底边 |
| 子流程边 | 主流程上标记"子"的边，可挂接子流程 |
| 虚拟节点 | 无需审批人、自动提交、退回/取回可跳过的节点 |
| 重点人员 | 命中重点人员清单时暂停待办，待运维确认后再放行 |

### 0.4 BPMN 2.0 元素对应

| BPMN 2.0 元素 | 本系统实现 |
|---|---|
| StartEvent | 开始节点（流程唯一） |
| UserTask | 任务节点 `S_x` |
| EndEvent | 结束节点（流程唯一） |
| SequenceFlow | 边 `R_x` |
| ExclusiveGateway | 排他边（边级条件互斥兜底） |
| CallActivity / SubProcess | 子流程（挂在主流程"子流程边"上，按组织机构差异化） |
| BoundaryEvent / Timer | 节点超时设置 |
| MessageEvent | 消息事件（启动/结束/终止/进入/离开） |
| TextAnnotation | 文本批注 |

## 2. 流程设计模块功能点

### A1. 流程分组管理

**功能描述**

对流程按业务域分组归类，方便流程管理员分类查找和管理。一个分组下可挂多个流程，分组按排序号展示。

**详细使用**

- 入口：流程管理 → 主流程设计 → 左侧分组树。
- 查看分组树：左侧树形展示当前系统下全部分组，按排序号正序排列；进入页面默认选中首条分组。
- 编辑分组：点击左上角"编辑"打开分组管理弹窗。
  - 新增：点击新增行，填写分组名称（必填），确定保存。
  - 上移 / 下移：调整分组排序，保存后树形顺序立即生效。
  - 删除：点击删除按钮，二次确认后删除。
- 字段：分组名称（必填）、排序号。

**使用场景**

- 财务类流程（报销、付款、借款）归入"财务共享"分组，HR 类流程（入职、调薪、请假）归入"人力资源"分组，便于按业务条线定位。
- 集团多业务线场景下，按事业部划分分组，各事业部管理员只维护本部分组。

**开发要点**

- 分组按"所属系统"过滤，只展示当前系统下的分组，分组类型固定为 flow。
- 删除分组前需校验该分组下是否存在流程；存在则提示用户先迁移流程或阻止删除（二选一，由开发方决定并文档化）。
- 排序号变动需级联更新，保证树形展示与存储顺序一致。
- 分组名称在同一系统内建议唯一，至少不能为空。

### A2. 主流程列表管理

**功能描述**

在选定分组下管理主流程列表，支持查询、启用/停用、创建副本、按年归档。这是进入主流程设计器（A3）的入口。

**详细使用**

- 入口：流程管理 → 主流程设计 → 右侧主流程列表。
- 加载：选中左侧某分组后，右侧加载该分组下全部主流程（过滤：所属系统=当前系统 且 操作类型=主流程 且 分组=选中分组），默认选中首条。
- 启用 / 停用：状态列展示当前状态。启用状态点"停用"按钮置为停用；停用状态点"启用"按钮置为启用。停用的流程不能被发起。
- 创建副本：传入原流程编号、副本编号、副本名称、副本描述，复制原流程的全部信息（流程图、流程变量、节点权限、审批定义）。复制成功后可选择直接进入副本设计器。
- 按年归档：流程定义按年份归档，同一流程编号在不同年份可有多份定义。

**使用场景**

- 新版报销流程上线前，先复制旧版流程做副本，在副本上改版，改完启用新版、停用旧版，平滑切换。
- 年末归档：本年度流程定义冻结，次年新建年度版本继续维护。

**开发要点**

- 主流程与子流程通过"操作类型"字段区分；本列表只展示主流程，子流程在 A8 子流程设计入口管理。
- 创建副本必须完整复制流程图 BPMN XML、节点审批定义、分支条件、流程变量、按钮权限，缺一不可，否则副本不可用。
- 副本编号不能与已有流程编号重复，需前置校验。
- 启用/停用是状态字段切换；停用流程不允许发起新实例，但已存在的在途实例继续流转至结束。
- 流程编号、流程名称、所属系统、所属分组、状态、年份是主流程的核心字段。

### A3. 主流程设计器

**功能描述**

可视化绘制流程图，拖拽节点与连线，配置属性，保存为 BPMN XML。这是流程设计的核心工作台。

**详细使用**

- 入口：主流程列表（A2）中点击某流程进入设计器。
- 四个区域：流程基本信息（顶部）、流程工具栏、流程图画布（中部）、属性配置（右侧，随选中对象切换）。
- 工具栏操作：
  - 本地导入：从本地导入 BPMN XML 文件还原流程图。
  - 导出 BPMN：将当前流程图导出为 BPMN XML 文件。
  - 导出 SVG：将当前流程图导出为 SVG 图片。
  - 放大 / 缩小 / 重置：调整画布缩放比例。
  - 复制 / 粘贴：复制选中节点或边并粘贴。
  - 回退（撤销）/ 前进（重做）：支持多步撤销重做。
- 画布操作：
  - 追加结束节点：全流程唯一结束节点。
  - 追加任务节点：新增审批节点，编号 `S_x` 自动生成。
  - 追加文本批注：在画布上加文字说明，不参与流转。
  - 追加连接：在节点间画边，编号 `R_x` 自动生成。
  - 删除：删除选中节点或边。
- 属性配置随选中对象切换：空白处显示流程属性与流程事件（A4）；选中节点显示节点属性、节点事件、按钮权限（A5）；选中边显示边属性（A6）。
- 保存：点击保存触发流程校验（是否存在任务节点、是否定义子流程、是否定义审批人），校验不通过弹窗提示具体原因；校验通过则保存流程图。

**使用场景**

- 流程管理员新建差旅报销流程：开始 → 部门经理审批 → 财务审批 → 结束，逐个拖拽节点连线并配置。
- 已有流程需要调整节点顺序：导入旧 BPMN，调整连线后导出新版本。

**开发要点**

- 一个流程有且仅有一个开始节点、一个结束节点，校验时必须检查。
- 节点编号 `S_x`、边编号 `R_x` 由系统自动生成且不可编辑，作为流程内唯一标识，新增节点时递增分配。
- 保存前必须校验三件事：流程是否存在至少一个任务节点、引用了子流程边的边是否已配置子流程、各任务节点是否配置了审批人（虚拟节点除外）。任一不通过都阻止保存并给出明确提示。
- BPMN XML 需包含节点、边、文本批注、分支条件表达式、事件配置、按钮权限，保证导入导出可完整还原。
- 撤销重做需维护操作栈，保存动作可作为一个撤销点。
- 画布缩放、复制粘贴不能破坏节点编号与连线关系。

### A4. 流程属性与流程事件

**功能描述**

配置流程级属性（编号、名称）与流程级事件（启动、结束、终止时触发消息或通知制单人）。

**详细使用**

- 入口：主流程设计器画布空白处，右侧属性面板显示流程属性与流程事件。
- 流程属性：
  - 流程编号：不可编辑，系统分配。
  - 流程名称：可编辑，必填。
- 流程事件（复选触发，可多选）：
  - 启动事件：消息事件、通知制单人事件。流程实例创建时触发。
  - 结束事件（正常结束）：消息事件、通知制单人事件。流程实例正常流转到结束节点时触发。
  - 终止事件（被终止/废弃）：消息事件、通知制单人事件。流程实例被制单人终止或被管理员作废时触发。

**使用场景**

- 报销流程启动时通知制单人"单据已提交"，正常结束时通知制单人"单据已审批通过可打款"，被终止时通知制单人"单据已作废"。
- 启动事件同时发消息到企业微信群，让相关人知晓有新单据进入审批。

**开发要点**

- 三类流程事件（启动/结束/终止）触发时机必须严格区分：启动=实例创建瞬间；结束=流转到结束节点；终止=被作废。三者互斥，一个实例只会触发其一对应的事件。
- "通知制单人事件"指给制单人发 IM/邮件；"消息事件"指往消息总线发业务消息（供其他系统订阅）。两者是不同通道，可同时勾选。
- 事件触发失败不能阻塞主流程流转，失败记录进入 D2 异常单据监控与 D4 流程信息补偿。
- 流程名称必填，保存前校验。

### A5. 流程节点配置

**功能描述**

配置任务节点的全部属性：基本属性、审批设置、节点事件、按钮权限。节点是流程审批的基本单元。

**详细使用**

- 入口：主流程设计器选中某任务节点，右侧面板切换为节点属性。
- 基本属性：
  - 节点编号 `S_x`：自动生成，不可编辑，唯一标识。
  - 节点名称：默认"任务"，可编辑，必填，双击节点也可改名。
- 审批设置（复选/单选混合）：
  - 待办提醒：勾选则节点进入待办时向审批人发待办消息；不勾选不发。
  - 排除制单人审批：勾选则不允许设置制单人为该节点审批人。
  - 允许发起催办：勾选则制单人可对该节点发起催办（B13）。
  - 无审批人时自动审批：勾选则无审批人时自动通过并提交下一节点；不勾选则停留在该节点（进入异常监控）。
  - 重复审批处理方式：自动审批通过（默认）/ 禁止自动审批。见 B19。
  - 虚拟节点：勾选则可不设审批人，自动提交，退回/取回可跳过。
  - 业务属性：键值对（key/value），供节点处理时读取业务参数。
- 节点事件：
  - 进入事件：节点被激活时触发，含消息事件、通知制单人。
  - 离开事件：节点被通过/取回/退回/转签离开时触发。
- 节点按钮权限（复选启用，决定审批人界面上显示哪些操作按钮）：
  - 提交、退回、取回、重置、转签、事前协审、事后协审、作废。
  - 子流程节点额外含"悬挂"按钮。

**使用场景**

- 部门经理审批节点：开启待办提醒、允许催办，按钮权限开放提交和退回，不允许转签（防止经理把审批责任转给下属）。
- 系统自动节点（如自动校验节点）：设为虚拟节点，无审批人自动提交，退回时跳过。
- 财务复核节点：开启"无审批人时自动审批"，避免财务人员离职导致单据卡死。

**开发要点**

- 节点编号一旦生成不可变更，删除节点后编号不回收复用。
- "排除制单人审批"与"虚拟节点"互斥：虚拟节点无需审批人，排除制单人无意义。
- "无审批人时自动审批"与"虚拟节点"是两种不同的自动通过机制：虚拟节点是设计态就确定自动提交；无审批人自动审批是运行态审批人解析为空时兜底。开发时需区分。
- 按钮权限直接决定运行时审批人能执行哪些操作（B2-B7、B14、B15），未启用的按钮在前端不展示且后端拒绝执行。
- 子流程节点的"悬挂"按钮用于主动挂起子流程，需与 B15 挂起恢复联动。
- 业务属性键值对在节点处理时可被读取，用于扩展业务逻辑（如标记节点类型供业务系统识别）。

### A6. 流程边配置

**功能描述**

配置节点间连线的属性，包括边名称、是否子流程边、是否排他边、子流程前是否自动提交，以及边的通过条件（分支条件见 A7）。

**详细使用**

- 入口：主流程设计器选中某条边，右侧面板切换为边属性。
- 基本属性：
  - 边编号 `R_x`：自动生成，不可编辑。
  - 边名称：展示该边的分支条件摘要，可编辑，非必填。
- 流转属性（复选）：
  - 子流程边：勾选则该边可作为子流程挂接点，保存后流程图上该边显示绿色"子"字标记。子流程在 A8 中绘制。
  - 排他边：勾选则当该节点其他出边条件都不满足时走此边（兜底）。一个节点的出边中排他边应有且仅有一条。
  - 子流程前自动提交：勾选则子流程前的边自动提交，无需审批直接进入子流程；不勾选则需满足边条件后才进入子流程。
- 通过条件：见 A7 分支条件配置。

**使用场景**

- 报销金额 > 10000 走"总经理审批"分支，否则走"财务直接审批"分支，两条边各挂条件；再加一条排他边作为兜底（条件都没匹配时走默认路径）。
- 某边标记为子流程边，用于挂接"分公司差异化审批"子流程，不同分公司走不同子流程。
- 子流程前的边勾选"子流程前自动提交"，让单据无缝进入子流程，不再停留主流程节点。

**开发要点**

- 一个节点的出边中，排他边最多一条；若存在排他边，当所有带条件的出边都不匹配时走排他边；若没有排他边且无匹配，记异常"当前节点无出去的边"或"解析分支条件异常"，进入 D2。
- 子流程边与普通条件边可共存于同一节点的出边集合。
- "子流程前自动提交"只对子流程边有意义，对普通边无效。
- 边名称建议自动同步分支条件的可读描述，方便用户在图上识别分支走向。
- 边的删除需校验：若该边是子流程边且已挂接子流程，需提示用户子流程将失效。

### A7. 分支条件配置

**功能描述**

为边配置通过条件，支持行式条件表达式（函数 + 变量 + 比较符 + 比较值 + 括号 + 连接符），运行时求值决定单据走哪条边。

**详细使用**

- 入口：选中某条边，在边属性的"通过条件"处打开条件设置弹窗。
- 条件弹窗操作：增加、删除、上移、下移、条件预览、确定、取消。
- 每行条件项：

| 项 | 说明 | 必填 |
|---|---|---|
| 序号 | 行序号，自动生成 | 否 |
| 左括号 | `(` / `((` / `(((` | 否 |
| 函数 | 日期差值、数值绝对值、字符截取、外键属性函数、用户所属岗位、比较变量、自定义值集 | 否 |
| 变量 | 流程变量（如 `BMSX_JE`，对应单据字段） | 是 |
| 比较符 | 随变量类型变化（数值：等于/大于/小于/不等于/≥/≤；字符：等于/包含/不等于） | 是 |
| 比较值 | 参照值，表单弹窗录入（如 2000） | 是 |
| 右括号 | `)` / `))` / `)))` | 否 |
| 连接符 | 并且 / 或者 | 否 |

- 条件预览：把行式条件拼成可读字符串展示，便于确认逻辑。
- 确定：保存条件表达式到该边；取消：放弃修改。

**使用场景**

- 报销金额 `BMSX_JE > 10000` 并且 申请人职级 `BMSX_ZJ ≥ 5`，走总经理审批边。
- 请假天数用"日期差值"函数计算后 `> 3`，走分管领导审批边。
- 申请人所属岗位用"用户所属岗位"函数判断，命中"销售岗"走销售总监审批边。

**开发要点**

- 行式条件需解析为可求值的表达式树：行内先对变量应用函数得中间值，再用比较符与比较值比较得布尔；行间按连接符（AND/OR）与括号优先级合并。
- 括号需配对校验，左右括号数量与嵌套层级必须合法，否则保存报错。
- 变量需与单据字段做数据映射，运行时从单据实例取值；变量名建议有字典维护，避免手填出错。
- 比较符随变量类型动态切换：数值型给数值比较符，字符型给字符比较符，开发时按变量类型自动适配。
- 函数库需可扩展（自定义值集），新增函数不影响已有条件。
- 条件求值失败（变量取不到值、函数执行异常）记"解析分支条件异常"，进入 D2，单据挂起等待处理。
- 与 A6 排他边配合：节点出边的求值顺序、排他边兜底逻辑见 A6 开发要点。

### A8. 子流程设计

**功能描述**

为同一主流程在不同组织机构下配置差异化的审批子流程。子流程挂在主流程的"子流程边"上，主流程流转到该边时按当前单据所属组织匹配子流程进入，子流程结束后回到主流程。

**详细使用**

- 前置：在主流程中标记子流程边（A6 勾选"子流程边"）并保存主流程。
- 入口：流程管理 → 子流程设计。
  - 左侧加载组织机构树，默认选中首条组织。
  - 右侧加载该组织下全部主流程，默认选中首条。
- 打开主流程图：点击目标流程行的"打开流程图"，新页签展示主流程图，子流程边上有绿色"子"字标记。
- 进入子流程设计器：点击子流程边上的"子"字，打开子流程设计器。
- 绘制子流程：操作同主流程（追加结束/追加任务/追加文本批注/追加连接/删除）。子流程同样只有一个开始节点、一个结束节点。
- 配置子流程属性：
  - 流程编号：主流程编号 + 后缀，自动生成，不可编辑。
  - 流程名称：主流程名称 + 子流程边前节点名称，自动生成，不可编辑。
  - 进入子流程条件：打开条件弹窗配置（操作同 A7）。
- 配置子流程节点/边：审批设置、事件、按钮权限、边条件（同 A5/A6/A7），子流程节点按钮权限额外含"悬挂"。
- 保存：保存子流程。注意：新建子流程在设置"进入子流程条件"前必须先保存一次，否则点"编辑"按钮会提示"未保存子流程"。
- 作废：不再使用的子流程可作废，二次确认后提示"已作废"并关闭页面。

**使用场景**

- 集团报销主流程统一，但各分公司审批层级不同：北京分公司走"部门经理→财务"，上海分公司走"部门经理→分管副总→财务"。为每个分公司绘制各自的子流程挂在同一条子流程边上。
- 采购流程中，超过 50 万的采购走"招标子流程"，50 万以下走"询价子流程"，通过"进入子流程条件"区分。

**开发要点**

- 子流程与主流程的关联：子流程记录所属主流程编号、所属主流程节点、所属主流程边（子流程边），三者定位唯一挂接点。
- 子流程按组织机构差异化：同一主流程 + 同一子流程边，在不同组织下可有不同子流程定义；运行时按当前单据所属组织匹配。
- 主流程流转到子流程边时的调度逻辑：
  1. 取当前单据所属组织。
  2. 查询该主流程 + 该组织 + 该子流程边下的子流程定义。
  3. 未找到子流程定义：按"子流程前自动提交"或边条件处理；仍无可用子流程，记"解析子流程异常"，进入 D2。
  4. 找到子流程：求值"进入子流程条件"。满足则创建子流程实例，按子流程图生成首个任务，主流程挂起等待子流程结束；不满足则不进入子流程，按主流程出边继续流转。
  5. 子流程执行至结束节点 → 子流程实例结束 → 回到主流程，从子流程边后继续流转。
- 子流程实例是独立实例，有自己的实例 ID，但生命周期依附主流程：主流程终止则子流程同步终止。
- 全程记录流程操作日志；子流程异常计入 D2。
- 子流程节点/边的属性配置项与主流程一致，开发时可复用 A5/A6/A7 的实现。
- 子流程作废后，已存在的在途子流程实例继续流转至结束，但不再匹配新单据。

### A9. 流程审批定义

**功能描述**

为每个任务节点配置审批对象（处理方式 + 审批人/场景）、超时设置、抄送设置。这是会签、票签、超时处理等高级审批能力的配置入口。

**详细使用**

- 入口：流程管理 → 流程审批定义。左侧组织机构树，右侧流程列表，点击"审批定义"进入节点审批对象定义。
- 处理方式（单选，默认或签）：

| 处理方式 | 说明 |
|---|---|
| 或签 | 任意一人审批即通过 |
| 串行会签 | 按顺序依次审批，最后一人通过则节点通过 |
| 并行会签 | 同时收到待办，全部通过则节点通过；可开启"票签"并设置"票签通过总权重" |

- 对象类型（单选，默认指定人员）：

| 对象类型 | 说明 |
|---|---|
| 指定人员 | 指定单/多人审批；并行会签 + 票签时需设每人"票签权重" |
| 指定场景 | 通过场景过滤人员；串行会签展示各场景审批顺序，并行会签展示各场景票签权重 |

- 指定人员操作：人员选择弹窗（左可选 / 中移动 / 右已选），确定后回显。权重列仅在"并行会签 + 票签 + 通过权重"时出现。
- 指定场景操作：
  - 或签：仅选场景。
  - 串行会签：设各场景会签顺序（上移/下移调整）。
  - 并行会签：设各场景权重比例。
- 节点超时设置：
  - 超时提醒开关。
  - 审批时效（小时，启用时必填）：到达节点后超此时长视为超时，向待办人发提醒。
  - 频次（小时）：首次超时后循环提醒间隔，每隔 N 小时监测一次直至审批完成。
  - 超时处理：提交（超时处理时间到自动提交下一节点）/ 退回到上一节点 / 重置（退回制单节点重走）。
  - 示例：审批时效 8h、频次 2h、超时处理 14h=提交 → 8h 首次提醒，每 2h 提醒一次，14h 仍无人处理则自动提交下一节点。
- 抄送设置：
  - 允许抄送开关（默认开启）。
  - 自动抄送：目标可为人员或场景，展示于列表。

**使用场景**

- 三方法审合同：法务、财务、业务三方并行会签，全部通过才进入下一步。
- 董事会投票：5 位董事并行会签 + 票签，每人权重 20%，通过总权重 60%，累计达 60% 即通过。
- 逐级审核：组长 → 经理 → 总监串行会签，按顺序逐人审批。
- 紧急审批节点设超时 4h 自动提交，避免单据卡住影响业务。
- 报销审批通过后自动抄送制单人所在部门负责人知情。

**开发要点**

- 四种会签策略的运行时聚合逻辑见 B8，本功能点只负责配置存储。
- 处理方式、对象类型、票签开关、通过总权重、审批人/场景列表、权重、顺序、超时、抄送共同构成节点审批定义，需完整持久化。
- 票签通过总权重是百分比阈值（如 60%）；累计通过权重大于该阈值即通过。权重分配需校验：所有审批人权重之和应等于 100%（或允许自定义，由开发方决定并文档化）。
- 串行会签的顺序由审批人列表顺序决定，上移/下移直接调整存储顺序。
- 超时三要素（时效、频次、处理）需联动 B16 超时定时任务：定时扫描到期任务，发提醒、按频次循环、达处理时间执行自动处理。
- 抄送在节点通过后触发（B9），抄送目标解析同审批人解析（A10）。
- 审批定义与流程图分离存储但通过节点编号关联；流程图改版时审批定义需跟随迁移。

### A10. 审批人解析

**功能描述**

运行时根据节点配置解析出实际的审批人列表。支持多种解析来源，并处理制单人相关规则、自动提交、重复审批人、重点人员拦截。

**详细使用**

- 解析来源（节点审批定义中配置）：
  - 指定人员：直接取配置的人员列表。
  - 指定岗位：按"岗位所属组织 + 岗位编号"取该岗位下所有人。
  - 提单人部门领导：提单人部门领导 / 上级部门领导 / 上上级部门领导 / 顶级部门领导。
  - 委托人部门领导：委托人部门领导 / 上级 / 上上级 / 顶级部门领导。
  - 指定场景：按场景过滤人员。
- 制单人相关规则：
  - 排除制单人审批：节点勾选则从解析结果中剔除制单人。
  - 互相审批：节点审批人含制单人时，制单人不显示该任务，由其他审批人审批。
  - 代为审批：节点审批人含制单人时，可将制单人待办转他人，制单人不可审批自己单据（不收到自己单据待办）。
- 自动提交模式：
  - 默认原则：全局自动审批配置开启 + 节点有且只有一个审批人 + 此人已在前面节点处理过 → 自动审批；否则不自动。
  - 强制自动提交：节点无论是否配置审批人均自动提交。
  - 禁止自动提交：即使符合自动审批条件也不自动提交。
  - 无审批人时自动审批（节点级勾选）：无审批人则自动通过提交下一节点。
- 重复审批人处理：
  - 自动审批通过（默认）：当前节点审批人与前面已通过节点审批人相同，则自动通过，无需再审。
  - 禁止自动审批：相同审批人必须再次审批方可通过。
- 重点人员拦截：命中重点人员清单的审批人，待办先暂停并记录，由运维确认配置是否正确后决定是否继续；确认无误后该单再次走到此节点不再拦截。

**使用场景**

- 请假流程的"直属领导审批"节点配"提单人部门领导"，自动解析发起人所在部门的领导，无需为每个部门单独配置。
- 多级组织：某节点配"上上级部门领导"，集团层面的审批自动落到事业部负责人。
- 制单人恰好是审批人时（如经理审批自己提的单），用"代为审批"把待办转给副经理，避免自己批自己。
- 同一人连续出现在多个节点时，默认自动跳过重复审批，减少冗余审批环节。

**开发要点**

- 解析顺序建议：先按配置来源解析出候选人员集合，再依次应用排除制单人、互相审批、代为审批规则，最后应用自动提交与重复审批人规则，得到最终审批人列表。
- 部门领导解析需组织机构层级数据支持（E1/E2），"上级/上上级/顶级"按组织树逐级上溯。
- 重点人员拦截需查询重点人员清单（运维维护）；命中后待办状态置为暂停，触发 D2 监控通知运维；运维确认放行后待办恢复正常，且该单该节点的拦截状态置为已确认不再拦截。
- 自动提交三模式（默认/强制/禁止）优先级：强制 > 禁止 > 默认原则。强制自动提交时即使无审批人也直接通过；禁止自动提交时即使符合条件也不自动。
- "无审批人时自动审批"是节点级开关，与自动提交三模式独立：解析后审批人为空时，若勾选则自动通过，否则挂起进异常。
- 重复审批人处理基于"前面已通过节点的审批人集合"判断，需维护实例的已审批人历史。
- 解析失败（岗位无人、部门无领导）按"无审批人"处理，走无审批人自动审批或异常分支。

### A11. 流程信息导入导出

**功能描述**

将流程图信息、流程审批信息、分支条件在系统间迁移。支持导出为文件再导入还原，便于从测试环境迁移到生产环境，或跨系统复制流程。

**详细使用**

- 入口：流程管理 → 流程信息导入导出。
- 导出：选择一个或多个流程，导出包含流程图 BPMN XML、审批定义、分支条件的文件包。
- 导入：选择文件包导入，系统校验流程编号是否冲突，冲突时提示覆盖或跳过。
- 导入后流程默认为停用状态，需手动启用（A2）后才可发起。

**使用场景**

- 测试环境调通的新版报销流程，导出后导入生产环境，避免在生产环境重新画图。
- 集团总部设计的标准流程下发给各子公司系统，各子公司导入后按本地组织微调。

**开发要点**

- 导出内容必须完整：流程图、节点审批定义、边分支条件、流程事件、按钮权限、子流程定义（若有）。缺项会导致导入后流程不可用。
- 导入时按流程编号匹配：编号已存在则提示冲突，由用户选择覆盖或跳过；覆盖前建议自动备份原定义。
- 导入的流程默认停用，避免误发起。
- 子流程导入需同时导入主流程与子流程，并保持挂接关系（主流程边、组织、节点关联）完整。
- 导入导出过程记录日志，便于追溯（可复用 D3 流程配置操作日志）。

---

### A12. 流程审批信息批量复制

**功能描述**

将一个流程的审批配置（审批对象、会签、超时、抄送等）批量复制到其他流程，避免重复配置。

**详细使用**

- 入口：流程管理 → 流程审批信息批量复制。
- 选择源流程：选定一个流程作为审批配置来源。
- 选择目标流程：勾选一个或多个目标流程。
- 映射节点：源流程与目标流程的节点按节点编号或节点名称匹配，支持手动调整映射关系。
- 执行复制：将源流程各节点的审批定义复制到目标流程对应节点，覆盖目标流程原有配置。
- 复制完成提示成功/失败列表。

**使用场景**

- 集团上线 10 个分公司的报销流程，画完 1 个分公司的审批定义后，批量复制到其余 9 个，再各自微调审批人。
- 新版流程与旧版节点结构相同，直接把旧版审批定义复制到新版，省去重新配置。

**开发要点**

- 节点映射是关键：源与目标节点按编号匹配优先，编号不一致时按名称匹配，仍不匹配则标记为未映射由用户处理。
- 复制是覆盖操作，目标流程原有审批定义被替换；复制前应提示用户确认或自动备份。
- 指定场景、指定岗位等引用型配置复制时，需校验目标流程所属系统/组织是否存在同名的场景、岗位，不存在则提示。
- 批量复制需事务保证：要么全部成功，要么全部回滚，避免出现部分流程复制成功部分失败的不一致状态。
- 复制操作记录 D3 流程配置操作日志。

## 3. 流程审批运行时模块功能点

> **统一接口规范**：本模块所有运行时操作遵循统一规范——请求方式 POST，请求体 JSON 含 `userId`、`userName`、`timestamp`、`bizParam`（单对象或数组）；响应体 `{"code":"0","data":{"failList":[],"successList":[...]}}`，`code:"0"` 表示成功。批量操作返回成功/失败列表。各功能点下只列差异化的必传入参与关键出参。

### B1. 流程发起

**功能描述**

制单人提交单据启动流程实例，创建全局唯一的实例 ID，进入首个任务节点生成待办。

**详细使用**

- 入口：业务单据页面填写完成后点"提交"。
- 操作：填写单据内容 → 选择流程（若单据绑定了流程则自动选）→ 提交。
- 触发：创建实例 → 触发启动事件（A4）→ 进入首个任务节点（A3 中开始节点的下一节点）→ 解析审批人（A10）→ 生成待办。
- 制单人收到"提交成功"反馈，可查看在途单据。

**使用场景**

- 员工填完差旅报销单点提交，单据进入部门经理待办。
- 采购员创建采购申请单提交，按金额走不同分支。

**开发要点**

- 实例 ID 全局唯一（建议 32 位类 GUID），创建后不可变更。
- 发起前校验流程处于启用状态（A2），停用流程拒绝发起。
- 首个任务节点若是虚拟节点或命中自动提交条件（A10），需自动通过并继续流转，不生成待办。
- 启动事件（A4）触发失败不阻塞实例创建，失败进 D2/D4。
- 实例创建与首个任务生成需在同一事务内，避免出现"有实例无任务"的脏数据。
- 记录流程操作日志（操作类型"创建"）。

---

### B2. 提交

**功能描述**

审批人通过当前节点，驱动单据流转到下一节点。支持提交到指定流程、指定节点。

**详细使用**

- 入口：审批人待办中打开单据 → 填写处理意见 → 点"提交"。
- 必传入参：`taskId`、`instanceId`。可选：`opinion`（处理意见）、`appointNodeApprover`（指定下一节点审批人）、`submitToFlowId`（提交到指定流程）、`submitToNodeId`（提交到指定节点）。
- 关键出参：`finishNodeFlag`（是否结束节点）、`instanceId`、`mainFlowId/mainFlowName`、`mainNodeId/mainNodeName`、`subFlowId/subFlowName`、`subNodeId/subNodeName`、`taskUserId`（下一节点待办人）。
- 处理流程：完成当前任务 → 求值出边条件选边（A6/A7）→ 若是子流程边则调度子流程（A8）→ 生成下一节点任务并分配审批人 → 触发离开/进入事件 → 记日志。
- 会签节点：提交即该审批人通过，按 B8 聚合规则判断节点是否整体通过。

**使用场景**

- 部门经理审批通过报销单，提交给财务复核。
- 主管审批时指定下一节点"总经理审批"的具体审批人为张总（appointNodeApprover）。
- 流程走到子流程边，提交后自动进入对应组织的子流程。

**开发要点**

- 必须校验操作人是当前任务的合法待办人，非待办人提交拒绝。
- 出边选择按 A6/A7 规则：带条件边求值，无匹配走排他边，仍无匹配记"当前节点无出去的边"异常进 D2。
- `submitToFlowId`/`submitToNodeId` 用于跳过常规边求值直接指定目标，需校验目标节点是否在流程图可达路径上。
- `finishNodeFlag` 为 true 时触发结束事件（A4），实例状态置为已结束。
- 提交是高频操作，需对实例加锁防止并发提交（异常类型含"操作加锁异常"）。
- 操作幂等：按 `taskId + instanceId + timestamp` 控制，重复提交安全。
- 触发离开事件（当前节点）与进入事件（下一节点），失败不阻塞流转，进 D4。

---

### B3. 取回

**功能描述**

下一节点任务尚未被审批时，撤回已提交的任务。制单人可取回任意节点的任务。

**详细使用**

- 入口：制单人在"在途单据"或审批人在"已办"中对待办已提交的任务点"取回"。
- 必传入参：`taskId`、`instanceId`。可选：`opinion`。
- 出参：`successList:[{instanceId}]`。
- 边界：下一节点任务已被审批则不可取回，提示用户。

**使用场景**

- 制单人提交报销单后发现有金额填错，下一节点经理还没审，立即取回修改后重新提交。
- 经理提交给财务后想起要补充说明，财务还没看，取回补充再提交。

**开发要点**

- 取回的核心校验：当前节点的下一节点任务必须存在且状态为待办（未被任何审批人处理过）。下一节点只要被任意一人处理（提交/退回/加签等），即不可取回。
- 制单人特权：制单人可取回任意节点的任务（不限于自己提交的节点）；普通审批人只能取回自己刚提交的任务。
- 取回后：下一节点任务作废移入历史，当前节点任务重新激活为待办，审批人重新收到待办。
- 虚拟节点在取回路径上可跳过（A5）：取回时若途经虚拟节点直接跳到上一个有审批人的节点。
- 取回需对实例加锁，记操作日志。

---

### B4. 退回

**功能描述**

审批人将单据退回上一节点或指定节点重新审批。

**详细使用**

- 入口：审批人待办中点"退回"。
- 必传入参：`taskId`、`instanceId`。可选：`opinion`、`rollbackToFlowId`（退回到指定流程）、`rollbackToNodeId`（退回到指定节点）。
- 出参：`successList`/`failList`。
- 行为：不指定目标则退回上一节点；指定则退回到该节点。

**使用场景**

- 财务复核发现报销单据不全，退回给部门经理重新确认。
- 总经理审批时认为需要从制单人重新填报，指定退回到开始节点（等同 B5 驳回）。

**开发要点**

- 退回目标节点必须在该实例已走过的路径上，不允许退回到未到达的节点。
- 退回时清理当前节点及之后节点的待办任务，在目标节点重建待办。
- 会签节点退回：任一审批人退回则整个节点退回，单据按退回目标回退（B8）。
- 退回需记回滚日志，便于追溯与 D3 查询。
- 退回目标若是虚拟节点，跳过虚拟节点退回到上一个有审批人的节点。
- 与 B5 驳回的区别：驳回是退回到开始节点的特例，本功能点是退回到任意已走过节点。

---

### B5. 驳回

**功能描述**

将单据退回到开始节点，相当于重新填报。

**详细使用**

- 入口：审批人待办中点"驳回"。
- 必传入参：`taskId`、`instanceId`。可选：`bizNo`（单据编号）、`opinion`。
- 出参：`successList`/`failList`。
- 行为：退回到开始节点（制单人节点），制单人重新收到待办可修改后重新提交。

**使用场景**

- 审批人认为单据整体不符合要求，驳回让制单人重填。
- 会签节点中任一审批人认为不通过，驳回整单。

**开发要点**

- 驳回是退回的特例（目标=开始节点），可复用 B4 退回实现，目标固定为开始节点。
- 会签节点任一人驳回即整单驳回，其他审批人的待办同步作废。
- 驳回后实例不结束，状态仍为运行中，等待制单人重新提交。
- 记操作日志与回滚日志。

---

### B6. 加签

**功能描述**

当前审批人临时增加审批人。分事前加签与事后加签两种。

**详细使用**

- 入口：审批人待办中点"事前协审"或"事后协审"按钮（按钮权限见 A5）。
- 必传入参：`taskId`、`instanceId`、`assignType:"8"`、`assignToUserId`、`assignToUserName`。可选：`opinion`、`assignApprovalType`。
- 出参：`{"code":"0"}`。
- 事前加签：A 加签 B，B 审完后任务回到 A，A 审完才进入下一节点。流程：A → B → A → 下一节点。
- 事后加签：A 加签 B，B 审完后节点即通过进入下一节点（等同转签 B7）。流程：A → B → 下一节点。

**使用场景**

- 部门经理审批采购单时觉得需要技术确认，事前加签技术负责人，技术确认完再回到经理，经理通过后进下一节点。
- 经理审批通过后想再多一位副总知情会签，事后加签副总，副总审完节点直接进入下一节点。

**开发要点**

- 事前加签与事后加签的流转路径不同，开发时需按 `assignApprovalType` 严格区分。
- 事前加签 B 审完后必须回到加签发起人 A，A 仍是该节点的待办人；A 再次提交才推进。
- 事后加签 B 审完后节点即通过，不再回到 A。
- 加签目标人 B 必须是合法用户，且不能是当前已在该节点待办的人（避免重复）。
- 加签操作记日志，标注加签类型与加签人、被加签人。
- 按钮权限（A5）控制：未开放"事前协审"/"事后协审"按钮的节点不允许加签。

---

### B7. 转签

**功能描述**

当前审批人将任务转给他人审批，他人审完后直接进入下一节点。

**详细使用**

- 入口：审批人待办中点"转签"按钮（按钮权限见 A5）。
- 必传入参：`taskId`、`instanceId`、`takeUserId`、`takeUserName`。可选：`opinion`。
- 出参：`{"code":"0"}`。
- 流程：A 转给 B，B 审完进入下一节点（不回到 A）。

**使用场景**

- 经理出差，把待办转签给副经理代审，副经理审完直接进下一节点。
- 某审批人发现自己不合适审批此单（利益相关），转签给更合适的人。

**开发要点**

- 转签与事后加签（B6）效果相同：都是转给他人且他人审完进入下一节点。区别在语义入口与按钮权限。
- 转签后原审批人 A 不再是该任务待办人，待办转移给 B；A 的已办记录保留转签说明。
- 转签目标人 B 必须合法，转签操作记日志含转出人、转入人。
- 按钮权限（A5）控制：未开放"转签"按钮的节点不允许转签。
- 会签节点中某个审批人转签，只转该审批人自己的待办，不影响其他会签人。

---

### B8. 会签运行

**功能描述**

运行时按节点配置的会签策略（或签/串行/并行/票签）生成任务并聚合审批结果，决定节点是否通过。配置见 A9，本功能点是运行时聚合逻辑。

**详细使用**

- 四种策略运行行为：

| 策略 | 任务生成 | 通过条件 | 退回影响 |
|---|---|---|---|
| 或签 | 多人共享一个任务 | 任一人通过 | 任一人退回则单据退回 |
| 串行会签 | 按顺序拆分多个任务，逐人激活 | 末人通过 | 任一人退回则单据退回 |
| 并行会签 | 同时拆分多个任务，全部激活 | 全部通过 | 任一人退回则单据退回 |
| 票签 | 同时拆分多个任务，带权重 | 累计通过权重 > 通过总权重 | 任一人退回则单据退回 |

- 或签：多人共享一个待办，任一人提交即节点通过，其余人待办作废。
- 串行会签：按配置顺序仅激活首人，首人通过后激活下一人，末人通过则节点通过。
- 并行会签：全部审批人同时收到待办，全部通过才节点通过。
- 票签：并行会签基础上，每个审批人有权重，累计通过权重大于阈值即节点通过，剩余待办可终止。

**使用场景**

- 或签：秘书处三人任一人都可审批收文登记。
- 串行会签：组长 → 经理 → 总监逐级审核合同。
- 并行会签：法务、财务、业务三方同时审合同，全通过才进入签署。
- 票签：董事会 5 人投票，权重各 20%，达 60% 即通过。

**开发要点**

- 任务生成按策略拆分：或签生成 1 个共享任务；串行生成 N 个任务但仅首人激活；并行/票签生成 N 个任务全部激活。
- 聚合逻辑：
  - 或签：任一通过 → 节点通过，其余待办标记无效。
  - 串行：当前人通过 → 激活下一人；末人通过 → 节点通过。
  - 并行：每人通过标记已完成；全部完成 → 节点通过。
  - 票签：每人通过累加其权重；累计权重 > 阈值 → 节点通过，剩余待办终止；若所有人投完仍未达阈值 → 节点不通过。
- 退回：任一审批人退回，整个节点退回，单据按退回目标回退（B4），其余会签人待办作废。
- 驳回：任一审批人驳回，整单驳回（B5）。
- 票签权重与阈值来自 A9 配置，运行时累加需持久化累计值，防止重复累加。
- 会签人解析见 A10，解析后若只剩一人则退化为单人审批。

---

### B9. 抄送

**功能描述**

节点通过后将审批结果以 IM/邮件通知抄送列表人员。抄送是知会性质，抄送人无需审批。

**详细使用**

- 配置：A9 抄送设置中配置允许抄送与自动抄送目标（人员或场景）。
- 触发：节点通过时自动抄送给配置的目标；审批人提交时也可手动添加抄送人（若允许抄送开启）。
- 通知方式：IM 消息、邮件（E3）。

**使用场景**

- 报销审批通过后自动抄送制单人所在部门负责人，让其知晓本部门有人报销。
- 合同审批通过后抄送档案管理员，准备归档。

**开发要点**

- 抄送目标解析同审批人解析（A10），支持人员与场景。
- 抄送在节点通过后触发，与下一节点任务生成可并行，不阻塞流转。
- 抄送失败不阻塞流程，失败进 D4 信息补偿重发。
- 抄送记录入流程操作日志，含抄送人、被抄送人、通知方式。

---

### B10. 委托审批

**功能描述**

某审批人设定一段时间内其待办单据由被委托人代为审批。委托生效后委托人与被委托人均可见待办。委托关系配置见 C4。

**详细使用**

- 配置：在 C4 委托审批设置中新增委托关系（委托人、被委托人、起止时间、流程、组织）。
- 生效：流程流转到委托人作为审批人的节点时，若在委托有效期内，待办同时推送给委托人和被委托人。
- 处理：委托人或被委托人任一处理即完成该任务。

**使用场景**

- 经理出差一周，委托副经理代审出差期间的所有报销单。
- 某审批人长期病假，委托同事代审其负责的合同流程。

**开发要点**

- 委托关系按"委托人 + 流程 + 组织 + 时间段"匹配，运行时审批人解析（A10）后需检查是否存在有效委托。
- 委托生效后委托人与被委托人都收到待办，任一人处理即完成，另一人待办作废。
- 委托有起止时间，过期自动失效；不在有效期内不触发委托。
- 委托人部门领导解析（A10）中的"委托人部门领导"特指被委托人所在部门的领导，需与委托关系区分。
- 委托处理记日志，标注是委托人还是被委托人处理。

---

### B11. 跳转

**功能描述**

将当前流程实例跳转到任意办理节点，不受常规边流转约束。

**详细使用**

- 入口：通常由管理员在 C3 单据流程介入中使用，或特殊业务场景下由系统调用。
- 行为：指定目标节点，实例当前任务作废，在目标节点生成新待办。

**使用场景**

- 单据走到一半发现流程配置有误，管理员直接跳转到正确节点继续审批，不用退回重走。
- 业务特批场景：跳过某些常规审批节点直接到终审。

**开发要点**

- 跳转是高风险操作，应限制为管理员权限（C3）或特定业务接口，普通审批人不开放。
- 跳转目标节点必须在同一流程图内（主流程或当前子流程），不支持跨流程跳转。
- 跳转需清理当前及跳过节点的待办，在目标节点按 A10 重新解析审批人生成待办。
- 跳转记操作日志，标注原节点、目标节点、操作人，便于审计。

---

### B12. 已阅

**功能描述**

审批人打开单据后记录首次打开时间到流程审批记录，标记该审批人已阅。

**详细使用**

- 入口：审批人打开待办单据时自动触发。
- 行为：仅记录首次打开时间，重复打开不重复记录。

**使用场景**

- 统计审批人从收到待办到打开单据的时长，分析审批响应速度。
- 知会型节点（无需审批只需知晓）通过已阅记录确认相关人员已查看。

**开发要点**

- 已阅只记首次打开时间，后续打开不更新。
- 已阅记录入流程审批记录，与提交/退回等操作记录区分。
- 已阅不改变任务状态（任务仍为待办），只是附加阅读记录。
- 性能考虑：打开单据是高频操作，已阅记录需轻量，避免影响打开速度。

---

### B13. 催办

**功能描述**

制单人通过 IM/邮件通知当前处理人尽快处理单据。

**详细使用**

- 入口：制单人在"在途单据"中对某单据点"催办"。
- 必传入参：`instanceId`。
- 出参：`{"code":"0","errorMessage":"催办成功"}`。
- 前置：节点需勾选"允许发起催办"（A5），否则催办按钮不显示。
- 行为：向当前节点所有待办人发送催办消息（IM/邮件）。

**使用场景**

- 报销单提交三天还没审批，制单人催办提醒经理尽快处理。
- 紧急采购单提交后立即催办，加快流转。

**开发要点**

- 催办需校验当前节点是否开启"允许发起催办"，未开启则拒绝。
- 催办消息发给当前节点全部待办人，含制单人、单据摘要、催办时间。
- 催办频率建议限制（如同一单据对同一节点 N 小时内只能催办一次），避免骚扰，具体由开发方决定。
- 催办记日志，含催办人、被催办人、单据。

---

### B14. 终止

**功能描述**

制单人终止作废单据流程，流程实例不再继续流转。

**详细使用**

- 入口：制单人在"在途单据"中点"作废"/"终止"按钮（按钮权限见 A5）。
- 行为：终止流程实例，不产生新任务，原待办任务移入历史，实例状态置为已终止。
- 触发：触发终止事件（A4），通知制单人单据已作废。

**使用场景**

- 制单人提交报销单后发现单据作废（如发票丢失），主动终止流程。
- 业务变更，已提交的采购申请不再需要，制单人终止。

**开发要点**

- 终止权限通常只给制单人；管理员可通过 C3 介入作废。
- 终止后实例不可恢复，所有待办作废；若存在子流程，子流程同步终止（A8）。
- 终止触发终止事件（A4），与正常结束事件互斥。
- 终止记操作日志，标注终止人、终止原因。
- 终止需对实例加锁，防止与审批操作并发。

---

### B15. 挂起与恢复

**功能描述**

审批人将流程实例挂起暂停，并通知制单人；挂起后可恢复继续流转。

**详细使用**

- 入口：审批人待办中点"挂起"按钮（按钮权限见 A5）。
- 必传入参：`instanceId`、`taskId`。
- 出参：`{"code":"0"}`。
- 行为：挂起后流程暂停，当前待办保留但不推进；通知制单人流程已挂起。
- 恢复：由挂起人或管理员恢复，流程从挂起节点继续流转。

**使用场景**

- 审批人审批时发现需要制单人补充材料，挂起流程并通知制单人，待材料补齐后恢复。
- 业务待确认期间挂起流程，避免超时自动处理误触发。
- 子流程节点可通过"悬挂"按钮挂起子流程（A5），与主流程挂起独立。

**开发要点**

- 挂起后实例状态置为挂起，待办不消失但不计时（B16 超时定时对挂起实例不触发）。
- 恢复后实例状态回到运行中，待办重新激活，超时计时重新开始（或按业务规则处理）。
- 挂起/恢复需记操作日志。
- 子流程挂起不影响主流程（主流程本就在等待子流程）；主流程挂起则整体暂停。

---

### B16. 超时提醒与超时处理

**功能描述**

按节点配置的审批时效、频次、超时处理，定时监测任务超时并执行提醒或自动处理。配置见 A9。

**详细使用**

- 配置（A9 节点超时设置）：审批时效、频次、超时处理（提交/退回上一节点/重置）。
- 运行行为：
  - 任务到达节点后开始计时。
  - 到达审批时效：向待办人发超时提醒。
  - 之后按频次循环提醒，每隔 N 小时提醒一次。
  - 到达超时处理时间：按配置执行自动处理（提交下一节点 / 退回上一节点 / 重置到制单节点）。
  - 任务被处理后（无论人工还是自动），停止计时与提醒。
- 示例：审批时效 8h、频次 2h、超时处理 14h=提交 → 8h 首次提醒，每 2h 提醒一次，14h 仍无人处理则自动提交下一节点。

**使用场景**

- 报销节点设审批时效 8h、频次 4h、超时处理 24h=提交，避免经理出差导致单据卡死，24h 自动通过。
- 紧急合同审批节点设审批时效 2h、超时处理 4h=退回上一节点，超时退回让上一节点重新指派。
- 重要审批节点设超时处理=重置，超时退回制单人重新确认。

**开发要点**

- 定时任务扫描所有待办任务，按节点的审批时效判断是否超时。
- 挂起（B15）、终止（B14）的实例不参与超时计时。
- 超时处理三选一：
  - 提交：等同审批人通过，调用 B2 提交逻辑推进到下一节点。
  - 退回到上一节点：调用 B4 退回逻辑退回上一节点。
  - 重置：退回到开始节点（制单节点），调用 B5 驳回逻辑。
- 超时提醒与超时处理都记日志，标注是系统自动触发。
- 超时定时任务需考虑分布式部署下的并发控制，避免多节点重复处理同一任务（E5 分布式锁）。
- 频次提醒需持久化已提醒次数与上次提醒时间，防止重启后重复提醒。

---

### B17. 流程事件触发

**功能描述**

在流程实例生命周期的关键节点触发事件，向消息总线发业务消息或通知制单人。事件分流程级与节点级。

**详细使用**

- 流程级事件（A4 配置）：
  - 启动事件：实例创建时触发。
  - 结束事件：实例正常流转到结束节点时触发。
  - 终止事件：实例被终止/作废时触发。
- 节点级事件（A5 配置）：
  - 进入事件：节点被激活（任务生成）时触发。
  - 离开事件：节点被通过/取回/退回/转签离开时触发。
- 每类事件可勾选：消息事件（发业务消息到总线）、通知制单人事件（给制单人发 IM/邮件）。

**使用场景**

- 流程启动时发消息事件，触发下游系统（如财务系统预生成付款单）。
- 节点进入时通知制单人"单据已到 XX 审批环节"。
- 流程结束时通知制单人"单据已审批通过"。
- 流程终止时通知制单人"单据已作废"。

**开发要点**

- 事件触发时机必须精确：启动=实例创建瞬间；结束=流转到结束节点；终止=被作废；进入=任务生成；离开=节点通过/取回/退回/转签。
- 不同操作触发不同事件组合：提交触发当前节点离开 + 下一节点进入；退回触发当前节点离开（退回方向）+ 目标节点进入；取回触发当前节点重新激活（进入）。
- 事件触发失败不阻塞主流程流转，失败记录进 D2 异常单据监控与 D4 流程信息补偿重发。
- 消息事件与通知制单人事件是两个独立通道，可同时触发。
- 事件需带完整上下文（实例 ID、节点 ID、操作人、操作类型、单据摘要），供下游系统消费。

### B18. 流程图查看

**功能描述**

流程提交后预览所有审批节点及待审批人，展示当前流转位置。

**详细使用**

- 入口：在途单据或已办单据中点"查看流程图"。
- 访问方式：通过 URL 携带实例 ID 打开流程图页面，形如 `.../index.html#/formPlay?type=react&formID=sys_flow_show_image&username=xxx&OBJ_GUID={instanceId}`。
- 展示内容：流程名称、流程编号、节点颜色图例（已办/待办/未办）、流程图、流程任务列表（节点名称、流程名称、处理人、节点操作、转签/协审说明、处理时间、耗时、处理意见）。

**使用场景**

- 制单人查看报销单走到哪个节点、当前待办人是谁。
- 审批人查看流程全貌，了解前序审批意见与处理人。
- 管理员在 D2 异常监控中查看异常单据的流程图定位问题节点。

**开发要点**

- 流程图按实例当前状态渲染：已办节点、当前待办节点、未办节点用不同颜色区分。
- 流程任务列表按时间顺序展示全部节点处理记录，含转签/加签说明。
- 耗时按天计算（处理时间 - 节点进入时间）。
- 子流程实例的流程图需能从主流程图点击进入子流程图查看。
- 流程图查看是只读操作，不修改实例状态。

### B19. 流程审批整合

**功能描述**

自动整合重复审批人，同一人在前面节点已通过审批后，当前节点若该人仍是审批人则自动跳过，避免重复审批。

**详细使用**

- 配置（A5 节点审批设置）：重复审批处理方式 = 自动审批通过（默认）/ 禁止自动审批。
- 行为：
  - 自动审批通过（默认）：当前节点审批人与前面已通过节点审批人相同，则自动通过，无需再审。
  - 禁止自动审批：相同审批人必须再次审批方可通过。

**使用场景**

- 报销流程"部门经理审批"和"分管副总审批"都含张经理，张经理在第一节点审过后，第二节点自动通过，不再重复打扰。
- 某领导同时负责多个环节的最终把关，配置自动整合后只在其首次出现的节点审批一次。

**开发要点**

- 整合基于"前面已通过节点的审批人集合"判断，需维护实例的已审批人历史。
- 自动通过时记日志，标注是"重复审批自动通过"。
- 禁止自动审批时，即使审批人重复也正常生成待办要求其审批。
- 与 A10 自动提交的"默认原则"联动：默认原则中"此人已在前面节点处理过 → 自动审批"即依赖本整合逻辑。
- 会签节点的整合：会签人列表中若有人已在前面节点通过，按整合规则自动标记该人通过，剩余会签人正常审批。

---

### B20. 自动审批

**功能描述**

无需人工干预自动通过节点。分自动提交三模式与无审批人自动审批两类。配置见 A5/A10。

**详细使用**

- 自动提交三模式（节点级）：
  - 默认原则：全局自动审批配置开启 + 节点有且只有一个审批人 + 此人已在前面节点处理过 → 自动审批；否则不自动。
  - 强制自动提交：节点无论是否配置审批人均自动提交。
  - 禁止自动提交：即使符合自动审批条件也不自动提交。
- 无审批人时自动审批（节点级勾选）：审批人解析为空时自动通过提交下一节点。
- 虚拟节点（A5）：设计态确定自动提交，无需审批人。

**使用场景**

- 系统自动校验节点（如发票校验）设为强制自动提交，由业务系统通过事件回调决定是否通过。
- 财务人员离职未及时配置审批人，节点开启"无审批人时自动审批"避免单据卡死。
- 关键审批节点设"禁止自动提交"，即使同一人重复出现也必须人工确认。

**开发要点**

- 三模式优先级：强制 > 禁止 > 默认原则。强制自动提交时即使无审批人也直接通过；禁止自动提交时即使符合条件也不自动。
- "无审批人时自动审批"与三模式独立：解析后审批人为空时，若勾选则自动通过，否则挂起进异常（D2："存在未设置审批人的节点"）。
- 虚拟节点是设计态确定自动提交，与运行态自动审批不同，开发时区分。
- 自动审批需记日志，标注自动通过原因（强制/默认原则/无审批人/虚拟节点/重复审批）。
- 自动审批后照常触发节点离开事件与下一节点进入事件（B17）。

---

### B21. 重点人员拦截

**功能描述**

命中重点人员清单的审批人，待办先暂停并记录，由运维确认配置是否正确后决定是否继续。确认无误后该单再次走到此节点不再拦截。

**详细使用**

- 配置：运维维护重点人员清单（重点人员表）。
- 运行行为：节点审批人解析（A10）后，若审批人命中重点人员清单：
  - 待办状态置为暂停。
  - 记录拦截日志，触发 D2 异常单据监控通知运维。
  - 运维确认配置正确后放行，待办恢复正常，审批人收到待办。
  - 该单再次走到此节点不再拦截（拦截状态置为已确认）。

**使用场景**

- 高管人员作为审批人时，运维需确认流程配置是否有误（高管不该出现在普通报销节点），拦截后人工核查。
- 敏感岗位（如审计、合规）出现在审批节点时拦截，防止配置错误导致越权审批。

**开发要点**

- 重点人员清单由运维维护，支持增删改。
- 拦截是节点级 + 单据级：同一单据同一节点确认后不再拦截；不同单据或不同节点仍拦截。
- 拦截后待办暂停不计时（B16 超时定时对暂停待办不触发）。
- 运维放行操作记日志，标注确认人、确认结论。
- 拦截状态需持久化（已拦截/已确认），便于 D2 监控与再次流转判断。

---

### B22. 消息提醒

**功能描述**

单据状态变化时通过 IM/邮件通知审批人与发起人。贯穿流程全生命周期。

**详细使用**

- 触发场景：
  - 新待办生成：通知审批人有新待办（节点开启待办提醒，A5）。
  - 单据被处理：通知制单人单据进度变化（提交/退回/驳回/终止/挂起）。
  - 超时提醒：通知待办人单据超时（B16）。
  - 催办：通知待办人被催办（B13）。
  - 抄送：通知抄送人审批结果（B9）。
  - 委托：通知委托人与被委托人委托关系生效（B10）。
- 通知方式：IM 消息、邮件（E3）。

**使用场景**

- 经理收到 IM 消息"您有 3 条待办审批"，点开直接处理。
- 制单人收到邮件"您的报销单已被退回，请修改后重新提交"。
- 审批人收到超时提醒"您有 1 条待办已超时 8 小时，请尽快处理"。

**开发要点**

- 消息提醒依赖 E3 消息通道集成，IM 与邮件通道可独立配置。
- 待办提醒受节点"待办提醒"开关控制（A5），关闭则不发新待办消息。
- 消息内容需含单据摘要、操作入口链接、当前节点、待办人。
- 消息发送失败不阻塞流程，失败进 D4 信息补偿重发。
- 消息推送建议异步，避免影响主流程性能（E5 缓存与待办推送）。
- 消息发送记录入邮件发送日志（D3）。

## 4. 流程运维模块功能点

> 运维模块是管理员对在途单据与流程配置进行人工干预的入口，权限通常限于流程管理员或运维角色。

### C1. 待办转发

**功能描述**

将某用户名下的待办单据批量转给另一个用户。常用于人员离职、岗位调整、长期请假场景。

**详细使用**

- 入口：流程运维 → 待办转发。
- 操作步骤：
  - 选择原审批人（从用户列表选）。
  - 系统查询该用户全部待办（待办状态 pending 且待办人=选中用户）。
  - 设置目标审批人（从用户列表选）。
  - 设置"给新审批人发送消息"开关。
  - 勾选要转发的待办行（可全选）。
  - 点"转发"执行，将选中待办转给目标审批人。
- 转发后原审批人待办消失，目标审批人收到新待办。

**使用场景**

- 张经理离职，把他名下 20 条待办转发给接任的李经理。
- 某审批人休长假，期间待办转发给同事代为处理。

**开发要点**

- 查询待办按"待办人=原审批人 且 状态=pending"过滤，不含已办历史。
- 转发是待办人变更，不改变流程实例与节点，只换处理人。
- 转发记录入待办转发日志（D3 可查），含原审批人、新审批人、转发时间、单据列表。
- "给新审批人发送消息"开关控制是否触发 B22 消息提醒。
- 批量转发需事务保证，部分失败时返回失败列表。
- 转发后原审批人的已办记录保留（历史可追溯），只是待办转移。

### C2. 审批人批量替换

**功能描述**

批量替换流程节点配置中的指定人员，以及在途单据的审批人。比 C1 待办转发更彻底：不仅改在途待办，还改流程定义中的审批人配置。

**详细使用**

- 入口：流程运维 → 审批信息批量替换。
- 操作步骤：
  - 选组织机构。
  - 选当前审核人（要被替换的用户）。
  - 系统查询两类列表：
    - 流程节点指定人员调整：该用户作为指定审批人出现的流程节点配置。
    - 在途单据审批人调整：该用户作为审批人的在途单据待办。
  - 设置替换审核人（新审批人）。
  - 勾选要替换的行。
  - 点"替换"执行，将选中行的审批人从原用户替换为新用户。

**使用场景**

- 王主管调岗到其他部门，把他作为审批人的所有流程节点配置和在途单据批量替换给赵主管。
- 组织架构调整，某岗位撤销，该岗位下所有人的审批配置需批量替换到新岗位。

**开发要点**

- 查询分两类：流程定义中的审批人配置（影响未来单据）+ 在途单据的审批人（影响当前单据），两类都需替换才能彻底切换。
- 替换流程节点配置：修改审批定义中的指定人员，新单据发起后按新审批人生成待办。
- 替换在途单据：修改运行中任务的待办人，新审批人立即收到待办。
- 替换需事务保证，返回成功/失败列表。
- 替换记录入流程配置操作日志与待办转发日志（D3）。
- 替换是覆盖操作，替换后原审批人不再出现在该节点/该单据，需谨慎并二次确认。

---

### C3. 单据流程介入

**功能描述**

管理员对异常单据直接执行提交/退回/重置操作，绕过常规审批流程。是处理异常单据的兜底手段。

**详细使用**

- 入口：流程运维 → 单据流程介入。
- 操作步骤：
  - 输入单据编号搜索，定位异常单据。
  - 查看单据当前节点、状态、流程图。
  - 选处理方式：提交 / 退回 / 重置。
  - 填写审批意见（处理人默认当前登录管理员）。
  - 点"执行"：
    - 提交 → 调用 B2 提交逻辑推进到下一节点。
    - 退回 → 调用 B4 退回逻辑退回指定/上一节点。
    - 重置 → 调用重置逻辑退回到制单节点。

**使用场景**

- 单据卡在某个节点长时间无审批人处理（审批人离职且未配置替换），管理员介入直接提交推进。
- 流程配置有误导致单据异常，管理员介入退回到正确节点。
- 单据需要重新填报，管理员重置退回制单节点。

**开发要点**

- 介入是管理员特权操作，需严格权限控制并记操作日志（操作人、操作类型、单据、目标节点）。
- 介入的提交/退回/重置复用 B2/B4/B5 的底层逻辑，但跳过待办人校验（管理员不是待办人也能操作）。
- 介入操作应在 D2 异常单据监控中标记该单据已处理。
- 介入前建议展示流程图让管理员确认当前节点与目标节点，避免误操作。
- 重置退回到制单节点后，制单人重新收到待办可修改重新提交。

### C4. 委托审批设置

**功能描述**

维护委托审批关系，配置某用户在一段时间内将其待办委托给他人代审。委托运行时生效见 B10。

**详细使用**

- 入口：流程控制 → 委托审批设置。
- 新增/编辑委托（抽屉表单）字段：
  - 委托人：发起委托的用户。
  - 被委托人：代为审批的用户。
  - 委托开始时间、委托结束时间：委托有效期。
  - 委托流程：指定委托哪些流程（可选全部或指定流程）。
  - 组织机构：委托范围的组织。
  - 使用状态：启用 / 停用。
- 列表展示：序号、委托人、被委托人、委托流程、组织机构、使用状态、委托开始/结束时间、操作（编辑/删除/停用启用）。
- 操作均需二次确认。
- 支持按委托人筛选查询。

**使用场景**

- 经理出差一周，提前设置委托关系，出差期间报销单自动委托给副经理。
- 某审批人休假，设置委托并指定委托流程范围（只委托报销和请假流程，合同流程不委托）。

**开发要点**

- 委托关系字段需完整持久化，运行时 B10 审批人解析时查询匹配。
- 委托范围支持按流程和组织过滤，不指定则全部流程全部组织。
- 使用状态控制委托是否生效，停用后即使有效期内存也不触发。
- 委托时间到期自动失效，建议有定时任务清理过期委托或运行时判断有效期。
- 删除委托关系不影响已按委托处理的在途单据，只影响后续。
- 编辑/删除/启停操作记流程配置操作日志（D3）。

### C5. 流程信息导入导出（运维）

**功能描述**

运维侧的流程信息迁移，与 A11 功能重叠但入口在运维模块。用于运维人员跨环境迁移流程。

**详细使用**

- 入口：流程运维 → 流程信息导入导出。
- 功能同 A11：导出流程图、审批信息、分支条件；导入还原。

**使用场景**

- 运维从测试环境导出调通的流程导入生产环境。
- 跨系统迁移流程配置。

**开发要点**

- 与 A11 共用底层实现，只是入口不同（一个在设计侧，一个在运维侧）。
- 运维侧操作需更高权限，记录流程配置操作日志（D3）。
- 其余开发要点同 A11。

## 5. 流程监控模块功能点

> 监控模块是流程运行可观测性的核心，覆盖全局驾驶舱、异常处理、日志查询、消息补偿。

### D1. 驾驶舱

**功能描述**

对流程审批的全局量化展示，含人员审批节点、岗位审批节点、会签审批节点、节点人员/岗位/会签信息、岗位定义、流转条件、审批任务、单据信息的统计视图。

**详细使用**

- 入口：流程监控 → 驾驶舱。
- 展示维度：
  - 人员审批节点统计：按审批人统计待办数、已办数、平均耗时。
  - 岗位审批节点统计：按岗位统计审批任务分布。
  - 会签审批节点统计：会签节点的通过率、平均完成人数。
  - 节点信息：各节点配置的人员/岗位/会签信息汇总。
  - 审批任务：在途任务总数、按流程分布、按节点分布。
  - 单据信息：单据状态分布（待办/在途/已结束/异常）。

**使用场景**

- 流程管理员每日查看驾驶舱，了解全局审批负载，识别瓶颈节点。
- 管理层查看会签通过率，评估会签流程合理性。
- 运维查看异常单据占比，及时发现系统问题。

**开发要点**

- 驾驶舱是只读统计视图，数据来自运行时任务表与流程定义表。
- 统计数据量大时建议预聚合或缓存（E5），避免实时全表扫描影响性能。
- 展示维度可按时间范围、组织机构、流程类型过滤。
- 驾驶舱数据有延迟可接受（准实时即可），不需与运行时强一致。

---

### D2. 异常单据监控

**功能描述**

查询和处理流程运行中的异常单据。异常类型覆盖流程引擎各类错误，是异常兜底处理的核心入口。

**详细使用**

- 入口：流程监控 → 异常单据监控。
- 查询条件：
  - 时间范围：精确到秒。
  - 异常类型：下拉选择。
  - 表单编号：文本输入（如 `CLBX20231226001`）。
- 异常类型枚举：
  - 业务服务调用异常
  - 审批信息异常
  - 解析分支条件异常
  - 解析子流程异常
  - 制单节点提交检查异常
  - 操作加锁异常
  - 存在未设置审批人的节点
  - 无待办任务
  - 当前节点无出去的边
  - 流程没有启动
  - 引擎异常
- 操作：
  - 处理：标记已处理，单据从异常列表消失（配合 C3 介入修复）。
  - 刷新：重新加载列表。
  - 查看异常类型、查看异常信息详情。
  - 查看流程图：展示流程名称/编号、分支条件过滤、节点颜色图例（已办/待办/未办）、流程图、流程任务列表（节点名称、流程名称、处理人、节点操作、转签/协审说明、处理时间、耗时、处理意见）。

**使用场景**

- 审批人离职导致节点无审批人，单据进入"存在未设置审批人的节点"异常，运维通过 C2 批量替换审批人后在 D2 标记已处理。
- 分支条件配置错误导致"解析分支条件异常"，运维查看流程图定位问题边，修正条件后标记已处理。
- 子流程未配置导致"解析子流程异常"，运维补充子流程配置后处理。

**开发要点**

- 异常类型枚举需覆盖流程引擎全部错误场景，新增异常类型时同步更新枚举。
- 异常单据需记录异常发生时间、异常类型、异常详情、实例 ID、节点 ID，便于定位。
- "处理"操作是人工标记，不自动修复单据；实际修复靠 C2/C3 运维操作。
- 查看流程图复用 B18 流程图查看能力，附加异常位置高亮。
- 异常列表量大时需分页与按时间范围过滤，避免全量加载。
- 重点人员拦截（B21）产生的暂停待办也在此监控，异常类型可归为"审批信息异常"或独立类型。

---

### D3. 流程日志查询

**功能描述**

8 类流程日志分页签查询，覆盖流程运行全过程可追溯。每类日志独立查询条件与数据来源。

**详细使用**

- 入口：流程监控 → 流程日志查询。
- 8 类日志页签：

| 日志类型 | 关键查询条件 | 用途 |
|---|---|---|
| 操作流程回滚日志 | 单据编号、单据 GUID | 追溯退回/取回/驳回的回滚记录 |
| 流程服务执行日志 | 单据编号 | 追溯流程服务调用记录 |
| 待办转发日志 | 单据编号、单据 GUID | 追溯 C1 待办转发与 C2 批量替换 |
| 流程数据迁移日志 | 开始/结束时间 | 追溯 A11/C5 导入导出迁移 |
| 邮件发送日志 | 单据编号、开始/结束时间 | 追溯 B22 邮件通知发送 |
| 结束流程日志 | 单据编号、开始/结束时间 | 追溯流程实例结束记录 |
| 流程操作日志 | 单据编号、单据 GUID | 追溯提交/退回/加签等全部操作 |
| 流程配置操作日志 | 表单类型、操作表、组织机构编号、流程编号 | 追溯流程定义与审批定义的配置变更 |

- 每个页签支持查询与重置。

**使用场景**

- 单据审批有争议时，查"流程操作日志"还原完整审批轨迹。
- 怀疑待办被误转发，查"待办转发日志"确认转发人与时间。
- 流程配置被误改，查"流程配置操作日志"定位变更人与变更内容。
- 邮件未收到，查"邮件发送日志"确认是否发送成功。

**开发要点**

- 8 类日志对应不同存储，查询时按类型路由到对应数据源。
- 日志需包含操作人、操作时间、操作类型、操作对象（实例/节点/单据）、操作详情，保证可追溯。
- 日志量大需分页查询，按时间倒序展示。
- 日志是只读，不允许修改，保证审计可信。
- 流程操作日志是核心，需覆盖 B1-B17 全部运行时操作。
- 流程配置操作日志需覆盖 A1-A12 的设计态配置变更与 C1-C5 运维操作。

### D4. 流程信息补偿

**功能描述**

流程事件消息发送异常时，通过该功能重新发送消息。是事件触发的兜底补偿机制。

**详细使用**

- 入口：流程监控 → 流程信息补偿。
- 查询发送失败的事件消息列表。
- 选择失败消息，点"重发"重新发送到消息总线或通知制单人。

**使用场景**

- 流程结束时本应通知财务系统打款，但消息总线异常发送失败，运维在 D4 手动重发。
- 节点进入事件未通知制单人，运维补偿重发通知。

**开发要点**

- 事件触发失败（B17）时，失败消息记录到补偿表，含事件类型、实例 ID、节点 ID、消息内容、失败原因、失败时间。
- 重发复用 B17 事件触发逻辑，重发成功后标记为已补偿。
- 重发可多次尝试，记录重发次数与最近重发时间。
- 补偿表需定期清理已补偿成功的记录，避免无限增长。
- 补偿是人工触发，也可配置定时任务自动重发失败消息。

## 6. 系统集成与配置模块功能点

> 本模块是流程中心与外部系统、基础设施的集成层，为上述 A-D 模块提供底层支撑。开发时建议优先实现本模块，再实现业务模块。

### E1. 组织机构集成

**功能描述**

加载组织机构树，供流程设计、审批人解析、子流程匹配按组织过滤。组织机构是流程差异化的核心维度。

**详细使用**

- 数据来源：组织机构主数据（外部主数据系统或内置组织表）。
- 加载方式：提供组织机构树加载服务，返回树形结构（组织 ID、组织名称、上级组织、层级、排序）。
- 使用场景：
  - A8 子流程设计左侧组织树。
  - A9 流程审批定义左侧组织树。
  - C2 审批人批量替换选组织。
  - A10 部门领导解析时上溯组织树。

**使用场景**

- 子流程按分公司差异化：加载集团组织树，选中"北京分公司"后配置该分公司的子流程。
- 部门领导解析：员工 A 在"销售部-华东大区"，解析其上级部门领导需沿组织树上溯到"销售部"。

**开发要点**

- 组织机构树需支持懒加载（节点展开时加载子节点），避免全量加载大数据量组织树。
- 组织层级关系需完整（上级组织指针），支持"上级/上上级/顶级部门领导"逐级上溯解析（A10）。
- 组织数据缓存（E5）减少频繁查询主数据系统。
- 组织变更（合并、拆分、撤销）时，已配置的流程审批定义需能适应（按组织 ID 匹配，组织撤销后相关配置失效）。
- 提供按组织过滤流程、待办、单据的通用能力。

---

### E2. 用户与岗位集成

**功能描述**

加载用户、岗位、部门领导数据，供审批人解析、人员选择、委托配置使用。

**详细使用**

- 数据来源：用户主数据、岗位主数据。
- 用户数据：用户 ID、姓名、所属组织、岗位、职级等。
- 岗位数据：岗位编号、岗位名称、岗位所属组织、岗位下人员列表。
- 部门领导：组织与领导的对应关系（某组织的正职/副职领导）。
- 使用场景：
  - A9 审批定义的人员选择弹窗。
  - A10 审批人解析（指定人员/指定岗位/部门领导）。
  - C1 待办转发、C2 批量替换的用户选择。
  - C4 委托审批设置的委托人/被委托人选择。

**使用场景**

- 报销节点配"指定岗位 = 财务复核岗"，运行时解析该岗位下所有人员作为审批人。
- 请假节点配"提单人部门领导"，自动解析发起人所在部门的正职领导。

**开发要点**

- 用户与岗位是多对多关系（一人可多岗，一岗可多人），解析时需完整返回。
- 部门领导解析需明确"正职/副职/上级/上上级/顶级"的层级规则，与 E1 组织树配合。
- 人员选择弹窗需支持按组织、按岗位、按姓名筛选，大数据量时分页加载。
- 用户、岗位数据缓存（E5），主数据变更时刷新缓存。
- 用户离职/调岗时，其作为审批人的在途单据需通过 C2 批量替换处理。

### E3. 消息通道集成

**功能描述**

集成 IM 与邮件通道，为待办提醒、催办、抄送、事件通知提供消息发送能力。

**详细使用**

- 通道类型：
  - IM 消息：企业 IM（如飞书、钉钉、企业微信），推送待办、催办、状态变更通知。
  - 邮件：发送审批结果、抄送、异常通知邮件。
- 消息内容：单据摘要、操作入口链接、当前节点、待办人、操作类型。
- 调用方式：提供统一消息发送接口，内部路由到 IM 或邮件通道。

**使用场景**

- 审批人收到 IM 待办推送，点击直接打开单据处理。
- 制单人收到邮件"您的报销单已审批通过"。
- 超时提醒通过 IM 推送给待办人。

**开发要点**

- IM 与邮件通道独立配置，可分别启用/停用。
- 消息发送异步化，不阻塞主流程流转；发送结果回调更新发送状态。
- 消息发送失败记录到 D3 邮件发送日志与 D4 信息补偿表，支持重发。
- 消息内容模板化，不同场景（待办/催办/抄送/超时/终止）用不同模板。
- 消息去重：同一事件短时间内不重复发送（如节点进入事件因重试只发一次）。
- 通道适配层设计，便于扩展新通道（短信、站内信等）。

### E4. 多数据库适配

**功能描述**

支持 MySQL、Oracle、国产数据库，流程定义与运行时数据可跨数据库部署。

**详细使用**

- 支持数据库：MySQL、Oracle、国产数据库（如达梦、人大金仓）。
- 标准库导入：提供标准库脚本，初始化流程中心所需全部表结构。
- 数据库切换：通过配置切换数据库类型，SQL 自动适配。

**使用场景**

- 企业信创要求，流程中心部署在国产数据库（达梦）上。
- 不同客户环境不同，一套代码适配 MySQL 与 Oracle。

**开发要点**

- SQL 需兼容多数据库方言，避免数据库特定语法；或通过数据库适配层翻译。
- 主键生成策略需跨数据库一致（如使用 GUID 而非数据库自增）。
- 分页查询不同数据库语法不同（MySQL LIMIT / Oracle ROWNUM / 国产库），需适配。
- 大字段（BPMN XML）存储各数据库类型不同（TEXT/CLOB），需适配。
- 标准库脚本需随版本升级提供增量脚本，支持平滑升级。
- 提供数据库连接配置与切换的统一管理。

### E5. 缓存与分布式锁

**功能描述**

基于 Redis 提供缓存、分布式锁、待办推送能力，保障高并发下的性能与数据一致性。

**详细使用**

- 缓存：流程定义、组织机构、用户岗位、字典等热点数据缓存到 Redis，减少数据库查询。
- 分布式锁：流程实例操作（提交/退回/取回/加签等）对实例 ID 加锁，防止并发篡改。
- 待办推送：待办生成时通过 Redis 发布订阅推送给前端，实现待办实时刷新。
- 会话与状态：运行时任务状态、超时计时等可基于 Redis 维护。

**使用场景**

- 高并发报销审批（月末集中报销），缓存流程定义避免每次查库。
- 同一单据被两人同时提交，分布式锁保证只有一个提交成功。
- 审批人前端待办列表实时刷新，新待办即时可见。

**开发要点**

- 缓存需设置合理过期时间与刷新策略，避免脏数据；主数据变更时主动刷新缓存。
- 分布式锁需设超时时间，防止持锁进程异常导致死锁；锁粒度为实例 ID，不影响其他实例并发。
- 待办推送基于 Redis 发布订阅，前端订阅待办频道实时接收；需处理断线重连与消息补偿。
- 缓存击穿/雪崩防护：热点 key 加互斥锁，缓存同时过期时分级过期。
- Redis 需高可用部署（主从/集群），避免单点故障导致流程中心不可用。
- 锁异常记入 D2 异常单据监控（异常类型"操作加锁异常"）。

## 7. 功能点开发优先级建议

|---|---|---|
| P0 | E1 组织机构集成、E2 用户与岗位集成、E4 多数据库适配、E5 缓存与分布式锁 | 底层支撑，所有业务功能依赖 |
| P0 | A1 流程分组管理、A2 主流程列表管理 | 流程管理入口 |

## 8. 关键业务规则速查

以下规则散落各功能点，开发时需全局遵守，汇总于此便于对照。

1. 一个流程有且仅有一个开始节点、一个结束节点；子流程同理（A3/A8）。
2. 节点编号 `S_x`、边编号 `R_x` 自动生成且不可编辑，删除后不回收复用（A3/A5/A6）。
3. 子流程挂在"子流程边"上，按组织机构差异化；进入子流程需满足"进入子流程条件"；新建子流程设置条件前必须先保存一次（A8）。
4. 会签四种策略：或签（任一通过）、串行会签（顺序全通过）、并行会签（全部通过）、票签（累计通过权重 > 阈值）；任一人退回则整单退回，任一人驳回则整单驳回（A9/B8）。
5. 重复审批人默认自动通过；可设禁止自动审批（A5/B19）。
6. 自动提交三模式优先级：强制 > 禁止 > 默认原则；无审批人时自动审批是独立开关（A10/B20）。
7. 排他边为出边条件全不满足时的兜底，一个节点出边中排他边最多一条（A6）。
8. 取回要求下一节点未审批；制单人可取回任意节点，普通审批人只能取回自己刚提交的（B3）。
9. 驳回 = 退回开始节点；退回可指定节点或上一节点；退回目标必须在已走过路径上（B4/B5）。
10. 加签分事前（B 审完回 A）/事后（B 审完节点即过，等同转签）；转签后原审批人不再待办（B6/B7）。
11. 委托生效后委托人与被委托人均可见待办，任一处理即完成（B10/C4）。
12. 超时支持提醒（时效 + 频次）与处理（提交 / 退回上一节点 / 重置）；挂起、终止的实例不计时（A9/B16）。
13. 重点人员命中即暂停待办，运维确认后放行，同单同节点再走不再拦截；暂停不计时（B21）。
14. 流程事件分流程级（启动/结束/终止）与节点级（进入/离开），触发失败不阻塞流转，进 D4 补偿（A4/A5/B17）。
15. 所有运行时操作记日志；异常进 D2 异常单据监控并支持补偿（D2/D3/D4）。
16. 虚拟节点设计态自动提交，退回/取回可跳过；与运行态"无审批人自动审批"是两种机制（A5/B20）。
17. 流程实例操作（提交/退回/取回/加签等）需对实例 ID 加分布式锁，防止并发篡改（B2/E5）。
18. 操作幂等：按 `taskId + instanceId + timestamp` 控制，重复提交安全（B2）。
19. 按钮权限（A5）决定审批人能执行哪些操作，未启用的按钮前端不展示且后端拒绝执行。
20. 停用的流程不允许发起新实例，但已存在的在途实例继续流转至结束（A2）。

## A

### aggregate · 聚合
- **中文**：聚合
- **章节**：[09-主从协调器](09-主从协调器-CmxMasterSlave.md)、[10-弹性组合](10-弹性组合-FlexibleCombination.md)
- **解释**：把子表的某些字段按 sum/avg/min/max/count 汇总到主表。子表行变化时自动重算。
- **示例**：分录的 `debit` 改了 → 表头 `totalDebit` 自动 sum。

### aggregation rule · 聚合规则
- **章节**：[09-主从协调器 §6](09-主从协调器-CmxMasterSlave.md#6-aggregations聚合规则怎么配)
- **解释**：聚合规则的"配方"，含 `from / agg / field / to / toField` 五要素。
- **示例**：`{from:'head.items', agg:'sum', field:'debit', to:'head', toField:'totalDebit'}`。

### anchor / 锚点
- **章节**：[10-弹性组合 §4-6](10-弹性组合-FlexibleCombination.md#4-字段速查表)
- **解释**：驱动弹性组合列变化的"维度组合"。形如 `{ account: '1122' }`。
- **示例**：选了"应收账款"科目 → `account='1122'` 就是锚点。

### attribute · 属性
- **章节**：[10-弹性组合 §8](10-弹性组合-FlexibleCombination.md#8-字段三态fieldspeckind)
- **解释**：维度自带的"次要字段"，由所选维度自动带出，无需用户手输。
- **示例**：选了"产品"后，自动出现"规格/单位"——这些就是 attribute。

### autoLoad · 自动加载
- **章节**：[04-字典模型 §3](04-字典模型-CmxDCTMeta.md#3-字段速查表)、[05-单据模型](05-单据模型-CmxDOCMeta.md)
- **解释**：页面打开后，是否自动调 `loadById` 加载元数据。
- **示例**：`CmxDCTMeta { autoLoad: true }` → 页面连进来就 GET 元数据。

## B

### baseFieldSet / 基础字段集
- **章节**：[06-基础元数据 §6](06-基础元数据-BASE是什么.md#6-字段集分类dct-vs-doc)
- **解释**：DCT/DOC 字典表/单据表上引用的"基础字段集"——一般放 `id/code/name/status` 等通用字段。
- **示例**：`{ baseFieldSet: { use: 'common_audit' } }` → 加载 `common_audit` 字段集。

### BASE 元数据 · 基础元数据
- **章节**：[06-基础元数据](06-基础元数据-BASE是什么.md)
- **解释**：DCT/DOC 文档里**独立于本表**的共享字段集存放地。多个文档可共享。
- **示例**：`base_dct_meta_v1.json` 里写一份 `common_audit` 字段集，GL/AR/AP 都引用它。

### batch loading · 批量加载
- **章节**：[04-字典模型 §5](04-字典模型-CmxDCTMeta.md#5-加载方式4-种优先级)
- **解释**：`loadMetaBatch` 一次性把多个 DCT/DOC + 它们的 base 拉完，避免 N 次请求。
- **示例**：`loadMetaBatch([{domain:'fi', module:'gl', file:'...' }, {domain:'fi', module:'ar', file:'...' }])`。

## C

### caption · 显示标题
- **章节**：[13-常用字段速查 §2](13-常用字段速查表.md#2-cmxcolumn-字段速查)
- **解释**：列/字段在 UI 上的"名字"。支持多语言对象 `caption: { zh_CN: '...', en_US: '...' }`。
- **示例**：`caption: { zh_CN: '借方金额' }`。

### CmxColumn · 列对象
- **章节**：[08-列模型](08-列模型-CmxColumnModel.md)
- **解释**：列模型里"一列"的运行时对象，含 id/caption/dataType/edit/display 等。
- **示例**：`new CmxColumn({ id:'debit', dataType:'number', agg:'sum', edit:{mode:'input'} })`。

### CmxColumnGroup · 列组
- **章节**：[08-列模型](08-列模型-CmxColumnModel.md)
- **解释**：把多列合成一组，可整组合并单元格 / 整组做合计。
- **示例**：`{ id:'amountInfo', caption:'金额信息', members:['debit','credit'] }`。

### CmxColumnModel · 列模型
- **章节**：[08-列模型](08-列模型-CmxColumnModel.md)
- **解释**：表格"列模板"，定义有哪些列、每列怎么显示和编辑。被 `<cmx-revo-grid>` 等可视组件消费。
- **示例**：`new CmxColumnModel({ datasetId:'items', members:[...] })`。

### CmxDCTMeta · 数据字典元数据
- **章节**：[04-字典模型](04-字典模型-CmxDCTMeta.md)
- **解释**：运行时加载并暴露"数据字典"元数据的模型组件。
- **示例**：`host.glDctMeta.getDictionary('gl_account')`。

### CmxDataSet · 数据集
- **章节**：[07-数据集](07-数据集-CmxDataSet.md)
- **解释**："一堆行"的容器，可树形。`CmxMasterSlave` 用它组织主子数据。
- **示例**：`new CmxDataSet({ datasetId:'items' })`。

### CmxDOCMeta · 业务单据元数据
- **章节**：[05-单据模型](05-单据模型-CmxDOCMeta.md)
- **解释**：运行时加载并暴露"业务单据"元数据（含 `voucherTables` / `voucherCommonFieldSet`）的模型组件。
- **示例**：`host.voucherDocMeta.getDocument('voucher')`。

### CmxFlexibleCombination · 弹性组合
- **章节**：[10-弹性组合](10-弹性组合-FlexibleCombination.md)
- **解释**：按维度组合动态生成 `CmxColumn[]` 并写入目标 CmxColumnModel 的模型组件。
- **示例**：`host.detailFC.loadByAnchor({ account: '1122' })`。

### CmxMasterSlave · 主从协调器
- **章节**：[09-主从协调器](09-主从协调器-CmxMasterSlave.md)
- **解释**：业务无感知的"主从多表管家"。负责数据树、视图绑定、选中联动、自动聚合。
- **示例**：`host.ms.setFlatData({ head, items, details }, { relations: [...] })`。

### column / 列
- **章节**：[08-列模型](08-列模型-CmxColumnModel.md)
- **解释**：表格里的一列，含 id/caption/dataType/edit/display/agg 等。

### columnModelId · 列模型实例名
- **章节**：[10-弹性组合 §4](10-弹性组合-FlexibleCombination.md#4-字段速查表)
- **解释**：弹性组合要写入的"目标 CmxColumnModel"的 `instanceId`。**必填**。
- **示例**：`columnModelId: 'detailModel'` → 弹性组合会改 `host.detailModel` 的列。

### cmx-container
- **章节**：[01-项目总览](01-项目总览-两个项目干什么的.md)、[00-术语表 §1](00-术语表-名词解释.md#1-项目相关)
- **解释**：Rust 后端。**替代了原 `cmx-node-server`**（Node 服务已于 2026-06 下线），统一提供 REST API + 数据存储。业务在 `crates/libs/cmx-portal/`，HTTP 在 `crates/libs/cmx-api/`，模型中心在 `crates/libs/cmx-model/`。
- **示例**：`cd cmx-container && cargo run -p web-server`（默认 `:8080`）。
- **数据根**：`cmx-container/data/`（由 `dev-local.toml` 的 `[portal] data_root = "./data"` 指定；亦可用 `CMX_PORTAL_DATA_ROOT` 覆盖）。
- **常见子目录**：
  - `data/html-pages/sources/` — 设计器导出的 HTML 页面源文件
  - `data/dict/entries/` — 数据字典条目
  - `data/meta/definitions/` — DCT/DOC/BASE 元数据 JSON
  - `data/meta/flexible-combination/` — 弹性组合规则 JSON
  - `data/fact/` — 业务事实数据

### cmx-data-comp
- **章节**：[01-项目总览](01-项目总览-两个项目干什么的.md)
- **解释**：共享数据组件库（`packages/cmx-data-comp/`），提供 6 大模型类的实现 + 运行时初始化入口。
- **示例**：`import { CmxMasterSlave } from 'cmx-data-comp/lib/cmx-master-slave.js'`。

### CMX
- **章节**：[00-术语表 §1](00-术语表-名词解释.md#1-项目相关)
- **解释**：整套低代码开发框架的总称。
- **示例**：CMXHTMLDesigner / CMXPortalManager / cmx-data-comp / cmx-container 都是 CMX 家族成员。

### CMXHTMLDesigner
- **章节**：[01-项目总览](01-项目总览-两个项目干什么的.md)
- **解释**：HTML 页面可视化设计器，开发者用拖拽出业务页面。
- **示例**：`cd CMXHTMLDesigner && npm run dev`。

### CMXPortalManager
- **章节**：[01-项目总览](01-项目总览-两个项目干什么的.md)
- **解释**：门户管理端，管理菜单、字典、单据、弹性组合等设计期元数据。**纯前端**，不再自带后端（后端统一走 cmx-container）。
- **示例**：`portal-definition-manager` 组件就在这里。

### kind · 四大文件类型枚举
- **章节**：[16-后端 API §1.4](16-后端API详解.md#14-kind-枚举值详解dct--doc--base--flc)
- **解释**：`/api/definitions/*` 等接口的 `kind` 参数。共 4 个值：DCT / DOC / BASE / FLC。
- **四者速记**：
  - **DCT** = Data Code Table（**字典**），给 [CmxDCTMeta](04-字典模型-CmxDCTMeta.md) 用
  - **DOC** = Document Of Content（**单据**），给 [CmxDOCMeta](05-单据模型-CmxDOCMeta.md) 用
  - **BASE** = 基础元数据（**字段集集合集**），被 DCT/DOC 通过 `use: 'xxx'` 引用
  - **FLC** = Flexible Combination Logic（**弹性组合规则**），给 [CmxFlexibleCombination / ContextProfile](10-弹性组合-FlexibleCombination.md) 用
- **存储路径**：
  - DCT/DOC/BASE → `cmx-container/data/meta/definitions/<domain>/<app>/<module>/<file>`
  - FLC → `cmx-container/data/meta/flexible-combination/<domain>/<app>/<module>/<scenario>/<file>`

### dictKind · 字典种类
- **章节**：[17-元数据 JSON §3.5.1](17-元数据JSON文件字段详解.md#351-dictmeta字典元信息)
- **解释**：DCT 字典的分类，三种值：
  - `BUSINESS` 业务主数据（客户、科目、银行账户）
  - `CLASSIFY` 基础分类（国家、币种、科目组）
  - `GROUP` 分组层级（报表版本、fs_version）
- **影响**：设计期会按 `dictKind` 默认加载不同的 `baseFieldSet`

### selfHierarchy · 自分级
- **章节**：[17-元数据 JSON §3.5.1](17-元数据JSON文件字段详解.md#351-dictmeta字典元信息)
- **解释**：字典表**内部**是否有父子关系（gl_account 父子科目、fs_version 报表版本）
- **`true` 时**：多了 `hierarchyFieldSet: "dictionaryHierarchyFields"`（parent_id / full_path / level_no / is_leaf）
- **`false` 时**：是平表，只有一个 `parent_id` 也没有
- 与"关系字典（dictionaryCommonFields relationCommonFields）"不同——`selfHierarchy` 是表内，`relationCommonFields` 是表间

### physicalField · 物理列名
- **章节**：[17-元数据 JSON §2.2](17-元数据JSON文件字段详解.md#22-通用列字段每个-fields-元素几乎都有)
- **解释**：字段对应的**实际数据库列名**或**外部系统列名**（SAP 字段名）。
- **例子**：`physicalField: "MANDT"` / `"BUKRS"` / `"LOGSYS"`
- **何时用**：数据迁移、从 SAP 导入、跨系统对接

### voucherSchema · 凭证结构
- **章节**：[17-元数据 JSON §5.4](17-元数据JSON文件字段详解.md#54-voucherschema单据的形状)
- **解释**：DOC 业务单据的"形状"——含 3 个子段：
  - `schema`：二维数组，描述单据有几层、每层有几张表
  - `relations`：层间主外键关系
  - `aggregations`：逐层上卷的聚合规则
- **真实例子**：cmxfico 凭证 4 层（批→头→科目行→辅助行）

### ContextProfile · 弹性组合的别名
- **章节**：[02-模型体系全景图](02-模型体系全景图.md)、[10-弹性组合 §1](10-弹性组合-FlexibleCombination.md#1-它是啥)、[11-模型事件 §6](11-模型事件与脚本.md#6-弹性组合的事件)
- **解释**：6 大模型里第 6 个 `FlexibleCombination` 的**早期别名 / 同义词**。常见出现位置：
  - **代码层**：类名 `CmxFlexibleCombination`（`packages/cmx-data-comp/src/lib/cmx-flexible-combination.js`）、后端 crate `cmx-model::flexible_combination`（`cmx-container/crates/libs/cmx-model/src/flexible_combination/`）
  - **设计器**：`__designer_meta__.models[i].modelType` 字符串值为 `"FlexibleCombination"`
  - **AI 知识库 / 工具**：`.qoder/repowiki/zh/content/...` 整本 wiki + [docs/AI_Form_Agent_task-23d.md:322](file:///media/yqs/工作/rustspace/cmx/docs/AI_Form_Agent_task-23d.md#L322) 把 `modelType` 枚举写成 `CmxDataSet/CmxMasterSlave/CmxColumnModel/CmxDCTMeta/CmxDOCMeta/ContextProfile`
  - **文档别名**：`flexible-combination-overlay-design.md` 用的术语是 "CTX"（Context 取首字母）
- **关系总结**：三处指同一物——AI 提示词写 `ContextProfile`，设计器 `modelType` 写 `FlexibleCombination`，代码 import 用 `CmxFlexibleCombination`，后端叫 `flexible_combination`。**读文档时看到 ContextProfile = 看 FlexibleCombination**。

### cursor-changed · 游标变化
- **章节**：[11-模型事件 §3.1](11-模型事件与脚本.md#31-cmxdataset-事件)
- **解释**：CmxDataSet 的"当前行"移动时触发。`event.detail = { index, prevIndex, row, id }`。

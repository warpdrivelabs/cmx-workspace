# 共享格式 + 多套数据：报表模板与数据维度分离方案

> 主题：多 sheet 报表结构体中，**行/列/单元格的格式是一套（共享），但单元格里的数据可以有多套**。
> 典型场景：多个公司共享同一套报表格式，报表中的数据可以是不同公司的；可在相同格式下切换公司/类别，显示不同的数据。

## 一、核心思路：格式层与数据层分离

一句话：**把"格式/结构"和"数据"拆成两层。**

| 层 | 内容 | 份数 |
|----|------|------|
| **模板层（格式/结构）** | 行、列、单元格位置、样式、数字格式、合并区、**公式文本**、静态标签 | 全局**一份**共享 |
| **数据层** | 数据格的实际值、公式格的缓存结果 | 按业务维度**多套**（每公司/类别/期间一套） |

这正是 OLAP / 报表模板的经典分离：**模板定义"长什么样、怎么算"，数据维度提供"算什么数"。**

> 反面教训：如果像第一篇那样把 value 直接放在 cell 上，那么"多公司"就只能复制整张表 N 份——模板改一处要改 N 份、体积 ×N、格式极易漂移。分离后模板永远一份。

## 二、三层概念模型

```
┌───────────────────────────────────────────────────────────┐
│ 模板层 Template（共享一份）                                 │
│   Sheet 结构：rows/cols 稳定身份 + 顺序 + 合并区             │
│   TemplateCell：位置 + 样式 + 数字格式 + 种类(静态/数据/公式)│
│     · 静态格：值就在这里（标签/表头，所有维度相同）          │
│     · 数据格：只占位，值来自数据层                          │
│     · 公式格：公式文本在这里，结果在数据层                  │
└───────────────────────────────┬───────────────────────────┘
                                 │ 套用
        ┌────────────────────────┼────────────────────────┐
        ▼                        ▼                        ▼
┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│ DataPlane     │        │ DataPlane     │        │ DataPlane     │
│ 上下文=C001   │        │ 上下文=C002   │        │ 上下文=合并    │
│ {数据格→值,   │        │ {数据格→值,   │        │ {...}         │
│  公式格→缓存} │        │  公式格→缓存} │        │               │
└──────────────┘        └──────────────┘        └──────────────┘
  (稀疏，只存有值的格)
```

- **模板层**：一份，常驻内存。
- **数据层**：每个"上下文"（维度坐标）一张稀疏的 `DataPlane`，按需加载。
- **渲染**：`模板 + 当前上下文的 DataPlane` 合并出最终可见表格。

## 三、单元格的三种类型（关键）

模板里每个单元格必须标明它属于哪一类——这决定了它的值放在模板还是数据层：

| 种类 | 含义 | 值放哪 | 例子 |
|------|------|--------|------|
| **Static 静态格** | 标签、表头、固定说明 | **模板**（所有上下文相同） | "销售收入"、"单位:万元"、"项目" |
| **Data 数据格** | 录入项 | **数据层**（每上下文一份） | 收入金额、数量 |
| **Formula 公式格** | 计算项 | 公式文本在**模板**；**缓存结果在数据层** | `=B2-B3`、`=SUM(B2:B10)` |

⚠️ **公式格是最容易设计错的地方**：

- 公式文本 `=SUM(B2:B10)` 是**结构**——所有公司都用同一条公式，放模板。
- 但它的**计算结果**因各公司的 B2:B10 数据不同而不同——是**数据**，放各上下文的 plane（缓存结果）。

所以：**公式文本共享，缓存结果按上下文。**

## 四、数据维度（上下文）模型

"切换公司"只是一维。实务中维度往往多轴：

```
上下文 DataContext = { company, category, period, scenario }
                       公司      类别      期间      情景(实际/预算)
```

- 单轴（只按公司）是多轴的退化情形，多轴设计可直接覆盖未来"按期间""实际 vs 预算对比"等需求。
- 一个上下文 = 维度空间里的一个坐标点 = 一张 `DataPlane`。
- **workbook 级有一个"当前激活上下文"**；切换 = 改它 + 重渲。

> 设计建议：维度轴做成**可配置列表**而非写死字段，不同报表簿可声明自己的维度（有的只有公司，有的有公司+期间+情景）。下面 DDL 给"半结构化"做法（固定常用轴 + JSONB 扩展轴）。

## 五、关系型数据库设计

在第一篇的基础上做两处改造：① `cell` 拆成"模板格"+"格数据"；② 新增"数据上下文"表。

```sql
-- ① 模板单元格（共享格式层；去掉了易变的 value，只保留静态值/公式/样式）
CREATE TABLE template_cell (
  id            BIGINT PRIMARY KEY,
  sheet_id      BIGINT NOT NULL REFERENCES sheet(id) ON DELETE CASCADE,
  row_id        BIGINT NOT NULL REFERENCES sheet_row(id),    -- 稳定身份(见第一篇稳定身份方案)
  col_id        BIGINT NOT NULL REFERENCES sheet_column(id),
  cell_kind     SMALLINT NOT NULL,        -- 0=静态 1=数据格 2=公式
  -- 静态格的值（cell_kind=0 用）：复用类型化列
  static_type   SMALLINT,                 -- 1数值 2文本 3布尔 4日期 ...
  static_number DOUBLE PRECISION,
  static_string_id BIGINT REFERENCES shared_string(id),
  -- 公式（cell_kind=2 用）
  formula       TEXT,
  formula_type  SMALLINT DEFAULT 0,
  -- 格式（所有种类共享）
  style_id      BIGINT REFERENCES style(id),
  data_format   VARCHAR(64),              -- 数据格的录入/校验提示（可选）
  UNIQUE (sheet_id, row_id, col_id)
);

-- ② 数据上下文（维度坐标：公司 × 类别 × 期间 × 情景；扩展轴走 JSONB）
CREATE TABLE data_context (
  id            BIGINT PRIMARY KEY,
  workbook_id   BIGINT NOT NULL REFERENCES workbook(id) ON DELETE CASCADE,
  company_code  VARCHAR(64),
  category      VARCHAR(64),
  period        VARCHAR(32),              -- 如 '2026-06' / '2026Q2'
  scenario      VARCHAR(32),              -- 'actual' / 'budget' / 'forecast'
  ext_dims      JSONB,                    -- 额外维度轴(不同报表簿自定义)
  label         VARCHAR(255),             -- 显示名，如 '北京分公司·2026年6月·实际'
  ctx_kind      SMALLINT DEFAULT 0,       -- 0=叶子(实录) 1=合并(派生)
  UNIQUE (workbook_id, company_code, category, period, scenario)
);

-- ③ 单元格数据（多套、稀疏：只存数据格/公式格在某上下文下的值）
CREATE TABLE cell_data (
  id              BIGINT PRIMARY KEY,
  template_cell_id BIGINT NOT NULL REFERENCES template_cell(id) ON DELETE CASCADE,
  context_id      BIGINT NOT NULL REFERENCES data_context(id) ON DELETE CASCADE,
  value_type      SMALLINT NOT NULL,      -- 同第一篇:1数值 2文本 3布尔 4日期 5错误
  value_number    DOUBLE PRECISION,
  string_id       BIGINT REFERENCES shared_string(id),
  value_bool      BOOLEAN,
  value_error     VARCHAR(16),
  is_formula_cache BOOLEAN DEFAULT FALSE, -- true=该值是公式缓存结果
  UNIQUE (template_cell_id, context_id)
);
-- 按上下文取数（加载某公司的整表）/ 按模板格取数（同一格各公司对比）
CREATE INDEX idx_celldata_ctx  ON cell_data (context_id, template_cell_id);
CREATE INDEX idx_celldata_cell ON cell_data (template_cell_id, context_id);
```

要点：

- **静态格不进 `cell_data`**：标签的值在 `template_cell`，零冗余。
- **`cell_data` 极稀疏**：只存"数据格 + 公式格"× "实际填了值的上下文"。一个 100 格模板 × 50 公司，若每公司填 60 个数据格，也才 3000 行。
- **两个索引对应两类查询**：`(context_id, …)` 取"某公司整表"；`(template_cell_id, …)` 取"某一格在各公司的值"（横向对比报表）。
- **大数据量**：`cell_data` 可按 `context_id` 或 `period` 分区。

## 六、Rust 结构体设计

承接第一篇的命名（`RowKey/ColKey/StyleId/StringId/CellValue`），新增 `ContextId`，并把 `Cell` 拆成"模板格 + 数据层"。

```rust
use slotmap::{new_key_type, SlotMap};
use std::collections::HashMap;

new_key_type! {
    pub struct SheetKey;
    pub struct RowKey;
    pub struct ColKey;
    pub struct ContextId;     // 新增:数据上下文(维度坐标)的稳定句柄
}

// ── 维度坐标 ──────────────────────────────────────────────
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct DataContextDims {
    pub company:  Option<String>,
    pub category: Option<String>,
    pub period:   Option<String>,
    pub scenario: Option<String>,
    pub ext:      Vec<(String, String)>,   // 扩展轴
}

#[derive(Debug, Clone)]
pub struct DataContext {
    pub dims:  DataContextDims,
    pub label: String,
    pub kind:  ContextKind,
}

#[derive(Debug, Clone)]
pub enum ContextKind {
    Leaf,                                  // 叶子:实录数据
    Consolidated { members: Vec<ContextId>, method: ConsolidationMethod },  // 合并:派生
}

#[derive(Debug, Clone, Copy)]
pub enum ConsolidationMethod { Sum, Weighted, /* 权益法等 */ }

// ── 模板层:单元格 ────────────────────────────────────────
#[derive(Debug, Clone)]
pub struct TemplateCell {
    pub kind:  CellKind,
    pub style: Option<StyleId>,
    pub data_format: Option<String>,       // 数据格的录入/校验提示
}

#[derive(Debug, Clone)]
pub enum CellKind {
    Static(CellValue),                     // 标签/表头:值在模板,所有上下文相同
    Data,                                  // 数据格:值来自当前上下文的 DataPlane
    Formula { source: String, kind: FormulaKind },  // 公式文本共享;结果在 DataPlane
}

// ── 数据层:每上下文一张稀疏平面 ──────────────────────────
#[derive(Debug, Clone, Default)]
pub struct DataPlane {
    // 只存"数据格的值"和"公式格的缓存结果";静态格不在这里
    pub cells: HashMap<(RowKey, ColKey), CellData>,
}

#[derive(Debug, Clone)]
pub struct CellData {
    pub value: CellValue,                  // 数据格的录入值 或 公式格的缓存结果
    pub is_formula_cache: bool,
}

// ── Sheet:模板 + 多个数据平面 ────────────────────────────
pub struct Sheet {
    pub name: String,
    // 模板层(结构+格式,一份)
    pub rows: SlotMap<RowKey, Row>,
    pub cols: SlotMap<ColKey, Column>,
    pub row_order: Vec<RowKey>,
    pub col_order: Vec<ColKey>,
    pub template: HashMap<(RowKey, ColKey), TemplateCell>,  // 稀疏模板
    pub merged: Vec<MergedRegion>,
    // 数据层(多套):每上下文一张平面,按需加载
    pub planes: HashMap<ContextId, DataPlane>,
}

// ── Workbook:持有所有上下文 + 当前激活的 ────────────────
pub struct Workbook {
    pub name: String,
    pub sheets: SlotMap<SheetKey, Sheet>,
    pub sheet_order: Vec<SheetKey>,
    pub contexts: SlotMap<ContextId, DataContext>,   // 所有维度坐标
    pub active_context: ContextId,                   // 当前展示哪一套数据
    pub strings: StringPool,
    pub styles: StylePool,
}
```

设计要点：

- **`template` 一份**，`planes` 按上下文 N 份且稀疏——内存 = 模板(1×) + 已加载平面(k×稀疏)。
- **`active_context` 在 Workbook 级**：切公司一处生效，所有 sheet 同步切（财务报表三张表同时切到同一公司）。
- **静态格不进 plane**：标签零冗余。
- **`ContextId` 用 slotmap**：上下文也是稳定身份，公式跨上下文引用（合并报表）不怕重排。

## 七、关键操作

### 7.1 渲染：模板 + 当前平面合并

```rust
impl Sheet {
    /// 取「视觉第 r 行第 c 列」在指定上下文下的最终值
    pub fn render_cell(&self, r: usize, c: usize, ctx: ContextId) -> CellValue {
        let rk = match self.row_order.get(r) { Some(&k) => k, None => return CellValue::Empty };
        let ck = match self.col_order.get(c) { Some(&k) => k, None => return CellValue::Empty };
        let tpl = match self.template.get(&(rk, ck)) { Some(t) => t, None => return CellValue::Empty };
        match &tpl.kind {
            CellKind::Static(v) => v.clone(),                         // 标签:直接来自模板
            CellKind::Data | CellKind::Formula { .. } => {
                // 数据格/公式格:从当前上下文的平面取值(公式取缓存结果)
                self.planes.get(&ctx)
                    .and_then(|p| p.cells.get(&(rk, ck)))
                    .map(|d| d.value.clone())
                    .unwrap_or(CellValue::Empty)
            }
        }
        // 样式恒取 tpl.style —— 所有上下文共享格式
    }
}
```

### 7.2 切换公司 / 维度

```rust
impl Workbook {
    /// 切换到另一个上下文:O(1) 改指针 + 触发重渲;平面缺失则懒加载
    pub fn switch_context(&mut self, ctx: ContextId) {
        self.active_context = ctx;
        // 若 self.sheets 里某 sheet.planes 不含 ctx → 从 DB 懒加载该上下文的 cell_data
        // 前端只需重渲,模板/样式完全不动
    }
}
```

切换代价 = 换一个 key + 重渲，**不复制模板、不重建结构**。

### 7.3 编辑：两种编辑模式（重要）

| 编辑模式 | 改什么 | 影响范围 | 权限 |
|----------|--------|----------|------|
| **数据编辑** | 某上下文 plane 里的数据格值 | 只影响当前公司 | 普通用户 |
| **模板编辑** | 行列结构、样式、公式文本、静态标签 | **影响所有上下文** | 模板管理员 |

```rust
impl Sheet {
    /// 数据编辑:只动当前上下文,其它公司不受影响
    pub fn set_data(&mut self, ctx: ContextId, at: (RowKey, ColKey), v: CellValue) {
        // 仅当该格在模板里是 Data 种类才允许(静态/公式格不可直接录入)
        if let Some(t) = self.template.get(&at) {
            if matches!(t.kind, CellKind::Data) {
                self.planes.entry(ctx).or_default()
                    .cells.insert(at, CellData { value: v, is_formula_cache: false });
                // 之后触发本上下文内依赖该格的公式增量重算
            }
        }
    }

    /// 模板编辑:改公式文本(所有上下文生效),需对每个已加载平面重算缓存
    pub fn set_formula(&mut self, at: (RowKey, ColKey), source: String, kind: FormulaKind) {
        self.template.insert(at, TemplateCell {
            kind: CellKind::Formula { source, kind },
            style: self.template.get(&at).and_then(|t| t.style),
            data_format: None,
        });
        // 对所有 planes 重算该公式格(每上下文用各自数据)
    }
}
```

### 7.4 重算的上下文隔离

公式 `=SUM(B2:B10)` 在每个上下文里**用该上下文自己的数据**算，结果写回该上下文的 plane。重算引擎按 `(ContextId, 公式格)` 维度跑，互不串。

## 八、一个完整的小例子

**模板（利润表，一份）：**

| 行\列 | A（静态标签） | B（数据/公式） |
|-------|--------------|---------------|
| 1 | `Static("项目")` | `Static("金额")` |
| 2 | `Static("销售收入")` | `Data` |
| 3 | `Static("销售成本")` | `Data` |
| 4 | `Static("毛利")` | `Formula("=B2-B3")` |

**数据层（两套）：**

```
DataPlane[C001 北京分公司]: { (r2,B):1000, (r3,B):600, (r4,B):400(缓存) }
DataPlane[C002 上海分公司]: { (r2,B):1500, (r3,B):900, (r4,B):600(缓存) }
```

**渲染：**

- 切到 C001 → A 列标签恒为"项目/销售收入/销售成本/毛利"，B 列显示 1000/600/400。
- 切到 C002 → A 列标签**完全一样**，B 列显示 1500/900/600。
- 模板（标签、`=B2-B3` 公式、样式）**只存了一份**；改公式 `=B2-B3` → `=B2-B3-税费`，两家公司同时生效、各自重算。

## 九、高级议题

### 9.1 合并报表（派生上下文）

"合并"上下文的数据 = 多个成员公司上下文的聚合：

```rust
ContextKind::Consolidated { members: vec![c001, c002], method: Sum }
```

- 它的 plane 不是录入的，而是**由成员 plane 派生**（逐格 SUM / 加权 / 权益法）。
- 成员数据变 → 合并上下文重算。
- 可做多级合并（分公司→大区→集团），上下文形成树（用 `ContextId` 引用，稳定身份不怕重排）。

### 9.2 内存管理：模板常驻 + 平面 LRU

```
内存占用 = 模板(1×，常驻) + 已加载平面(k× 稀疏，LRU 淘汰)
```

- 模板一份永远在内存。
- 平面按访问 LRU：只保留最近看的几家公司，其余从 DB 懒加载、淘汰回收。
- 50 家公司不必同时全load，内存随"同时浏览的公司数"而非"总公司数"增长。

### 9.3 维度可配置

不同报表簿声明各自的维度轴（有的只有公司；有的公司+期间+情景）。`DataContextDims` 的固定字段 + `ext` 扩展轴 + DB 的 JSONB `ext_dims` 支撑这点。

### 9.4 数据格的"未填" vs "填 0"

plane 稀疏 → 某格在某上下文**没有条目** = 未填（显示空）；**有条目值为 0** = 明确填了 0。两者语义不同，渲染时要区分（`Option<CellData>`）。

## 十、与持久化 / 协同的衔接

### 与第一篇（持久化）

- 第一篇的 `cell` 表 → 拆成本篇的 `template_cell`（格式层）+ `cell_data`（数据层）+ `data_context`（维度）。
- 稳定身份行列方案不变，`template_cell` 用 `row_id/col_id` 引用。

### 与第二篇（多用户协同）

- **数据编辑**天然按上下文隔离：用户 A 编辑 C001、用户 B 编辑 C002，**根本不冲突**（改的是不同 plane）。协同压力大幅下降。
- 真正需要协同冲突解决的，只剩"同一上下文同一格双改"和"模板编辑"。
- Op 模型要带上 `context_id`：
  ```rust
  pub enum Op {
      SetData     { sheet: SheetKey, ctx: ContextId, at: (RowKey,ColKey), value: CellValue },
      SetFormula  { sheet: SheetKey, at: (RowKey,ColKey), source: String },  // 模板级,无 ctx,影响所有
      InsertRow   { sheet: SheetKey, after: Option<RowKey>, new: RowKey },   // 模板级
      // ...
  }
  ```
- **模板编辑是高权限、低频、影响全局**的操作，建议单独的权限与审计，且模板改动要触发所有已加载平面的重算。

## 十一、结论

| 关注点 | 方案 |
|--------|------|
| 一套格式多套数据 | **模板层（共享一份）+ 数据层（每维度一张稀疏 DataPlane）分离** |
| 单元格 | 分**静态/数据/公式**三类：静态值在模板，数据值+公式缓存在 plane |
| 公式 | **文本共享（模板），结果按上下文（plane）** |
| 维度 | 多轴上下文 `{公司,类别,期间,情景,…}`，单轴是退化情形 |
| 切换公司 | 改 `active_context` + 重渲，O(1)，按需懒加载平面 |
| 编辑 | **数据编辑**（按上下文隔离）vs **模板编辑**（影响全局，高权限） |
| 合并报表 | 派生上下文 `Consolidated{members,method}`，由成员平面聚合 |
| 内存 | 模板常驻 + 平面 LRU，随并发浏览数而非总公司数增长 |

**三条铁律：**

1. **格式与数据物理分离**——模板永远一份，绝不为多公司复制整表。
2. **公式文本是模板、缓存结果是数据**——别把公式结果当结构存。
3. **编辑分两级**——数据编辑按上下文隔离（协同友好），模板编辑影响全局（高权限 + 全平面重算）。

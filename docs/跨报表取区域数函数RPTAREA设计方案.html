CMX 财务报表平台 · 设计方案

跨报表取区域数自定义函数 · RPTAREA

取另一张报表某 sheet 某命名区域的数，按参数聚合（汇总/平均/极值/罗列）。核心诉求：被引用报表插行/列导致坐标变化时，函数自动跟随，参数无需调整。
函数 RPTAREA(报表, sheet, 区域, 模式) 锚定 = 命名区域（坐标无关） 取数 = 读已落库 cr_cell_value 状态：设计（不动代码）

§0结论速览

"自动跟随"的本质：把跨报表引用从裸坐标改为命名锚点。报表 A 永远按区域名字读数，报表 B 内部插行导致坐标从 C3:C12 变成 C5:C14，只要区域名 area_assets 不变，A 的公式 =RPTAREA('BS','s1','area_assets','SUM') 就永不改动。坐标只是报表 B 自己的内部事务，A 全程看不到坐标、天然免疫。

一句话架构
RPTAREA = 命名区域锚点（报表 B 内部维护）+ 落库单元格值（cr_cell_value 按 block_id 稀疏存）+ 读取聚合（按名字 JOIN 查值）。 报表 A 与报表 B 的耦合只有一个稳定字符串——区域名。这把"自动跟随"的全部负担收敛到报表 B 的编辑侧，A 侧零负担。

§1需求与核心难点

✓ 需求（已确认）

  • 取另一张报表某 sheet 某区域的数。
  • 参数控制聚合：汇总 SUM / 平均 AVG / 最大最小计数 / 罗列 LIST。
  • 坐标自动跟随：目标报表插行列，函数参数不改。
  • 取数来源：读已落库实例 cr_cell_value。
  • 函数需指定：目标报表 + sheet + 区域 + 模式。

核心难点

  • 锚定什么才能让坐标变化自动跟随？→ 命名区域。
  • 取哪份数据？→ 已落库实例（但落库链路当前为零）。
  • LIST 罗列返回多值，与引擎"单格单值"模型冲突。
  • 目标报表未落库怎么办？
  • 命名区域自动平移在哪一层实现？

§2三个改变设计的发现

探查现有代码后，三个事实直接重塑了方案——两个大幅简化，一个必须先补齐。

发现 1 · 命名区域不用新建模型 —— blocks 已经就是"按范围锚定的区域"
每个 sheet 的 grid.blocks[] 结构为 {id, range:"A14:F14", role}，model 页已有 addBlock/setBlock/removeBlock，prop 页已有区块管理 UI + 命中测试逻辑。命名区域 = 一种 role/kind:'named' 的 block，id 即区域名。而且 cr_cell_value 已有 block_id（"所属区块"）列——落库时每格写 block_id，读取时 WHERE block_id='area_assets'，天然免范围解析。全程复用，这是最大简化。
发现 2 · "插行/列"操作本身当前不存在
全仓 grep：设计器与 Ignite 组件没有任何 insertRow/insertColumn/deleteRow 逻辑（只有 sheet 增删、列宽行高、合并）。所以"C3:C12 → C5:C14"这个结构编辑目前还无法发生。这决定了"自动跟随"分两层实现（见 §3.2、§9c），真正的"插行自动平移"要到最后里程碑 M6。但读取侧的坐标免疫（按名字读）从 M2 就成立——这才是用户诉求的本质。
发现 3 · cr_cell_value 唯一键缺 sheet 维度，必须先补
cr_cell_value 唯一键是 (instance_id, cell_addr)——多 sheet 报表里两个 sheet 都有 C3 会撞键。用户又明确要求"函数指定 sheet"。必须加 sheet_id 列，唯一键扩为 (instance_id, sheet_id, cell_addr)。DDL 由 base_rpt_meta 的 storageTables 生成且幂等升级，可安全加列。

§3命名区域模型

3.1 复用 blocks，不新建 names 段

结论：命名区域 = kind:'named' 的 block。不复用 cell.name（那是"单格审计名"，1 格 1 名，表达不了多格区域；两者并存互不干扰）。

// 模板 sheet.grid.blocks —— 命名区域与角色块共用一个数组，kind 区分 "grid": { "blocks": [ { "id":"area_assets", "kind":"named", "range":"C3:C12", "caption":"资产明细区" }, { "id":"blk_body", "range":"A14:F14", "role":"body" } ] }

id 是被 RPTAREA 引用的稳定区域名（报表内唯一）。落库时区域成员靠 cr_cell_value.block_id 记，不靠 cell_name。blocks 已随模板 save() 持久化，零新增存储逻辑。

3.2 坐标自动跟随 —— 分两层

读取层（A 读 B）· M2 即成立
永远按 block_id 读。B 重新出表落库后，落库的格地址已是新地址（C5:C14），但 block_id 仍是 area_assets。A 读 WHERE block_id='area_assets'，不碰坐标，报表 A 全程免疫、无需 B 的模板。这是"自动跟随"用户真正要的效果。
维护层（B 的 range 平移）· 分两步
M3（先做）：不在编辑期维护范围，落库时用命中测试为每格算所属 block_id；范围由用户在区域管理 UI 手工设（当前无插行，范围本手工）。
M6（后做，真自动）：model 页实现最小 insertRow/insertColumn —— 位移单元格 + 平移所有 block.range + 调整本 sheet 公式地址。这才让"插行→范围自动平移"成真。

§4函数语法与语义

4.1 RPTAREA 签名

RPTAREA(reportCode, sheetId, regionName, mode) reportCode 目标报表 moduleMeta.moduleCode（= cr_report_instance.tpl_code），如 'BS' sheetId 目标 sheet id，如 's1' regionName 命名区域 id（block_id），如 'area_assets' mode 'SUM'|'AVG'|'MAX'|'MIN'|'COUNT'|'LIST' // 示例 =RPTAREA('BS','s1','area_assets','SUM') // 前端 UDF 键 / 引擎 func_key（现有逻辑直接可用，字面量参数冒号连接） RPTAREA:BS:s1:area_assets:SUM

org / period 继承报表 A 的出表上下文（同实体、同期间读 B），scope 阶段 1 固定 'single'。这是合理默认，后续可加可选第 5/6 参覆盖。parser 已统一 to_uppercase()，函数名大小写不敏感。

4.2 LIST 罗列 vs 单值模型的冲突（难点 a）

冲突
引擎全链路是标量：CellValues = HashMap<addr, f64>，eval 返回 f64，ComputeOutput.fetches: HashMap<String, f64>，Ignite UDF 返回单个 ExcelCalcValue——无 spill（溢出多格）机制。LIST 想返回 N 值铺 N 格，与之根本冲突。
模式返回落地方案阶段
SUM / AVG / MAX / MIN / COUNT标量走现有数值通道，SQL 聚合直出，无冲突M2
LIST多值单格分隔串：区域各值按 row_no,col_no 排序拼成字符串，走 str_value / 独立字符串 fetch 通道，一个格里显示，明确标注"单格罗列"M5
LIST 真·多格铺开N 格拒绝：Ignite 无 spill、引擎无多值格。真正有用的"把 B 的行项目作为行导入"是另一种特性（设计器行展开），列为后期独立里程碑后期

5.2 落库写入路径（新端点 POST /api/rpt/land）

让 /rpt/compute 保持无副作用；落库单独端点。流程：

1
compute() 得到各 sheet 值（复用现有引擎）
2
解析实例键：tpl_code=meta.report_code、org_id=ctx.org(i64)、period_code=ctx.period、scope='single'
3
Upsert 头表 cr_report_instance（ON CONFLICT 唯一键更新 calc_at）→ 得 instance_id
4
DELETE FROM cr_cell_value WHERE instance_id=$1 → 批量插每个有值格
INSERT INTO cr_cell_value (id, instance_id, sheet_id, cell_addr, row_no, col_no, block_id, cell_name, num_value, str_value, formula_snapshot) VALUES (...); -- row_no/col_no: 由 addr 拆解（col_to_index + 行号） -- block_id: 对每格做命中测试，落 kind:'named' 的 block id -- cell_name: 来自 cell.name（单格审计名） -- id: snowflake_id_str()（现有铸号）

5.3 读取路径（RPTAREA 求值 SQL）

-- 标量聚合（AVG/MAX/MIN/COUNT 换聚合函数） SELECT COALESCE(SUM(cv.num_value),0) AS v FROM cr_report_instance ri JOIN cr_cell_value cv ON cv.instance_id = ri.id WHERE ri.tpl_code=$1 AND ri.org_id=$2 AND ri.period_code=$3 AND ri.scope=$4 AND cv.sheet_id=$5 AND cv.block_id=$6; -- LIST：取明细按坐标排序 SELECT cv.num_value, cv.str_value FROM ... ORDER BY cv.row_no, cv.col_no;
坐标免疫在这一句 SQL 里兑现
WHERE ... block_id=$6——整条查询不含任何单元格坐标。报表 B 插行导致区域成员从 C3:C12 变 C5:C14，只要落库时这些格的 block_id 仍是 area_assets，本查询原样命中，报表 A 的公式一字不改。唯一键保证实例唯一、无歧义。执行器复用 mm.query_sql_with_datavalues（读）/ execute_sql_with_datavalues（写），db_id 取自请求头（cr_* 与报表同库）。

§9三大难点取舍结论

(a) LIST 罗列 vs 单值模型
引擎/UDF 全标量、无 spill。→ 标量五模式先行；LIST 阶段 1 用"单格分隔串"（str_value 通道）妥协交付并明确标注；真正多格 spill / 行导入列为后期独立特性。
(b) 目标报表未落库
默认报错 / 诊断降级：返回 0 / 空 + warnings 里"报表 BS 期间 2026-06 未出表落库"，透传到 compute 响应。不默认实时重算（违背"读已落库"决策，且引入跨报表递归/环风险）；实时降级仅作后续可选开关。
(c) 自动跟随实现位置
读取侧永远按 block_id 读 → 报表 A 天然免疫（M2 即成立）。范围维护：阶段 1 用落库期命中测试 + 手工区域 UI（M3）；后期加 model 页 insertRow/Col 结构编辑（M6）平移 block.range + 单元格 + 公式，才让"插行自动"成真。

# 列与字段设置 — 现状梳理与统一方案

> 状态：方案文档（不含代码改动）。目的：把散落在 5 处的"列 / 字段"属性设置梳理清楚，给出统一的命名、模型、UI 与落地路线。

---

## 0. TL;DR（结论先行）

当前同一个概念——"一列/一个字段长什么样、怎么编辑、怎么显示"——被**5 套不同的 schema、3 套不同的字段名键、2 套不同的设计器 UI** 各自实现，命名和取值都不统一：

| 概念 | 弹性组合字段 | DCT/DOC 字段 | 设计器列面板 | 设计器组件Inspector | 运行时 CmxColumn（基准） |
|---|---|---|---|---|---|
| 字段标识 | `code` | `fieldName` | `id` | `key` | `id` |
| 标题 | `caption` | `label`（+`fieldComment`注释） | `caption` | `label` | `caption` |
| 数据类型 | `dataType`(text/number/date/boolean) + `kind`(dimension/…) | `dataType`(VARCHAR/INT/…) | `type` | `type` | `type` |
| 编辑器 | `edit.mode` | `uiControl`（13种扁平枚举） | `editMode` | (详情抽屉) | `edit.mode` |
| 显示方式 | `display.*` | (无) | (无) | `formatter`预设 | `display.*` |
| 字典/引用 | `dict.dictId`/`valueField` | `refDict`/`refField`/`displayField` | (无) | `source`/`valueField` | `edit.source`/`editSettings` |
| 必填 | `edit.required` | (无，有`fieldControl.requiredWhen`) | (无) | (无) | `edit.required` |
| 校验 | `validations[]`{expr,message} | `pattern`/`fieldControl.*` | (无) | (无) | `edit.validate`/`validateWhen` |

**核心问题**：`CmxColumn` 已经是设计良好的"列设置基准模型"（display/edit 分层 + legacy 别名归一 + 逃生舱），但**上游三个录入端（弹性组合、DCT/DOC、设计器面板）都没有以它为准**，各自发明了字段名和子集，导致：
- 同一属性多个名字（字段名有 4 种叫法）
- 同一属性多个位置（编辑器类型在 `edit.mode` / `uiControl` / `editMode` / `column.edit.mode` 四处都能设）
- 取值枚举不统一（`uiControl` 13 项 vs `edit.mode` 9 项，命名风格 `*-edit` / `*-select` / `refSelect` 混杂）
- 弹性组合里甚至有"双轨"：`field.edit.*` 语义层 + `field.column.edit.*` 逃生舱层，同一概念两套入口

**方案主线**：确立 **CmxColumn 为唯一基准模型**；上游各端的字段对象通过**显式映射层**编译到 CmxColumn；统一录入控件枚举；消除"双轨"和"多处可设"。

## 1. 五处现状详录

### 1.1 运行时基准：CmxColumn / CmxColumnGroup / CmxColumnModel
位置：`packages/cmx-data-comp/src/lib/cmx-column*.js`

**CmxColumn**（已是良好的分层模型）
- 顶层：`id` `caption` `type` `length` `integerDigits` `decimalDigits` `width` `align` `visible` `frozen` `required` `agg` `calcFormula` `actionRef`
- `display.*`：`align` `format` `decimalDigits` `zeroAsBlank` `emptyText` `mode`(text/badge/link/icon) `badgeMap` `icon` `link` `cellStyle` `thousandSeparator` `render`(逃生舱)
- `edit.*`：`mode`(input/select/date/ref/combo/ignite-combo/dict-select/readonly/none) `trigger` `options` `source` `valueField` `displayTemplate` `parent` `dropdownColumns` `dropdownWidth` `dropdownMaxHeight` `placeholder` `dependents` `required` `requiredWhen` `validate` `validateWhen` `readonlyWhen` `editor`(逃生舱)
- **legacy 别名归一**：`editMode→edit.mode`、`displayMode→display.mode`、`displayMask→display.format`、`align→display.align`、`decimalDigits→display.decimalDigits`、`required→edit.required`、`validateFormula→edit.validate`、`actionRef→display.link.actionRef`、`editSettings.*→edit.*`
- `type`(数据是什么) 与 `edit.mode`(用什么编辑器) 是**正交两层**，模型层不做 type→mode 推导
- 序列化：`toJSON`(持久化，剥离函数) / `toDescriptor`(适配器用，保留函数+旧顶层冗余)

**CmxColumnGroup**：`id` `caption` `aggregate{sum,avg,max,min,count}`(布尔开关) `aggregatePosition`(before/after) `members[]`

**CmxColumnModel**：`datasetId` `caption` `toTitleCols` `iconCol` `members[]` + `columns-changed` 事件

> 评价：**这是唯一一套设计完整、分层清晰、有归一化和逃生舱的模型。应作为统一基准。**

### 1.2 弹性组合字段（profile.rules[].detail.fields[]）
位置：`../cmx-portal-manager`

字段对象顶层散键：`code` `caption` `kind`(dimension/attribute/measure/text) `dimension` `dataType` `formula` `dependsOn` `unitField` `sourceColumn`
嵌套：
- `edit.*`：`mode` `required` `placeholder` `requiredWhen` `readonlyWhen`
- `display.*`：`align` `mode` `format` `decimals`(⚠️非 decimalDigits) `thousand`(⚠️非 thousandSeparator) `zeroBlank`(⚠️非 zeroAsBlank) `negativeColor`
- `dict.*`：`dictId` `valueField` `displayMode` `helpLayout`（+导入时 `labelField`）
- `source.*`（attribute 带出）：`dimension` `attribute`
- `defaultFrom.*`（measure 默认值）：`dimension` `attribute`
- `validations[]`：`{expr, message}`
- **`column.*`（逃生舱双轨）**：`width` `frozen` `visible`(特殊boolean-visible) `align` `agg` `column.display.format` `column.display.mode` `column.edit.mode` `column.source`

分组 `groups[]`：`caption` `aggregatePosition` `aggregate.{sum,avg,max,min,count}` `members[]`（字符串=字段，对象=子组）
列模型 `columnModel`：`caption` `datasetId` `toTitleCols` `iconCol`（profile级 + rule级两份）
字段集 `fieldTabs[]`：`id` `name` `table` `fields[]` `groups[]` `columnModel{}`

> 问题点：
> - `display.decimals/thousand/zeroBlank` 与 CmxColumn 的 `display.decimalDigits/thousandSeparator/zeroAsBlank` **命名不一致**（引擎已做别名修复，但录入层仍用错名）
> - **双轨**：`edit.mode` 与 `column.edit.mode` 并存、`display.*` 与 `column.display.*` 并存——用户不知道该在哪设
> - `kind` 是档案特有的"维度/度量/属性"语义，与 `type` 不同维度但混在一起
> - inspector 区块多（编辑/显示/字典/带出/默认值/校验/列属性），且"列属性 field.column"整段是给懂行的人用的逃生舱，新手会困惑

### 1.3 DCT/DOC 字段（dictionaryTables[].fields[] / voucherTables[].fields[]）
位置：`../cmx-portal-manager`

字段对象：`fieldName` `fieldComment` `dataType`(VARCHAR/INT/BIGINT/TINYINT/DECIMAL/DATE/DATETIME/TEXT/BOOLEAN) `fieldLength` `intDigits` `decimalDigits` `nullable` `dimType`(dimension/measure/attribute/relation) `refDict` `refField` `displayField` `defaultValue` `unique` `pattern` `enumValues` `label` `uiControl` `searchable` `filterable` `sensitive` `i18n` `fieldControl.{requiredWhen,editableWhen,visibleWhen}`
表级覆盖：`table.fieldRefDicts[fieldName]`（引用字段的字典覆盖）

录入控件 `uiControl` 可选值（13项扁平枚举，**命名风格混杂**）：
`text-edit` `textarea` `rich-text-edit` `number-edit` `date-edit` `datetime` `checkbox` `dict-select` `enum-select` `select` `refSelect` `image-edit` `video-edit`

> 问题点：
> - 字段名 `fieldName`、注释 `fieldComment`、标题 `label` —— 三个都和 CmxColumn 的 `id`/`caption` 不一样
> - 数据类型用 SQL 物理类型（VARCHAR/DECIMAL），与 CmxColumn 的逻辑类型（text/number）不同层级
> - `uiControl` 与 `edit.mode` 是同一概念两套枚举，且 `uiControl` 内部命名就不统一（`-edit`后缀 vs `-select`后缀 vs `refSelect`驼峰 vs `checkbox`裸名）
> - 引用三件套 `refDict/refField/displayField` vs 档案的 `dict.dictId/valueField` vs CmxColumn 的 `edit.source/valueField` —— 三套

### 1.4 设计器·模型面板列编辑器
位置：`../cmx-html-designer`

存到 `models[].props.columns[]`，每列**只暴露 5 个属性**：`id` `caption` `type`(text/number/date/select/ref/readonly) `editMode`(input/select/date/ref/readonly/none) `width`
分组只设 `id`+`caption`（**无聚合 UI**，存 `{__type:'group',id,caption,children}`）
模型级：`instanceId` `datasetId` `toTitleCols` `iconCol` `columnsSource` `columns`（⚠️用 `columns` 不是 lib 的 `members`，且无 `caption` UI）

> 问题点：
> - 列字段键 `id/caption/type/editMode/width` 是 CmxColumn 的**简化子集**，靠构造函数 legacy 别名归一（能跑通，但 UI 能设的太少）
> - 分组聚合 UI 缺失——聚合得去 CmxMasterSlave 的 `aggregations[]` 另设
> - 模型面板用 `columns`，lib 用 `members`，序列化时不一致（靠适配器吸收）

### 1.5 设计器·组件 Inspector 列编辑器
位置：`../cmx-html-designer`

存到元素 `data-cmx-columns` 属性，列字段用 `key`/`label`/`type`/`width`（⚠️又一套键名）
详情抽屉更丰富：`placeholder` `dependents` `onChange`/`formatter`(预设) `numeric` `options` `source` `valueField` `displayTemplate` `helper` `from`/`field`/`materialize`(ref-display)

> 问题点：字段键 `key/label` 与模型面板的 `id/caption` 又不一样——同一个设计器内部就有两套列编辑器、两套键名。

## 2. 问题归类

| 类别 | 具体表现 |
|---|---|
| **命名分裂** | 字段名 4 种（`id`/`code`/`fieldName`/`key`）；标题 3 种（`caption`/`label`/`fieldComment`）；编辑器 4 种（`edit.mode`/`uiControl`/`editMode`/`column.edit.mode`）；显示子键名不一致（`decimals`vs`decimalDigits`、`thousand`vs`thousandSeparator`、`zeroBlank`vs`zeroAsBlank`） |
| **同概念多处可设** | 弹性组合的"编辑器/显示/对齐/合计"在语义层(`edit.*`/`display.*`)和逃生舱层(`column.*`)双轨；设计器有模型面板+组件Inspector两套列编辑器 |
| **取值枚举不统一** | `uiControl`(13项)、`edit.mode`(9项)、设计器`editMode`(6项) 三套互不对齐；`uiControl` 内部命名风格混杂 |
| **数据类型分层混乱** | DCT用SQL物理类型(VARCHAR/DECIMAL)，档案用逻辑类型(text/number)+`kind`维度语义，CmxColumn用逻辑类型(text/number/select/ref…)——三层 |
| **引用/字典三套模型** | `refDict/refField/displayField`(DCT) vs `dict.dictId/valueField/displayMode`(档案) vs `edit.source/valueField`(CmxColumn) |
| **分组聚合能力分散** | CmxColumnGroup有完整聚合，但设计器面板没UI，要去CmxMasterSlave的aggregations设；档案里在group节点设；DCT没有 |

## 3. 统一方案

### 3.1 原则
1. **CmxColumn/Group/Model 为唯一基准模型**（display/edit 分层 + 逃生舱 + 归一化已经具备）。所有上游录入端的"字段/列对象"最终都编译为 CmxColumn。
2. **录入端保留各自的领域语义**（DCT 有物理类型/SQL 约束、弹性组合有维度/度量语义），但**面向"列设置"的那部分属性，名字和取值必须向 CmxColumn 对齐**。
3. **消除双轨**：同一概念只在一个地方设。逃生舱(`column.*`/`render`/`editor`)仅作高级透传，UI 上明确标注且默认折叠。
4. **统一录入控件枚举**：一套 `edit.mode` 值域，各端共用；DCT 的 `uiControl` 改为这套值（或映射表收敛）。
5. **映射层显式化**：每个录入端到 CmxColumn 的转换写成一个集中的、有测试的映射函数（引擎里 `_fieldToColumn` 已是弹性组合的映射，作为范本推广）。

### 3.2 统一术语表（建议的"规范键名"，= CmxColumn 基准）

| 规范概念 | 规范键（CmxColumn） | 各端现状 → 收敛动作 |
|---|---|---|
| 字段标识 | `id` | 档案`code`/DCT`fieldName`/Inspector`key` → 映射层统一转 `id`（录入端键名可保留领域名，但映射唯一） |
| 标题 | `caption` | DCT`label`→`caption`；`fieldComment`保留为"注释/描述"另一字段(见下) |
| 注释/描述 | `description`（建议新增到 display 或顶层） | DCT`fieldComment` → `description` |
| 逻辑数据类型 | `type`(text/number/date/boolean/select/ref/combo/dict-select) | DCT物理`dataType`→映射到`type`；档案`dataType`已接近，统一到这套 |
| 物理类型（DCT专有保留） | `dataType`(VARCHAR/…) | 仅 DCT/DOC 保留，作为生成 DDL 用；编译 CmxColumn 时映射到 `type` |
| 维度语义（档案专有保留） | `kind`(dimension/measure/attribute) | 仅档案保留，映射时驱动 `type`/`agg`/对齐 |
| 编辑器 | `edit.mode` | **统一值域**(见3.3)；DCT`uiControl`、设计器`editMode`、档案`edit.mode` 全部对齐 |
| 显示方式 | `display.mode`/`display.format`/`display.align`/`display.decimalDigits`/`display.thousandSeparator`/`display.zeroAsBlank` | 档案`display.decimals/thousand/zeroBlank`→改用规范名 |
| 字典/引用 | `edit.source`+`edit.valueField`+`edit.displayTemplate`（或 `dict` 子对象统一为一种） | DCT`refDict/refField/displayField`、档案`dict.*` → 收敛为一套引用配置 |
| 必填 | `edit.required` / `edit.requiredWhen` | 各端对齐 |
| 校验 | `edit.validate`(+`validateWhen`) | 档案`validations[]`→编译为`edit.validate`(已做)；DCT`pattern`→`edit.validate` |
| 宽度/对齐/冻结/可见 | `width`/`align`/`frozen`/`visible` | 消除档案双轨`column.*`，UI 只在一处设 |
| 合计 | 列`agg` / 组`aggregate` | 统一：列级单选`agg`，组级布尔集`aggregate`，去掉分散入口 |

### 3.3 统一"录入控件 edit.mode"值域（建议）

以 CmxColumn 现有 9 项为基础，吸收 DCT 的富控件需求：

```
input          普通输入（文本/数字按 type 区分）
textarea       多行文本
rich-text      富文本           (DCT rich-text-edit → 此)
number         数字             (DCT number-edit → 此；或用 input+type:number)
date           日期             (DCT date-edit → 此)
datetime       日期时间         (DCT datetime → 此)
checkbox       复选框/布尔
select         静态枚举下拉      (DCT select/enum-select → 此)
ref            外键引用选择      (DCT refSelect → 此)
combo          组合框（远端搜索）
dict-select    数据字典选择      (DCT dict-select → 此)
image          图片             (DCT image-edit → 此)
video          视频             (DCT video-edit → 此)
readonly       只读
none           不可编辑
```

收敛 DCT `uiControl` → `edit.mode` 的映射表（一次性）：
`text-edit→input` `number-edit→number` `date-edit→date` `rich-text-edit→rich-text` `image-edit→image` `video-edit→video` `enum-select→select` `refSelect→ref`，其余同名直通。

### 3.4 消除"双轨"
- 弹性组合 inspector 去掉/折叠"列属性 field.column"整段；把其中**确实有意义且不重复**的项（如 frozen/visible/width 若 `edit/display` 没覆盖）提升为一等公民，放进"显示"区；其余纯透传项收进一个"高级（CmxColumn 透传）"折叠区，明确标注"覆盖编译结果"。
- `display.decimals/thousand/zeroBlank` 三个错名在录入层改为规范名（引擎别名兼容可保留一段时间作 BC）。

### 3.5 设计器两套列编辑器收敛
- 模型面板版（`id/caption/type/editMode/width`）与组件 Inspector 版（`key/label/...`）**统一键名为 `id/caption`**，共用同一套列属性 schema 与控件组件。
- 模型面板列编辑器**补齐 align/display/必填/校验/数据源**的 UI（目前只有 5 项），或直接复用组件 Inspector 的详情抽屉组件。
- 分组聚合 UI 补到设计器（目前缺失），与 CmxColumnGroup 的 `aggregate`/`aggregatePosition` 对齐。

### 3.6 落地形态（不改语义，先统一接口）
建议产出一个**共享的"列设置 schema 定义"模块**（单一事实来源），描述每个规范属性的：键名、中文标签、控件类型、取值枚举、所属分区、是否高级。三个录入端的 inspector UI 都由这份 schema 驱动渲染，从根上杜绝"同概念不同名/不同控件"。映射层（各端字段对象 ↔ 规范 CmxColumn）各写一个集中函数 + 测试。

## 4. 实施路线（分阶段，每阶段可独立验证）

| 阶段 | 内容 | 风险 | 验证 |
|---|---|---|---|
| **P0 文档与对齐** | 本文档定稿；确立 CmxColumn 为基准；定下统一术语表与 `edit.mode` 值域 | 无（纯文档） | 评审通过 |
| **P1 录入控件统一** | DCT `uiControl` 值改为统一 `edit.mode` 值域 + 映射表；引擎/表单消费端按统一值渲染 | 低（加映射，旧值兼容） | 现有页面回归；新值生效 |
| **P2 显示子键改名** | 弹性组合 `display.decimals/thousand/zeroBlank` → 规范名；引擎别名兼容保留 | 低 | 引擎测试 + 页面回归 |
| **P3 消除档案双轨** | inspector 折叠/收编 `field.column.*`；把有效项提升、纯透传收进"高级"折叠区 | 中（UI 调整） | 档案编辑/保存/编译回归 |
| **P4 共享 schema 驱动** | 抽出"列设置 schema"单一定义；三端 inspector 改由 schema 驱动渲染 | 中高（重构 UI 渲染） | 三端逐一回归 |
| **P5 设计器两套合一** | 模型面板列编辑器与组件 Inspector 统一键名/组件；补齐 align/display/校验/聚合 UI | 中高 | 设计器列编辑回归 + 保存 JSON 兼容 |
| **P6 映射层集中+测试** | 各端→CmxColumn 映射函数集中、补全、加单测；逃生舱明确化 | 中 | 映射单测全绿 |

> 建议先做 **P0→P1→P2**（低风险、收益明显：录入控件和显示键名统一），再评估 P3-P6（涉及 UI 重构，需更多回归预算）。

---

## 5. 决策点（需确认后再动代码）

1. **统一 `edit.mode` 值域**是否采纳 §3.3 的 14 项？`number`/`datetime`/`rich-text`/`image`/`video` 是否都要进基准模型（CmxColumn 当前只有 9 项，需扩 type/mode）？
2. **引用/字典模型**收敛为哪一套：DCT 的 `refDict/refField/displayField`、还是 CmxColumn 的 `edit.source/valueField`、还是新的统一 `dict{}` 子对象？
3. **DCT 物理类型 `dataType`(VARCHAR…)** 与逻辑 `type` 的关系：保留物理类型仅供 DDL、编译时映射到 `type`，是否可接受？
4. **设计器两套列编辑器**是合并为一套，还是保留两套但统一键名？
5. 实施范围：先做 P0-P2（低风险统一），还是一并规划 P3-P6（含 UI 重构）？

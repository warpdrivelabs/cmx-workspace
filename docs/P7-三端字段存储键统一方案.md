# P7 — 三端字段存储键统一（DCT/DOC/CTX 同键）实施计划

## 目标
DCT/DOC/CTX 三端「相同含义」的字段属性，**存储键名统一**（不只是 UI 统一）。需要时同步修改引擎、校验器、服务端、存盘数据。

## 已确认决策
1. **录入控件**：统一用 CTX 的 `edit.mode`（DCT/DOC 的 `uiControl` → 改存 `edit.mode`）
2. **其他相同内容**：一律以 DCT/DOC 为准
3. **字段标识**：CTX `code` → `fieldName`（彻底，含运行时键/存盘迁移）
4. **数据类型**：`dataType` 也统一（CTX 逻辑类型与 DCT/DOC 物理类型合一）

## 统一后的字段存储键（规范键 = 三端共用）

| 含义 | 统一存储键 | 旧 CTX | 旧 DCT/DOC |
|---|---|---|---|
| 字段标识 | `fieldName` | `code` | `fieldName` |
| 标题/注释 | `fieldComment` | `caption` | `fieldComment` |
| 录入控件 | `edit.mode` | `edit.mode` | `uiControl` |
| 数据类型 | `dataType`(统一值域) | `dataType`(text/number) | `dataType`(VARCHAR/DECIMAL) |
| 维度语义 | `dimType` | `kind` | `dimType` |
| 引用字典/字段/显示 | `refDict`/`refField`/`displayField` | `dimension`+`dict.*` | `refDict`/`refField`/`displayField` |
| 必填 | `nullable`(反) 或 `edit.required` | `edit.required` | `nullable` |
| 必填/只读条件 | `fieldControl.requiredWhen`/`.readonlyWhen` | `edit.requiredWhen`/`readonlyWhen` | `fieldControl.requiredWhen`/`editableWhen`/`visibleWhen` |
| 约束类 | `defaultValue/unique/pattern/enumValues` | 同名(已统一) | 同名 |
| 治理类 | `label/searchable/filterable/sensitive/i18n` | 同名(已统一) | 同名 |
| CTX 独有 | `display.*`/`formula`/`dependsOn`/`validations`/`source.*`/`defaultFrom.*`/`unitField`/`column.*` | 同 | 无（保留 CTX 专有，不强求 DCT/DOC 有） |

### 数据类型值域统一方案
- 统一存 **物理类型**（VARCHAR/INT/BIGINT/TINYINT/DECIMAL/DATE/DATETIME/TEXT/BOOLEAN），因为 DCT/DOC 要喂后端 DDL。
- 引擎 `_colType` 增加 物理→逻辑 映射（INT/DECIMAL→number, DATE→date, BOOLEAN→boolean, 其余→text），CmxColumn 仍拿逻辑 type。
- CTX 存盘里的 `dataType:"number"` 等逻辑值迁移为物理值（number→DECIMAL 或 INT，按是否有小数位）。

### 维度语义值域统一
- 统一存 `dimType`，值域 `dimension/measure/attribute/relation`（DOC 现状）。
- CTX 旧 `kind` 值 `text` → 迁移为 `''`(无维度语义) 或 `relation`；`dimension/measure/attribute` 一一对应。
- 引擎所有 `field.kind === 'dimension'` 改读 `field.dimType`；校验器 `FIELD_KINDS` 同步。

### 引用字典统一
- CTX 旧 `dimension`(维度code) + `dict.valueField/labelField` → 统一为 `refDict`(=维度code) + `refField` + `displayField`。
- 引擎 `_dictSettingsForField` 重写：`dimCode = field.refDict || field.fieldName`；dict 配置从 `refField/displayField` + 维度 `dim.dict` 组装。

## 兼容/迁移策略（关键安全措施）
**在 `normalizeProfile` 里加 field 级迁移层**：读入旧键自动转新键（`code→fieldName`、`kind→dimType`、`dataType` 逻辑→物理、`dimension→refDict` 等），使：
- 旧存盘 profile 不改也能被新引擎读（运行期归一）
- 存盘迁移脚本只是"固化"归一结果，降低风险
- 回滚时旧代码读新数据需反向兼容（可在迁移层双向支持一段时间）

## 实施步骤（分阶段，每步可验证）
| 步 | 内容 | 验证 |
|---|---|---|
| 1 | normalizeProfile 加 field 迁移层（旧键→新键，运行期归一，不动存盘） | 旧 profile 经引擎编译结果不变（引擎测试全绿） |
| 2 | 引擎 + 校验器改读新键（配合迁移层，旧数据仍可跑） | engine/validator 测试改断言后全绿 |
| 3 | 服务端 portalManagerService 536-539 改新键 | 服务端解析维度集合正确 |
| 4 | UI manager + adapter + schema 改用统一键（写盘产出新键） | 三端 UI 回归；新建/编辑字段写出新键 |
| 5 | 迁移脚本固化 3 个存盘 profile → 新键 | diff 核对；编译/校验/预览不变 |
| 6 | 移除迁移层里的旧键兼容（可选，或保留一版） | 全量回归 |

> 建议 1→2→3 先行（加迁移层 + 引擎/校验/服务端读新键，旧数据靠迁移层兼容，**不动存盘**），验证稳定后再做 4→5（UI 写新键 + 固化数据）。

## 风险
- **最高：`code→fieldName`** —— `row[code]` 是运行时行数据键，改了之后引擎读写行、字典 writeBack、dependsOn/分组引用全部联动；迁移层必须同时归一 field 键**和**任何引用 code 的地方（dependsOn 数组值、group members 字符串、anchor.match 键、columnModel.toTitleCols）。
- **dataType 逻辑↔物理** —— 迁移要按小数位猜物理类型，可能不完美；建议 number→DECIMAL(默认)、有 integerDigits 无小数→INT。
- **dimType 值域** —— CTX 的 `text` 无对应，迁移为空。
- 迁移脚本必须幂等 + 先备份。

## 不在范围
- DCT/DOC 的 `dataType` 物理类型不变（本就是基准）
- CTX 独有属性（display/formula/compute/列布局）不要求 DCT/DOC 也有
- 引擎对 CmxColumn 的输出契约不变（仍输出逻辑 type）

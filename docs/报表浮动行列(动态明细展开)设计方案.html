报表浮动行列 —— 动态明细展开设计方案

固定格式报表（资产负债表/利润表）之外的第二类：格式非固定报表。某些行/列在运行时按数据源浮动展开不定条数的明细（如应收账款前 N 大客户），且浮动行列本身可再分级（按地区 ▸ 客户）。目标：不新增表、复用既有 Region▸Row×Col▸Cell 与取数引擎，把"浮动"收敛为"模板行 × 数据源"的展开问题。

0核心结论 · TL;DR

"浮动"的本质：报表设计时并不知道会有多少行/列，只知道一条模板行长什么样和数据从哪来。运行时把模板行按数据源的行数复制 N 份、逐行套用模板的公式与样式，就得到浮动明细。这不是新结构，是既有 Region▸Row×Col▸Cell 模型的一次"实例化展开"。

复用既有（零改 / 配置级） 小改（既有模块加分支） 新增
能力落点做法状态

一句话架构
浮动行列 = 模板行（设计态，1 条）× 数据源（运行态，N 条）→ 展开引擎实例化（N 条实例行，落 cr_cell_data）。设计态永远只存"1 条模板 + 取数从哪来"，实例行是运行态派生物，与 org+period 绑定、每期一份。设计器/画布/取数引擎全部复用，唯一新增是"展开"这一步。

1需求 · 两类报表

1.1 固定格式 vs 浮动格式

① 固定格式（现已支持）

行数、列数在设计时完全确定。资产负债表、利润表、现金流量表——每一行是一个法定项目（货币资金/应收账款/存货…），行次固定、格式固定。设计时画好、运行时只填数。

当前平台的全部能力都在这一类。

② 浮动格式（本方案）

报表主体固定，但某些行/列在运行时按业务数据浮动出不定条数。设计时不知道有几行，只知道"这里要列出前 N 大待收款客户"。运行期实际有多少客户，就展开多少行。

列上同理：如"每个月一列"，月份数按期间范围浮动。

1.2 三种浮动形态

形态含义典型例
行浮动纵向展开不定行数的明细应收账款表列出前 10 大 / 前 N 大待收客户；存货明细按物料展开
列浮动横向展开不定列数按月/按期间横向铺列；按产品线横向铺列；多组织横向对比
分级浮动浮动行/列本身带层级按地区浮动 → 每个地区下再按客户浮动待收款；末级明细 + 地区小计 + 总计

2核心洞察 · 模板与实例分离

2.1 浮动区 = 模板行 × 数据源

把一个浮动行拆成两个正交的东西：

模板（设计态 · 1 条 · 与 org/period 无关）

  • 长什么样：单元格样式、缩进、字体、数字格式；
  • 放什么公式：B 列 = 期末余额、C 列 = 账龄、D 列 = 占比——公式带行维度占位符；
  • 挂在哪：属于哪个区域、父行是谁（分级时）。

数据源（运行态 · N 条 · 依赖 org+period）

  • 有哪些行：前 10 大客户是哪 10 个？某期实际发生的地区有几个？
  • 怎么排序/取多少：按余额降序取前 N、或全量、或按维度分组；
  • 每行的维度键：客户编码 = C001，地区 = 华东——喂给模板公式的占位符。
模板行 T（1 条） × 数据源行 [d1,d2,…dN] → 实例行 T·d1 … T·dN（N 条） → cr_cell_data 落值

2.2 为什么能复用 Region▸Row×Col▸Cell

已核实 cr_report_row / cr_report_col 的字典定义（cmxfico_report_dct_meta_v1.json）自带全部所需骨架，浮动几乎不引入新概念：

既有列类型浮动如何复用
row_typedata/subtotal/total/title/blank新增约定值 float（浮动模板行）；小计/合计沿用 subtotal/total
parent_id / full_path / level_no / is_leaf自分级骨架分级浮动直接落这里：地区行是父、客户行是子，物化路径天然表达层级
formula / account_range / balance_dir取数公式模板行的公式定义，展开时逐实例行替换维度参数
indent / is_bold / sort_no呈现模板缩进/加粗/排序，实例行继承并按展开顺序重排 sort_no
region_code区域归属浮动区就是一个 region_type='data' 的数据区，模板行与实例行同属它
关键结论
列结构 cr_report_col 与行完全同构（selfHierarchy:true、parent_id、col_type），所以列浮动 = 行浮动转置，同一套引擎处理，无需第二套代码。

3模型 · 浮动区定义

模板行在 cr_report_row 里就是一条普通行，只是多带一段"浮动描述"。用行的既有 remark 无法承载结构化描述，故把浮动描述放进行的扩展 JSON（版式 BLOB 里 model 侧 rows[].float，落库时投影到行的一个描述字段/或随 BLOB 走）。下面给出 model 侧契约。

3.1 行浮动区 floatRow

// ReportModel: sheets[].regions[].rows[] 里，一条模板行
{
  code: "TPL_AR_CUST", row_type: "float",   // ← 浮动模板行
  name: "{{cust_name}}",                    // 行标题模板，占位符运行时替换
  float: {
    axis: "row",                          // row | col
    dataSource: {                          // §3.4 数据源契约
      kind: "fn",                        // fn 取数函数 | dict 字典 | sql 具名查询
      expr: "FLIST('ar_cust', @org, @period, top=10, order='amt desc')",
      keyField: "cust_code",           // 每行的维度键字段
      labelField: "cust_name"
    },
    dims: ["cust_code"],                  // 该浮动行携带的维度，喂给单元格公式
    emptyPolicy: "hide"                 // 无数据时：hide 收起 | keepOne 保留占位 | zero 置零
  },
  cells: {                                  // 模板每列的公式（带占位符）
    B: "QM(0,@current,{{cust_code}})",     // 期末余额
    C: "QAGE(0,@current,{{cust_code}},'lt1y')",
    D: "=B{{r}}/B{{total}}"              // {{r}}=本实例行号 {{total}}=合计行号
  }
}

3.2 列浮动区 floatCol

与行完全对称，axis:"col"；数据源产出的是"列集合"（如 2026-01…2026-12），模板列的每个单元格公式带 {{period}} 占位符。展开时横向复制列，落到 cr_report_col（col_type 继承、parent_id 支持多级列头）。

{
  code: "TPL_MONTH", col_type: "float",
  name: "{{period_name}}",
  float: {
    axis: "col",
    dataSource: { kind:"dict", expr:"cr_acct_calendar", filter:"parent=@year && level=month", keyField:"period_code" },
    dims: ["period_code"]
  },
  cellsByRow: { /* 该浮动列 × 每个数据行 的公式，占位符 {{period}} */ }
}

3.3 分级浮动 hierarchy

分级 = 数据源产出带父子关系的行集合。地区是父维度、客户是子维度：

{
  code: "TPL_AR",
  float: {
    axis: "row",
    levels: [                                // ← 多级 = 分级浮动
      { dim:"region",  dataSource:{…}, rollup:"subtotal" }, // 地区：每组出小计行
      { dim:"cust_code", dataSource:{…}, rollup:"none" }     // 客户：末级明细
    ],
    grandTotal: "total"                  // 顶部/底部总计行
  }
}

展开时对每个地区取其客户集合，生成：地区小计行(subtotal) + 其下 客户明细行(float 实例, parent_id=地区行)，最后一条 总计行(total)。full_path = 华东.上海A 天然表达归属，小计/合计按 full_path 前缀归集。

3.4 数据源 dataSource 契约

kindexpr 含义产出典型
fn取数函数（复用 §8 引擎），如 FLIST 罗列[{key,label,...dims}]前 N 大客户按余额降序
dict字典表 + filter，如会计日历/组织树字典行集合按月铺列、按组织铺行
sql后端具名查询（白名单，不接受任意 SQL）结果集复杂业务明细
安全边界
sql kind 只接受后端登记的具名查询（参数化），绝不接受前端拼的原始 SQL——沿用平台既有的取数路由/白名单约定，杜绝注入。

4存储映射 · cr_* 表（不新增表）

4.1 定义态：模板存哪

模板是设计版式的一部分，随模式一走（见 报表两模式加载存储方案）：

  • 主真相：cr_report_fmt.doc_content BLOB（SpreadJS SSJSON + model 侧 rows[].float 描述）——无损复原；
  • 关系投影：模板行照常投影到 cr_report_row，row_type='float' 标记；浮动描述结构化字段可投影到行的一个 float_spec 描述列（若不想加列，则仅存 BLOB，投影行只留标记，展开时从 BLOB 读 spec）。
是否加列？
倾向不加列：float spec 只随 BLOB（model）走，关系表 cr_report_row 仅用 row_type='float' 做可查询标记。这样零 DDL、零迁移，符合"不动代码/表"。若后续需要按 spec 检索，再补 float_spec VARCHAR（幂等补列，见 RPT M1 经验）。

4.2 运行态：实例行怎么落

展开出的实例行不进设计态 cr_report_row（那是模板，多期复用），而是作为运行态派生物随数据落库。两个选择：

方案 A（推荐）· 实例行随 cell_data

实例行只在运行态展开缓存 + cr_cell_data 里存在。cr_cell_data 的 row_id 用稳定派生 ID（模板行 ID + 维度键哈希），cell_ref 记实际坐标，element_code/维度随行。设计态 cr_report_row 只有模板那 1 条。

复用 8 元键 org+period+report+version+sheet+region+row_id(派生)+col_id

方案 B · 实例行落 cr_report_row（带期）

展开后把实例行写回 cr_report_row。问题：行字典无 org/period 维度（是设计态字典），多期会互相覆盖。需要给行表加期维度——违背"不动表"，不推荐。

采用方案 A
设计态=模板（1 条，无期），运行态=实例（N 条，随 org+period 存 cr_cell_data）。行的"身份"由稳定派生 row_id 表达，同一客户跨期 row_id 稳定，可做同比/环比。

4.3 稳定 ID 与幂等

// 实例行稳定 ID（跨期一致、幂等重算不漂移）
row_id(instance) = stable_hash( templateRowId + "|" + dimKeyPath )
// 例：模板 TPL_AR_CUST(id=9001) × 维度 华东.C001
//     → dimKeyPath = "region=华东;cust=C001" → row_id = 9001_a3f2…（BIGINT 域内稳定）
  • 幂等：同 org+period 重复展开/取数，实例行 row_id 不变 → cr_cell_data ON CONFLICT(8 元键) UPSERT，不产生重复；
  • 跨期可比：华东.C001 在 2026-01 与 2026-02 的 row_id 相同 → 天然对齐做趋势；
  • 删除/收起：某期该客户无数据且 emptyPolicy='hide' → 不生成实例行、不落 cell_data，读时自然缺席。

5展开引擎 · Expand

新增一个后端服务 expand_report(code, version, org, period)，在一次装载内（对齐续30"打开只一次后端调用"）完成"模板 → 实例行 → 取数 → 落值"，返回展开后的完整 model 给前端渲染。

5.1 展开六步

① 读模板→ ② 解析 float spec→ ③ 拉数据源→ ④ 生成实例行(分级)→ ⑤ 公式重定位→ ⑥ 计算+落 cell_data
  1. 读模板：从 cr_report_fmt BLOB + cr_report_row(row_type='float') 取模板行与 spec；
  2. 解析 float spec：拿到 axis / levels / dataSource / dims / emptyPolicy；
  3. 拉数据源：按 kind 走取数函数 / 字典 / 具名查询，得到（分级的）维度行集合；
  4. 生成实例行：模板 × 数据源 → N 条实例行；分级则递归展开每层，插入 subtotal/total 行；计算稳定 row_id、full_path、level_no、sort_no（连续重排）；
  5. 公式重定位：见 §5.2；
  6. 计算+落值：把实例行喂给既有取数/计算引擎（QM/QC/FS + REF），UPSERT cr_cell_data。

5.2 公式重定位（关键难点）

模板公式有两类占位符，展开时替换：

占位符替换为例
{{dim}}（维度键）该实例行的维度值QM(0,@current,{{cust_code}}) → QM(0,@current,'C001')
{{r}}（本行号）实例行展开后的物理行=B{{r}}/B{{total}} → =B3/B1
{{total}}/{{parent}}归集目标行号小计引用其子行区间：=SUM(B3:B5)
坐标漂移免疫
模板里禁止写死坐标，只允许 {{r}}/{{total}}/{{parent}} 语义锚点 + 维度键。展开引擎负责把语义锚点翻译成展开后的真实坐标——这样无论浮动出多少行，公式都自愈。跨报表引用继续走 RPTAREA 的命名区域锚点（坐标无关），二者一脉相承。

5.3 小计/合计归集

展开后按 full_path 归集：

  • 小计行（row_type='subtotal'）：=SUM(子行区间)，子行 = full_path 以本行路径为前缀的末级实例行；
  • 总计行（row_type='total'）：汇总各小计，或全体末级；
  • 归集用语义锚点而非死坐标——引擎在实例行落定后一次性回填区间。分级越深，递归归集越自然（level_no 逆序汇总）。

6设计态 UI · 定义浮动区

在报表设计器（native-pages · portal.rpt.designer）的属性页"行/区域"段扩展，把某行标为浮动模板并绑定数据源。改的是 native-page（免构建、改源即生效），不动组件。

行属性页新增"浮动"子段

  • 开关：此行为浮动模板（置 row_type='float'）；
  • 数据源选择器：kind（函数/字典/查询）+ expr 向导（复用 fx 函数向导）；
  • 维度绑定：keyField / labelField / dims；
  • 分级：可加多层 level（地区▸客户），每层选 rollup（小计/无）；
  • 空策略：hide / keepOne / zero。

模板公式编辑

  • 在模板行的单元格里写带占位符的公式，fx 向导插入 {{cust_code}} 等维度令牌；
  • 设计态预览：用 1~2 条示例数据就地展开示意（不落库），让设计者看到浮动效果；
  • 小计/合计行用语义锚点向导（选"汇总本组明细"而非手写区间）。
与 fx 组件的关系
浮动模板的单元格公式仍走既有 fx 函数/公式编辑器（计划中的 cmx-fx-editor 公共组件）。浮动只是给公式多了一层"维度占位符"语义，向导里增加"插入维度令牌"入口即可，不改公式引擎本身。

7应用态 UI · 展开呈现

报表应用器（report-applier）打开报表时，后端一次调用返回"已展开的 model"（版式+实例行+数据+公式），画布直接渲染。对齐续30：打开只一次后端调用。

  • 展开发生在后端：前端拿到的就是最终 N 行/列，SpreadJS 照常 fromJSON + setFormula（自动计算）；
  • 分组折叠：分级浮动可利用 SpreadJS 的 row group/outline，把地区做成可折叠分组，小计置组头/组尾；
  • 刷新语义：切换 org/period 或点"取数/计算"→ 重新 expand（数据源可能变，客户名单随之变）；
  • 手工调整：允许对展开结果做有限手工覆盖（如手动排除某客户），覆盖记在 cr_cell_data（is_manual=1），下次展开保留手工态（幂等 row_id 保证对齐）。
列浮动的画布代价
列浮动会改变列数，SpreadJS 需按展开列数建列 + 多级列头合并。建议列浮动上限设阈值（如 ≤ 36 列/期），超出走"分页/横向滚动"而非无限铺列，避免画布性能塌陷。

8取数打通 · 数据源来源

浮动的"有哪些行"最终来自业务数据。三条来源，全部复用平台既有能力：

来源用于复用

9难点取舍

① 实例行落哪（已定）

方案 A：模板存设计态、实例随 cr_cell_data 运行态。避免给行字典加期维度。采纳

② 稳定 ID（已定）

模板行 ID + 维度键路径哈希 → 跨期稳定、幂等 UPSERT、可同比。采纳

③ 公式坐标漂移

模板禁死坐标，只用语义锚点 {{r}}/{{total}} + 维度键，展开引擎重定位。跨表继续用 RPTAREA 命名锚点。

④ 展开时机

后端展开（打开一次调用返回已展开 model），前端零展开逻辑；切期/取数触发重算。

⑤ 列浮动性能

设列数阈值，超限分页；多级列头用 parent_id 落 cr_report_col。

⑥ 手工覆盖 vs 重算

is_manual=1 的实例行在重展开时保留；稳定 row_id 保证对齐不丢。

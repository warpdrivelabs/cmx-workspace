# P9 — 页面元数据对程序员友好：函数体外置为真 `<script>`

> 状态：方案文档（不动代码）。目标：让 CMXHTMLDesigner 生成的页面既对设计器友好（可往返编辑），又对程序员友好（能用编辑器打开看/改函数）。

---

## 1. 问题本质

设计器把用户定义的全部内容塞进页面末尾**单行压缩的** `<script type="application/json" id="__designer_meta__">`。其中：

- **结构化声明数据**（`pageData` / `dataFlow` / `models` / `pageServices` 定义 / `pageDeps`）—— JSON 表达本就合理，可读。
- **JS 代码字符串**（`pageFns[].body`、`pageInterfaces[].body`，以及设计上的 `pageServices[].responseTransform/bodyTemplate`、`models[].events`、`dataSources[].transform`）—— 换行存成字面 `\n`、引号存成 `\"`，**压成一行**。

痛点实测：
| 页面 | meta 字符数 | pageFns 数 | 最长函数 |
|---|---|---|---|
| voucher | 15.7K | 13 | 52 行 |
| trade-form | 18.7K | 20 | 168 行 |
| voucher-neo | 50.3K | 25 | **273 行 / 12K 字符压成一行** |

273 行的函数压在一行 JSON 字符串里、全转义——纯文本编辑器几乎无法查看或修改。

**关键利好**：现有页面里真正是代码的只有 `pageFns[].body` + `pageInterfaces[].body`；services/models/events/dataSources 的代码槽位**当前全为空**。所以问题收敛为：**把函数体从 JSON 字符串拿出来，写成页面里真正的 JS。** 结构化数据继续留在 JSON。

---

## 2. 一个决定方案的架构事实（已实测核对）

存盘的页面 HTML **只有「画布 HTML + 单个 `__designer_meta__`」，没有任何运行态 `<script>`**（voucher.html 经核实：全文件仅 1 个 script 标签即 meta，无 new Function / __hydrateEvents / initPageModels）。

`__designer_meta__` 是**唯一事实源（SSOT）**，同时服务两端：
- **Portal 运行时**：渲染时 `workspace-html-page-preview.js:buildRunnableHtmlDocumentForPage` → `normalizeServerPageHtmlForDebug(html)` → 在内存里 `JSON.parse(meta)` + `buildCmxScriptBlockFromPageState` **即时编译**出可执行脚本块 → 注入执行。**编译产物只在运行态内存，从不回写存盘文件。**
- **设计器**：导入时 `JSON.parse(meta)` → `setState` 回填各面板、函数体回填 CodeMirror。

结论：函数体外置后，**两端都要改**——序列化侧把 body 写进外置 `<script>` 并随存盘 HTML 持久化；Portal 与设计器读回时都要从外置 `<script>` 取 body 来编译/回填。外置 `<script>` 是事实源的一部分（不是运行态产物），必须落盘。

---

## 3. 方案：函数体外置为具名 `<script>`，meta 只存结构

### 3.1 目标页面形态

```html
<!-- 画布 HTML（用户拖的组件，原样可读） -->
<div data-node-id="n-1"> ... </div>

<!-- 用户函数：真正的多行 JS，可高亮/可改/可断点。
     用 type="text/cmx-page-fns"（非 module、不执行）承载函数源文本，编译侧按函数名提取 body。
     函数体仍是全局作用域代码（裸用 $data/host/形参），与现有 new Function 语义一致。 -->
<script type="text/cmx-page-fns" id="__page_fns__">
  // pageFn: initVoucher  params:
  function initVoucher($data, host) {
    var ms = host.ms;
    if (!ms) { alert('协调器尚未初始化'); return; }
    // …真实换行、真实引号…
  }
  // pageFn: toggleVoucherEdit  params:
  function toggleVoucherEdit($data, host) {
    host.setVoucherEditMode(!$data.voucherEditing);
  }
  // iface: initPage
  function __iface_initPage($data, host) {
    if (host.initVoucher) host.initVoucher();
  }
</script>

<!-- meta：只剩结构化声明 + 函数名/签名/绑定引用（可读 JSON） -->
<script type="application/json" id="__designer_meta__">
{
  "pageData": [...],
  "dataFlow": {...},
  "models": [...],
  "pageServices": [...],
  "pageFns": [
    { "name": "initVoucher", "params": "", "readsVars": [], "writesVars": ["voucherEditing"] },
    { "name": "toggleVoucherEdit", "params": "", "readsVars": ["voucherEditing"], "writesVars": [] }
  ],
  "pageInterfaces": [ { "name": "initPage", "enabled": true } ]
}
</script>
```

> 存盘 HTML 只有「画布 + `#__page_fns__`（真 JS 函数）+ meta（结构）」三块，**没有运行态绑定脚本**——绑定块由 `buildCmxScriptBlockFromPageState` 在运行/调试时即时编译（现状如此，外置后改为从 `#__page_fns__` 取 body 编译）。
> meta 里 `pageFns` 不再有 `body`，只留 `name/params/readsVars/writesVars`；`pageInterfaces` 只留 `name/enabled`。函数体在 `#__page_fns__` 里是真 JS。

### 3.2 函数签名约束（外置必须复刻，否则函数跑不起来）

调研确认现有运行时签名（外置后必须保持一致）：

| 类型 | 现 `new Function` 签名 | 运行作用域 |
|---|---|---|
| pageFns | `("$data","host",<params>, body)` 再 `.bind(host,$data,host)` | 全局作用域 |
| pageInterfaces | `("$data","host",<params>)` | 全局 |
| pageServices | `("$data","host","params","_opts")` | 全局 |
| responseTransform | `("data","$data","host")` | 全局 |
| 模型事件 / DOM 事件 | `("event","host")` 包在 `with(host){}` | 全局 |

外置函数体内可裸用 `$data`/`host`/形参。**全局作用域**（body 内不能用 `import`/ES module 语法）。因此 `#__page_fns__` 用 **`type="text/cmx-page-fns"`（浏览器不执行，纯文本载体，与 JSON meta 同性质）**，编译侧按函数名提取 body 文本、再走现有 `new Function("$data","host",<params>, body).bind(host,$data,host)` 注入——签名与作用域语义**零变化**。不要用 `type="module"`+`export`（会与全局作用域 body 冲突，且模块 defer 语义打乱时序）。

**WebSocket 服务例外**：三函数共享 `_ws_<name>` 闭包，**必须内联**，不可外置（保留特例）。

### 3.3 改动点（不动代码，仅列清单）

**A. 序列化侧（设计器 → 存盘 HTML）**
- `designer-app.js:_buildSourceBundle`（~332）：除写 meta 外，新增生成并落盘 `#__page_fns__` 具名函数脚本（把 `pageFns[].body` + `pageInterfaces[].body` 写成多行真 JS）；meta 的 `JSON.stringify(state)` 改为剔除 `body` 字段、并加 `space=2` 多行格式化。`#__page_fns__` 是事实源的一部分，必须随 HTML 持久化。

**B. 编译侧（meta + 外置 script → 可执行）—— Portal 与设计器调试共用**
- `build-cmx-page-script-block.js`：现在从 `meta.pageFns[].body` 取函数体内联进 `new Function`。改为**从 `#__page_fns__` 取对应具名函数的体文本**再编译（签名/`.bind($data,host)` 注入语义不变）。services/transform/接口/模型事件五类各自处理。
- `normalize-server-page-html-for-debug.js`：它 `JSON.parse(meta)` 后调 `buildCmxScriptBlockFromPageState`。需先把 `#__page_fns__` 里的 body 合并回 state（或让 build 函数直接接收外置 script 文本），再编译。**这是 Portal 运行的必经路径，必须改对，否则页面跑不起来。**

**C. 还原侧（存盘 HTML → 设计器面板，保住往返可编辑）**
- `designer-app.js:_applyImportedHtml`/source-apply、`setState`：meta 已无 `body` → 从 `#__page_fns__` 解析出每个具名函数体文本，回填 `pageFns[].body` 再喂 CodeMirror。`parseDesignPageFunctionDeclarations`（已有类似能力）可复用/扩展。

**D. 整页导出**
- `wrapHtmlDocument`（html-utils.js）：导出可运行整页时一并写入 `#__page_fns__`，并让编译走外置取 body。
- `init-page-models.js:wireModelEvents`：模型事件若启用外置，改为引用；当前 events 全空，可暂不动。

### 3.4 兼容与迁移
- **旧页面**（body 还在 meta 里）：还原侧做兼容——meta 有 `body` 用 meta 的，无 `body` 则从 `#__page_fns__` 取。新存盘统一外置。
- 现有 6 个含 pageFns 的页面（voucher/voucher-neo/trade-neo/trade-form 等）可在设计器里"打开→另存"一次性转为新格式，或写迁移脚本批量转。

---

## 4. 风险
- **编译侧必须改对（最关键）**：Portal 运行的唯一路径是 `normalizeServerPageHtmlForDebug` → `buildCmxScriptBlockFromPageState`。函数体外置后，编译时必须从 `#__page_fns__` 取 body，否则编出的脚本块函数体为空，**页面直接跑不起来**。这不是"可选优化"而是"改了 A 就必须同步改编译侧"。
- **往返保真**：meta 去 body 后，设计器导入强依赖"从 `#__page_fns__` 反解 body 回填 CodeMirror"。反解必须健壮（函数名匹配、体文本精确切分），否则丧失可编辑性——主要工程风险点，需充分测试。
- **`#__page_fns__` 文本提取**：按函数名切分函数体要可靠（注释标记 `// pageFn: <name>` + 函数声明双保险），避免函数体内含 `function` 字样误切。
- **WebSocket 服务**：闭包约束，保留内联，不外置。
- **`</script>` 注入安全**：外置真 JS 里若出现字符串 `</script>` 会截断——需转义（现有 meta 用 `<`→`<`，外置脚本同样要处理）。
- **sourceURL/调试**：现有 `//# sourceURL=cmx://page-fn/...` 便于断点；外置后可保留 sourceURL，devtools 映射不退化。

## 5. 实施建议（分阶段，每步可验证）
1. **格式化兜底**（低风险打底）：先把 meta 的 `JSON.stringify` 加 `space:2`（结构部分立即可读），不动 body。立竿见影且零风险。
2. **外置 pageFns body**：序列化写 `#__page_fns__`（落盘）+ meta 去 body；**同步改 `buildCmxScriptBlockFromPageState` 从外置取 body 编译**；Portal 运行验证不变。
3. **还原侧反解**：设计器导入从 `#__page_fns__` 回填 CodeMirror；往返编辑验证。
4. **pageInterfaces 同法外置**；services/events 暂留（当前空）。
5. **迁移现有页面** + 回归（Portal 运行 + 设计器往返）。

## 6. 不在范围
- WebSocket 服务函数（保持内联）。
- 结构化数据（pageData/dataFlow/models/services 定义）——继续留 JSON，本就可读。

## 验证标准
- 生成存盘 HTML：函数以多行真 JS 存在于 `#__page_fns__`，编辑器可直接看/改；meta 为多行格式化 JSON 且无 body。
- Portal 运行：`normalizeServerPageHtmlForDebug` 从外置取 body 编译，页面功能与现状完全一致（函数照常挂 host、$data/host 注入不变）。
- 设计器往返：打开已存页面 → 函数体正确回填 CodeMirror → 改后另存无损。
- 旧格式页面：仍能正确打开（body-in-meta 兼容回退）。

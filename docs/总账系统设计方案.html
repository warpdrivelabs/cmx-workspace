总账系统（GL）· 设计方案

参照 SAP FI / S/4HANA ACDOCA 通用日记账，覆盖配置 · 初始化 · 做账 · 记账 · 冲销 · 折旧 · 查账 · 余额全链路。核心是新增一层过账引擎（ga_* 通用日记账 + 余额），把既有的「配置字典 cf_* + 录入单据 cv_* + 报表 cr_*」闭合成完整总账。后端 cmx-container（Rust · axum · tokio-postgres），前端复用四区工作台。
后端 cmx-gl crate 群（镜像 cmx-doc/cmx-rpt） 通用日记账 ga_journal（ACDOCA 范式） 复用 cf_*/cv_*/cr_* 与 ZmcDataSet 管线 新增 /api/gl/* · 过账/冲销/折旧/结账 状态：设计（不动代码）

§0结论速览

总账系统不是从零起的新系统。cmx 财务模块（fi.cmxfico.gl）已经有了三块地基：①配置层——35 部 cf_* 会计配置字典（科目表/公司代码/分类账/凭证类型/记账码/会计期间…，全部按 SAP 建模）；②录入层——4 层主从的凭证单据 DOC（cv_batch→cv_header→cv_acc_line→cv_aux_line，三区/四区工作台可录入、可校验借贷平衡）；③报表层——RPT 报表平台（cr_* 三表 + 取数公式，出资产负债表/利润表）。真正缺的，是把这三块串起来的那台发动机——过账引擎：凭证一旦「记账」，要写进一张不可变的通用日记账、滚动出科目余额，并支撑冲销、折旧、期末结账、账簿查询。本方案就是补这台发动机（新增 ga_* 一族物理表与 cmx-gl crate 群），全部长在既有流水线之上。

一句话架构

核心洞察
总账 = 做账（可改的草稿，cv_* 单据）+ 记账（一次不可逆的投影，落成 ga_journal 通用日记账）+ 余额（日记账的滚动汇总，ga_balance）。凭证是过程，日记账是账，余额是账的合计。 冲销、折旧、期末，本质都是「再生成一张凭证、再走一遍过账」——所以整套系统只有一个写账入口（过账引擎），一切账务变更都从它流过，天然可审计、可对账、可重算。查账则完全是读：从 ga_journal（明细）和 ga_balance（合计）出，绝不碰写路径。

§2目标 · 非目标 · 设计原则

✓ 目标（本方案覆盖）

  • 配置：会计科目表、公司代码、分类账（并行会计）、会计年度/期间变式、凭证类型、记账码、号码范围、字段状态组、账户组、货币/汇率、自动记账规则。
  • 初始化：物理表部署、配置装载、期初余额导入、期间开放、号段置初、资产原值接管。
  • 做账：凭证录入（多币种、辅助核算），借贷平衡/字段状态/科目有效性校验，预制暂存。
  • 记账：过账引擎——凭证投影为通用日记账 ga_journal + 增量滚动余额 ga_balance，取号、分类账扇出、事务化、幂等。
  • 冲销：标准反向冲销与负额红冲，冲销原因、跨期处理、双向勾稽。
  • 折旧：资产主数据、折旧范围/方法、计划折旧 vs 已提折旧、周期折旧运行生成凭证。
  • 查账：总账、明细账、多栏账、科目余额表、试算平衡表，逐格下钻到凭证。
  • 余额：期初/本期发生/期末，多币种（交易币/本位币/集团币）、多分类账、按维度余额、年结结转。

✗ 非目标（本期不做 / 另案）

  • 应收应付/资金/成本管理明细：本方案是总账（GL）。AR/AP/CO 作为子分类账，仅保留科目行的 customer_id/supplier_id/cost_center_id 维度与「特别总账标识」挂钩，明细子模块另案。
  • 物料账/生产成本核算：ACDOCA 的 MM/ML 维度列预留但不实现取数。
  • 合并报表抵消引擎：多组织汇总/合并归 RPT 报表平台（已有方案），本方案只保证 ga_balance 可按组织树读。
  • 税务申报/发票：只做税码在分录上的记录与税额行，申报另案。
  • 预算控制（可用额度检查）：保留 int_order/wbs 维度，主动式预算校验另案。

设计原则

  1. 单一写账入口。 一切账务变更（记账/冲销/折旧/结转）都必须经过同一台过账引擎产出 ga_journal。禁止任何旁路直接 INSERT 日记账或改余额。这是可审计、可对账、可重算的前提。
  2. 通用日记账是唯一事实源。 ga_journal 一旦写入即不可变（不 UPDATE、不 DELETE，纠错只能靠冲销）。ga_balance 是它的派生合计，任何时刻都能从 ga_journal 全量重算校验——余额错了以日记账为准。
  3. 做账与记账严格分离。 cv_* 凭证是可改草稿（做账）；ga_* 是不可改的账（记账）。过账是二者之间一次性、事务化的投影。凭证过账后锁定，改动只能冲销重做。
  4. 配置驱动，规则不写死在代码。 借贷方向来自记账码、期间开放来自期间字典、编号来自号段、折旧账户来自账户确定——引擎读 cf_*/ga_acct_determ 执行，不硬编码科目号或规则。
  5. 参照 SAP 但适配平台。 数据模型对标 BKPF/BSEG/ACDOCA，但金额沿用平台既有的借贷分列 6 度量（而非 SAP 的带符号金额 + 借贷标志），复用 cv_* 的聚合上卷语义，减少异构。
  6. 多分类账、多币种正交。 分类账（ledger）进主键、进扇出；币种是三组并列度量列。一次录入，各分类账/各币种各自成账，互不干扰（IFRS/CAS 并行）。
  7. 可复用者不新起炉灶。 判据：若 DOC/DCT/RPT/JOB/FLOW 已有，总账只允许加分支/加参数，不允许 fork。

§3领域模型：五层与 SAP 对照

在写任何表之前，先把总账的五层数据钉死，并逐层对上 SAP 的物理表。看清哪层已有、哪层要建，是后续所有设计的地基。

3.1 五层数据分层

① 配置层 Configuration 已就位 cf_*
会计核算的规则与主数据骨架：科目表、公司代码、分类账、凭证类型、记账码、会计期间、字段状态组、货币汇率…… 35 部 cf_* DCT 字典，设计期维护，运行期被引擎读取。决定「怎么记账」。
② 主数据层 Master Data 部分已就位资产新增
科目主数据（cf_gl_account，层级、性质、币种，已就位）+ 成本中心/利润中心/段（cf_* 已就位）+ 资产主数据 ga_asset/ga_asset_dep（折旧用，新增）。决定「记到哪个对象上」。
③ 凭证层 Document（做账）已就位 cv_*
可编辑的会计凭证草稿：批→头→科目行→辅助行。借贷平衡在此校验，状态 draft→audited。录入 = 制单，不是记账；此层可反复改、可删。 对标 SAP 预制凭证（BKPF.BSTAT='V'）。
④ 日记账层 Universal Journal（记账）新增 ga_journal

⑤ 余额层 Balances（余额）新增 ga_balance
日记账的滚动合计：按分类账×公司×科目×期间（×维度）汇总期初/发生/期末。过账时增量维护，可全量重算。查账与报表的主要读源。对标 SAP GLT0/FAGLFLEXT。= 报表引用却缺失的 cv_gl_balance。

3.3 通用日记账：单一事实源

本方案最重要的一个设计取向，是学 S/4HANA 的 Universal Journal（通用日记账）：把「账」收敛到一张行项目表 ga_journal，而不是像经典 SAP 那样散在 BSEG + 三张 open-item 索引表 + GLT0 + CO 的 COEP + 资产的 ANEP 里、期末还要对账。

为什么收敛成一张表
免对账：成本中心/利润中心/段/订单/资产等维度与总账分录在同一行，不存在「FI 与 CO 不一致」。免冗余：无需维护多套并行明细/合计表。天生多账多币：分类账进主键、6 币种进列，一次过账各账各币各自成行。可追溯：每行带 source_cv_* 与 awtyp/awkey，下钻回源单据。
余额是派生，不是并行
ga_balance 不是独立维护的第二套真相，而是 ga_journal 的 GROUP BY (分类账,科目,期间[,维度]) SUM(借/贷) 结果的物化。过账时增量更新是为了查得快；一旦怀疑不一致，以 ga_journal 全量重算为准（§13 提供 reconcile 作业）。这条纪律让「余额」永远有唯一权威来源。
与 SAP 的一处刻意偏离：金额表达
SAP ACDOCA 用带符号金额 HSL + 借贷标志 DRCRK 表达方向。本平台既有 cv_* 已采用借贷分列（entered_dr/entered_cr、local_dr/local_cr、group_dr/group_cr 六个度量，各自 agg:sum 上卷）。为与既有单据、报表、聚合语义一致，ga_journal 沿用借贷分列，不改用带符号金额。每行只会有借或贷一侧非零。转换关系：SAP 借方 SHKZG='S' → 填 *_dr；'H' → 填 *_cr。这不影响任何会计正确性，只是列布局取向。

§5系统初始化（初始化）

初始化 = 让一个空库变成「可以开始记账」的状态。分两类：系统级（建表、装配置，一次）与启用级（每个公司代码首次上线：导期初余额、开期间、置号段），后者可重复用于新公司接入。

1
部署物理表：POST /api/model/deploy {items:[{kind:"GL",...}]} → compile_gl 读 base_gl_meta.storageTables 建 ga_doc/ga_journal/ga_balance/ga_number_range_state/ga_period_status/ga_asset/ga_asset_dep（幂等，复用 PgTableDefineExecutor）。同时 deploy cf_*（配置字典）与 cv_*（凭证 DOC）。
2
装载配置数据：把 cf_*.json 种子导入配置表（科目表、公司代码、分类账、凭证类型、记账码、期间、账户确定…）。走既有 DCT upsert，后端铸号。
3
开放会计期间：为 (公司,分类账) 在 ga_period_status 建期间行，置启用期为 open；历史期 closed。配置默认来自 cf_fisc_period.posting_allowed。
4
号段置初：为每个 (号段,公司,年) 在 ga_number_range_state 写 from_no/to_no/current_no（首次 current_no=from_no-1），来源 cf_number_range。
5
导入期初余额：启用期上线时，把旧系统的科目期末余额作为新系统启用期期初写入 ga_balance（begin_balance）。校验：全公司 Σ借方期初 = Σ贷方期初（试算平衡）。可选生成一张「期初余额凭证」入 ga_journal 以保持「余额皆有源」。
6
资产原值接管（折旧用）：导入资产主数据 ga_asset 与已提折旧 ga_asset_dep（原值、累计折旧、已用期数、折旧方法），使折旧运行能从中途续提。
期初余额的三条铁律
① 必须试算平衡：导入前全局校验 Σ期初借 = Σ期初贷，否则拒绝。② 损益类科目期初通常为 0（年内启用则带累计发生）。③ 期初可有源可无源：推荐生成期初凭证（借贷方为「期初权益/上期结转」过渡科目）使 ga_balance 完全可由 ga_journal 重算；简化实现也允许 ga_balance 直接置初、ga_journal 从启用期起记。
初始化是长任务，接任务中心

§6做账：凭证录入（做账）

「做账」是制单，不是记账。它产出可反复修改的凭证草稿 cv_*，此层已完整就位（4 层 DOC + fico-ws 工作台 + 借贷平衡校验 + 状态机）。本节说明它如何对接过账，并补齐字段状态与预制两个细节。

6.1 录入即 cv_* 单据 DOC

一张凭证是一棵 4 层主从树，金额六度量（交易币/本位币/集团币 × 借/贷），已按 SAP BKPF/BSEG 建模：

cv_batch 凭证批（一次提交一组） ← Oracle GL_JE_BATCHES └─ cv_header 凭证头（日期/类型/币种/汇率） ← SAP BKPF └─ cv_acc_line 科目行（科目+记账码+借贷+金额）← SAP BSEG 主体 └─ cv_aux_line 辅助行（成本中心/利润中心/段/订单/往来…18 维）← BSEG 分析维度 // 主从链：child.upper_id = parent.id；6 币种度量各级 agg:sum 上卷 // 状态机 doc_status: draft ──audit──▶ audited ──post──▶ posted ──reverse──▶ reversed

6.3 预制与暂存（parking）

对标 SAP 预制凭证（BKPF.BSTAT='V'）：借贷不平也能存草稿（draft），供后续补录、他人接续、审批。只有到审核（audited）才强制借贷平衡，到过账（posted）才校验期间开放并真正动账。三态与过账/冲销的关系：

draft // 草稿：可不平衡、可反复改、可删。做账中 ──audit──▶ audited // 已审：强制借贷平衡；等待过账；仍可退回 draft ──post──▶ posted // 已过账：锁定，不可改；已写 ga_journal/ga_balance ──reverse──▶ reversed // 已冲销：生成反向凭证，原凭证留痕
做账 ↔ 记账的交接点
过账引擎的唯一输入就是一张 audited 的 cv_header（连同其 acc_line/aux_line 子树）。做账层不需要为记账做任何改造——它已经把「一张平衡的凭证」准备好了。§7 讲这张凭证如何变成账。

§7记账：过账引擎（记账）

这是全系统的心脏。「记账（过账）」把一张审核通过的凭证草稿，一次性、事务化地投影成不可变的通用日记账，并滚动更新余额。它是唯一的写账入口——冲销、折旧、结转最终都从这里流过。

7.2 过账事务七步

整个过账在一个 tokio-postgres 事务内完成，全成或全败：

PostingEngine::post(cv_header_id, ctx{operator, post_date?}) -> Result<PostedDoc> { let tx = pool.begin().await?; // 事务开始 1. load 读 cv_header + acc_lines + aux_lines；guard doc_status == "audited" 若已 posted → 409 冲突（幂等：拒绝重复过账） 2. validate ① 借贷平衡 Σlocal_dr==Σlocal_cr（每分类账/每平衡维度） ② 期间开放：post_date→period，查 ga_period_status（按科目类型段） ③ 科目末级+启用；④ 字段状态组必填；⑤ 外币须有汇率 任一失败 → 回滚 + 结构化 violations（复用错误码库） 3. assign_no 每目标分类账：doc_type▶number_range▶ga_number_range_state SELECT ... 幂等与并发：过账绝不能重复动账
① 幂等：步 1 以 cv_header.doc_status 为闸门，已 posted 直接 409；ga_doc 对 source_cv_header_id + ledger 建唯一键兜底，重复插入被 DB 拒。② 并发取号：步 3 用行锁串行化同一号段（见 §7.3）。③ 余额一致：步 6 的 UPSERT 在事务内原子完成；即便并发过账同一科目，行级锁保证累加不丢。④ 全程一个事务 → 要么日记账+余额+锁单全成，要么全回滚，不存在「记了账没滚余额」的中间态。

7.3 号码分配与并发

凭证号 doc_no 不是铸号（铸号给代理主键 id），而是按号段连续递增的业务编号（会计要求连续、可审计断号）。路径 doc_type → cf_number_range → ga_number_range_state：

// ga_number_range_state：一行 = 一个 (号段, 公司, 年) 的计数器 BEGIN; SELECT current_no, to_no FROM ga_number_range_state WHERE range_code=$1 AND comp_unit_id=$2 AND fiscal_year=$3 FOR UPDATE; // 行锁：同号段过账串行，杜绝跳号/撞号 // next = current_no + 1；校验 next <= to_no（超界报错） UPDATE ga_number_range_state SET current_no = current_no + 1 WHERE ...; // doc_no = 格式化(range_prefix, fiscal_year, next) 例：SA-2026-000123 COMMIT;
连续号 vs 高并发的权衡
行锁保证严格连续（会计合规），但同号段过账被串行化。缓解：① 按 公司×年×凭证类型 拆号段，分散热点；② 高吞吐场景可退化为「块号预取」（一次锁取 N 个号发给不同 worker，牺牲绝对连续换吞吐，需业务接受）。默认严格连续；号段状态表与过账在同一事务，回滚则号一并退回（不产生断号）。

1

2

§9冲销（冲销）

已过账凭证不可直接改，纠错靠冲销：生成一张与原凭证相抵的凭证，二者双向勾稽。冲销不是新引擎——它构造一张「反向凭证」交给过账引擎（§7），所以余额、试算平衡自动跟着对。

两种冲销机制

① 标准反向冲销 Reverse Posting

生成一张借贷方向对调、金额不变的新凭证。原凭证与冲销凭证的借贷发生额都真实入账（发生额虚增，但余额归零）。

借贷
原:6602 管理费用1200
原:1002 银行存款1200
冲:1002 银行存款1200
冲:6602 管理费用1200

② 负额红冲 Negative Posting

在原方向的同一侧记负数，直接冲减发生额（发生额不虚增，更贴近中式「红字冲销」）。需公司代码 + 冲销原因允许负额。

借贷
原:6602 管理费用1200
原:1002 银行存款1200
冲:6602 管理费用−1200
冲:1002 银行存款−1200

冲销处理流程

1
选原凭证 + 冲销原因：原 ga_doc 须 posted 且未被冲销（is_reversal != 2）。原因来自枚举（01 实际冲销 / 02 跨期冲销…）。
2
定冲销期间：默认冲到原凭证期间；若该期已结账，则冲到当前开放期（原因 02）。冲销凭证类型取原凭证类型的 reversal_doc_type（cf_doc_type）。
3
构造冲销凭证：按机制①或②生成一张 audited 的 cv_header（或直接构造过账入参），source 指向原凭证。
4
走过账引擎：冲销凭证过账 → 新 ga_doc（is_reversal=1）+ ga_journal + 余额自动更新。
5
双向勾稽：原 ga_doc.reverse_doc_id=冲销id、is_reversal=2；冲销 ga_doc.reverse_doc_id=原id。原 cv_header.doc_status → reversed。
冲销的三条约束
① 不可二次冲销：已冲销凭证不能再冲（闸门 is_reversal=2）。② 已清项不能冲：若原凭证行已被清账（AR/AP clearing_doc_id 非空），须先重置清账。③ 冲销也走期间开放校验：目标期间须 open。冲销凭证本身也是不可变账，错了只能再冲销冲销凭证（层层留痕）。

§11期末处理：结账 / 结转 / 估值

期末把一个会计期间「封口」，并为跨期/跨年做数据搬运。菜单已预留期末结转 / 期末结账 / 反结账三节点。全部动账动作仍走过账引擎。

外币估值 Valuation

期末对外币货币性科目/未清项按期末汇率重估，差额记未实现汇兑损益（账户确定 KDF）。生成估值凭证走过账；可配置下期初自动冲回。

结账 Close

校验本期全部凭证已过账、借贷平衡，跑完折旧/估值后，把 ga_period_status 置 closed，禁止再过账到该期。可按科目类型段分步关（先关损益、后关往来）。

余额结转 Carryforward

年末：资产负债类科目期末余额→次年期初（period_code=YYYY-00）；损益类科目余额→「本年利润/未分配利润」，损益科目次年期初归零。

结账 / 反结账流程

1
结账前检查：本期无 draft/audited 未过账凭证；折旧/估值已跑；试算平衡通过（Σ期初借=贷、Σ发生借=贷、Σ期末借=贷）。任一不过 → 拒绝结账 + 清单。
2
结账：ga_period_status 该期置 closed；记录结账人/时间。下期自动成为当前开放期。
3
年结转（12 期或末special期后）：BS 科目 end_balance → 次年 YYYY-00 的 begin_balance；PL 科目结转本年利润；生成结转凭证入 ga_journal（余额皆有源）。
4
反结账 Reopen（权限+审批）：把 closed 退回 open，允许补录/冲销。反结账全程留痕；若已年结转，反结账需连带回滚结转凭证。
期初 period_code=YYYY-00 的约定
把「年初期初余额」建模为一个特殊期间 YYYY-00，让 ga_balance 的期初/发生/期末在同一张表用期间维度自然表达，查账与结转都统一。特殊调整期（13-16）同理用 YYYY-13..16，不干扰 12 期正常账。

§13余额引擎（余额）

两条维护路径

① 增量维护（过账时，默认）

过账事务第 6 步对每 (分类账,科目,期间[,维度]) 做 UPSERT，实时把本笔借贷累加进 ga_balance。查得快，无需扫明细。

INSERT INTO ga_balance (...key..., period_debit, period_credit, ...) VALUES (...) ON CONFLICT (ledger_code,comp_unit_id,gl_account_id, period_code,profit_ctr_id,segment_id, cost_center_id,currency_code) DO UPDATE SET period_debit = ga_balance.period_debit + EXCLUDED.period_debit, period_credit = ga_balance.period_credit + EXCLUDED.period_credit, end_balance = ga_balance.begin_balance + (ytd 累计借 - ytd 累计贷) * 方向;

② 全量重算（对账/修复）

怀疑不一致时，从 ga_journal 按分组求和，重建该 (公司,分类账,期间) 的余额，与增量值比对。接 cmx-job 异步。

SELECT ledger_code, gl_account_id, period_code, SUM(local_dr) period_debit, SUM(local_cr) period_credit FROM ga_journal WHERE comp_unit_id=? AND fiscal_year=? GROUP BY ledger_code, gl_account_id, period_code; -- 再叠加上期期末 → 本期期初 → 本期期末

余额方向与期末公式

期末余额的算法取决于科目性质（cf_gl_account.account_type_code / pl_bs_flag）：

科目性质期末余额公式正常余额方向
资产 / 成本 / 费用期末 = 期初 + 借发生 − 贷发生借方（end_balance ≥ 0 表示借余）
负债 / 权益 / 收入期末 = 期初 + 贷发生 − 借发生贷方
损益类（PL）期内累计，年结转清零随性质
多币种、多分类账的余额是「多行」不是「多列」
不同分类账（0L/税务账）、不同币种（本位/交易/集团）的余额，是 ga_balance 里 ledger_code/currency_code 不同的多行，而非一行多列。这让「加分类账/加币种」是加数据、不是改表结构（呼应 SAP 弹性域思想的反面：这里用行扩展）。查询按需筛 ledger_code='0L' AND currency_code='CNY'。
按维度余额的粒度陷阱
若既要「科目汇总余额」又要「科目×利润中心明细余额」，用维度列 -1 哨兵区分两种粒度行：过账时同时 UPSERT 汇总行（dims=-1）与明细行（真实 dims）。否则汇总 = Σ明细 需运行时聚合，慢。存两份的代价是写放大，换读简单——总账读多写少，值得。

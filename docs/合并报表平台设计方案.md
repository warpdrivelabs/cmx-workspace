# 大型企业集团合并报表平台 · 设计方案

> 状态：**设计（仅方案，不动代码）** · 待审核 · 择机实现
> 参考基准：① 本平台现有报表/总账/规则/流程实现 ② LucaNet AG 合并方案方法论
> 准则口径：CAS 33《合并财务报表》/ CAS 20《企业合并》(对标 IFRS 10 / IFRS 3 / IAS 21 / IAS 28)

## 0. 结论速览 · TL;DR

**一句话架构**：合并 = **个别报表数据(ga_balance 分主体) → 科目映射 → 外币折算 → 内部往来对账 → 抵销分录(规则驱动,作为合并分类账凭证) → 分级汇总(master-slave/agg) → 合并工作底稿 → 合并报表出表(复用 RPT 平台,每主体一浮动列)**。抵销分录本质是"合并分类账"里的日记账凭证——与 SAP S/4 Group Reporting、LucaNet 的"合并日记账"同构,天然可审计、可追溯。

**核心判断：本平台已具备合并所需的 80% 基础设施,合并是"新增一个领域层 cmx-consol + 若干 cg_* 元数据表",而非从零造。**

| 合并能力 | 复用现有 | 新增 | 关键点 |
|---|---|---|---|
| 合并范围/组织架构/持股 | ✅ `cr_consol_org`(method/ownership/voting/currency/offset/自分级) | 扩展字段 | 已有多级合并骨架 |
| 个别报表数据源 | ✅ `ga_balance`/`ga_journal`(ACDOCA 通用日记账,含 entity+trading_partner+利润中心+segment+并行分类账) | — | 单一事实源,往来伙伴维度天然支持 IC 抵销 |
| 科目映射(地方→集团) | ✅ DCT 字典 + `cmx-master-slave` | `cg_coa_mapping` | 映射即字典 |
| 外币折算 + CTA | — | `cg_fx_rate` + 折算引擎 | 期末/平均/历史汇率,折算差额 |
| 内部往来对账 | ✅ 往来伙伴维度(ga_journal.trading_partner) | `cg_ic_recon` | 按伙伴匹配 + 容差 |
| 抵销分录 | ✅ `cmx-rule`(规则引擎) + GL 凭证模型(ga_doc/ga_journal 并行分类账) | `cg_elim_rule` + 合并分类账 | 规则驱动生成,凭证式落账 |
| 少数股东权益(NCI) | ✅ agg 汇总 | 计算规则 | 按持股比例 |
| 权益法/长投台账 | — | `cg_equity_invest` + `cg_goodwill` | 权益法调整、商誉减值 |
| 分级/逐级合并 | ✅ `cmx-master-slave`+`cmx-agg`(任意层级 roll-up) | 合并顺序编排 | 子集团先合、逐级上卷 |
| 合并工作底稿 | ✅ 报表浮动列(每主体一列)+ 公式引擎 | `cg_consol_data` | 个别数/调整/抵销/合并数四栏 |
| 合并报表出表 | ✅ RPT 平台(模板/浮动行列/公式/画布) | 取数函数 `CG/IND/ELIM` | 复用财务报表平台 |
| 合并流程编排 | ✅ `cmx-flow`(BPMN 引擎) | 关账流程定义 | 采集→折算→对账→抵销→出表→审批 |
| 长任务执行 | ✅ `cmx-job`(异步任务中心,SSE/断点/HA) | 合并作业 kind | 一次合并=一个可追踪作业 |
| 建表 | ✅ 模型中心元数据部署(`/api/model/deploy`) | `cg_*` 进 meta-JSON | 表在元数据声明,不在程序建 |
| 审计追溯/下钻 | ✅ 报表下钻 + GL 凭证追溯 | 合并数→抵销分录→个别数→原始凭证 | 全链条可回溯 |

**新增最小集**：一个领域 crate 群 `cmx-consol`(model/store-pg/api,一芯多壳) + 约 12 张 `cg_*` 元数据表 + 一个合并分类账(复用 GL 凭证模型) + 报表侧 3 个取数函数。**不新造** GL、报表、规则、流程、任务、部署链路。

## 1. 需求 · 大型企业集团合并的挑战

以中国建筑集团(CSCEC,demo 数据即此)这类大型央企集团为标靶:

- **主体多、层级深**:集团 → 股份公司 → 各工程局 → 分子公司,**多级(4~6 层)逐级合并**;数百至数千法人主体。
- **合并范围动态**:期间内并购/处置/股权变动 → **合并范围变动**(首次纳入、不再纳入、分步取得控制)。
- **多准则、多账簿**:法定合并(CAS)、管理合并(内部口径)、可能的 IFRS 转换 → **并行分类账 + 多合并方案**。
- **多币种**:境外主体外币报表 → **折算 + 折算差额(CTA)**。
- **海量内部交易**:集团内工程分包、材料购销、资金拆借 → **内部往来对账 + 内部交易抵销 + 未实现利润抵销**。
- **合并方法混合**:控制→全额合并;共同控制/重大影响→权益法;→ **方法混用 + 权益法调整**。
- **关账时效**:月度/季度/年度关账,几十步骤、多人协同、时限压力 → **流程编排 + 长任务 + 审计留痕**。
- **可追溯**:监管/审计要求合并数能**下钻到抵销分录、个别报表、原始凭证**。

**目标**:一套覆盖"采集→映射→折算→对账→抵销→汇总→出表→追溯"全链路、支持多级/多准则/多币种/范围变动、可审计的**集团合并报表平台**。

### 2.2 LucaNet 合并方法论精要(对标)

LucaNet(德国合并/计划软件,IFRS/HGB/US-GAAP)的核心范式,逐条映射到本方案:

| LucaNet 能力 | 方法要点 | 本方案落点 |

| **资本合并** | 长投 vs 子公司权益抵销、商誉(PPA 购买价分摊)、NCI 初始计量 | `cg_equity_invest`+`cg_goodwill` + 资本抵销规则 |
| **债权债务抵销** | IC 应收/应付、坏账准备抵销 | 债务抵销规则(按往来伙伴) |
| **损益抵销** | 内部收入/成本、内部利息、内部股利 | 损益抵销规则 |
| **中间利润抵销** | 存货/固定资产内部交易未实现利润 | 未实现利润抵销规则 + 台账 |
| **合并方法** | 全额/权益/比例/成本 | `consol_method` 分派引擎 |
| **分级合并** | 子集团先合成,逐级上卷(step consolidation) | `cmx-master-slave` 按 `cr_consol_org` 层级 |
| **少数股东权益** | 按持股比例计算 NCI 权益与损益 | agg + NCI 规则 |
| **合并日记账** | 所有抵销/调整以**日记账凭证**记录,可审计 | **合并分类账**(GL 并行分类账,ledger=CONSOL) |
| **合并范围变动** | 首次合并、处置、分步收购 | `cg_scope_change` + 期初结转规则 |
| **报表与分析** | 合并报表、下钻、审计追踪 | RPT 出表 + 全链下钻 |
| **关账流程管理** | 任务/状态/期间锁 | `cmx-flow` + 期间状态 |

### 2.3 差距分析(需新增的部分)

现有平台**缺**的,正是合并的"会计逻辑层":

1. **外币折算引擎**(汇率表 + 折算算法 + CTA)——全新。
2. **内部往来对账 + 抵销引擎**(规则驱动生成抵销分录)——逻辑新增,底座(规则/凭证)复用。
3. **权益法/长投/商誉台账**——全新主数据 + 计算。
4. **合并工作底稿组装 + 合并结果落库**(`cg_consol_data`)——逻辑新增,底座(浮动列/公式/agg)复用。
5. **合并专属取数函数**(`CG/IND/ELIM`)——报表引擎小改。
6. **合并顺序编排**(逐级合并的执行 DAG)——flow/job 编排新增。

**结论**:新增聚焦"合并会计算法 + 编排",基础设施全复用。

## 3. 合并会计核心域模型(CAS 33 / IFRS 10)

> 本节确立领域语言,后续 `cg_*` 表与引擎皆据此。

### 3.1 合并范围与控制
- **控制**三要素:权力 + 可变回报 + 用权力影响回报。判断驱动 `consol_method`。
- **合并范围** = `cr_consol_org` 中纳入合并的主体集合(按 `consol_scheme` 划分不同方案)。

### 3.2 合并方法
| 方法 `consol_method` | 适用 | 处理 |
|---|---|---|
| `full` 全额合并 | 子公司(控制) | 100% 并入 + 抵销 + 确认 NCI |
| `equity` 权益法 | 联营/合营(重大影响/共同控制) | 按份额确认投资收益,不逐行并入 |
| `proportional` 比例合并 | (CAS 下罕见) | 按比例并入 |
| `cost` 成本法 | 无重大影响 | 仅个别报表,合并层不调整 |

### 3.3 抵销分录体系(合并分类账)
| 抵销类型 | 内容 | 数据依据 |
|---|---|---|
| **资本抵销** | 长期股权投资 ↔ 子公司所有者权益;差额→商誉/合并价差;确认 NCI | `cg_equity_invest` + 子公司权益(ga_balance) |
| **债权债务抵销** | 内部应收/应付/其他往来 + 对应坏账准备 | 往来伙伴维度双边 |
| **内部购销抵销** | 内部营业收入 ↔ 营业成本 | 往来伙伴 + 收入成本科目 |
| **存货未实现利润** | 期末内部存货中的未实现毛利 | `cg_interim_profit` 台账 |
| **固定资产/无形内部交易** | 内部转让形成的资产未实现利润 + 多提折旧回转 | 台账 |
| **内部债券投资** | 应付债券 ↔ 债券投资 + 内部利息 | 往来伙伴 |
| **投资收益/股利抵销** | 母公司确认的子公司投资收益/分红回转 | `cg_equity_invest` |
| **权益法调整** | 联营/合营按份额确认损益 | `cg_equity_invest` |

**★ 期初结转(carry-forward)**:上期抵销分录影响留存收益/权益的部分,本期须**结转期初**(合并的连续性)。这是合并最易错点,须由引擎自动生成期初抵销。

### 3.4 少数股东权益(NCI)
- **少数股东权益**(资产负债表)= 子公司可辨认净资产 × (1 − 母公司持股比例)。
- **少数股东损益**(利润表)= 子公司净利润 × (1 − 持股比例)。
- 全额合并下,子公司 100% 并入后,把不属于母公司的份额划出为 NCI。

### 3.5 外币折算(IAS 21)
- **资产负债表**:期末汇率(closing)。
- **利润表**:平均汇率(average)。
- **权益(实收资本等)**:历史汇率(historical)。
- **折算差额 CTA** = 轧差,计入合并所有者权益"其他综合收益—外币报表折算差额"。

### 3.6 合并工作底稿(consolidation worksheet)
经典四栏(或多栏)结构,本方案用**浮动列**呈现:

```
科目            │ 母公司 │ 子A │ 子B │ … │ 合计 │ 调整 │ 抵销 │ 合并数
货币资金        │  ...   │ ... │ ... │   │ ...  │      │      │  ...
长期股权投资    │  ...   │  0  │  0  │   │ ...  │      │ (X)  │   0
少数股东权益    │        │     │     │   │      │      │ +Y   │   Y
```
- **主体列 = 浮动列**(按合并范围展开,复用已建的列浮动)。
- **调整/抵销列 = 抵销分类账汇总**投影。
- **合并数 = 个别合计 + 调整 + 抵销**(公式)。

## 4. 目标架构

### 4.1 分层流水线(合并的七段)

```
① 采集 Collect      ga_balance 分主体试算表(个别报表数据)
        ↓
② 映射 Map          地方科目 → 集团科目(cg_coa_mapping);维度对齐
        ↓
③ 折算 Translate    外币主体 × cg_fx_rate → 集团币;CTA 折算差额
        ↓
④ 对账 Reconcile    内部往来按伙伴双边匹配 → cg_ic_recon(差异/容差)
        ↓
⑤ 抵销 Eliminate    cg_elim_rule 规则驱动 → 抵销分录(合并分类账凭证)
                    含期初结转 carry-forward
        ↓
⑥ 汇总 Rollup       cmx-master-slave/agg 按 cr_consol_org 层级逐级上卷
                    NCI 计算;子集团先合、再上卷
        ↓
⑦ 出表 Report       工作底稿 cg_consol_data → RPT 平台合并报表(浮动列)
```
每段是**可独立执行、可重跑、可追溯**的作业步骤,由 `cmx-flow` 编排、`cmx-job` 执行。

### 4.2 新领域 crate 群 `cmx-consol`(一芯多壳,对标 flow/report/rule)

```
crates/libs/cmx-consol/
  cmx-consol-model/     语义中立核:合并方法/抵销类型/折算规则/工作底稿模型;零 DB/HTTP
  cmx-consol-store-pg/  持久化 + 合并引擎(采集/映射/折算/对账/抵销/汇总/组装)
  cmx-consol-api/       ConsolModule 路由(镜像 ReportModule);web-server merge
```
- **依赖方向**:store-pg 依赖 model + `cmx-master-slave`(agg) + `cmx-rpt-formula`(公式复用) + GL 读写门面;api 薄壳。
- **可独立微服务化**(后续):同 flow/report/rule 的"中立核 cmx-consol-app + 反代壳",支持独立部署/多租户。

### 4.3 新增 `cg_*` 元数据表(全部进 meta-JSON,模型中心部署,不在程序建)

**★ 合并分类账 `cg_elim_journal` = 复用 GL 凭证范式**:每条抵销/调整是一张"合并凭证",含借贷行、往来伙伴、是否期初结转、来源规则。可直接**复用 GL 的凭证号段/校验/过账**机制(或作为 `ga_journal` 的一个专用 `ledger='CONSOL'`)。这让抵销天然**可审计、可下钻、可红冲**。

## 5. 数据模型(cg_* 详解)

### 5.1 `cg_consol_scheme` 合并方案
一个方案 = 一套(准则 + 集团币 + 合并分类账 + 范围规则)。支持法定合并(CAS)、管理口径、IFRS 并行,互不干扰。方案是所有 cg_* 数据的顶层隔离维度(类比报表的 version)。

### 5.2 `cg_scope` 合并范围(方案 × 期间 × 主体)
- 承接 `cr_consol_org` 的层级 + 方法,但**按方案+期间快照**(合并范围随期变化)。
- `first_time`(首次纳入)/`disposal`(处置)/`step_acquire`(分步取得)标志 → 驱动范围变动处理。
- `consol_node` 概念:层级中的**每个非叶节点 = 一个合并节点**(子集团),逐级合并的目标。

### 5.3 `cg_coa_mapping` 科目映射
- (entity, local_account) → group_account,可带符号翻转/拆分/合并(1:1、N:1、1:N)。
- 复用 DCT 字典 CRUD 维护;复杂映射走 `cmx-rule`(rule_ref)。
- **映射即"采集②"的核心**:把各主体异构科目归一到集团科目表。

### 5.4 `cg_fx_rate` 汇率表
- (period, from_ccy, to_ccy, rate_type)。rate_type: `closing`(期末)/`average`(平均)/`historical`(历史)。
- 折算③按科目性质选汇率类型(资产负债→closing、损益→average、权益→historical)。

### 5.5 `cg_ic_transaction` / `cg_ic_recon` 内部往来
- `cg_ic_transaction`:每笔内部交易/往来余额(entity 视角 + partner 对手)。**可由 ga_journal 按 trading_partner 维度自动抽取**(伙伴非空即内部)。
- `cg_ic_recon`:双边配对结果(A 报 vs B 报)、差异、容差内/外、状态(待查/已核/差异)。差异 → 挂账或人工调整。

### 5.6 `cg_elim_rule` 抵销规则
- 规则式定义每类抵销:触发条件(elim_type + scope)、借贷科目、金额公式(FEEL/脚本)、作用范围(全范围/指定主体对)。
- 例:债务抵销 = 对每对(entity,partner),借"应付账款"、贷"应收账款",金额取对账匹配额。
- 走 `cmx-rule`:决策表配置常规抵销,决策图/脚本配置复杂抵销(如未实现利润按毛利率)。

### 5.7 `cg_elim_journal` 合并分类账(抵销/调整凭证)
- 一条抵销 = 一张合并凭证(doc_no)+ N 借贷行。含 `is_opening`(期初结转)、`source_rule`(可追溯到规则)、`partner`。
- **落在合并节点 org_code**(哪一级合并产生的抵销)。逐级合并时,下级抵销上卷到上级。
- 可红冲、可手工补录(手工抵销凭证,is_manual)。

### 5.8 `cg_equity_invest` / `cg_goodwill` / `cg_interim_profit`
- `cg_equity_invest`:长投台账(投资方/被投资方/方法/成本/持股/权益份额/商誉),支撑资本抵销 + 权益法。
- `cg_goodwill`:商誉初始 + 减值 + 账面(按 CGU 现金产出单元)。
- `cg_interim_profit`:内部交易未实现利润台账(存货/固资/无形),期末计提、下期实现回转。

### 5.9 `cg_consol_data` 合并结果(工作底稿落库)
- 8+ 元键:scheme + period + **org_code(合并节点)** + ledger + account(+ 维度)。
- 四(多)栏:`individual`(个别合计)、`adjust`(调整)、`elim`(抵销)、`consolidated`(合并数)。
- **cr_cell_data 的姊妹表**:cr_cell_data 存"报表单元格值",cg_consol_data 存"合并科目值";出表时报表取数函数从此读。

## 6. 合并引擎(cmx-consol-store-pg)

> 引擎 = 七段流水线的算法实现。每段是独立服务函数,返回结构化结果,由 flow/job 编排调用。全部**幂等可重跑**(按 scheme+period+node 重算前先清该维度的派生数据)。

### 6.1 采集与科目映射(Collect + Map)
```
collect_individual(scheme, period, node)
  → 遍历 cg_scope 下该合并节点的叶子主体
  → 读 ga_balance(entity, period, ledger=方案分类账)  ← 单一事实源
  → 按 cg_coa_mapping 归一到集团科目(1:1/N:1/1:N,符号翻转)
  → 复杂映射走 cmx-rule(rule_ref)
  → 落 cg_consol_data.individual(个别数栏)
```
- **零搬数**:优先直接读 `ga_balance`(ZmcDataSet 零拷贝),不复制试算表。
- 缺失主体/未过账 → 校验规则报缺口(阻断或告警)。

### 6.2 外币折算(Translate)
```
translate(scheme, period, node)
  → 对 consol_currency ≠ 集团币 的主体:
      资产负债类科目 × closing rate
      损益类科目     × average rate
      权益类科目     × historical rate(实收资本按出资时历史汇率)
  → 轧差 = 折算后借贷差 → CTA(其他综合收益·外币报表折算差额)
  → 折算差额生成一张"折算调整凭证"入 cg_elim_journal(elim_type=fx_translation)
```
- 折算在**映射后、抵销前**;折算差额进合并权益,不进损益(IAS 21 净投资法)。
- 历史汇率需 `cg_equity_invest`/出资台账支撑权益科目的历史成本汇率。

### 6.3 内部往来对账(Reconcile)
```
reconcile_ic(scheme, period)
  → 从 ga_journal 按 trading_partner≠null 抽 cg_ic_transaction(内部交易/往来)
  → 双边配对:对每对(A,B)+ic_type,比 A 报应收 vs B 报应付
  → 差异 ≤ 容差 → 匹配;> 容差 → 挂 cg_ic_recon(status=diff)待人工
  → 匹配额 = 抵销引擎的输入
```
- 对账**先于抵销**:抵销金额取"已核对"的匹配额,差异部分挂账或人工调整,不盲目抵销。
- 差异分析工作台(native-page):按主体对/类型列差异,支持人工核销/调整凭证。

### 6.4 抵销引擎(Eliminate,规则驱动)
```
eliminate(scheme, period, node)
  → 载入 cg_elim_rule(该方案启用的抵销规则,按 elim_type 排序)
  → 对每条规则:按 scope 找作用主体/主体对 → 求金额(FEEL/脚本)→ 生成借贷行
  → 落 cg_elim_journal(合并凭证,partner,source_rule,org_code=node)
  → 期初结转:上期影响留存收益/权益的抵销 → 本期生成 is_opening 期初凭证
```
抵销规则库(可配置,随准则/集团政策调整):

| 规则 elim_type | 生成逻辑(示意) |
|---|---|
| `capital`(资本抵销) | 借:实收资本/资本公积/盈余公积/未分配利润(子公司权益);贷:长期股权投资(母);差额→商誉 或 营业外收入;确认少数股东权益 |
| `debt`(债务抵销) | 借:应付账款/其他应付款(按 partner);贷:应收账款/其他应收款;连带抵销坏账准备 |
| `sales`(购销抵销) | 借:营业收入;贷:营业成本(内部购销匹配额) |
| `inventory_profit`(存货未实现利润) | 借:营业成本;贷:存货(期末内部存货 × 综合毛利率);下期实现回转 |
| `fixed_asset`(固资内部交易) | 借:营业外收入/资产处置;贷:固定资产原值;多提折旧逐期回转 |
| `dividend`(股利抵销) | 借:投资收益(母);贷:未分配利润/少数股东损益(子分红) |
| `equity_method`(权益法调整) | 按份额:借:长期股权投资;贷:投资收益(联营/合营) |

- **规则驱动**:常规抵销用 `cmx-rule` 决策表(elim_type × 科目 × 金额公式);未实现利润等复杂逻辑用决策图/Rhai 脚本。规则变更不改代码。
- **凭证式**:每笔抵销可查可红冲可追溯到规则,满足审计(对标 LucaNet 合并日记账)。

### 6.5 少数股东权益(NCI)
```
compute_nci(scheme, period, node)
  → 对全额合并的子公司:
      少数股东权益 = 子公司可辨认净资产 × (1 − ownership_pct)
      少数股东损益 = 子公司净利润 × (1 − ownership_pct)
  → 生成 NCI 划分凭证入 cg_elim_journal(elim_type=nci)
```
- 多级持股/交叉持股 → 用有效持股比例(逐级相乘);`cmx-rule` 或矩阵法计算。

### 6.6 分级合并(Rollup,逐级上卷)
```
rollup(scheme, period)
  → 按 cr_consol_org 层级自底向上(拓扑序):
      每个合并节点 = 其直接下级(个别数 + 已在下级完成的合并数)+ 本级抵销
      子集团先合成 → 作为一个"主体"参与上级合并(step consolidation)
  → cmx-master-slave/agg 做层间汇总(承接字段随子层 UPSERT)
  → 合并数 = 个别合计 + 调整 + 抵销(逐节点)
```
- **逐级 vs 一步到位**:本方案采用**逐级合并**(LucaNet/CAS 主流),子集团报表可独立出具;`cmx-master-slave` 的任意层级 roll-up 正是为此。
- 拓扑序执行(叶→根),复用 flow 的 DAG 编排。

### 6.7 工作底稿组装(Assemble)
- `cg_consol_data` 每合并节点一套:individual(个别合计)/adjust(调整)/elim(抵销)/consolidated(合并数)。
- consolidated = individual + adjust + elim(引擎写入,公式可核验)。
- 供出表与下钻的**单一结果源**。

## 8. 合并流程编排(cmx-flow)

一次集团关账 = 一个 BPMN 流程,把七段流水线 + 人工审核 + 期间锁编排为可追踪的关账作业:

```
[开启期间] → [各主体数据采集/过账校验] → 会签:各主体确认
   → [科目映射校验] → [外币折算] → [内部往来对账]
   → 网关:差异是否清零? ──否──→ [差异处理(人工)] ↺
                          └─是─→ [执行抵销(逐级)] → [NCI/权益法]
   → [生成合并工作底稿] → [出具合并报表] → 审批:财务负责人签批
   → [期间锁定 lock] → [归档]
```
- **逐级合并 = 子流程**:每个合并节点一个子流程(cmx-flow 子流程 + 组织路由已支持),按 cr_consol_org 层级拓扑串起。
- **期间状态机**:未开启/采集中/对账中/合并中/已出表/已锁定;锁定后禁止回改(复用 GL 期间状态 `ga_period_status`)。
- **协同**:多财务人员分主体/分步骤,会签/抄送/待办中心(cmx-flow 已具备)。
- **每步 = 一个 cmx-job 作业**:长任务(逐级合并可能数分钟)走任务中心,SSE 进度、可暂停/续跑/重跑、断点、分布式 HA。

## 9. 审计追溯与下钻(全链可回溯)

监管/审计的硬要求:合并数能一路下钻到底。本方案天然支持(每层都有结构化落库):

```
合并报表某格(如"合并·应收账款")
  → CG 取数 → cg_consol_data(node, account)  ← 合并数 = 个别 + 调整 + 抵销
      ├─ individual → 各主体 cg_consol_data.individual
      │     → ga_balance(entity, account)      ← 个别余额
      │         → ga_journal 明细行            ← 通用日记账
      │             → cv_* 原始单据             ← 业务凭证
      ├─ elim → cg_elim_journal(该科目相关抵销凭证)
      │     → source_rule → cg_elim_rule       ← 为何这样抵销
      │     → partner / cg_ic_recon            ← 对账依据
      └─ adjust → 调整凭证(手工/权益法/折算)
```
- **合并凭证式**是可审计的根基:每笔抵销/调整都是带借贷、来源规则、对手方的凭证,可红冲、可注释。
- 下钻 UI 复用报表下钻 + GL 凭证追溯;跨 cg_/ga_/cv_ 三层一贯。

## 10. 合并范围变动(scope changes)

合并最难的动态场景,单列处理:

| 变动 | `cg_scope` 标志 | 处理 |
|---|---|---|
| **首次纳入**(non-→控制) | `first_time` | 购买日 PPA(可辨认净资产公允价)、商誉、当期仅并入购买日后损益 |
| **不再纳入**(处置) | `disposal` | 处置日止并表、确认处置损益、结转商誉 |
| **分步取得控制** | `step_acquire` | 原权益法/成本法转全额合并,原持股按公允价重估 |
| **同一控制下合并** | `common_control` | 权益结合法,视同期初已合并、追溯 |
| **持股比例变动(未失控)** | `equity_change` | 权益交易,不确认损益,调资本公积 |

- 范围变动驱动**期初结转**与**当期并入范围**的差异化处理;由规则(cmx-rule)+ 引擎按标志分派。
- `cg_scope` 按方案+期间快照,范围变化留痕可比。

## 13. 待定 · 边界 · 风险

**待拍板**:
1. **合并分类账载体**:独立 `cg_elim_journal` vs 复用 `ga_journal`(ledger=CONSOL)。建议后者(与 SAP Group Reporting 一致,复用号段/校验/过账),但需 GL 支持"合并主体/合并层级"作为记账实体。
2. **合并数据源口径**:直接读 `ga_balance`(实时) vs 采集快照到 cg_consol_data(冻结)。建议快照(合并须可复现、期间锁后不变)。
3. **metaKind**:合并是否设第六元 `CONSOL`,还是作为 `fi/cmxfico/consol` 应用模块(DCT+DOC+RPT 组合)。建议后者(不新增 metaKind,复用三元)。
4. **现金流量表/权益变动表**:直接法/间接法、现金流量项目映射的维度设计需专项。
5. **多准则并行**:CAS + IFRS 双出,靠 `cg_consol_scheme` × 并行分类账;工作量评估另议。

**边界(本期不含)**:
- 合并预算/预测(计划态合并,LucaNet 强项)——后续。
- 分部报告、管理会计维度合并——后续(维度已在 ga_journal 就位)。
- 税务合并(汇算清缴)——独立议题。

**风险**:
- **期初结转**是最易错点(上期抵销对本期权益的连续影响),须引擎自动化 + 强校验。
- **交叉持股/多级少数股东**的有效持股计算(矩阵法),C6 需专项验证。
- **数据质量**(各主体过账完整性)决定合并质量,C1 校验须严。
- GL(ga_*)当前未在 fico 库部署(仅设计),合并落地前置依赖 GL 先行。

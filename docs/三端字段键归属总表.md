# 三端字段键归属总表（DCT / DOC / CTX）

> 数据来源：`packages/cmx-data-comp/src/lib/cmx-field-schema.js`（UI schema 键 + 端归属）
> + `cmx-field-adapter.js`（schema 键 → 各端实际**存储键**映射）。
>
> 说明两层概念：
> - **UI schema 键**：详编/表格里统一的属性键（data-field-prop / data-field-path）。
> - **存储键**：落到字段对象 JSON 里的实际键（引擎/校验器/服务端读的就是它）。
> P7 已把 CTX 多数存储键统一到与 DCT/DOC 一致；少数仅 UI 统一、存储仍异（见 §3）。

---

## 1. 三端公用的键（DCT/DOC/CTX 都有）

### 1a. 存储键真正一致（同一 JSON 键，引擎直读无歧义）

| 含义 | UI schema 键 | 统一存储键 | 备注 |
|---|---|---|---|
| 字段标识 | `fieldName` | `fieldName` | CTX 原 `code` 已迁移 |
| 标题/注释 | `caption`(CTX) / `description`(DCT/DOC) | `fieldComment` | 两端 UI 键不同，**存储都落 `fieldComment`** |
| 维度语义 | `kind`(CTX) / `dimType`(DOC) | `dimType` | 值域 `dimension/measure/attribute/relation`；CTX 原 `kind` 已迁移 |
| 数据类型 | `dataType`(DCT/DOC) / `logicalType`(CTX) | `dataType` | 物理类型(VARCHAR/INT/DECIMAL…)；CTX 原逻辑值已迁移 |
| 引用字典 | `refDict` | `refDict` | CTX=绑定的维度 code；DCT/DOC=字典编码 |
| 引用字段 | `refField` | `refField` | 取值列 |
| 显示字段 | `displayField` | `displayField` | 展示列 |
| 默认值 | `defaultValue` | `defaultValue` | 约束 |
| 唯一 | `unique` | `unique` | 约束 |
| 校验正则 | `pattern` | `pattern` | 约束 |
| 枚举值 | `enumValues` | `enumValues` | 约束（对象数组 `[{value,label}]`，label 可选） |
| 显示标签 | `label` | `label` | 治理 |
| 可搜索 | `searchable` | `searchable` | 治理 |
| 可筛选 | `filterable` | `filterable` | 治理 |
| 敏感级别 | `sensitive` | `sensitive` | 治理 |
| 多语言 | `i18n` | `i18n` | 治理 |
| 录入控件 | `editMode` | `edit.mode` | 三端统一存 `edit.mode`（DCT/DOC 原 `uiControl` 已迁移） |
| 必填条件 | `controlRequiredWhen` | `edit.requiredWhen` | 三端统一存 `edit.requiredWhen`（DCT/DOC 原 `fieldControl.requiredWhen` 已迁移） |

### 1b. ~~UI 统一、存储仍异~~ —— 已全部统一

> P7 后续已把"录入控件""必填条件"两项的存储键也彻底统一（见 §1a 末两行）：
> - 录入控件：DCT/DOC 原落盘 `uiControl` → 统一为 `edit.mode`
> - 必填条件：DCT/DOC 原落盘 `fieldControl.requiredWhen` → 统一为 `edit.requiredWhen`
>
> 适配器 `get` 保留对旧键（`uiControl`/`fieldControl.*`）的回退读，存量数据已用迁移脚本固化为新键。现已无"UI 统一但存储异"的残留项。

## 2. 各端独有的键

### 2a. DCT / DOC 独有（数据字典 / 业务单据）

| 含义 | 存储键 | 端 | 区 |
|---|---|---|---|
| 长度 | `fieldLength` | DCT/DOC | 基本 |
| 整数位 | `intDigits` | DCT/DOC | 基本 |
| 小数位 | `decimalDigits` | DCT/DOC | 基本 |
| 可空 | `nullable` | DCT/DOC | 基本 |
| 维度类型(内联列) | `dimType` | **DOC** | 基本（仅业务单据表格内联） |
| 可编辑条件 | `edit.editableWhen` | DCT/DOC | 字段控制（原 `fieldControl.editableWhen` 已迁移） |
| 可见条件 | `edit.visibleWhen` | DCT/DOC | 字段控制（原 `fieldControl.visibleWhen` 已迁移） |

> 注：`fieldLength/intDigits/decimalDigits` 由 `dataType` 物理类型联动启用（VARCHAR→长度、INT→整数位、DECIMAL→整数位+小数位）。

## 3. 存储统一现状：已彻底统一

三端"相同含义"的属性现已**存储键完全一致**（§1a + §1b 末两行）。包括之前唯二的例外（录入控件、字段控制条件）也已统一：
- DCT/DOC 存盘元数据（`gl_md_dct_meta_v1.json` / `gl_md_doc_meta_v1.json`）的 `uiControl` → `edit.mode`、`fieldControl.{requiredWhen,editableWhen,visibleWhen}` → `edit.{...}` 已用迁移脚本固化。
- 适配器 `get` 保留旧键回退读（`uiControl`/`fieldControl.*`），任何未迁移的历史数据仍可正确读取。
- 消费方（引擎、flexible-combination-manager 匹配条件元数据）均改读统一键并兼容旧键。

迁移脚本：`scripts/migrate-def-meta-uicontrol.cjs`（DCT/DOC 元数据）、`scripts/migrate-flexible-combinations.cjs`（CTX profile）。

## 4. 分区归属速览

| 详编分区 | DCT/DOC | CTX |
|---|---|---|
| 基本 | 字段名/注释/类型/长度/整数位/小数位/可空/(DOC)维度类型 | 字段名/标题/类型(kind)/数据类型(只读) |
| 引用字典 | 引用字典/引用字段/显示字段 | 引用字典/引用字段/显示字段 |
| 编辑 | 录入控件 | 录入控件/必填/占位符 |
| 约束校验 | 默认值/唯一/校验正则/枚举值 | + 校验规则 |
| 数据治理 | 显示标签/可搜索/可筛选/敏感级别/多语言 | 同 |
| 字段控制 | 必填条件/可编辑条件/可见条件 | 必填条件/条件只读 |
| 显示（CTX 独有） | — | 对齐/显示模式/格式/小数位/千分位/0显示空/负数红字 |
| 计算与带出（CTX 独有） | — | 公式/依赖/来源带出/计量单位列 |
| 列布局（CTX 独有） | — | 列宽/冻结/可见/合计 |
